# 可校验备份与恢复

这是**停机备份**：先停止教师、独立快传以及本地管理和统计导入程序，再执行命令。备份包含私钥、权限、额度、恢复记录、匿名身份相关状态和临时文件，应保存在受保护的本地目录，不上传为公开下载。源码包与验证证据包不包含这些实际数据。

## 创建与检查

在工具目录运行，将目标换成一个**不存在**、父目录已存在且位于整个工具目录之外的新目录：

```sh
node scripts/maintenance.mjs backup "../private-backup-20260908" --stopped
node scripts/maintenance.mjs verify "../private-backup-20260908"
```

`--stopped` 表示操作者已完成停机；不是自动停止服务的开关。服务／备份互斥锁拒绝本版正在运行的实例，SQLite 独占事务也阻止同时修改数据库。旧版服务、外部采集器或绕开本工具的手工写盘不遵守此锁，必须先结束，不能把一份正在变化的目录当成可靠备份。

备份只包括当前有效配置规范化后的 `config.local.json`，以及该配置实际 `dataDirectory` 下的文件。环境覆盖值会归入规范配置；不需要原开发机的 `FT_CONFIG` 路径。包括专用私钥、SQLite 和私有临时文件；不复制 `runtime.lock`、教师数据、源码依赖、工具其他数据目录或历史接入补丁备份。其他数据目录／教师环境和整个教师站备份需按原流程单独保留。

使用有界流复制，不把大文件整体装入内存；备份为普通目录，不压缩，目标需留足同等数据空间与至少 16 MiB 余量。完整目录校验会再次读盘，大目录需要等待。最多 100,000 个文件，路径和清单有边界；符号链接、硬链接和特殊文件拒绝，文件内容、名称或元信息变化会使校验失败。Unix 新建备份目录权限 700、文件 600；Windows 需由管理员检查目标目录 ACL，不能把 Unix mode 当作 Windows ACL。

备份目录包含 `payload/` 和 `BACKUP-MANIFEST.json`。清单记录大小及 SHA-256；`verify` 检查清单范围、重复／非法路径、额外文件、每个文件的大小和摘要，以及 SQLite owner、schema 8、默认 DELETE 日志模式和 quick_check。自行改成 WAL 等日志模式的数据库会拒绝，避免把 WAL 内容遗漏为不完整备份。摘要用于发现意外损坏，**不是第三方数字签名**；只恢复自己控制、可信的备份，不能用它证明攻击者提供的备份真实可信。

## 恢复到新位置

```sh
node scripts/maintenance.mjs restore "../private-backup-20260908" "../transfer-restored-data"
```

先完整验证源备份，再恢复到不存在的新目录，并再次核对目标哈希。目标已存在即拒绝，失败时清理本次新建的不完整输出，不覆盖当前配置或数据。输出只有 `config.local.json` 与实际 `storage/...`，**没有工具源码**。

停机后先保留当前目录，将恢复的数据与对应版本完整源码组合到新的 `file-transfer/` 目录，确认与教师工程同级，再运行诊断和启动；原目录保留为回退，不对正在运行的 `storage/` 合并覆盖。恢复后源文件和接收端本机记录仍需匹配；仅有服务端备份不能恢复用户本机丢失的文件或匿名 Cookie。

有效分享保持原期限，不因还原备份延期。回退旧备份可能恢复更早的领取次数、权限、额度和流量统计；在开放前复核权限与分享撤销情况，并对照真实当前账单校准。供应用量是现实中已经消耗的流量，不会跟着磁盘时间一起倒回去。

## 错误与处理

| 提示 | 处理 |
| --- | --- |
| `FT_RUNTIME_BUSY` | 停止同一目录的服务或维护任务；不杀死未知进程 |
| `FT_LOCK_INVALID`／`FT_LOCK_CHANGED` | 停机后检查异常锁；命令不猜测删除它 |
| `FT_BACKUP_SPACE` | 更换有足够容量的目标盘 |
| `EEXIST` | 使用新的目标目录，不覆盖原备份或原数据 |
| `FT_BACKUP_HASH`／`FT_BACKUP_CHANGED` | 原文件变化或损坏；重新停机备份或使用另一份可信备份 |
| `FT_BACKUP_FILE`／`FT_BACKUP_DIRECTORY` | 检查符号链接、硬链接、特殊文件及权限 |
| `FT_BACKUP_JOURNAL` | 数据库被改为非默认日志模式，拒绝直接复制；由管理员使用对应 SQLite 一致性备份流程 |
| `FT_BACKUP_SCHEMA`／`FT_BACKUP_OWNER` | 使用对应工具与数据版本，不能混入教师数据库 |

本工具不备份 VPN 供应商账号、教师会话密钥或用户浏览器下载目录。备份／还原 CLI 的实际跨平台脚本行为、数据量和 ACL 必须在目标 Windows 电脑验收；本次使用 Linux 的真实文件与 SQLite 完成了备份、验证和恢复重启。

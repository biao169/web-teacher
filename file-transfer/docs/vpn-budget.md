# VPN 流量与额度（第 7/8 步）

第 7 步完成采集、看板和预算账本，第 8 步已接入受控 WebSocket 中继和临时分享；已核验绕开 VPN 的 LAN/WAN 路径独立判断。教师源码没有新增修改。

## 三种不同的用量

| 用量 | 统计内容 | 对应控制 |
| --- | --- | --- |
| 个人／匿名额度 | 发送＋接收的获准任务大小，见身份说明 | 按账号、角色、匿名共享限制准入 |
| 受控传输预算 | 服务端即将读写的方向字节、开销余量、短时预留 | 第 8 步受控中继／暂存逐块检查 |
| VPN 出口观测值 | 指定接口或外部账单覆盖的全部流量，可包含教师网站及其他服务 | 日／月预算、安全余量、失联及耗尽停用 |

文件大小不能代表 VPN 账单。重试、双向中继、协议开销、网站页面和其他共用出口程序也可能消耗流量。只有确认文件数据绕开受限出口的 LAN 不扣该出口预算；它仍受原有匿名／用户权限、个人总量和可选 LAN 限速约束。

## 首次配置

1. 打开教师后台侧栏“文件快传管理”，进入原“VPN 流量防护”分区。
2. 根据实际账单选择 GB 或 GiB。1 GB = 1,000,000,000 字节，1 GiB = 1,073,741,824 字节；切换不改变已保存字节值。填写每日／每月限额，留空表示未配置，0 表示禁用。
3. 配置账单时区、入口／出口／双向计费、安全余量及预警比例。安全余量同时从当日和当月可用量扣除；默认 1 GB，不能只因演示金额小就误以为已超额。预算默认按自然日和自然月，不支持供应商非自然月账期。
4. 选择实际统计源，并核实它覆盖需要保护的全部共用出口。核验按钮记录管理员确认，程序不能替代真实路由和账单核验。服务器物理网卡可能包含非 VPN 流量；隧道接口可能不包含供应商收取的外层开销。不要选择不相关的接口。
5. 保存本页配置；有未保存草稿时校准／对账按钮不可用。
6. 本机接口模式显示新样本后，填写账单或可信出口记录中的“今日已用”“本月已用”，包含本工具开始采集之前的消耗。填写的用量应与最新接口样本尽量同步；延迟大的记录需要补充安全余量。之后按计数器增量累计。校准不降低当前周期已经累计的值。
7. 默认“严格保护”保持计费链路关闭，因为本版没有接入可核验的出口硬限额。选择“估算保护”且满足计量、路径和权限条件时，第 8 步中继／暂存可申请预算；计费 P2P 仍不开放。

初始统计源为“尚未接入”；没有虚构的剩余数。前台和后台都显示日／月观测值、可用估算、任务预留、待对账、最后统计时间、时区、重置时间和禁用原因。配置字段仍在同一后台页面，不新增第二个控制台。

## 本机接口采集

Linux：后台填写实际接口名，服务只读 `/sys/class/net/<接口>/statistics/rx_bytes`、`tx_bytes`、接口编号／状态及内核启动 ID。可检查部署主机的 `/sys/class/net/` 确定名称。接口不可读、关闭或采样失败会停用计费链路。无需浏览器读取本机网络，也不会自动修改路由、防火墙或 VPN 配置。

Windows：后台填写准确的适配器名称。服务通过固定随包 `scripts/read-interface.ps1` 调用系统 PowerShell 的 `Get-NetAdapter`、`Get-NetAdapterStatistics` 和启动时间；参数以独立字符串传递，不执行网页输入的命令，不绕过系统脚本执行策略。执行策略或权限不允许时显示统计不可用，由部署人员依据现有系统管理规则处理。本轮只验证参数与返回值适配，未在 Windows 真机执行。

接口统计的计费口径由系统和驱动决定，不能视为供应商账单承诺。参见 [Linux 网络统计](https://docs.kernel.org/networking/statistics.html)、[Microsoft Get-NetAdapterStatistics](https://learn.microsoft.com/en-us/powershell/module/netadapter/get-netadapterstatistics?view=windowsserver2025-ps)。

服务默认每 10 秒采集一次，30 秒未获得新有效样本即过期。采样间隔可设 2–60 秒，过期阈值 6–300 秒且至少为间隔的两倍。同一旧时间戳不会因被重复读取而变新。统计源、方向或时区更改、计数器下降／启动 ID 改变时，本机模式要求重新校准；后续样本不会自动掩盖重置。

跨日／跨月的两次计数差不能精确划分时，整个增量保守计入新周期。预算窗口不能跨过重置时间。服务重启后保留观测账本和已发出预留，未发出部分到期释放。

## 外部账单／网关快照

供应商 API 和网关差异较大，本版提供本机导入边界，不内置某个供应商账户客户端。由有权读取完整账单的本地采集器持续提供以下 JSON；账户密钥留在该采集器的受保护配置中，不填入快传页面或 JSON。

示例为 **2026-09-08 12:00 Asia/Shanghai** 的结构示意，不能直接当作当前采样导入：

```json
{
  "kind": "snapshot",
  "sourceId": "vpn-main",
  "observedAt": 1788840000000,
  "timeZone": "Asia/Shanghai",
  "billing": "both",
  "daily": { "start": 1788796800000, "resetAt": 1788883200000, "usedBytes": "1000000000" },
  "monthly": { "start": 1788192000000, "resetAt": 1790784000000, "usedBytes": "10000000000" }
}
```

时间均为 Unix 毫秒整数；字节值必须为十进制字符串，精确到 1 字节，最大 9223372036854775807。`sourceId`、`timeZone` 和 `billing` 必须与后台一致。`billing` 为 `inbound`、`outbound` 或 `both`。`daily`／`monthly` 是整个计费范围当前周期的绝对已用量，不是单次增量；本月不能小于今日。周期边界可复用 `server/usage.mjs` 的 `usagePeriods(observedAt, timeZone)`，包括夏令时处理。

Linux／bash，在 `file-transfer/` 内将采集器刚生成的快照经标准输入导入：

```sh
node scripts/import-vpn-snapshot.mjs < /实际路径/current-vpn-usage.json
```

Windows PowerShell：

```powershell
Get-Content -Raw -LiteralPath 'D:\实际路径\current-vpn-usage.json' | node scripts/import-vpn-snapshot.mjs
```

脚本从本工具配置确定数据目录，校验当前源与周期，在 SQLite 中观测并原子发布到 `storage/data/telemetry/vpn-snapshot.json`（配置自定义数据目录时相应变化）。Linux 文件模式为 0600；快照上限 8 KiB，只读取固定普通文件，拒绝符号链接、多硬链接及其他用户可写文件。导入命令不是常驻采集器；需要现有本地采集任务持续提供新数据。供应商账单若延迟大于设置阈值，应保留失联限制，不伪造更新的 `observedAt`。

同周期快照向下修订不会减少已观测量，避免延迟数据回退预算。样本必须是真实采集时点：读取旧文件或重新运行导入不能使旧数据恢复有效。本机导入属于受信任管理操作，不能由匿名用户提供计费快照。

## 原子预留与对账

可供新任务使用的额度按以下两项中的较小值计算，负值显示为 0：

```
周期上限 − 周期观测量 − 安全余量 − 未发出预留 − 已发出待对账量
```

服务端内部预算窗口最多 1 MiB（入口＋出口合计）、2 秒，并受样本有效期与日／月边界约束。方向依据计费设置取值，再加默认 10% 开销余量。SQLite `BEGIN IMMEDIATE` 串行化预留，两个进程不能拿走同一份剩余额度，见 [SQLite 事务说明](https://sqlite.org/lang_transaction.html)。

`server/metered-copy.mjs` 每块最多 64 KiB，读取任何可能产生计费的内容前预扣，通过计时器和每块检查限制授权；每 100 ms 检查计量／配置变化，通过 AbortSignal 中断协作读写。已发出的凭证不能跨配置版本、统计过期或有效期后复用；余量刚好为零时，已完整预留的现有窗口仍可在有效期内使用。

取消只释放未发出部分。读／写已经获准的块即使失败，也保守保留为待对账，避免统计延迟期间退款再放行。它可能和后续观测值暂时重复计入。已结束窗口压缩进账本，避免按每块长期增加数据库行。

本版不根据时间猜测“肯定已进入账单”。后台对账要求没有活动窗口、最新样本比最后结束窗口至少晚一个统计过期阈值，并由管理员确认该样本已经包含已结束任务。确认只移除重复保守预留，**不清空观测流量**；供审计的校准／对账最多保留 100 条、页面显示 20 条。供应商仍未计入时，不应点击确认。第 8 步传输器保留此保守策略；未来仅在可验证网关证据基础上扩展自动对账。

## 保护范围

统计失联、数据异常、预算不足或配置变化会拒绝新的受控预算，并使已有授权停止继续使用。前台显示相应说明；局域网按既有核验及权限继续工作。看板的重置时间只表示账期边界，不能保证统计故障在该时刻恢复。

这仍是估算控制。已经进入系统缓冲区的数据、不能响应中止信号的适配器、其他程序和 VPN 账户在别处的使用，不能由本工具的 Node 进程完整截断。默认严格模式因此保持计费链路禁用，且 `hardLimitAvailable` 始终为 `false`；本版没有出口硬截断插件或允许管理员“打勾当作已实现”的开关。要保证硬上限，需要在真实部署出口或供应商账户端设置实际限额和断流，并在后续集成中验证其有效性。

本轮自动验证包括实际 Linux 只读接口、SQLite 多连接争抢、字节复制、统计失联中止、跨期、重启、旧库升级和真实教师 HTTP 身份桥接。没有把内存适配器测试写成浏览器、双机 VPN 或 Windows 实机验收结果。

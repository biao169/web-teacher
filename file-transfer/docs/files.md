# 第四步：文件、目录与本机保存

## 已实现的使用流程

在发送视图选择多个文件或一个文件夹，也可拖放浏览器能够提供的文件/目录条目。页面展示相对路径、文件数量、目录数量、空目录数量与总字节数；初始渲染 100 条，滚动至清单尾部继续加载，按钮作为兼容方式。可移除单个文件/整棵目录、清空选择及填写任务备注。

点击“预览接收与保存（本机）”生成当前集合的只读快照并切换接收视图，可保存单文件、保存完整目录或下载 ZIP。以后修改发送集合不会暗中修改已有预览，重新点击该按钮可更新快照。清空选择会释放集合与预览引用；当前保存/采集运行时禁止修改集合，支持取消。

这是实际文件处理和保存，不是伪造文件内容。但**还没有跨设备传输**：接收内容来源于本机选择，界面明确标注；接收码不配对，不生成 WebRTC、上传、下载服务器或中继请求。本机处理不上传文件正文；页面资源、账号和配置接口仍会产生普通网站请求，不能将整个网站描述为“零网络流量”。

## 采集与兼容

| 入口 | 已实现行为 | 限制 |
| --- | --- | --- |
| 文件选择 | 多文件、空文件、元信息与延后读取的数据源 | 不一次性把全文读入内存 |
| 目录选择：目录句柄 | 递归目录与文件，包含所选根目录和空目录 | 由浏览器能力、安全上下文及用户授权决定 |
| 目录选择：webkitdirectory | 根据 `webkitRelativePath` 还原已选文件的层级 | FileList 不能提供空目录；页面明确说明可能缺失 |
| 拖放：现代句柄 | 在 drop 同一事件中立即捕获全部句柄，再异步遍历 | 浏览器必须暴露该接口 |
| 拖放：旧目录条目 | 循环读取所有 readEntries 批次，保留可见空目录 | 不只读取前 100 个条目 |
| 拖放：文件回退 | 使用已捕获 File 对象 | 未提供目录条目的文件夹不会伪装成完整目录传入 |

目录选择和写入通过能力检测决定，不以浏览器名称判断。原生目录选择要求用户操作触发，并依赖安全上下文与授权；常见入口为 HTTPS 或可信本机开发地址。[MDN：showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

兼容目录选择使用 `webkitRelativePath` 表示文件相对路径。[MDN：webkitdirectory](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)

拖放句柄在事件处理时捕获；旧目录读取不断读取批次直到返回空数组。[MDN：拖放句柄](https://developer.mozilla.org/en-US/docs/Web/API/DataTransferItem/getAsFileSystemHandle)、[MDN：分批目录读取](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemDirectoryReader/readEntries)

## 名称与目录校验

清单版本 1，每条为 `{ relativePath, kind, sizeBytes, modifiedAt }`。目录大小固定为字符串 `"0"`，文件大小为有符号 64 位范围内的非负十进制字符串，总量使用 BigInt 累加。目录与文件分开计数。

采集名称统一为 NFC。清单必须已是 NFC；拒绝绝对路径、空路径段、`.`/`..`、反斜杠、Windows 设备名、备用数据流冒号、控制字符、双向文字控制符、孤立代理项及以点/空格结尾的组件。路径最长 1024 UTF-8 字节、组件最长 255 UTF-8 字节、最多 64 层；拒绝文件占据父目录、父目录缺失及同路径多条记录。

冲突匹配采取保守大小写归一，文件名添加 `(2)`、`(3)` 等后缀，尽量保留扩展名；重名根目录整体改名并同步改写所有后代路径。页面列出改名记录，清单采用最终名称。不随意合并两个同名根文件夹。

所有输出在开始前重新校验清单。目录写入只使用校验后的逐段名称，新建带随机标识的子目录，检查已存在的目标，不静默覆盖已有内容。浏览器句柄能力负责实际访问权限，工具不接受服务器磁盘路径或任意下载 URL。

## 保存与内存边界

| 方式 | 实现 | 可观察状态 |
| --- | --- | --- |
| 原生单文件保存 | 用户选文件位置后，按不超过 1 MiB 的数据块写入，逐次等待完成 | close 成功才显示“本机保存完成” |
| 原生目录保存 | 用户选父目录，工具创建独立子目录并逐项还原；空目录也创建 | 失败/取消中止当前写入，报告新目录和已完成文件数 |
| 流式 ZIP/ZIP64 | 直接写入用户选择的 ZIP 文件；UTF-8 文件名、CRC32、数据描述符、自动 ZIP64 | 不把整个 ZIP 放入内存；大于等于 32 位边界使用 ZIP64 |
| 兼容 Blob 下载 | 先完成有界打包，再交由浏览器下载 | 只显示“已交给浏览器下载”，不声称操作系统已保存完成 |

原生文件写入通过 `createWritable()` 写入，并在成功关闭后提交；失败调用 abort。文件夹整体不是一笔原子事务，之前已关闭的文件与空目录可能保留，界面会说明；再次保存会创建另一独立目录。[MDN：可写文件流](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemWritableFileStream/write)

ZIP 仅打包、不压缩，避免压缩 CPU 开销；保留目录与空目录，时间字段采用 ZIP DOS 时间（约 2 秒精度），普通目录写入的修改时间由系统生成。ZIP/ZIP64 按公开记录格式实现，无新增 npm 依赖，互操作测试使用独立 Python zipfile 解码及 CRC 校验。[PKWARE ZIP 格式规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)

- 单集合最多 20,000 个文件/目录，路径元数据总计最多 8 MiB，避免无限目录扫描与无界清单。
- 文件选择先读取元信息，实际文件仅保存时按 1 MiB 以内分块读取；源大小/修改时间变化、读取长度不符或异常数据块会中止保存。
- 每块写入完成后才继续读下一块，取消时释放迭代器并 abort 当前文件。
- 兼容 Blob 下载单次和近期未回收下载数据的合计上限均为 **128 MiB**，ZIP 上限包含格式开销；超限在读取正文前拒绝。保留的下载 URL 约 60 秒后回收。界面解释等待或分批/流式保存选择，不自动转用服务器或 VPN。
- 构造 Blob 可能产生浏览器内部副本；工具限制的是显式缓冲和保留的下载数据，不能承诺浏览器进程总 RAM 固定为 128 MiB。原始文件系统缓存由浏览器管理。
- 文件对象、句柄及读取函数放在按 Nuxt app 隔离的 WeakMap 中，不序列化进 SSR/useState，不写 localStorage/IndexedDB，不进入教师媒体库或工具 SQLite。

后台的预设权限、单文件/任务上限和文件数量限制用于前台提示。本机预览不是网络传输；第 5/6 步已将同一清单和有界读取接口接入真实配对、数据通道和准入规则，第 7/8 步已接入出口估算预算及受控中继／暂存（不是供应商硬限额）。

## 验证边界

本轮验证了普通 ZIP 和强制 ZIP64 小样本的独立解码，以及超过 4 GiB 文件的 ZIP64 标头与大小规划。没有声称完成多 GiB 实物文件的浏览器磁盘测试。原生目录/文件写入适配器使用可检查的句柄替身验证结构、顺序、关闭/中止与部分失败；实际浏览器授权窗口、Windows 文件系统、拖放行为与网络场景仍需实机验收。

中继和临时分享额外限制控制清单为 256 KiB，文件正文逐块处理；直连的清单上限保持原值。更多条件见 [广域网与分享](network-sharing.md)。

第 9 步网络准备生成按相对路径稳定排序的清单快照；不修改本机选中文件列表。单文件和目录可从已提交检查点恢复，ZIP 在原授权任务内重新生成；浏览器大文件检查点自适应减少重复复制，细节见 [任务恢复](recovery.md)。

## 开关、页面和导航

`FT_TEACHER_MODULE_ENABLED=true` 启用模块，缺省为关闭；配套 `teacher.mjs` 显式启用。
关闭时不会导入同级模块，所以移走工具目录后，教师网站仍能以关闭状态构建。
模块内部使用 `import.meta.url` 和宿主 rootDir 定位，服务端适配器随 Nitro 内联，不保留开发机绝对导入。
开关影响构建；生产环境变更开关后必须重新构建，不能只修改运行中进程的环境变量。

| 路由 | 实现 |
| --- | --- |
| `/zh/transfer`、`/en/transfer` | 真实教师 `public` 布局，共用导航、登录/退出、姓名、语言、字号和页脚 |
| `?mode=send`、`?mode=receive` | 同一前台页面的两个视图，切换语言保留视图参数与本机文件集合 |
| `/transfer-admin/` | 独立布局的一个 Nuxt 管理页面；与教师构建一起交付，不复制前台导航 |
| `/transfer-api/v1/session` | 服务端重新验证教师会话，取得工具可用身份和权限 |
| `/transfer-api/v1/admin/overview` | 工具独立检查管理授权，返回管理状态 |
| `/transfer-api/v1/admin/settings` | GET 读取完整配置；PUT 同源、CSRF、身份与独立授权校验后原子保存配置和管理授权 |
| `/transfer-api/v1/capabilities` | 当前版本能力，实际传输保持关闭 |

前台默认补充“文件快传”导航。若后台已有 `/transfer` 或中英文对应路径的内部导航，使用其名称/路由，只显示一次。
可用模块选项 `{ enabled:true, navigation:false }` 关闭自动补充入口。自定义导航记录仍归教师后台管理；本步未自动添加数据库导航记录。
当前页高亮按原导航和扩展组件的实际路径匹配；无需改变教师论文等筛选导航逻辑。

## 身份信任

浏览器 → 教师同域 API → 当前有效教师会话 → 工具专用签名授权 → 独立工具服务验签及授权。
每次工具 API 请求都从数据库读取最新会话和账号状态，不把浏览器传来的 UID、角色、Bearer 凭证或 Cookie 转发到工具服务。
授权使用 Ed25519 签名的紧凑 JWS，固定发行方、受众、算法、路径、GET/PUT 方法与正文 SHA-256 摘要，30 秒有效；校验允许至多 3 秒的签发时钟偏差。
每个授权具有唯一 nonce，SQLite 原子消费一次，重启后仍拒绝重复使用。私钥和授权字符串不返回浏览器。
独立工具仅使用自己的公钥配置，不读取教师会话密钥或教师账号库。

工具管理权限按教师 UID 在独立 `admin_grants` 中明确授予。普通后台权限、角色等级或“管理员”名称不能替代授权。
首次授权及本机恢复用 `manage-admin.mjs`；本步未提供未鉴权的远程初始化接口。
教师角色变更每次请求读取最新值；显式 UID 授权是独立设置，不因改成普通角色就暗中消失，也不因升为管理员而自动出现。
账号停用、会话退出/到期及必须改密状态分别阻止后续管理请求；工具授权撤销立即作用于下一次请求。
已在途请求可能完成；尚未消费的签名只存在于服务端传递中，并受上述短期有效期限制，不声称跨网络零时间撤销。

## 缓存和故障

工具页面与身份/管理响应使用 private/no-store，身份在前端挂载后单独加载，不进入公共 SSR 数据或列表缓存。
本窗口登录/退出先清空旧权限；跨窗口变化在重新聚焦/返回可见状态或 30 秒检查时更新。服务端始终逐次核验。
快传服务超时只影响工具状态；教师公共布局不等待它。前台提供重试，教师首页可继续浏览。
管理写入复用教师现有 `protectJsonWrite` 和有界 JSON 读取工具，通过模块别名接入，不修改教师认证实现。同源 JSON、有效会话 CSRF、131072 字节上限在签发授权前检查；独立工具在读完正文后重新核验短期签名和当前管理授权，并在事务内检查授权和配置版本。

## 撤回和数据

`integrate-teacher.mjs revert` 只撤回匹配的接入片段，保留其他本地修改；所有文件预检通过后才写入，修改前保存工具内备份。
停用或撤回后重新构建教师服务；停止独立工具进程。保留数据和备份，脚本不删除它们。
独立数据库 schema 1 → 2 添加 `admin_grants`、`bridge_nonces`；schema 2 → 3 添加 `tool_settings` 与 `settings_audit`，保留原数据。需要回退到旧服务时应恢复升级前数据备份。


第四步文件信息与数据源放在以 Nuxt app 为键的 WeakMap 内，不进入共享 SSR 单例、useState 序列化数据或持久化缓存。所有文件采集和保存代码位于工具 `web/files/`、`web/composables/useTransferFiles.ts` 与 `web/components/FileWorkspace.vue`，未扩展教师媒体 API，也没有开放工具传输 API。

## 第 5 步新增接入

工具模块另注册精确的 WebSocket 路由 `/transfer-api/v1/signal` 并启用当前 Nitro 2 的 `experimental.websocket`。仍使用原有 3 处教师扩展位置，无新增教师源码改动。信令处理器只代理固定工具服务地址，票据首帧提交；LAN/WAN 直连只代理信令，第 8 步中继／暂存还转发有界文件封装。`PUT /transfer-api/v1/pairing-ticket` 复用教师端同源/CSRF 与最新会话。代理需允许 Upgrade，示例见 `deploy/nginx-transfer.conf.example`。

数据库 schema 3 → 4 为保存的设置补充 `lanNetworks:''`、`lanVerified:false`；既有值优先保留，没有新业务表。升级前备份，退回第 4 步须恢复 schema 3 备份。步骤和验收范围见 `docs/lan-transfer.md`。

## 第 8 步升级

沿用同一 WebSocket 代理和原 3 处接入，无新增教师源码改动。完整更新工具目录后必须重建教师服务，以更新前台、管理页和桥接路由。新增身份受控的分享撤销与管理接口，schema 6 → 7 保留原账本。服务器路径核验必须涵盖教师代理和工具服务。详见 [广域网与临时分享](network-sharing.md)。

## 第 9 步升级

仍使用原 3 处接入和同一鉴权 WebSocket。新增控制消息在工具模块内处理，没有新增教师路由源文件。schema 7 → 8 保留有效分享及账本；服务端新增纯 JavaScript 前缀校验模块，更新时必须复制完整工具目录并重新构建教师站。第 8 版中断任务没有恢复凭据，不能追溯续传；结束旧任务并刷新已打开页面后升级。

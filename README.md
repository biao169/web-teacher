## 后台排序快速编辑（v0.15.118）

具有 sort_order 或 display_order 的功能列表可直接修改排序数字。更改后按 Enter 或点击 ✓ 保存；Esc 恢复当前已知保存值；离开输入框不自动保存。排序值越小通常越靠前，实际列表按当前选定列和方向排列，相同数值保留既有次级排序。没有编辑权限或该字段被导航固定时只显示数字。

排序列已加入适用模块的默认推荐列；若浏览器保留了旧列偏好，请在“列设置”勾选排序列或恢复默认列。保存后局部刷新，保留筛选、搜索、列偏好、滚动位置、可见勾选及仍在列表中的排序草稿。记录移出当前页时显示提示。修改导航条目的排序后，后台导航栏完整刷新页面时同步。

数据库和依赖不变，更新代码并重启即可。第五步联调已在 v0.15.119 完成。详见 [使用说明](docs/inline-order-v118.md)。

## 日期时间与时区（v0.15.117）

新闻发布时间使用日期时间组件，旁边可以选择或输入 IANA 时区（如 Asia/Shanghai、America/New_York）。首次默认为北京时间，当前浏览器会记住时区选择。已经填好时间后切换时区，会转换显示值并保持实际时刻不变；保存仍使用 UTC，历史记录不改写。

前台首页、列表和详情的发布时间按访客浏览器时区显示，附带 GMT 偏移；无 JavaScript 时回退为明确标注的北京时间。日期和年份字段不转换。夏令时不存在的时间禁止保存，重复时间需选择较早或较晚一次。

数据库结构不变。本次新增 tzdata==2026.4 依赖，更新时需同步依赖并重启；Windows 常规启动脚本会按锁文件变更同步依赖，生产部署使用包含依赖同步的更新流程，不要只覆盖源码。详见 [使用说明](docs/timezones-v117.md)。

## 磁盘核对列表与左侧预览（v0.15.113）

进入后台“媒体库 → 目录核对”。核对表格复用媒体库的表头、列设置、多选、分页及缩略图组件。左侧图片直接显示小预览；视频、PDF 及图片均可点击预览入口，在弹窗中查看。未收录文件也可直接预览，查看不会自动登记或移动文件。

- 搜索文件名、标题和完整路径；表头可逐列筛选，核对结果与文件类型支持多选（Ctrl/Command 或 Shift）。同一字段多个选项按“或”匹配，不同字段与搜索条件按“且”匹配。
- 表头箭头切换升降序；筛选和排序覆盖整个已扫描报告，然后分页显示，每页可选 10/20/50/100 条。扫描未完成时明确显示当前范围。
- 当前页多选、全选、清空选择；支持复核所选、复制所选路径。收录仅处理勾选的未登记项，每次最多 10 项，继续使用原来的预检与确认流程。
- 保留媒体目录内的完整磁盘绝对路径，可展开和复制；大小使用整数 KB。核对列表的列宽与显示偏好独立保存，不覆盖媒体库偏好。
- 新报告在原缓存目录内保存合并元信息索引；筛选不重新扫描磁盘或读取媒体正文，每个报告只保留一个查询缓存槽。图片懒加载，视频/PDF 点击后才读取预览。

本版不改数据库表结构、依赖和部署脚本；更新源码后重启网站即可。已有报告可继续读取，过期后清除报告并重新扫描。复核结果显示在对应行，统计与筛选仍依据扫描时状态；需要刷新全部统计时重新扫描。详细变更与验证见 [磁盘核对列表说明](docs/media-audit-v113.md)。

## 媒体读取与预览简化（v0.15.112）

本地媒体在访问权限校验后，只定位和打开一次原文件，再按 64 KiB 连续分块发送，不再每一块重新打开文件和重复比较磁盘版本。正常完成、传输异常或浏览器断开时均释放文件句柄；R2 继续采用每块最多 1 MiB 的版本一致性读取。

取消预览读取接口额外的 20 MiB 限制；读取按小块进行，不把整文件装入内存。上传仍受后台配置与原有上传上限约束。图片、PDF、MP4、WebM 和 ZIP 共用文件头识别；历史错误后缀不再只针对图片兼容。未知类型仍作为下载文件，保留媒体访问权限及目录范围校验。

后台媒体详情根据实际文件头选择预览组件，并显示网站媒体目录内的磁盘绝对路径；目录核对页也支持展开完整路径。读取权限不足、磁盘暂不可读、文件缺失等提示分别显示；图片和视频的临时预览失败最多自动重试两次，浏览器不支持的视频编码提供原文件入口。

本版没有修改数据库结构、依赖锁文件、上传配额或部署脚本。更新源码后重启网站即可，无须重建数据库或重新上传现有媒体。多选筛选表格的全面复用与未收录文件直接预览仍属于后续目录核对界面改造，本版聚焦共用读取流程。详细文件清单和验证范围见 [媒体读取修改说明](docs/media-read-v112.md)。

## Python 依赖源与失败续装（v0.15.111）

Linux 一键安装、整站更新、源码删除后的恢复和依赖单独更新共用同一安装方法，默认使用已验证可用的清华 HTTPS 源：`https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple`。保持锁文件中的依赖版本，不关闭 SSL 校验，不修改系统全局 pip 配置。每次明确指定唯一 index-url，忽略 pip 配置文件和冲突的 PIP_* 参数；保留常规网络代理和显式 PIP_CERT 证书包。失败最多重试 2 次，网络超时为 20 秒；不自动混用多个来源。

新安装默认即可，选择官方源可加 `--pip-source pypi`。已安装管理器提供：

```bash
tweb pip-source          # 查看当前源
tweb pip-source tuna     # 保存清华源
tweb pip-source pypi     # 保存官方源
tweb update --scope dependencies
```

依赖源保存在现有 install.json，不新建配置目录；旧安装未记录该字段时默认使用清华源。更换来源只影响之后的依赖下载，不改变当前已安装版本，也不自动执行更新。设置环境变量 PIP_INDEX_URL 不再覆盖此选择；请通过 --pip-source 或 tweb pip-source 配置。

如果仍停留在先前首次安装的 pip 依赖失败阶段：先在服务器解压本版、进入 teacher-site 目录（默认受管安装路径），执行：

```bash
sudo install -o root -g root -m 0644 deploy/linux/tweb.py /opt/teacher-site/tweb.py
sudo tweb pip-source tuna
sudo tweb resume-install
```

续装仅允许：安装状态 preparing、已创建服务账号、尚无 current/服务文件、且只有一个暂存源码目录。它校验原源码清单，复用已创建的虚拟环境，再完成依赖、配置、数据库初始化、权限检查和启动，不卸载、不清空数据、不重新下载源码。若目录不唯一、已有服务或已进入后续安装阶段，则拒绝猜测和覆盖，需按具体错误检查。安装管理员账号时可能需要交互输入。

将完整新版本上传到 GitHub web-py 后，后续远程安装才会使用新默认值；避免用仓库旧版本覆盖更新后的管理脚本。直接启动器和 Windows 依赖策略本轮不变。本版数据库表和索引未变，无需重建。详细验证及文件清单见 [依赖源修改说明](docs/pip-source-v111.md)。

## 修复生产域名健康检查误判（v0.15.110）

生产站点对所有请求校验 Host。旧脚本用 127.0.0.1 访问健康接口却未带配置域名，正常服务也会返回 HTTP 400，被误判为启动失败。本版 tweb 和直接启动器仍连接本地端口，但携带生产域名 Host；不经过 DNS/代理，不放宽网站的域名校验。健康失败显示实际 HTTP 状态或连接原因；非预期 HTTP 200 页面不会算作健康。

旧管理器可能因这个错误导致整站更新回滚。默认安装路径下，先解压本版并进入 teacher-site 目录，再执行：

```bash
sudo install -o root -g root -m 0644 deploy/linux/tweb.py /opt/teacher-site/tweb.py
sudo tweb restart
```

这只替换管理程序，不重置数据库、不修改账号或媒体。非默认安装路径以现有 tweb 入口指向的路径为准。若要随后更新整站，先将本版上传到 GitHub web-py，再执行 tweb update。直接运行 start.sh 的用户应同时更新 deploy/shared/launcher.py。

如果依旧失败，查看错误中的状态码、端口和 Host，并执行 `sudo journalctl -u teacher-site.service -n 80 --no-pager` 与 `sudo tweb logs` 检查实际启动错误。启动早期异常可能只存在于 journal 中。此修复不能替代对真实权限错误、数据库不匹配、端口占用或进程退出的处理；本版无需数据库重建。不要通过跳过健康检查来掩盖启动失败。

验证包含真实本地服务的 HTTPS 域名配置：错误 Host 返回 400、正确 Host 返回健康 JSON，管理器检查及共享启动器均通过；67 项相关测试通过。尚未连接真实生产服务器。

## tweb 单次执行与步骤日志（v0.15.109）

## Ubuntu/Debian 部署管理增强（v0.15.108）

安装时可输入内部应用端口，默认 8003；也可以显式指定：

```bash
sudo bash install.sh --domain teacher.example.org --port 9103
```

安装后输入 `tweb` 显示**同时中英文、带简短说明的彩色菜单**。普通系统用户运行时，入口会通过 sudo 请求系统管理权限；没有 sudo 权限的用户不能执行管理操作。菜单只执行一次；主菜单或子菜单留空/输入 0 即退出，成功、失败或中断后均不重新显示菜单。输出重定向或设置 `NO_COLOR=1` 时关闭颜色。

| 操作 | 示例与作用 |
| --- | --- |
| 改端口 | `tweb port 9103`；同步服务、健康检查、代理示例 |
| 整站更新 | `tweb update --scope all` |
| 仅源码 | `tweb update --scope source`；复用虚拟环境，不修改数据库、不安装依赖 |
| 仅界面资源 | `tweb update --scope frontend`；更新 frontend 内模板、CSS、JS，要求后端兼容 |
| 仅依赖 | `tweb update --scope dependencies`；按已安装源码的锁文件同步 |
| 仅数据库 | `tweb update --scope database`；复用已有结构核验/已支持升级，不下载源码，不自动重置 |
| 仅部署配置 | `tweb update --scope config`；刷新受管配置和代理示例，保留存储路径、环境变量及服务其他参数 |
| 权限检查/修复 | `tweb permissions` / `tweb permissions --repair` |
| 分项删除 | `tweb remove --scope cache`；还可选 logs、media、transfer、database、source、all |

分项删除先显示路径，并要求输入对应确认词，如 `DELETE-CACHE`；完整卸载输入 `DELETE`。媒体与快传文件删除只删物理文件，数据库引用/任务记录保留，相关资源将不可再读取。数据库删除和源码删除后保持停服，分别使用 `db-init` / `update --scope all` 恢复，再执行 `start`。数据库按新站重建使用 `tweb db-reset`，确认词为 `RESET`。

端口范围为 1024–65535，主站与快传共用一个 `127.0.0.1` 监听端口，公网 HTTPS 通常仍由反向代理提供。改端口后需将 `tweb proxy` 给出的新上游端口同步到现有 nginx/Caddy 配置，再校验并重载代理；脚本不会改动其他站点的代理和防火墙。

继续使用已有目录，不新增缓存、备份或环境目录。源码单独更新复用原虚拟环境路径，整站更新成功后删除前一版本。数据目录仅服务账号可写，不使用 777；安装完成前执行服务账号实际读写探测。权限修复会暂时停服；失败时保持停止并显示原因。自定义到受管范围外的存储路径拒绝自动删除或权限修复。

直接运行模式也支持 `bash start.sh --port 9103`，兼容入口 `start-transfer.sh` 共用同一参数。`.sh` 仍放根目录，`.cmd` 仍全部放在 deploy 中。

本版数据库结构未变，不需要数据库更新或重建。详细操作范围和恢复方法见 [Linux 管理教程](deploy/linux/README.md)，验证记录见 [部署管理验收](docs/deployment-controls-v108.md)。

## 运行维护第四步：后台资源与策略管理（v0.15.106）

系统管理员登录后台后，从左侧“系统管理 → 运行维护”进入，地址 `/admin/runtime-maintenance`。可以查看当前进程内存、系统可用内存、数据库及前台缓存占用、各目录所在磁盘可用空间；点击“更新文件占用统计”按批次统计媒体、缓存、日志和快传文件。刷新状态复用统计结果，不重扫文件目录。

先“预览下一批”，确认后可执行一批清理；页面显示类别数量、失败原因和最近结果。关闭主站自动清理不影响手动操作、日志轮转或快传文件独立的到期设置。策略存入已有 service_meta，数据库表和索引不变，无需重建。运行维护仅在本地 Windows/Linux 部署开放；Worker/R2 不支持此页面。详见 [运行维护后台说明](docs/runtime-admin-v106.md)。

## 五、Ubuntu / Debian：远程一键部署

### 部署前准备

- 使用运行 systemd 的 Ubuntu/Debian 主机，并准备 Python 3.12+（支持 venv）。旧系统可通过 `--python` 指定已经安装的解释器。
- 将本项目目录内的文件上传到公开 GitHub 仓库的目标分支；仓库根目录应直接包含 install.sh、backend、deploy 等。
- 准备指向服务器的域名。默认仓库已设为 `biao169/web-teacher`、分支 `web-py`；命令中的域名需要换成实际值。

在交互式 SSH 终端执行以下一行命令（需要 curl）：

```bash
( f=$(mktemp) && trap 'rm -f "$f"' EXIT && curl --fail --show-error --location --proto '=https' --tlsv1.2 'https://raw.githubusercontent.com/biao169/web-teacher/web-py/install.sh' -o "$f" && sudo bash "$f" --domain 'teacher.example.org' )
```

已有源码也可以在项目根目录执行：

```bash
sudo bash install.sh --domain teacher.example.org
```

需要指定解释器时追加 `--python /opt/python/bin/python3.12`。脚本安装必要系统依赖，准备独立虚拟环境和单一服务，并交互创建管理员。安装完成只表示本机应用健康检查通过，仍需配置公网 HTTPS。

### 反向代理与 HTTPS

执行 `sudo tweb doctor` 检查系统现状，执行 `sudo tweb proxy` 查看当前域名的配置示例。选择 Nginx 或 Caddy 其中一种：

- Caddy：将生成的片段合并到 `/etc/caddy/Caddyfile`；执行 `sudo caddy validate --config /etc/caddy/Caddyfile`，通过后 `sudo systemctl reload caddy`。
- Nginx：在对应域名已有证书和 TLS 配置的 server 中加入生成的 location 片段；执行 `sudo nginx -t`，通过后 `sudo systemctl reload nginx`。

脚本不会覆盖现有代理或防火墙配置。检查云安全组和系统防火墙，开放实际 SSH 端口及 TCP 80/443，不对公网开放内部应用端口（默认 8003）。完成后访问 `https://你的域名/`、`/admin` 和 `/transfer/`。

### tweb 日常管理

运行 `tweb` 打开双语菜单（需要系统管理权限），或使用下列命令：

| 命令 | 用途 |
| --- | --- |
| `sudo tweb start` / `stop` / `restart` | 启动、停止或重启，分别执行对应命令 |
| `sudo tweb status` | 查看服务状态 |
| `sudo tweb logs` | 持续查看日志，Ctrl+C 退出 |
| `sudo tweb paths` | 查看网站地址及相关文件路径 |
| `sudo tweb doctor` | 检查服务、监听端口、防火墙与代理情况 |
| `sudo tweb proxy` | 查看代理配置示例 |
| `sudo tweb update` | 从已保存的仓库/分支更新整站 |
| `sudo tweb update --branch staging` | 更新到指定分支 |
| `sudo tweb update --scope frontend` | 前台局部更新；后台或数据库结构不兼容时拒绝 |
| `sudo tweb db-init` | 初始化空库或核验现有结构 |

### 文件夹增强第三步（0.15.83）：按原层级保存

1. 接收方打开文件夹分享链接，会进入文件快传的接收区并自动填入链接。也可手动粘贴，再点击“检查文件 / 目录”。检查信息不占用下载次数。

### 文件夹增强第四步（0.15.84）：三种传输模式

先在上方“选择文件夹 · 目录预览”选择目录，再根据需要操作：

| 模式 | 发送入口 | 接收方式 | 服务器文件内容 |
| --- | --- | --- | --- |
| 局域网直连 | 切换到局域网直连，点击“发送上方已选文件夹” | 一个配对码；加入后选择本地保存目录 | 文件内容不经本站中转；连接信息和目录清单仍经本站 |
| 广域网在线中转 | 点击“中转上方已选文件夹” | 一个配对码；双方开始，接收方选择保存目录 | 单个待确认分块，最多1 MiB/会话，不写文件缓存盘 |
| 临时缓存 | 上方点击“发送到临时缓存” | 分享链接；接收方可以稍后保存目录 | 按后台容量和保留期暂存 |

三个模式均保留目录层级、空目录和零字节文件，无需先压缩。接收方在选定位置下新建子目录，同名自动加后缀；已完成文件保留。扫描目录本身不上传，在线模式创建配对时才提交目录清单；清单完整封存后才显示配对码。

在线模式的目录清单每批100项，单任务序列化清单最多2 MiB；局域网协商和在线中转每个进程共享8 MiB序列化清单预算。此限制针对目录元数据，**不是文件内容大小上限**；达到上限时可改用缓存模式。中转文件分块仍由 `TRANSFER_RELAY_ROOMS` 限制并发（默认4、最大8），每会话仅保留最多1 MiB待确认文件内容。以上不是整个Python进程的RSS内存上限，HTTP请求、解析和运行环境还有固定受限缓冲及开销。

所有模式都遵守身份允许方向、单文件大小、文件数、任务总大小及并发配置。在线中转按发送和接收两个方向预留/计量总字节；重试继续按既有规则计费。局域网直连无法由服务器核实实际文件字节，因此保留原有硬流量配额保护：启用了相关硬配额时需使用服务器可计量的模式。

在线中转允许在原页面短时暂停/继续，双方需要保持页面在线；局域网数据通道断开后需要重新配对。取消、到期、权限失效会清理在线配对清单；服务重启后在线配对失效。不会自动把直连失败的任务改为服务器中转。浏览器目录授权、HTTPS/localhost等要求与第三步相同。

实现与测试记录见 `docs/features/transfer-folder-step4-v84.md`。下一步进行浏览器兼容、Windows本地目录和真实双端网络验收。

复用现有译文优先规则：人工英文字段优先，本条人工译文或明确复用优先，之后使用无冲突的共享译文。手动停用、历史、失败、已变更原文、隐藏来源及项目私密字段不会成为公开搜索的译文来源。搜索及读取下拉项不会调用在线翻译或写入缓存。

例如原项目名是“人工智能研究”，已有有效译文“Artificial Intelligence Research”，输入 `intelligence` 即可找到该项目。若尚无任何对应英文内容，英文同义词不会自动命中，需要先在后台补齐译文。

多值字段按原有分隔符生成选项。只复用每个词条的精确译文，不根据组合译文猜测各词条对应关系。

实现与验证见 [双语搜索第四步](docs/features/navigation-bilingual-step4-v89.md)。下一步按第五步规划专项联调筛选、重置、排序、连续滚动、引用复制、详情及中英文切换。

### 前台访问修复与自适应缓存（v0.15.93）

没有启用的网站设置记录时，中英文页面使用安全的默认标题，不再因缺少英文站名而报错。不会为了展示页面自动创建或改写数据库记录。

Windows/Linux 本地运行默认启用匿名前台查询缓存：依据系统可用内存与 Linux cgroup/服务内存上限，有请求时每 15 秒重新计算容量；通常最高 32 MiB/进程，并按 `WEB_CONCURRENCY` 声明的进程数分摊预算。可用内存不足 64 MiB 时停用查询缓存。模板缓存随资源条件在 32/96/192/256 个模板之间调整，模板文件变化仍会自动重新加载。

查询缓存只用于匿名 GET 的前台页面、滚动分片及公开数据接口；登录身份、后台、媒体下载、文件快传、表单提交及整页 HTML 不共享缓存。写入数据库后失效，并检测其他进程提交及数据库替换。普通查询最多缓存 30 秒，使用数据库时钟的查询最多 1 秒；新闻到期发布不会被长期缓存阻挡。查询缓存只在内存中，重启即清空；译文记录仍保存在原数据库中。

如需限制内存，可在 Windows `deploy\windows\local.cmd` 设置 `set "TEACHER_PUBLIC_CACHE_MB=16"`；设置 `0` 可关闭查询缓存用于排查。Linux 使用同名环境变量。该值是上限，实际仍受自动预算约束；多进程部署需同步设置 `WEB_CONCURRENCY`，未声明时按单进程计算。文件快传的文件缓存期限、容量与流量限制继续由后台配置控制，不会因内存多而自动放宽。

数据库结构与 v0.15.92 一致，无需重建。保留原数据库和媒体，更新源码后重启；Windows 保留现有开发数据使用 `deploy\windows\start-existing.cmd`。

可运行 `python -B tests/benchmark_public_cache.py` 进行临时示例数据的本机对照测试，不会读取或改写现有网站数据。


### 上传到 GitHub 的 web-py 分支

将压缩包中 `teacher-site/` 内的全部源码放在仓库根目录，包含 `.gitignore`、`.gitattributes`、`release-manifest.json`，不要额外套一层 `teacher-site/`。默认仓库为 `https://github.com/biao169/web-teacher.git`，分支为 `web-py`。直接上传本次完整源码可使用已有发布清单；如果修改了代码、文档或添加文件，提交前在根目录执行：

```bash
python -B -m deploy.vps.release manifest --refresh
python -B -m deploy.vps.release verify
```

把刷新后的清单与源码放在同一个提交中。清单只做文件完整性校验，不能代替对仓库代码来源的信任。部署在安装 Python 依赖、切换版本之前执行校验；清单不匹配会停止，请在开发端重新生成并提交。

`.gitattributes` 保持文件原始字节，避免 Git 的 `core.autocrlf` 改写发布内容；`.sh` 强制 LF，现有 `.cmd` 保留 CRLF。初始化仓库时先放入该文件再添加源码。已有 Git 工作区应用本规则后，可执行 `git add --renormalize .`，检查变更，再重新生成清单并提交。安装命令使用 `bash install.sh`，不依赖从 ZIP 保留可执行位。

`.gitignore` 排除默认数据库/媒体/缓存目录、环境凭据、本机配置、虚拟环境和压缩包；自定义到其他位置的运行目录也应单独排除。不要把运行数据上传到源码仓库。

首次安装默认使用 web-py。`sudo tweb update` 使用已保存的安装来源，不强行覆盖管理员选择的分支。已有站点如需切换到本仓库，执行：

```bash
sudo tweb update --repo https://github.com/biao169/web-teacher.git --branch web-py
```

本步骤仅变更部署配置和发布流程；数据库结构、教师网站功能及文件快传功能不变。GitHub 分支需先上传并可读取，才能执行云端真实安装。

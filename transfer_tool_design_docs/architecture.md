# 功能架构

## 传输模式

系统支持四类传输路径：

```text
1. 局域网直连
   发送端 -> 接收端

2. web03 实时中转
   发送端 -> web03 -> 接收端

3. 云服务器实时中转
   发送端 -> 云中转节点 -> 接收端

4. 临时暂存
   发送端 -> 本机临时落盘或云端暂存 -> 接收端稍后下载
```

## 默认连接策略

推荐默认策略为 `auto`：

```text
1. 优先尝试 WebRTC 局域网直连。
2. 局域网不可用时，尝试公网直连。
3. 直连失败时，根据后台控制表决定是否允许 web03 实时中转。
4. web03 中转不可用或被限制时，根据后台控制表决定是否允许云服务器中转。
5. 如果接收方不在线，且后台允许临时暂存，则进入本机临时落盘或云端临时暂存。
```

## 实时中转原则

实时中转不应保存完整文件：

```text
接收一个 chunk
校验和计量
限速
转发给接收端
释放 chunk
```

这样可以避免大文件传输时占满 web03 磁盘。

## 文件夹传输原则

前端读取文件夹时生成相对路径清单：

```text
photos/2026/a.jpg
photos/2026/b.jpg
docs/readme.txt
```

接收端写入时恢复目录结构。路径必须做安全校验，禁止：

```text
../
..\
绝对路径
盘符路径
控制字符
```

## 理论无限容量的条件

所谓理论无限容量，是指系统设计不强制完整缓存文件。实际仍受以下条件限制：

```text
发送端文件可读
接收端磁盘足够
网络不中断或支持断点续传
后台流量额度足够
后台磁盘水位未触发保护
临时暂存模式的容量额度足够
```

一旦启用本机临时落盘或云端暂存，就必须受容量、有效期和配额控制。

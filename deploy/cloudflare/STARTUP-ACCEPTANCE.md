## 发布核对

1. 将完整 deploy 文件夹提交至 web-py，确认提交包含当前补丁标识。
2. 保持现有正确的域名、D1 和 R2 构建变量；执行原 `python build.py check`、`python build.py deploy`。
3. 日志需依次出现 STARTUP-CHECK、PACKAGE、BUNDLE、R2-READY、D1-READY、DEPLOY 成功以及 PUBLISHED。dry-run 成功不等于发布成功。
4. 在目标 Worker 的 Deployments 中核对成功版本是否为当前活动版本，确认 Domains & Routes 对应此 Worker。
5. 若仍出现 Hello world，不重置数据库；优先核对 Worker 名称、活动部署、分支提交及域名绑定。

## 云端需要人工完成的业务项

| 验收项 | 操作与预期 |
| --- | --- |
| 管理员登录 | 使用已有账号登录，能打开后台；不要为改版重建管理员 |
| 重复请求 | 多次打开首页、后台和快传；无 500、无重复初始化错误 |
| 六位码 | 发送端创建房间，接收端输入两字母四数字码，能加入同一任务 |
| 局域网 | 两个浏览器/设备传输，确认内容完整 |
| 远程中继 | 发送和接收同时在线，分块接收完成，最终文件一致 |
| 文件夹 | 浏览器支持目录保存时核对层级、空文件与多文件 |
| 权限/撤销 | 未登录限制符合配置，撤销码后旧码不能加入 |
| 媒体 | 上传一张测试图片并预览，之后按后台正常功能清理 |

以上项目需要真实账号、双端浏览器和云端运行环境，当前未标记通过。应用复用仅限实例存活期间；部署/回收后在线房间需重新配对，不能将实例复用误认为永久保存在线房间。

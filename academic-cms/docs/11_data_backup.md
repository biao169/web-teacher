# 数据导入、导出与备份

## 格式与用途

入口为 `/admin/import-export`，需要对应权限。导出和恢复仅处理受支持的白名单数据表。

| 格式 | 用途 | 内容边界 |
| --- | --- | --- |
| JSON | 数据交换、安全导出及导入 | 不包含密码哈希、服务密钥等被剔除的敏感值 |
| CSV | 单表导出、表格查看 | 当前为导出能力，导入界面不接收 CSV |
| `.acms` | 加密备份与恢复 | 可保存需要保护的完整字段及选择包含的媒体对象 |

系统会话、临时限流和其他内部运行表不作为任意表导出入口。完整数据库字段字典描述存储结构，不表示所有表都可在网页中导出或编辑。

## 导出与加密备份

选择需要的数据表和导出方式。安全 JSON/CSV 适合交换公开或去敏数据；保留密码哈希、翻译服务凭据等敏感配置时使用加密 `.acms`。

加密备份采用 AES-256-GCM，口令派生使用 PBKDF2-SHA-256，600,000 次迭代。口令至少 15 位；口令不保存在可恢复的备份明文中，遗失后不能通过网站找回备份内容。

选择 `media_assets` 时可勾选包含受管理媒体文件。当前媒体随包上限为 100 个对象、原始总大小 24 MiB；外部 HTTPS 对象和静态资源不随包复制。只导出媒体元数据不会把原文件带入备份。

## 导入预检与恢复

上传 JSON 或 `.acms`，加密文件输入对应口令。选择目标表和合并方式，先运行预检，检查预计新增、更新、删除、字段错误和缺失引用。

| 模式 | 行为 |
| --- | --- |
| 按 UID 合并 | 依据稳定 UID 判断新增和更新 |
| 替换所选表 | 按明确选择替换目标表内容，包含删除现有记录；界面要求明确确认 |

确认预检结果后再执行。提交时会再次检查文件及预检摘要，避免预检后内容变化。数据库写入采用事务；伴随媒体恢复会暂存新对象，数据库失败时处理本次新对象，减少半成品状态。

## 当前容量边界

| 项目 | 上限 |
| --- | --- |
| 导出总记录数 | 20,000 条 |
| 网页在线恢复 | 500 条记录 |
| 请求体 | 48 MiB |
| 解密后文档 | 32 MiB |
| 随备份媒体 | 100 个对象，原始总大小 24 MiB |

导出容量大于在线恢复容量，大批数据不能假定一次网页恢复完成。预检提示超限时，应缩小所选范围；不要手工删去必要关联后强行导入。

## 恢复后使用

确认目标数据、媒体和角色权限符合预期。涉及网站、导航或翻译设置的恢复会更新相关运行缓存。

安全 JSON 会剔除敏感内容，因此不是完整账号与服务凭据备份。教师备份也不包含文件快传独立数据库、临时分享文件、桥接私钥或用户本机接收目录。文件快传的备份用法见 [12_file_transfer_usage.md](12_file_transfer_usage.md)。

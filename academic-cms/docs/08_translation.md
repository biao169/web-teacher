# 翻译功能与用法

## 英文内容如何产生

前台优先使用适用的人工英文专用字段，例如姓名、简介、研究方向名称、导航名称和学生分类标签。其他可翻译字段读取当前有效翻译缓存；没有英文内容或有效译文时回退原文。

访客切换英文不会临时调用外部翻译 API。翻译任务在后台 `/admin/translation` 运行。

| 来源 | 纳入的主要内容 |
| --- | --- |
| 网站设置和导航 | 当前站点名称、适用标题与 SEO、页脚；启用公共导航文本 |
| 教师与研究方向 | 姓名、身份与归属、简介、经历、招生说明；方向名称与说明 |
| 论文 | 题名、作者、期刊/会议、类型、角色、索引、标签、摘要、关键词 |
| 项目与专利 | 名称、来源、基金、角色、成员、状态、简介；专利相关文本 |
| 学生与分类显示 | 姓名、培养和去向等文本；启用的分类显示标签 |
| 新闻 | 标题、分类和正文 |
| 课程 | 名称、学期、对象、简介和参考资料 |

来源扫描按各模块的公开、启用等条件选择可翻译内容。账号密码、邮箱凭据、媒体二进制和文件快传正文不属于此翻译范围。

## 服务配置

在全局设置中维护默认及可用服务。当前支持 MyMemory、LibreTranslate、DeepL、Google Translate、Microsoft Translator。未配置其他服务时可使用默认的 MyMemory 通道，实际请求仍受外部服务可用性和额度约束。

按服务填写地址、API Key、区域或邮箱等所需配置，并使用服务测试入口验证连接。每批条数、并发和超时可以设置；每批条数范围为 1–50，并发范围为 1–8，MyMemory 的实际调度使用单并发。

## 手动与连续运行

| 操作 | 实际作用 |
| --- | --- |
| 扫描来源 | 检查当前来源，建立或更新需要翻译的缓存任务 |
| 执行下一批 | 只执行一次有上限的批次，结束后停止本次调度 |
| 自动运行至完成 | 当前页面持续扫描来源、处理批次，并按规则等待可重试任务 |
| 暂停 | 停止继续调度；已经发出的请求可能仍完成 |
| 重试失败 | 对允许重试的失败任务重新处理 |
| 人工修订 | 保存人工译文并标记为人工维护 |
| 失效处理 | 使指定缓存不再作为当前有效译文使用 |

要连续处理全部可处理任务，打开翻译管理，确认服务配置后选择“自动运行至完成”，保持该页面打开。它由当前浏览器页面驱动，不是服务器常驻定时任务；关闭页面、切换离开或暂停后，不会继续启动后续批次。

遇到服务限流或暂时失败时，会按任务规则等待或重试。达到重试限制或永久失败的记录需要查看原因，修正配置或来源后再处理，不能把“自动运行结束”理解为所有条目都必然翻译成功。

## 人工译文与原文更新

编辑缓存译文并保存，会标记为人工维护。常规自动任务不会覆盖当前人工译文。原文、来源字段或来源版本改变时，系统按来源标识及内容摘要更新有效状态，旧版本译文不会继续冒充新原文的译文。

`translation_cache` 保存原文、译文、源语言、目标语言、提供方、状态、人工标记、当前有效标记和来源元数据。详细字段见 [02_database_schema.md](02_database_schema.md)。

富文本正文属于可扫描来源，但翻译服务对格式和专有名词的结果需要预览确认；附件 PDF 文件本身不会在此被翻译或 OCR。

## 常见问题

| 问题 | 说明 |
| --- | --- |
| 点一次“执行下一批”为什么只处理一部分？ | 这个按钮只执行一个批次；连续运行使用“自动运行至完成” |
| 离开页面后是否继续？ | 不继续调度；需要保持管理页打开 |
| 英文页面仍有中文？ | 检查专用英文字段、来源是否被扫描、缓存是否成功且有效，以及是否有新原文 |
| 人工译文被忽略？ | 检查对应的来源记录、字段和版本，确认它仍是当前有效缓存 |
| 服务请求失败？ | 查看错误状态，检查网络、凭据、可用服务及批量/并发设置 |
| 历史值建议是否会自动翻译？ | 历史建议是已有字段值联想，与翻译任务不同 |

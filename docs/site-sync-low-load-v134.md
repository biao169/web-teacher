# v0.15.134：统一低负载同步——第二步

本步改造内容读取与版本复核，复用既有签名接口、任务快照、事务游标和任务租约，不新增数据库表或依赖。Worker 与 Ubuntu/Debian 使用相同策略。

## 已完成

- 内容页最多5条；普通页序列化数据不超过64KiB。先读取有界UID/大小清单，再读取选定记录，不做OFFSET、全表COUNT或每页全站扫描。
- 保守估算JSON转义开销，实际按UTF-8序列化字节复核。长记录单独成页，每条最多200,000字节；超过上限明确报告表及UID并暂停，不跳过，不生成不完整的删除清单。
- 修复“第六条超大记录导致前五条正常记录也不能读取”的问题。未返回的记录保留在下一次游标之后。
- 版本页最多20条，只读取UID与更新时间。摘要按表边界和有序记录逐条累计，与分批大小无关；空表也参与摘要。预览、执行前复核和最终提交保护复用同一摘要算法。
- 请求可携带更小的条数限制，任务使用已保存的policy。测试覆盖同一任务从5条降至1条续读、版本页在1/7/20/3条之间切换。自动降档与设置按钮留待第五步。
- 快照内容和游标仍在同一事务保存；失败保留上次已提交位置。读取期间发生编辑仍需重新预览，不能混用新旧快照。
- UID游标长度与数据库128字符上限保持一致。

## 更新方式

两站配套更新至本版。协议升级为6、任务格式5；升级前完成或取消正在执行的旧同步任务，升级后重新生成预览。数据库结构不变，不需要初始化或重置数据库。只更新一端时接口会明确拒绝协议不一致。

浏览器请求间隔仍为1秒。总量上限仍为每站2000条、两站快照合计4MiB。此次没有提高这些限制，也没有修改部署时跳过源码完整性校验的行为。

## 验证与边界

本地针对新旧分页、任务租约、保存点、签名握手和执行保护进行31项回归；SQLite/文件、D1/R2适配器三种组合另有15项回归通过。D1/R2使用真实适配器配合模拟绑定，不等于线上Cloudflare资源配额验收。

最终差异比较、引用分析、恢复清单准备及最终事务版本保护仍有集中处理；因此本版不保证所有1102问题已经消失。下一步将拆分差异比较和依赖分析，减少重复字段规范化及引用扫描，继续保留“先替换引用、再删除旧媒体”的规则。

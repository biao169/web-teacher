# v0.15.153：第六步任务状态展示补全

## 本次交付

在已保存的 v0.15.152 第六步代码上补全状态显示。此前对话的进度检索遗漏了 v152 文件；本版以其实际代码为基础，包含 v152 的全部任务面板功能。

后台入口：数据与备份 → 两站同步 → 任务运行状态。

- 默认列出未完成任务，每页20项；取消勾选可查看已完成、取消、失效记录。
- 状态区分：等待完成回执、回执逾期待核对、等待重试、重试时间已到、暂停需人工处理、待继续读取、待推进、待确认/审批、已转入准备子任务、已重新开始、已完成、已取消、已失效。
- 显示任务编号、方向、最新500项标识、父任务/准备子任务/重新开始任务编号、阶段和当前操作。
- 显示保存步骤、已读/候选/已准备/已提交数量、媒体文件进度、已下载KB、协商分片大小；这些是保存的检查点，不是实时流量。
- 显示创建、最近启动、最近保存及距今时间、最近失败、重试/回执等待截止、连续失败次数、上一步耗时、错误码及简短原因。
- 新增本页状态汇总与“回到最新任务”；汇总只统计当前页，不冒充全站任务总数。
- 修正其他操作结束后误启用失效任务“查看”按钮的问题；翻页失败保留原列表及页游标，刷新可正确重试。

## 资源与操作边界

保持 v152 的每60秒自动刷新。页面隐藏或同步操作忙碌时跳过；刷新失败关闭自动刷新并保留旧数据。一次只允许一个状态请求，查询最多21条摘要判断下一页，显示20条，不加载任务正文或业务数据，不请求对端，不触发重试或同步写入。

监控范围是本站已有同步任务；未创建任务的推送提案仍在下方提案模块中。已清理的历史任务无法显示。正在由浏览器推进的任务可同时查看页面原有的步骤进度区；任务列表显示最近一次读取的检查点。

没有实时进程心跳，不能保证标记 running 的请求仍在执行，因此显示“等待完成回执”；恢复等待到期显示“回执逾期 · 待核对”，并不直接认定失败。重试时间已到也不等于重试已发生，仍由原执行端或后台下一轮调度推进。工作步骤耗时是墙钟耗时，不是 Worker CPU 时间。SQL仍会解析JSON；返回条数有界不代表数据库扫描成本恒定。

## 更新方法

增量包适用于 v0.15.151 或 v0.15.152：将包内相对路径覆盖到网站源码根目录，重新部署/重启，再刷新后台。包含 v152 的后台接口、状态投影、模板及前端代码，无需另外安装 v152。已有自定义前台、独立多实例安装脚本不在补丁中。

完整包由 v147 完整代码依次叠加 v148–v152 补丁，再加入本次改动生成。首次部署可使用完整包。已有站点优先使用增量包；不要将运行中的数据库或媒体目录替换为示例文件。

无需修改数据库结构、初始化数据库、重置同步任务或清除媒体。此改进是本站管理面板功能，两端分别更新后各自可查看状态。通信协议、审批规则和同步执行算法不变。

增量包不覆盖全量发布清单，因为现有站点可能有自定义文件。如果通过 Git/VPS 的发布清单校验部署，请在合并完成的源码根目录执行：

```bash
python -B deploy/vps/release.py manifest --root . --refresh
python -B deploy/vps/release.py verify --root .
```

然后将生成的 release-manifest.json 与源码一起发布。完整包已重新生成并校验清单。

## 部署后核对

打开任务列表，检查状态与最近保存时间；进入历史第二页后用“回到最新任务”返回。查看一个任务应只读取其保存进度，不自动继续。出现临时错误时检查等待截止时间；任务在后台推进后手动刷新，确认步骤与保存时间变化。仅在接收站启用定时拉取，避免两端相互覆盖。

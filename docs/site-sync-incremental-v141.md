# v0.15.141：第二步，按需准备及逐条提交

## 生效范围

从简要候选点击「准备所选内容及依赖」所创建的新任务，使用按需准备流程：

1. 仅读取选中条目的源站正文，每步处理一个来源条目、目标条目或引用。
2. 目标站只读取 UID、更新时间、创建时间、短标题和必要的关联定位字段，不读取旧正文。
3. 引用指向未选中的媒体或父记录时，加入必要依赖；删除条目时，分页查找其目标站引用者，并准备相应更新或删除。
4. 准备后的条目列表仍留在明细表，服务端分页显示；不聚合为完整任务 JSON。准备完成后选择冻结，改变范围请重新开始。
5. 手动拉取确认后，先完成媒体准备；业务记录按表依赖顺序逐条提交，删除在更新之后按反向依赖顺序进行。
6. 每条业务写入、审计和完成游标在同一事务内提交。响应丢失后重试不会重复写入已完成记录。

准备阶段不写入业务数据。相同内容也会列入覆盖，不做全文比较、不计算全文摘要、不执行全库版本扫描。完整记录仅存放在现有 sync_task_items 中；任务状态保留游标、最多500个选择/依赖编号和媒体计划，不含正文集合。

## 恢复与取消

- 发生暂时性网络错误，可以打开原任务继续；已完成条目不会再次写入。
- 对当前待写入记录检查源站和目标站的单条版本。该条记录变化时停止，提示重新准备；无关条目变化不会阻断同步。
- 取消后已提交条目保留，不整体回滚。尚未登记到媒体库、且仍属于本任务版本的暂存文件可以清理；已经登记或版本已变化的文件保留。
- 重新开始需先取消未完成的执行任务，生成新候选并重新勾选、确认。
- 源站缺失的媒体不产生目标站媒体删除；真正需要永久删除时，在目标站媒体库操作。

## 保留的必要检查

继续复用身份认证、共享密钥签名、角色权限、任务租约、数据库约束、单条版本条件和媒体引用锁。

单条提交会防止准备后新增的引用被数据库 SET NULL 隐式清除；此类冲突停止本条，不改变已完成记录。单例网站设置保留目标站 UID，目标站部署私密配置不被公共同步字段覆盖。待清理媒体不能被重新登记覆盖。

## 部署及兼容

- 两站均更新至 v0.15.141。握手增加 selected_execute 能力标记；不具备能力的对端不能开始按需准备。
- 数据库表结构、同步协议版本7和任务格式8保持不变；无需初始化或重置数据库。
- v140 以及更早版本已经生成的详细准备/执行任务继续原路径；要使用新流程，请新建候选并准备。
- 新手动推送可以按需准备，并只发送选择提案；接收方仍需批准，接收方审批复核目前继续旧的详细准备路径。
- 定时自动拉取目前继续旧路径。后续统一调度时再切换，避免本次修改改变已有授权和待批准提案的语义。
- Linux 部署的跳过源码完整性校验行为未改变。

## 当前限制与下一步

本步不是对所有1102/502的全面修复，尚未在真实Worker或生产Ubuntu服务上测量CPU和总内存。

- 源站单条记录上限仍为200KB；正文规范化及引用解析仍需处理一条完整正文，不能保证任意正文都符合最低CPU配额。
- 最多500个所选及依赖条目；编号及媒体计划仍保留在小型任务状态中。
- 删除反向引用查询虽然每次最多返回1条，数据库内部仍可能扫描缺少索引的关联字段。
- 媒体仍使用既有64KiB分片、Base64签名响应、分步合并与摘要检查；单文件20MiB、总计24MiB等限制未改变。
- 每次只提交一条记录，因此中途失败可能留下已同步的部分内容；这是为了可恢复的低负载运行采用的明确语义。

下一步重点优化媒体传输：降低编码和内存复制，完善单文件/分块检查点，继续保证文件准备成功后才更新引用；随后将审批与定时流程接入同一按需执行器。

# 运行日志 v0.15.103

共用入口 deploy/shared/service.py 在同一个服务进程中启动 Uvicorn，不增设服务或端口。Windows 与 Linux 均在配置的 data_dir/logs 写入 service.log 及 service.log.1～5。保持单 worker，避免多进程争用归档文件。容量：10 MiB/份，最多 5 份归档；归档最长保留 14 天，每 60 秒及启动时检查。活动日志按大小轮转，14 天期限仅作用于归档。

首次错误保留，完全相同的错误在 60 秒内合并并输出重复次数。合并表最多 128 项，不使用无界队列；Python 标准输出/错误也进入日志。单条截断至 16 KiB，截断时保留完整 UTF-8 字符。无法写日志时向原始标准错误每分钟最多提示一次。

根目录 start.sh 及 deploy/windows 启动脚本复用 launcher；Linux 部署生成的 systemd 服务改用此入口，取消无界文件追加。启动配置中的日志路径通过 Settings 解析，Python 解释器沿用现有虚拟环境配置。tweb paths/logs 同步更新。日志随已管理的数据目录卸载，不添加外部 logrotate 配置或定时任务。

更新旧部署必须执行 `tweb update --scope all`，然后执行 `tweb restart` 重新生成服务配置并重启。旧路径日志保持原状，不做隐式迁移或删除；管理员可停服核对后移除。操作记录、会话、媒体、快传文件和数据库没有被清理，也没有数据库结构变化。

本轮验证包括：小容量触发连续轮转、归档数量和体积约束、过期归档删除而无关文件保留、重复错误汇总、合并表上限及重启追加。未执行 Windows 实机或服务器长时间压测。

验证结果：日志及部署测试 37 项通过，其中真实子进程使用新日志入口完成更新、重启、数据库维护及卸载流程测试；另有发布包与 Git 仓库部署回归。后台业务代码、前台、快传和数据库均与 v0.15.102 逐文件一致。独立 urllib 健康探测受环境连接问题影响未通过，真实进程回归使用既有 httpx 探测已通过。

# 前台访问与自适应缓存 v0.15.93

## 已复现的访问故障

在仅初始化数据库或没有启用 site_settings 记录时，英文页头在 StrictUndefined 模式下直接访问 site.site_name_en，抛出 UndefinedError。根路径默认跳转英文，所以看起来整个前台不能访问；没有首页教师时，首页标题/副标题还存在同类空配置风险。旧测试创建了网站设置，未覆盖这一场景。

现对空配置提供只读默认值，并在页头和首页使用安全字典读取。保留严格模板检查，不自动创建或启用设置记录。新增空数据库/仅示例数据/停用设置场景测试，检查中英文首页、八个主要页面及根路径。

## 缓存检查及修改

原模板缓存固定32项，SQLite每次查询新建连接，前台没有可跨请求复用的查询结果缓存。本次保留短连接和原始权限读取，新增内存查询缓存，并调整模板缓存容量。

- 范围：匿名 GET 前台页面、滚动分片、公开分类/引用/简介接口。登录用户、后台、身份与权限查询、媒体下载、文件快传和表单不进入共享查询缓存。HTML与挑战令牌不整页缓存，响应仍为 no-store。
- 预算：每次使用时至多每15秒探测一次。Windows调用系统物理内存接口；Linux读取MemAvailable并检查当前cgroup及父级限制，支持容器和systemd内存上限。无探测能力时使用保守默认值。
- 查询缓存：默认上限32 MiB/进程，实际取配置上限、总内存/256/声明进程数、可用内存/64/声明进程数的较小值；可用内存不足64 MiB时关闭。环境变量TEACHER_PUBLIC_CACHE_MB可设置0关闭或设置更小上限；代码最高允许64 MiB。WEB_CONCURRENCY应与实际进程数一致，未声明按1处理。
- 模板缓存：32、96、192、256个模板，随总内存和可用内存调整；仍自动检查模板文件修改。登录用户也受益于模板缓存。
- 上界：LRU最多2048个查询；超过500行、文本总长度65536字符或编码后256 KiB的结果不缓存，并为缓存项预留额外内存开销。结果以JSON字节保存，每次读取产生独立对象，避免翻译/格式化修改污染缓存。
- 新鲜度：本进程提交后清空；文件/WAL版本签名检查其他进程修改和数据库替换。普通查询最多30秒；数据库时钟表达式最多1秒。带精确当前时间参数的新闻发布查询不会复用不同时间的结果。现有译文数据仍在数据库中，更新同样使查询缓存失效。
- 不改变文件快传的流量、缓存文件容量与保留时间，也不增加数据库表或索引。

## 验证

相关回归406项通过，范围包括所有前台用例、导航、账号、翻译、数据库结构、默认路径和真实本机HTTP启动/退出/重启。随后针对缓存容量、嵌套cgroup、TTL和大结果限制的最终专项复验9项全部通过（与前述用例有重叠，不能相加作为独立用例总数）。未在真实Windows浏览器、Windows内存API或生产反向代理环境中实测。

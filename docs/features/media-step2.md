# 0.15.33：第二步，资源加载与媒体预览

以0.15.32为基线，修改媒体读取的图片类型识别、共享预览恢复、主站有界并发设置及测试。保留第一步列表修复，不修改翻译共享、账号删除、数据库结构或运行依赖。不转码、覆盖或修补用户原图，也未部署用户网站。

## 原因与证据

| 问题 | 已确认事实 | 边界 |
| --- | --- | --- |
| 静态503 | 真实应用与Uvicorn的受控测试中，8个保持连接使原上限8返回503；设为16后相同请求返回200。 | 不证明用户现场一定由此触发，不是生产容量测试。 |
| 图片类型识别 | 原读取逻辑要求签名与后缀一致；PNG内容配`.jpg`键会识别失败，返回普通二进制类型。 | 用户失败JPG是否属于此类仍需样本。 |
| 故障恢复 | 原预览逐张立即发起HEAD诊断，没有有限自动恢复；多图失败会增加请求。 | 新测试验证最多2个诊断并发、2次自动重试及离开页面后的清理。 |

## 修改与复用

- 复用`media_response`、`signature`和类型白名单，仅为PNG/JPEG/GIF/WebP补充按签名识别；响应类型和通用下载后缀与识别结果一致。不相信数据库声明的MIME；HTML、SVG及未知正文仍作为附件。上传、恢复和收录的扩展名校验不放宽。
- 复用`watchMediaPreview`，列表、详情、选择器和字段预览使用同一逻辑，不另建HTML模板。增加HTTP状态、空文件及权限等诊断提示。
- 诊断最多2个HEAD并发。502/503/504且没有Retry-After要求，或HEAD可读取但图片加载失败时，最多延迟重试2次；之后停止并保留手动重试。成功加载、旧响应过期或控件销毁均取消待处理操作。
- 不自动重试401/403/404/409/413/429、外部重定向或直接外链；不改动外链签名。手动重试可开始新的有限周期。自动操作全部只读，不重试上传、删除或保存。
- 启动器和VPS配置生成器共用并发函数。主站默认16；`TEACHER_HTTP_CONCURRENCY`可设8–32的整数，非法值在启动/生成前拒绝。快传仍为8；单worker、20MiB读取上限、上传预留和既有分段读取不变。

文件头识别不等于完整图片校验或解码。损坏、截断、特殊色彩/编码、过大像素和外链反盗链等，需要原图及浏览器证据，不能靠更换Content-Type解决。

## 更新与验收

1. 备份数据库、配置与媒体；停服后解压到新文件夹，沿用原数据路径及启动入口。不要运行重置或示例脚本。
2. 重启后完整刷新浏览器，检查媒体列表、详情、字段预览和选择器；图片恢复后失败提示应消失，失败时可查看原因或打开原文件。
3. 检查教师表头筛选/排序仍正常；媒体列表局部刷新后没有无限重试或重复写入。
4. Windows命令提示符可在启动前使用`set TEACHER_HTTP_CONCURRENCY=16`（默认无需设置）。现有VPS systemd服务不会因解压自动改变，仅新生成服务文件使用新值；须审核后按既有部署流程更新，不直接覆盖现有配置。
5. 若JPG仍失败，请提供1–2个失败原图、所在入口、浏览器及报错，必要时提供响应状态码、Content-Type、Content-Length、Content-Range。不要发送Cookie、令牌、密码或未经处理的完整HAR。

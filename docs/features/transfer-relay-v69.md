# 0.15.69 · 第五步：广域网在线中转

## 交付内容与使用

主站 `/transfer/` 增加「广域网在线中转 · 双方在线」。采用同站 HTTPS 请求逐块转发，继续使用主站域名、进程、端口、身份及数据库。没有另开WebSocket服务或端口；本步选择规划中的HTTPS传输实现。

1. 管理员在快传后台开启「允许广域网在线中转」。默认关闭；此开关同步现有身份规则的 `wan-relay` 模式授权，仍遵守每条规则的发送/接收权限。
2. 发送方选择文件，创建中转配对，将配对码交给接收方，点击「开始 / 继续」。双方均需保持页面在线。
3. 接收方加入配对，核对名称、大小，点击「开始 / 继续」并选择保存位置。此时才原子预留双方额度，额度不足不会开始文件传输。
4. 接收文件逐块校验并写入，确认后才允许发送下一块；最终关闭保存流成功后通知发送方。进度100%不是最终落盘成功的替代。

仍保留局域网直连与临时分享，模式不会自行切换。在线中转没有200MiB技术上限，仍遵守后台单文件/任务大小、身份规则与额度。接收需HTTPS及浏览器流式文件保存能力；通常使用支持API的桌面Chrome/Edge。不能接收的浏览器显示提示，不用整文件Blob撑满内存。匿名默认不能发送，允许匿名接收需后台授权。

## 复用与必要改动

- 复用主站鉴权、同源/CSRF校验，双方能力凭证与身份绑定；128位随机配对码、每侧256位独立凭证。
- 复用 `Accounting` 的日/周/月预留、记账与释放，记录在原 `transfer_allowances`。无新增表、无schema迁移。
- 复用 `receive-core.js` 的校验、写入、ACK、失败保留确认状态；抽取 `chunk-client.js` 共用有界响应读取，临时分享接收也使用此方法。
- 复用 `BoundedIO` 的全站快传数据请求准入/空闲超时，正文读取复用 `read_chunk`。原主站一般页面不占快传数据名额。
- 后台仅增加原 `relayEnabled` 字段开关及对应说明；其他内容管理不改。Caddy示例及生成配置添加中转请求大小限制和小间隔刷新，不启用整请求/整响应缓存。

## 内存、并发和网络边界

每个中转会话至多保留一个1MiB文件块；接收端未确认时拒绝后续位置的上传，不会继续排队读取整个文件。每个会话只保留一个当前块和上一块的摘要/位置，没有增长的文件块列表。

| 控制 | 实现 |
| --- | --- |
| 中转房间 | `TRANSFER_RELAY_ROOMS` 默认4，可配置1–8；空闲等待配对也占用房间；满额立即拒绝 |
| 保留的文件正文 | 默认至多4MiB，最大设置8MiB；这是房间持有量，不是整个进程RSS |
| HTTP数据在途 | 与临时分享共用 `TRANSFER_IO_CONCURRENCY` / `TRANSFER_BUFFER_MIB` / `TRANSFER_IO_IDLE_SECONDS`；默认4个数据请求、16MiB应用估算预算 |
| 额外控制请求 | 至多16个，正文4KiB，读取10秒；不创建无限等待队列 |
| 数据请求 | 正文最多1MiB；原总接收120秒/默认空闲30秒限制；响应发送期间继续占用准入名额 |
| 代理 | Caddy中转路径请求体最多1,048,576字节，刷新间隔10ms；不设置 `request_buffers` 或 `response_buffers`；仍需目标反代验收 |
| 生命周期 | 每侧独立180秒租约，正常页面约每10秒续租；任一侧到期释放房间和文件正文；后台计时器清理，不依赖下一次来访 |

房间正文预算与在途请求预算相加，此外还有Python、ASGI、TLS、操作系统和代理缓冲，不能把4MiB或16MiB说成进程总内存上限。Uvicorn/代理各有网络缓冲；本次不增加WebSocket消息队列。现有VPS服务单元的内存约束继续保留，实际主站加中转的RSS及并发曲线仍需在目标服务器测量。

单进程保存活动会话；不能自行改成多个Uvicorn worker或不带会话路由的多实例。停止/重启会丢弃所有在线中转文件块，临时分享数据不受影响。载荷不写入 `transfer-data`、`temporary_shares` 或 `transfer_chunks`。在线房间不伪装成可恢复的离线任务，因此不会出现在临时分享任务列表中。

## 配额、重试及恢复

接收方确认保存位置后，为发送方与接收方各预留一次完整文件大小，共计2倍文件字节。两个预留在同一数据库事务完成；总配额、身份配额和并发任一失败，两者均不提交。

- 上传按已接受的有效正文记账；下载按已安排发送的有效正文记账。这是应用授权量，不是运营商网卡/TLS流量账单，也不代表接收方已最终落盘。
- 同一待确认块最多接受3次上传、最多提供3次下载。重复传输额外预留并结算对应字节，受剩余额度限制；不会无限免费重试。
- ACK幂等，不重复记账。已确认上传不会自动重发；页面恢复先查询接收确认位置。接收端保留尚未确认的写入状态，ACK响应丢失时只重试ACK，不重复写盘。
- 暂停/短时断线可在同一页面继续，前提是双方租约、服务器会话与接收保存流仍有效。刷新、关闭页面或服务重启后不能续传，需要重新配对；不是跨重启断点续传。
- 取消释放未用额度，保留已记账量；过期的未用预留沿用现有账本的到期折算。成功保存才发完成通知；若文件已close但通知丢失，界面提示「文件已保存，通知未确认」，继续只补发通知。
- 速率沿用WAN配置，在每次接受/安排发送后设定下一次数据操作时间，不使用睡眠占住请求槽位。首块允许有限突发，后续需要等待；上传和下载串行进入同一会话节流门。
- 配额周期沿用原系统授权开始时的日/周/月归属，不把跨周期已预留任务改成另一种结算方式。

双方账号/会话/权限、当前角色规则、工具方向开关、文件限制和设置版本在操作及写事务中复查。权限或策略失效会停止并释放未用额度。请求取消时，已开始的记账事务和内存状态转换先完成，防止「已记账却丢检查点」而重复扣费。

## 升级

从0.15.68升级无新增数据库迁移。停服、备份、替换代码，保留主数据库、配置和整个 `transfer-data`，再启动原主站。更早版本仍先按0.15.66/0.15.67文档处理旧库整合及分块索引升级。

如使用Caddy，合并本版本生成/示例中的中转路径配置，只改本站配置，先用实际安装的Caddy验证配置再重载。不要为中转启用整请求/整响应代理缓存或自动重试POST。正式接收使用HTTPS。没有修改或部署用户实际服务器、数据库和文件。

## 验证证据与仍需验收

完整回归466项Python、181项前端测试通过；新增四房间并发测试后，中转专项11项复测通过，累计覆盖467项Python用例。新增用例采用专项复测，并非第二次全量运行。

自动化结果见 `transfer-relay-v69-verification.json` 与同目录测试日志。当前环境无Caddy可执行文件，未运行生成的反代配置；需在目标环境验证后再使用。

- 真实本机HTTP：通过原单站启动器，两个独立HTTP客户端经同一服务收发8MiB数据，校验源/目标SHA-256；测试ACK响应丢失后的重复确认、主站健康接口仍可用、无 `.part` 文件落盘。这不是公网跨网测试。
- 合成服务内存测试：独立进程分别处理8MiB和256MiB数据（确实逐块传入/读出，不只是大文件元信息），完整摘要一致；房间正文峰值均1MiB，结束为0。Python堆峰值分别2,123,793/2,123,858字节；进程峰值RSS分别43,312/43,240KiB。这一小幅差异是独立进程基线差异，不代表文件越大内存越小。测试不含HTTP/TLS/浏览器/代理。
- 并发专项：四个房间同时保留四个1MiB块，第五房间被拒绝，接收未ACK前不会继续接收下一块，取消后正文持有量归零。
- 权限、跨源、正文上限、配额原子性、额外重试计费、过期、取消、错误摘要、限速及请求中断后的状态一致性均有测试。

尚待目标环境验收：两端真实不同公网网络；HTTPS+Caddy/现有反代；Windows/移动浏览器；慢网、断网、磁盘满；多GB文件及多任务的进程/反代RSS、服务器实际网卡流量；代理配置重载。不能把上述本机和服务测试称为已经完成公网部署或完整实机验收。

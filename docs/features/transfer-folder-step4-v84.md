# 文件夹增强第四步：直连与在线中转（0.15.84）

## 本次实现

- `live-folder.js`组合复用已有folderFile、metadata、readManifest、folderSink；不创建第二套目录遍历或保存实现。一个目录被视为有路径清单的顺序数据流，原DataChannel及HTTPS relay分块/ACK/哈希协议保持。
- 两个在线模式增加“发送上方已选文件夹”按钮，使用上方预览选择；保留单文件入口。清单封存后展示一个配对码，接收方根据任务类型选择文件保存器或目录选择器。
- 服务端共用`live_folders.py`：描述、分页提交、幂等重试、封存、分页读取、路径和父子关系校验，最多10000文件/2000目录/32层，与前两步一致。发送和接收方重新检查自己的规则。
- 单文件限制检查实际最大文件，任务限制检查目录总字节，文件数单独检查。空根目录、空目录和零字节文件受支持；总字节为零也必须完成目录保存后才通知发送方成功。
- LAN只通过本站交换连接信息及目录清单，文件内容仍通过host-only WebRTC DataChannel，保留不使用STUN/TURN、不自动中转的既有行为。物理局域网/VPN路径仍需要实测；服务器不声称能对直连字节实施硬计量。
- WAN在线中转复用每会话一个待确认分块、ACK后推进和计量；按总文件字节预留双方配额，重试继续计费。目录页请求也维护已有额度租期，不绕过权限/额度状态。
- 在线目录元数据仅在内存保存序列化页，不落数据库或磁盘。每任务最多2 MiB，两个在线模式每进程共享8 MiB序列化页预算。校验时只短暂构造一个目录的路径索引；页请求最大512 KiB且保留既有并发门限。此预算不等于进程RSS总上限。
- LAN增加到期清理定时器，和WAN一起在取消、到期、权限失效时释放目录清单预算；不保留重启后的在线任务。
- 目录选择发生在用户点击手势内；保存沿用同名避让、逐文件close、取消保留已完成文件。写入失败不报告成功。中转可原页面短时继续，LAN连接断开需重新配对。

## 复用与边界

不新增后台配置界面、数据库表、SQL初始化文件或端口。没有把目录文件内容复制到大Blob或ZIP。控制请求和元数据会消耗少量服务器流量；“直连不经服务器”指文件内容。在线元数据超过上限时提示使用临时缓存，后者的目录持久化来自第二步。

目录权限、符号链接、操作系统属性、跨页面恢复仍不在当前功能范围。支持目录写入的安全上下文和浏览器要求沿用第三步。实际浏览器目录授权、双设备网络和Windows磁盘行为尚未实测，不将模拟数据通道测试当成真实网络验收。

## 验证与下一步

测试覆盖两种在线模式的分页、清单封存前禁止加入、路径冲突/危险名称、声明与实际字节核对、单文件与总大小区分、角色凭证、零字节/空目录、额度预留、ACK及元数据内存预算释放；保留单文件和临时缓存回归。

Node测试复用模拟文件系统，测试直连和在线中转共用目录保存组件、空目录不发送二进制文件块、元数据超限预检及实际前端控制器在封存后才展示配对码。

最终测试数量和日志见同目录verification与test-results文件。第五步将进行兼容性和真实双端环境验收，并整理故障恢复与部署说明。

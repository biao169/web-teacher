# 前台重规划第五步：扩展示例与联调（0.15.57）

本步增加独立的 `frontend-130-v1` 示例批次：30 名学生与 100 篇论文均为追加数据，不替换原有基础样例。已在隔离 SQLite 中实际保存、重复导入并核对；用户正在运行的网站数据库未在本环境连接或修改。

## 数据覆盖

| 内容 | 数量与覆盖 |
| --- | --- |
| 学生 | 博士 10、硕士 12、本科 8；6 名已毕业；中英文姓名、不同年级、方向、奖项、去向、长短简介、头像有无 |
| 论文 | 期刊 70、会议 30；2020—2026 年、中英文题名、1—8 位作者、不同位置及多位通讯作者、长短刊名、虚构收录标签 |
| 引文 | 每篇均有 GB/T、Elsevier、APA、IEEE 和 BibTeX；复用 `publication-tools.mjs` 生成并随包保存，运行网站或导入时无需 Node |
| 附件 | 复用原示例的 3 张原创几何头像和 1 份演示 PDF；论文 20 条有 PDF 引用，其中 10 条公开、10 条隐藏；其余无附件 |

所有人物、单位、奖项、期刊、会议及成果明确标为虚构。学生邮箱仅使用 `example.invalid` 并设为隐藏，学号不进入前台。全部 DOI 留空，避免伪造可解析的真实成果链接；DOI 的边界显示继续由隔离测试夹具覆盖。分类通过原有学位、分类、年级、方向和状态字段匹配现有启用规则，不写入、启用或重排“学生分类”。如果网站没有启用可匹配规则，学生会按现有逻辑归入“其他学生”。

## 如何导入到实际网站

从 0.15.53—0.15.56 更新无需新增迁移。更早版本仍须按 README 先停服并显式升级数据库。不要运行重置命令。

1. 替换程序代码，沿用原 `TEACHER_CONFIG` 或数据路径配置，停止主站与快传服务。
2. Windows 双击根目录 **`add-frontend-examples.cmd`**，输入已有系统管理员的账号和密码。脚本使用普通启动器的 `normal` 数据配置，并先显示数据库路径；自定义配置仍优先。需先通过普通启动入口准备运行环境，或设置 `TEACHER_PYTHON`；已有自定义 `TEACHER_VENV` 也会复用。
3. 查看最终输出：首次完整导入应为 `created: 130`、`failed: 0`、`complete: true`。再次执行应为 `created: 0`、`kept: 130`；已有部分示例时，数量按实际情况变化。
4. 重新启动网站核对前台。首页是否展示学生和论文、展示多少条，仍受原网站设置控制；导入不会代改首页数量。

Windows 命令行可用同一配置检查进度或限制本次新增数：

```bat
.venv\Scripts\python.exe deploy\windows\frontend_examples.py status
.venv\Scripts\python.exe deploy\windows\frontend_examples.py add --limit 20
.venv\Scripts\python.exe deploy\windows\frontend_examples.py add --group publications
```

VPS/本地 Python 环境使用相同的 `TEACHER_CONFIG` / `TEACHER_DATA_DIR`：

```sh
python -m backend.app.native.frontend_examples status
python -m backend.app.native.frontend_examples add
```

命令默认只查询批次状态，只有明确传入 `add` 才添加内容；登录和退出仍产生真实会话记录。每完成 10 条输出一次进度；`--limit` 限制本次**新增业务记录**，不是前台每页数量。遇到错误停止后续导入，保留此前已成功提交的条目；修正原因后重跑即可补齐。`unprocessed` 为本轮未处理的条目数量，`after` 为数据库实际覆盖数量。控制台中断后可用 `status` 核对。原后台“示例中心”和 `add-demo-data.cmd` 仍为原 113 条样例，不会自动增加本批次。

本入口面向 Windows/VPS 的 SQLite 数据配置，不会连接或修改远程 Cloudflare D1，也没有新增管理 HTTP 接口。若只更新程序而未运行导入，原数据库不会自行多出 130 条记录。

## 保留与回退

每条数据使用独立、固定 UID。已存在的 UID 即保留，包括管理员改过的引文、姓名、排序、可见性及附件引用。已回收、已删除文件或大小变化的原示例媒体不会被静默恢复；需要到现有媒体库处理后重试。

如需清理本批次，`backend/app/native/frontend_example_rows.json` 中的 UID 是准确清单。通过原后台列表核对本批次条目，保留已改成真实内容的记录，再使用现有删除功能；仍按原权限、并发版本和关联关系规则处理。不要凭“示例”字样删除所有样例，也不要清空表。关联的 4 个示例媒体可能被旧内容共用，不随本批次自动删除；只在媒体库确认无引用后按原回收站流程处理。

## 验证与改动范围

新增入口复用 `Examples` 的权限、互斥与媒体校验，以及 `Content.save` 的字段校验、关联检查和原子审计。原后台界面、管理功能、数据库结构、共享认证、媒体服务和快传代码均未修改；新增文件只在显式导入时加载。没有新增前端框架、构建依赖或启动时填充行为。

已验证：在原 10 名学生及 10 篇论文样例之外再追加 30/100；原记录和分类设置保持不变；重跑不重复；人工修改/撤下保留；限量、失败后续传；提交时撤权与审计失败不留下业务记录；完整中英文分片、默认排序、分类、长刊名分页候选、四种显示引文、隐藏联系方式/PDF、首页总量控制。100 篇论文连续追加后仍保留勾选，批量复制等于保存的引用文本，标签和按钮不混入复制。

具体通过数量见 `frontend-replan-step5-verification.json`，实际隔离入库记录见 `frontend-replan-step5-import-report.json`。Windows Edge/Chrome 的视觉布局、真实滚动和剪贴板尚需人工验收；模拟 DOM 不代替真实浏览器验收。本次未部署网站，也未访问用户实际数据库。

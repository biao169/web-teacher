## Windows 实机清单

使用可丢弃的开发数据目录，不用正式站点数据。解压至有中文和空格的目录，复制 `deploy/windows/local.example.cmd` 为 `local.cmd` 并按注释指定 Python 3.12+、可选虚拟环境及专用开发目录。

1. 双击 `deploy/windows/start.cmd`，设置测试管理员，确认首页、后台、快传均可打开。
2. 新增一条测试内容，关闭开发服务，再次 start.cmd；确认旧记录清空、重新生成管理员/基础示例。改用 start-existing.cmd，确认本次数据保留。
3. 检查办公室/可见联系方式、首页两卡片、学生方向与获奖、项目状态靠右；未登录/普通用户不能在页面或网络响应中看到项目金额、负责人、成员。
4. 在 1440px 桌面宽度及 390px 手机宽度检查无横向溢出；搜索、筛选、排序、滚动加载、引文选择、勾选复制正常；Tab 焦点、弹窗关闭/焦点恢复正常。
5. 检查登录/注册关闭提示，中英文切换；新闻 PDF 水印、逐页加载与下载权限；留言失败保留内容。
6. 在项目根目录的 cmd 终端运行：

```bat
deploy\windows\test.cmd --dom --report "%TEMP%\teacher-site-acceptance.json"
```

`--dom` 需要 Node/npm；只验收 Python 可去掉。脚本自动准备测试依赖，测试使用独立数据。报告位于 `%TEMP%\teacher-site-acceptance.json`；保留控制台输出中的 passed/failed/skipped 及具体原因。JSON 的 `windows_browser` 仍为人工待验收，不能以脚本通过替代上面的操作。

## Ubuntu/Debian 测试服务器清单

在独立测试主机使用 `deploy/linux/README.md` 的一行命令；先替换真实仓库、分支、域名。不要在共用生产数据库上做以下重置/卸载验收。

| 顺序 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 首次 install.sh，输入测试管理员 | 独立账号、目录、虚拟环境和单一服务创建；本机健康检查通过 |
| 2 | `sudo tweb paths`、`sudo tweb doctor` | 路径/地址正确；仅 127.0.0.1:8003 提供网站上游；无独立快传端口 |
| 3 | 根据 `sudo tweb proxy` 配置一套代理并启用 HTTPS | 公网域名证书有效，登录/退出/后台入口正常，不影响其他站点 |
| 4 | 上传媒体，创建测试内容，测试两台设备快传 | 内容可读；局域网直传与远程中转按 UI 实际模式工作；限额/缓存时间生效 |
| 5 | `sudo tweb restart` | 主站与快传恢复；内容/任务状态符合持久化规则 |
| 6 | 推送仅前台变更，`sudo tweb update --scope frontend` | 前台更新，数据保留；后台/SQL 不兼容变更会拒绝局部更新 |
| 7 | `sudo tweb update --scope all` | 整站版本更新、依赖准备先于停服；数据保留 |
| 8 | `sudo tweb db-reset`，输入 RESET | 数据库按新站重建，重新输入管理员；媒体磁盘文件保留，无迁移/备份 |
| 9 | `sudo tweb uninstall`，输入 DELETE | 本站受管目录/数据库/媒体/快传/虚拟环境/服务/账号/命令删除，其他站点不受影响 |

后台上传/下载限额按测试设置验收。文件校验可比较发送与接收文件 SHA-256；局域网直传要检查实际连接模式与 VPS 流量，不能仅因速度快就判定绕过 VPS。重置/卸载前确认是测试主机；手动合并到 Nginx/Caddy 的站点配置需要手动移除，不属于自动卸载范围。

建议分别在目标 Ubuntu 与 Debian 系统记录发行版、Python 版本、安装命令、测试时间、结果和错误日志。当前 v0.15.77 交付中的自动化结果不代替这些真实记录。

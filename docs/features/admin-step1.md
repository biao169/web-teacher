# 新一轮优化第一步：后台界面与账号（v0.15.37）

## 已完成

以v0.15.36为基线，调整公共后台界面和账号流程，复用原有工作区、控件、删除接口、权限检查与审计。数据库定义和依赖锁文件不变。

- 后台概览按内容管理、资源与工具、网站配置、系统管理排列，卡片留白、标题、数量和链接保持对齐。无内容模块权限时显示说明与账户安全入口。
- 左侧导航采用同一分组规则，自定义入口独立分组且保留原相对顺序；权限提示、选中入口、桌面收起、手机抽屉、焦点恢复沿用原实现。
- 概览/预览桌面内边距20px，窄屏16px。媒体详情、记录详情、译文版本、正文预览、论文检索预览共享样式参数；长文本局部滚动，长名称换行。列表仍保持原紧凑密度。
- 新建用户界面默认已启用，默认要求首次登录修改密码。固定导航明确限定状态时仍服从固定范围；已有禁用账号不自动启用。
- 所属角色必须明确选择，候选只提供启用角色；系统角色标注“系统管理员”，说明普通网站用户角色不自动授予后台权限。服务端也拒绝新建/改属停用角色，并在事务内再次检查。
- 允许具备相应权限的系统管理员删除其他管理员账号，删除同步清除其主站会话；保护当前登录账号、初始化账号及最后一个可用系统管理员。可用指账号启用且系统角色启用；首次改密账号仍需完成改密后使用后台。
- 操作列直接展示保护原因。删除事务复核剩余可用管理员及目标角色，目标角色在打开页面后改变时要求刷新核对。系统角色、注册默认角色和有成员角色的保护继续有效。

## 验证

完整统一验收通过：111项Python测试、28项模拟DOM测试。新增8项Python测试覆盖真实表单默认值创建普通/管理员账号、实际登录和首次改密、旧会话失效、其他管理员删除、停用角色过滤及伪造请求、停用角色提交竞争、最后管理员原因、相互删除竞争、自定义菜单顺序及当前入口。原有“所有管理员都不能删除”用例按本轮已采纳规则更新。

新增3项模拟DOM测试覆盖桌面收起与移动抽屉切换、Escape关闭及焦点恢复、浏览器存储不可用和权限提示。发布联调继续验证主站/快传真实HTTP启动、退出及重启后的数据保留。

测试使用临时数据，未访问实际业务数据库。当前环境为Linux，未完成Windows浏览器的真实布局检查；模拟DOM不会证明像素排版、字体或缩放效果。现场需检查桌面、平板及手机宽度下的文字、冻结列、菜单滚动和固定操作栏。

复现命令：安装requirements-test.lock以及tests/package.json的测试依赖后，在项目根目录运行：

```sh
python -B tests/run_acceptance.py --dom
```

## 更新与现场检查

备份数据库、媒体和配置，停服后解压到新目录，沿用原数据路径并重启，无需重建数据库。后台CSS使用0.15.37版本参数。

1. 新建测试账号时确认“已启用”和“首次改密”，明确选择启用角色。登录后先完成密码修改，再核对角色授予的功能。
2. 只用测试账号验收删除；普通账号及其他管理员应可删除，当前账号与初始化账号显示保护原因。
3. 核对已有禁用账号仍禁用，角色停用时不能分配给新账号。
4. 检查概览卡片、媒体与文字预览的留白，以及长标题、窄屏、导航折叠和权限不足提示。

# 0.15.70 · 第六步：离线缓存与后台策略

## 已实现

本地主站（Windows/Linux）临时分享移除200MiB技术上限。沿用1MiB分块、分页检查点、幂等上传确认及原下载方式，不将整个文件读入内存。发送者上传完成后可以离线，接收者在有效期内凭链接下载，不要求同时在线。

后台统一支持大于200MiB的全站/身份单文件上限，仍保留缓存总量、分享有效期、下载次数、匿名接收及日/周/月流量控制。新增/公开：

| 项目 | 默认与含义 |
| --- | --- |
| 自动清理到期缓存 | 开启；仅处理到期、撤销及已进入清理流程的任务 |
| 到期检查间隔 | 15分钟，可设1–1440分钟；启动后先检查，有可处理积压时短间隔继续分批处理 |
| 磁盘安全余量 | 64MiB，可明确设为0；创建和分块写入都进行检查 |
| 离线缓存与磁盘状态 | 管理员按需刷新，显示空闲磁盘、待上传预留、安全余量、缓存预留和最近清理状态 |

全站文件大小留空表示不额外限制，不代表磁盘、流量额度或浏览器无限。前台首页与后台上传均移除写死的200MiB限制，服务器仍做最终校验。当前缓存有效期保持原语义：从创建任务开始，单位小时，允许1–168小时。改变有效期影响新任务，已创建任务不重新计时。

## 容量与写盘

新任务同时满足：身份/全站文件限制、流量预留、缓存总量，以及实际磁盘容量。

`新文件大小 + 所有未完成有效上传的剩余字节 + 磁盘安全余量 <= 当前磁盘空闲字节`

缓存总量继续按未物理清理任务的完整预留量控制。过期文件尚在磁盘时，不因逻辑到期就提前释放缓存容量；分批清理完成后才释放。降低缓存上限不会擅自删除未到期文件。

本地主站共用磁盘准入锁，串行核对创建与分块写盘，防止多个本进程任务同时重复使用同一份空闲空间。中断请求会先完成已开始的事务和状态转换再释放锁，避免未知提交结果造成预留重叠。

其他进程仍可能写入同一文件系统，因此这不是操作系统级物理预分配。每块写入前重新检查；真正发生ENOSPC/EDQUOT时返回可理解的错误，该块不推进检查点、不计为成功上传。原子写入失败会尝试移除未确认对象；释放空间后可重新选择同一文件继续。磁盘权限或设备错误也不会伪装为成功。

示例文件生成复用同一磁盘策略。辅助缓存目录不纳入文件分享配额，但其实际磁盘占用会反映在空闲容量中。碎片、文件系统元数据、小文件开销及其他应用占用可能导致提前耗尽，安全余量用于降低这类风险，不能保证任何平台写入必定成功。

## 自动清理与恢复

使用主站应用生命周期启动/停止维护协程，不需要管理员访问网页，也不额外启动端口或进程。复用现有 `Management.purge` 的持久撤销、清理租约、分块游标、失败记录与额度释放。

- 每轮最多32次清理推进，每次至多8个已登记分块；末尾至多再检查/删除8个生成的遗留对象。不递归载入整棵文件树，也不把全任务文件列表装入内存。
- 到期、撤销文件先停止继续传输，再逐块删除。失败时保留 `cleanup_failed`、游标和错误提示，默认至少间隔60秒重试失败任务，其间仍可处理其他任务。
- 主站重启后根据数据库检查点继续；尚在旧清理租约内的任务不会被另一个操作抢占。已不存在的已登记文件按幂等删除处理。
- 清理完成前保留任务和缓存预留；完成后标记文件已清理、移除分块索引及空任务目录，保留任务历史和已用流量记录。
- 对已终止任务目录中「写盘后、数据库提交前」留下的分块或临时文件，也做有界清理。只接受快传生成的文件名；遇到未知文件、特殊对象、符号链接或Windows联接点停止并记录失败，不扩大到其他目录。
- 自动维护使用私有、只允许到期/撤销任务的服务，不借用管理员账号，不新增万能角色，也不接受前台传入系统身份。正常管理员手动清理仍走原鉴权与租约。
- 关闭快传总开关不阻止已有到期缓存清理；单独关闭「自动清理」才暂停自动维护，手动清理仍可使用。

清理期间正在下载的到期/撤销文件不会获得额外保留期。下载会停止或失败，不能把不完整文件当成成功。维护初始化或检查异常不会停止主站业务；后台状态和任务列表用于核对问题。存储不可访问时，相关快传请求本身仍可能失败。

## 边界与升级

从0.15.69升级**无新增数据库迁移**。先停服备份，替换代码，保留数据库、配置及完整 `transfer-data` 后启动原主站。更早版本仍按0.15.66/0.15.67的整合和schema升级说明执行。没有替用户升级实际数据库或部署。

首次启动会按已有任务期限检查到期/撤销文件，包含旧版本留下的积压。需要保留的资料应先另行备份；该行为属于本轮已经授权的自动到期清理。维护关闭时按后台设置保留，磁盘与缓存配额仍生效。

继续保持单进程部署；多进程共享磁盘的全局预分配不在本次范围。独立Cloudflare Worker没有本地磁盘维护协程，仍保留原200MiB传输技术限制；不能把本地主站的功能视为Worker已实现。直接调用原管理服务不会自动启动维护，必须使用正常主站ASGI生命周期。

任务目录中的未知文件/链接由管理员在原缓存管理中核对处理；不会为了清空磁盘自动删除未知数据。本次不自动扫描或删除没有任务记录的任意目录，也不移除主站媒体文件。

# 翻译来源与批次管理

后台翻译列表和译文编辑页提供“批量扫描与翻译”入口。所有任务使用现有翻译执行器、权限、媒体校验、Bootstrap控件和顶部通知；不新增数据库表、生产依赖、编译流程或常驻进程。普通启动与打开页面不会扫描、联网或改写任务进度。

## 来源字段

| 模块 | 可扫描文本 |
| --- | --- |
| 教师与团队 | 姓名、角色、职称、单位、实验室、介绍、教育、工作经历、招生说明 |
| 研究方向 | 名称、描述 |
| 论文 | 标题、作者、刊物、出版类型、作者角色、通讯作者、索引类型、展示标签、关键词 |
| 科研项目 | 名称、来源、基金名称、项目角色、负责人、成员、状态 |
| 专利软著 | 名称、国家、类型、发明人、权利人、法律状态、简介 |
| 学生 | 姓名、学位、分类、方向、状态、去向、获奖、介绍 |
| 学生分类 | 显示名称 |
| 新闻动态 | 标题、分类、正文 |
| 课程 | 名称、学期、授课对象、简介、参考资料 |
| 导航与按钮 | 标题，排除后台侧栏入口 |
| 网站设置 | 网站名称、横幅标题/副标题、SEO标题/描述/关键词、页脚文本 |

仅扫描发起者有查看权限和公开范围的内容；检查原生可见性、启用标志及新闻发布时间。网站设置只处理当前启用记录。联系方式、账号、凭据、URL/标识、文件正文、引文格式、论文摘要和内部项目简介均不自动纳入。部分保留字段的访客模板尚未输出，产生译文不等于新增前台区块。

专用人工英文字段优先，空文本及不含汉字的文本跳过；当前自动扫描范围为中文到英文，不是通用语言检测。超过60000个UTF-8字节的源字段不送译。字段是否扫描与浏览器翻译列表的临时筛选无关。

来源扫描按模块、原生id和字段位置推进，建立任务时固定各模块id上界。期间新增记录，以及已扫过记录的后续修改，在下一次新扫描纳入。进度总数是扫描开始时估算的字段数，期间删除和撤下可令实际检查数减少。

## 批次操作

| 操作 | 行为 |
| --- | --- |
| 扫描来源 | 建立新的有限来源快照和队列，核对历史当前译文；扫描本身不调用服务 |
| 继续任务 | 继续已保存的扫描或尚未结束的执行模式；打开页面不自动继续 |
| 执行下一批 | 按全局translation_batch_size最多处理1–50条后停止；有限重试也计入条数 |
| 连续运行 | 页面保持打开时不断发起串行小请求，直到结束、暂停或遇到需处理的配置问题 |
| 暂停 | 停止后续调度；已发出的请求可以完成，最终提交仍检查来源、权限和人工修改 |
| 重试失败 | 只重新排入本任务仍有效的非人工失败条目，并执行一个批次；不顺带消费其他待办 |
| 刷新状态 | 只读取服务器进度，不扫描、不恢复执行 |
| 停用译文 | 取消当前生效标志并保留正文；扫描尊重停用选择，人工编辑保存可恢复 |

发起者能控制自己的任务；系统管理员可以暂停其他人的任务，并在其请求结束或领取到期后重新扫描。其他有翻译查看权限的账号只看计数，不返回他人来源范围及最近来源链接。修改操作还需翻译创建/编辑权限，运行时持续检查各来源模块的查看权限。

本任务来源和服务选择在创建时记录，页面明确显示当前任务范围；下方选项的修改只在新扫描时采用。`default`在执行时读取有效全局默认；选定具体服务则固定服务标识，修改密钥和超时配置仍对后续请求有效。回退只有明确选择时采用，会将原文发送给后续启用服务。

## 暂停、恢复与资源

实际并发为1；translation_worker_count是配置上限，不创建额外进程。扫描仍逐字段推进；执行时最多收集12个来源、合计60000个UTF-8字节，按独立原文和服务限制装箱；“下一批”仍以来源条目预算停止。来源正文按行读取，最近结果最多10条，任务JSON有大小上限；无需Redis、Celery或Node。

`global_settings.translation_job_state`保存单个有版本的任务、来源游标、上界、计数和短期领取。`translation_cache.source_refs`保持原生数组结构，在首个来源对象内记录有限尝试次数、重试时间、任务标识和停用标记。译文正文、哈希、当前标志和人工标志仍使用原列。

领取采用数据库比较更新，两个页面不能同时推进同一请求。异常领取180秒后可恢复，已落库的成功结果不重复请求；条目完成标记与进度计数在同一事务保存。全站单条翻译、批次和连接测试共用网络租约，遇到占用时等待，不消耗供应商重试次数。

已收到响应的限流及服务故障最多自动尝试3次，间隔30、120秒；等待是页面发起下一请求前的截止时间，不占用常驻线程等待。配置、凭据或禁用服务导致失败时暂停，修正后需明确重试。其他永久错误不无限重试。连续运行也可能留下失败或跳过条目，界面显示原因。

关闭或离开页面后不再发起后续请求，已发出的请求仍可完成。重新打开、程序重启及代码更新均保留原生数据库内的任务进度，但不会自行恢复联网。恢复依赖同一数据库地址、有效账号及对应权限，不依赖原浏览器内存。

扫描和执行会按需写入队列、进度及操作日志，历史译文不会自动删除；磁盘占用随实际内容和操作记录增长。每个执行步骤的UTF-8分段、20次HTTP请求上限、总超时和响应限额仍有效，详见[翻译服务](translation-services.md)。

## 译文复用与保护

新建来源队列、单条翻译、后续扫描和批次执行共用复用服务。原文摘要之外还核对完整原文、源语言、目标语言以及纯文本、Markdown、HTML格式。可复用来源必须仍公开、启用、可查看，且与当前原文一致；已停用、历史失效、已填写专用人工英文的来源不能提供自动复用。候选条件先在数据库筛选，再读取有效结果，不受最近8条记录限制。

有效人工译文优先于自动结果；如果不同来源的当前人工译文不一致，暂停该原文的自动复用与调用，由用户进入“来源与版本”核对。可先选用一个当前版本，再填入指定的待译/失败空白来源；不改写其他来源已有译文，不把这次选择保存为全局默认。已有人工记录和历史版本保留。

新增相同原文来源时，具备翻译编辑权限会直接填入可用译文；仅有创建权限则建立待译记录。单条和批次联网前再检查复用，已保存的当前成功译文不重复调用。人工译文若在请求途中出现，提交会拒绝旧的自动结果，需重新核对。复用提交还校验供稿译文、两端来源版本、媒体引用、人工冲突、权限以及批次领取。

新队列在原生source_refs数组中记录原文格式和有限复用来源信息。旧新闻正文未记录格式时保持独立，不推断其历史格式；从当前来源重新建队列，或在核对原文后人工保存即可记录当前格式。普通文本字段的历史格式可确定为纯文本。格式变化不会复用原先不同格式的结果。

扫描核对原文修改、删除、撤下及专用人工英文后，将不再有效的当前译文停用，保留历史正文。来源、译文版本、角色/会话权限及媒体引用在结果写入时再次检查；晚到响应不能覆盖人工改动或新的原文。

英文公开展示使用与复用服务一致的有效候选和人工优先规则，按完整原文、摘要、语言及格式匹配其他公开来源的译文。专用人工英文字段、本来源人工缓存、明确选用版本和停用设置优先；人工冲突不产生任意全局选择。教育/经历、网站名称、导航标题和其他既有展示字段共用此规则。访客浏览不调用供应商、不写缓存或原文，不改变公开页面布局；后台状态数量仍按已保存记录统计。

计数表示本任务累计处理结果；失败后明确重试会继续累计成功与失败，不能把两者相加当作当前唯一条目数量。历史扫描与运行结束也不承诺所有字段已成功翻译。


人工编辑采用原文与译文对照，来源支持新标签定位并保留当前草稿；版本变化、无权来源及安全原文显示见[原文对照与来源定位](source-navigation.md)。列表分组、多来源筛选和明确选用译文见[翻译分组与来源版本](translation-groups.md)。

## 多原文请求与结果核对

同一语言对和格式的原文在步骤内去重，HTML只发送经过清理的文本节点；标签、链接、媒体地址、pre/code内容不送译。共享文本片段只发送一次，结果按已固定的映射填回各个文档。Google、DeepL、Microsoft和LibreTranslate使用原生数组；MyMemory使用随机标识和连续边界编号。普通单条翻译与旧任务保留原有执行方式，新扫描采用合批。

| 通道 | 本地单次上限 | 结果核对 |
| --- | --- | --- |
| Google / DeepL / Microsoft | 32段、5000字符、16000 UTF-8字节 | 原生响应数组与请求等长，逐项验证文本；Microsoft还核对目标语言 |
| LibreTranslate | 8段、4000字符、12000 UTF-8字节 | translatedText数组等长；单项兼容字符串 |
| MyMemory | 8段、总计500 UTF-8字节，包含分隔标记 | 随机标识、编号、数量、顺序、首尾全部匹配后才拆分 |

上述为保守本地限制，单次JSON请求体另限90000字节，HTTP响应限1MiB，合计译文限200000字符；一个执行步骤总计最多20次HTTP、总时限按现有配置1–120秒、单次最多12秒。每段按UTF-8边界切分，不切断字符。若单份文档已确定无法在20次请求内完成，联网前拒绝并提示改用适用服务。响应数量或分隔标记异常、请求过大时只二分失败包，成功的完整文档不会参与拆分重试。缩小到单段仍失败则保留失败原因。没有原文标识的原生数组只能依赖供应商约定的返回顺序，无法检测供应商自身语义串位。

每条完整译文、对应来源的完成标记、累计计数和请求记录移除在同一原生事务提交；来源、缓存、人工修改、角色/会话、媒体和任务领取均重新核对。一个来源冲突不会撤销其他已保存译文。长文仅部分片段成功时不会保存不完整正文。

请求发出前保存有限请求意图和涉及的来源ID；响应到达后累计已收到响应次数。超时或进程中断无法确定远端是否处理的请求标为待确认，恢复时不自动重发；点击“重试失败”才明确重试。请求意图已记录但进程在实际发送前退出也保守视为待确认，因此请求次数是持久化尝试数，不是供应商账单。已收到响应但长文尚未完整保存的片段不跨进程缓存，恢复后提示该条目需明确重试；已保存的完整译文始终复用。

有待确认记录时先继续原任务完成核对，不能直接新扫描丢弃请求记录。暂停阻止后续HTTP，已发出的整包结果仍按来源逐条校验保存。刷新只读取状态，重开页面不自行恢复。界面区分来源记录、去重原文、送译原文、请求尝试、已收到响应、请求结果待确认；成功/复用/失败为累计操作数，不同于唯一原文数。减少HTTP次数不保证按字符收费同比例减少。

协议依据：[Google v2](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate)、[DeepL](https://developers.deepl.com/api-reference/translate)、[Microsoft限制](https://learn.microsoft.com/en-us/azure/ai-services/translator/service-limits)、[LibreTranslate](https://docs.libretranslate.com/api/operations/translate/)、[MyMemory](https://mymemory.translated.net/doc/spec.php)。

# 新一轮第二步：媒体管理（0.15.38）

本版在0.15.37上修改，不包含第三至第五步的新功能。复用共享列表、表头、分页、操作通知、媒体上传与读取、目录核对永久清理核心；没有新建一套平行媒体列表。

## 已实现

- 媒体列表表头为“大小/KB”。0.15.42起1 KB按1024字节换算、向上取整展示，默认列宽100px；表头筛选输入KB并转换为整数字节，排序仍使用数据库数值。既有URL中的 `f.size`、导航固定值、JSON/CSV的 `size` 仍为字节。外链显示“—”，悬停解释未核验远程大小，不将0字节当成已核验的远程大小。
- 新增可空只读元数据 `original_filename`。统一上传服务保留原文件名（最长255字符，去除客户端路径，拒绝控制字符），支持中文、空格；列表和媒体选择器可搜索。媒体标题可独立修改。详情提供下载按钮；HTTP通过UTF-8文件名参数建议保存原名，浏览器仍可能因本地重名调整名称。
- 磁盘/R2仍使用唯一对象键。同名上传不会互相覆盖，已存在的引用地址不变；未知或危险内容继续以安全的通用文件名下载。旧记录不从标题反推原文件名；外链原名未知。目录核对收录可记录当时实际文件名，无法因此还原文件更早的上传名称。
- 回收站行内及工具栏新增永久删除。先预检、再确认，删除数据库登记及本地/R2对象；外链仅删除登记，不请求远程服务器删除。缺失文件允许在通过检查后清理登记。
- 0.15.42起回收站手动单条/批量永久删除不受保留期限制，不再要求额外勾选；仍须拥有媒体删除权限，并受引用、状态、记录版本、文件版本检查约束。目录核对的到期清理仍遵守保留期。仅有查看/编辑权限不会获得删除权限。
- 批量逐项预检后统一确认，执行遇错即停，显示成功、失败或待核对、未处理数量。服务端预检绑定账号、记录、存储配置、导航和30分钟有效期；同一账号再次预检同一记录会替换旧凭据。
- 保留原有“先记清理意图、再删文件、最后删登记”的流程。文件删除失败，或文件已删但数据库事务失败，保留回收站登记和重试状态，阻止恢复/新引用；重新核对并执行可完成清理。数据库与文件系统不能组成单个原子事务，不会将这种中间状态假称为成功。

## 升级已有Windows/Linux数据库

1. 停止主站及关联启动器，备份现有数据库和媒体文件。将新代码解压到新目录，沿用原来的 `TEACHER_CONFIG`、`TEACHER_DATA_DIR` 或启动器数据目录。不要把业务数据复制进源码目录。
2. Windows运行包根目录 `upgrade-data.cmd`。它复用现有启动器配置和Python环境；如需demo配置，使用 `deploy\windows\launch.cmd migrate --profile demo`。
3. Linux/已自行配置环境：在新项目目录使用网站对应的Python运行 `python -m backend.cli migrate`；使用共享启动器默认数据目录者运行 `python deploy/windows/launcher.py migrate`，避免把两种配置来源混用。
4. 升级只接受本包保存的0.15.37完整结构签名；先获得运行锁、核验数据库完整性，再在数据库旁创建 `原数据库文件名.before-v0.15.38.sqlite3` 快照，然后在事务中添加一个可空字段。保留用户、角色、内容、媒体记录、对象键和时间戳。未知结构拒绝修改；快传数据库不变。完成后重复运行会返回当前结构，不再新增快照。
5. 正常启动。新安装的空数据库直接使用新结构，无须迁移。旧库直接启动会给出升级提示，不会静默重置。不要运行 `reset-data.cmd` 升级。

若快照文件已存在但数据库仍是旧结构，先核对上一次结果并保留快照，再移走该快照后重试；程序不会覆盖已有备份。失败后不要删除原库。

## 备份、恢复、回退与D1

- 新版JSON/CSV及完整备份包含原文件名。旧JSON缺少该字段仍可导入，原名保持未知；导出大小继续为字节。
- 新版SQLite备份/恢复工具继续要求当前完整结构。需要恢复旧SQLite快照时，先把快照复制到独立临时数据路径，对副本运行本版迁移并核验，再用现有恢复工具恢复该已升级副本；不要直接修改唯一备份，也不要把旧库当作损坏库重置。
- 回退旧代码需要同时恢复升级前数据库快照，停服操作；升级后新增/修改的数据应先另行备份处理。数据库快照不包含媒体正文，不能恢复已经永久删除的磁盘/R2对象，因此媒体备份必须独立保留。
- D1不运行本地SQLite迁移器。本版Worker准备包带有 `migrations/0011_media_original_filename.sql`；停写、备份并确认主站旧结构后对明确选定的主站D1执行一次，仅新增字段。初始化SQL只用于空库；快传库不执行该迁移。R2删除继续沿用已有版本检查和失败重试契约。本轮没有连接真实D1/R2进行生产迁移或删除。

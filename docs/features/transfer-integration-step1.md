# 登录与快传整合第一步：0.15.65

基于0.15.64完成第一步登录/注册统一。没有实施第二步共库、同端口或文件迁移。

## 展示与交互

前台页头登录按钮打开原生dialog，登录/注册共用auth-form.html；直接访问/auth/login、/auth/register使用相同组件的紧凑备用页面。表单不铺满页面，输入与按钮留足间距，小屏控制宽度和高度并允许滚动。继续使用Jinja、原生JavaScript和现有CSS基础，字体字号颜色与交互状态由public-theme.css维护。

注册开放时显示注册入口；关闭时登录页显示“当前未开放注册”，注册页不显示可用注册表单，POST再次检查开关。语言随前台或lang参数选择，独立认证页语言切换保留模式和返回地址。注册成功转登录，弹窗模式保持在同一弹窗内，不自动改变账号权限或自动登录。

登录失败保留账号（注册失败也保留邮箱），密码不进入返回HTML、不写浏览器存储，每次提交结束清空。原生label、autocomplete与密码管理器入口保留。打开后焦点进入账号或反馈；原生dialog提供模态焦点约束与Esc关闭，关闭后焦点回触发链接；提交时禁止重复提交和关闭，20秒后未知结果给提示，不自动重试写请求。关闭未完成的读取会取消请求，迟到表单不会覆盖页面。

前台弹窗传递当前路径及查询条件，登录成功返回该位置；原生备用链接保留对应模块/详情路径。没有返回参数时，后台有权限账号进入/admin，一般账号进入对应语言首页。快传桥接入口未登录时增加/transfer/login返回目标。返回目标仅接受本站/zh、/en、/admin和/transfer路径，拒绝站外、协议相对地址、反斜杠、控制符、编码路径、父目录段及认证循环地址。

## 复用和边界

新增public_auth.py只负责公开认证路由的展示和响应；登录调用原Auth.login/会话机制，注册调用原public_actions.register。保留账号状态、角色有效性、密码算法、限流、来源校验和Cookie策略。失败响应更新表单令牌；仅返回明确的展示错误，不输出密码或数据库异常详情。

原Auth/public_actions实现、后台模板、数据库与迁移、快传业务、部署脚本均保持不变。web.py将登录/注册入口交给统一处理器；留言仍走此前同一校验/保存/响应，剥离旧共用注册分支，不改变留言服务。没有创建第二套账号或会话，没有部署或操作用户实际数据库。

## 验证与限制

认证专项覆盖注册开关、开关提交前变化、账号冲突、密码不回显、原生和JSON响应、安全返回地址、后台登录、快传返回、缺失Cookie/错误Origin拒绝及中英文。模拟DOM覆盖弹窗加载/切换、焦点恢复、失败重试、重复提交拦截、注册后原位登录及关闭取消。全量405项Python与159项模拟DOM测试通过；认证补测模块16项通过（其中3项新增，共408个Python用例已有通过记录）。详见transfer-integration-step1-verification.json。

Cloudflare仅本地准备并核对新模板/模块/脚本，不等于已部署。Windows Chrome/Edge和手机真实浏览器的视觉、密码管理器、软键盘和原生dialog焦点行为仍待实机验收，模拟DOM不能替代此项。

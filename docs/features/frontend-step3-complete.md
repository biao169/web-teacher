# 第三步公开取数与学生分组完成（0.15.48）

用户已批准0.15.47列出的最小公开取数改动，并明确学生默认按“学生分类”的配置顺序分组。本说明覆盖frontend-step3.md中的待批准状态。

## 学生默认展示

读取student_category_displays中enabled=1的有效规则，按display_order升序、ID稳定排序。匹配复用已有parse_keywords与五个MATCH_FIELDS；大小写与特殊字符语义保持后台预览一致。多规则命中时归入最靠前分类，每个学生出现一次；未命中放最后的“其他学生”，空组不显示。空关键词和旧版非法关键词规则不参与分组，学生仍可在其他组中显示，不会丢失。后台匹配预览仍独立显示各规则命中项，其写入和预览语义未改。

组内默认学生sort_order升序、ID稳定排序。组内升降序可切换，分类先后始终服从配置。选择姓名/入学时间等普通排序则使用平铺列表，不再分组；日期排序空日期置后。分类名称使用配置的中文/英文名称，英文缺省回退中文。修改后台规则后刷新前台即可取得新分组，不改写学生category字段或其他数据。

分组在SQL排序与LIMIT/OFFSET之前确定，不在已加载页面里假分组，不下载全部学生。每批10/20条；倒序序号按当前筛选总数跨组连续。同一分类延续到滚动下一批时保留一个组标题；显式分页第一页仍显示当前分类名。原选择保留，新追加项默认不选中，分类标题不参与复制。

## 公开字段与筛选

学生首屏含两行简介、状态及允许公开的邮箱；教师补齐身份和实验室。保留原有译文覆盖/原文回退，摘要在匹配译文后限制长度。展开读取已有公开详情全文；学号不公开，隐藏联系方式不会出现在前台与复制数据中。

教师职称/单位，学生分类/学位/年级/状态/方向下拉采用完整公开范围的SQL DISTINCT，禁用教师和非公开记录不贡献选项。初始最多50项，超过时提供“更多选项”，每次再取最多50项，不一次性下载人物记录。空值不显示，只有一种取值且未选中时不显示该筛选框。当前值即使在后续选项页也保持选中；控件自然宽度，极长内容在控件区域滚动，窄屏换行。

GET /api/public/people/{table}/facets/{field}?page=N为严格按表/字段白名单的只读接口，不提供任意字段、账号、学号或联系方式聚合。查询使用参数化值，分片人物请求不重复读取筛选选项。

## 改动范围和兼容

- public_data.py：列表白名单、默认学生排序、人员分类聚合。
- 新增public_students.py：共享关键词解析、配置分组SQL与当前页分组标记。
- content.py：仅公开字段筛选、学生公开分组和日期空值排序分支；管理查询、写入与权限规则保持原样。
- web.py：人员公开筛选上下文和只读分类接口。
- 前台人员模板/CSS/JS：下拉、分组标题、选项分批加载及失败重试。

无数据库结构变更，无新依赖，不涉及管理模板、共享前端、账号/认证、快传或部署操作。从0.15.46/0.15.47升级无需新增迁移；更旧版本仍按README执行既有升级步骤。

SQL分组把关键词打包为单个JSON绑定，避免分类较多时超过绑定参数预算。D1的JSON扩展支持依据[Cloudflare SQL文档](https://developers.cloudflare.com/d1/sql-api/sql-statements/)，本次在本地SQLite执行验证；Worker仅做资源准备校验，不表示已部署或在真实D1执行。

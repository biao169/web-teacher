# 0.15.34：第三步，翻译合并显示与译文共享

以0.15.33为基线。修复后端共享查询和展示覆盖，复用现有分组、来源版本、权限和选用写入流程，仅在已有列表模板中补充说明。数据库结构、运行依赖、原文和历史译文均不迁移或清理；用户/角色删除留到第四步。本包未部署到用户现有网站。

## 原因与对照复现

旧版已经按完整原文、摘要、语言和格式在数据库中分组后分页，不是缺少全部合并逻辑。实际不一致是：列表以字符串最大值选代表译文，提供方又独立取最大值；保存复用按人工优先选择；英文展示只查本来源的缓存，其他同文来源的有效译文不会即时显示。

在同一临时数据库建立两个同文来源：人工译文`A manual`、自动译文`Z automatic`，另建待译课程。直接运行旧版与新版函数得到：

| 位置 | 0.15.33 | 0.15.34 |
| --- | --- | --- |
| 合并列表代表译文 | Z automatic | A manual |
| 待译课程英文展示 | 共同原文 | A manual |

## 统一后的规则

1. 分组仍要求完整原文、摘要、源语言、目标语言和格式一致，不模糊合并空格不同的文本，也不混合HTML、Markdown与纯文本。未知格式的历史新闻正文继续独立保留。
2. 代表候选必须当前成功、非空、未停用，且来源仍公开有效、原文和格式未变化。人工优先；无冲突时，同优先级按现有记录ID从新到旧稳定选择。代表译文和提供方来自同一记录；排序使用完整选中译文，界面仍显示320字符预览。
3. 当前有效人工译文不一致时，不选择任意全局代表。已有本来源有效版本继续保留，没有自身版本则显示原文。仍通过已有“来源与版本”界面为指定待译来源明确选用，不将该选择设为全局默认。
4. 英文页面可即时读取其他公开来源的相同原文译文，包括目标没有缓存记录或仍待译的情况。原生英文字段、本来源人工缓存、明确选用版本及停用标记优先。可共享人工译文修改后，未被上述规则保护的来源下次读取即可看到新内容。
5. 公开读取只使用公开有效来源，不借用当前管理员权限；后台代表候选、计数、来源和导出仍受当前角色、分类筛选和固定导航范围限制。筛选掉候选后列表可以显示“当前范围暂无可共享译文”，不意味着公开页面无法从其他公开来源共享。
6. 页面读取不联网翻译、不保存缓存，不改变记录状态。因此后台待译/成功数量表示已保存记录，不能将即时共享误当作已批量写入。显式选用仍走原有权限、时间戳和事务保护。

## 复用及改动范围

- `translation_index`集中候选有效性、稳定排序与数据库分组排名，供`translation_reuse`、`translation_groups`和`translation_sources.overlay`调用。
- `overlay`对一个来源的多个字段批量查询，最多读取每个字段的本地优先记录及每个匹配组的代表候选；不会把全部历史加载到应用内存。
- 公开导航查询补充已用于筛选的公开/启用字段，让同一展示规则可用于导航标题。
- 合并列表保留原有模板和操作，只补充暂无可共享译文及状态含义提示。不修改公开页面布局或翻译供应商接口。

## 验证与限制

新增29项翻译回归，覆盖代表译文与提供方一致、无缓存来源共享、人工冲突、原生英文字段、人工留空、明确选用、停用保护、失效/隐藏/未发布来源、格式隔离、权限与分类筛选、译文排序、分页、导出、106条历史记录完整分组、译文修改后的共享更新及公开导航。测试使用临时数据库和合成账号，不调用供应商。

完整回归结果：81项Python测试、23项模拟DOM测试全部通过，117个Python文件通过语法检查；其中包含前两步的列表和媒体测试。依赖弃用警告与Node VM Modules实验性提示不影响结果。真实Windows浏览器、用户现有翻译库及Cloudflare D1生产环境仍需验收；本地SQLite/HTTP测试不能替代生产负载与平台限制验证。

## 更新与验收

1. 备份数据库、媒体和配置，停服后解压到新目录；沿用原数据路径并重启。不要运行重置或添加示例脚本。
2. 找一组相同原文的公开来源，清除临时状态/来源筛选，确认列表合并为一组，来源与历史记录可全部查看。
3. 保留一份有效人工译文，查看另一个无译文来源的英文页面，应显示共享结果；中文页面及数据库原文不应改变。
4. 分别检查本来源专用英文、人工译文、明确选用和停用记录是否受保护。加入不同人工译文后，列表应提示冲突，不覆盖各来源已有版本。
5. 若结果不符，提供来源模块、字段、原文、语言/格式及译文状态；排查时无需提供账号密码或服务密钥。

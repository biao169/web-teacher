# 0.15.68 · 第四步：同站配对与局域网直连

## 已实现内容

在主站 `/transfer/` 增加「局域网直连 · 双方在线」区域。发送方选一个文件、创建配对码；接收方在同一网站加入配对，核对文件名和大小后，选择保存位置。原临时分享的上传、下载、逐块保存、任务管理继续使用。

- 原主站进程和端口承担配对与连接描述交换；身份及工具策略继续来自主数据库。不增加数据库表、独立服务、监听端口或文件缓存目录。
- 配对码为128位随机值，发送/接收控制凭证分别为256位随机值；同源校验，登录用户另外校验主站CSRF。双方凭证不同，配对只接受一个接收方。凭证只保留在当前页面，刷新后需重新配对。
- 只创建可靠、有序的 WebRTC DataChannel，ICE配置不含STUN或TURN。服务端拒绝非host候选以及音视频媒体描述。无法直连时停止，不自动改用VPS文件中转。
- 每个逻辑块最多1MiB，SHA-256校验；DataChannel帧最多16KiB并适配协商消息上限。发送缓冲高于64KiB时等待；接收消息队列最多70条且字节总量不超过1MiB+64KiB，超限关闭。
- 复用 `receive-core.js` 的「校验 → 写入 → ACK → 下一块」流程；发送方只保留当前块，收到确认后才读取下一块。接收文件流 `close()` 成功后才通知发送方已保存，不通过整文件Blob拼接。
- 传输进度显示接收写入确认量，100%不单独代表最终保存成功；最终状态另行显示。取消、校验失败、断网、写盘失败都会停止，未完成的临时写入流会尝试abort。已完成close但最后通知中断时，明确提示文件已保存而通知失败。
- 连接区显示实际选中候选的类型、协议（浏览器能提供时），不展示具体IP。不把host候选等同于物理局域网：设备VPN、虚拟网卡、网络策略均可能影响实际路径。

## 配对资源与权限边界

配对保存在当前单进程内存中，不保存文件数据。最多64个房间；每个身份遵守现有并发设置并最多8个房间，匿名共用身份池。每侧单独续租180秒，任一侧过期就不可继续使用；过期数据在后续请求中清除。重启服务会终止配对，临时分享原数据不受影响。不要自行配置多个Uvicorn worker；多进程的分布式信令不在本次实现范围。

每个SDP最多32KiB，请求正文最多48KiB、读取最多10秒；至多16个信令请求同时处理，无等待队列扩容。每侧普通信令操作间隔至少200ms。房间中只保留每侧一个连接描述，不保存增长的候选/消息历史。连接建立期间约每2秒查询，传输期间约每10秒续租。

所有操作重新核验主站账号、会话、当前角色、权限及工具策略；房间参与方的角色规则也重新选择。后台关闭工具/直连、撤销权限后，下一次正常客户端心跳会停止传输（通常约10秒），不是服务器逐字节拦截。浏览器已建立的点对点链路不经过主站，不能把客户端协作控制说成服务器能强制中断任意改造客户端。

后台复用「启用工具」「上传/下载」「身份规则」「单文件/任务大小」「并发」「VPN保护」，添加既有 `lanEnabled` 字段的可见开关。允许匿名接收开关同时控制默认匿名规则的临时分享和直连接收；默认匿名不发送。未更改教师、论文等内容管理业务。

### 流量与大小限制

- 直连没有临时分享200MiB技术上限，文件长度使用JavaScript安全整数，仍受后台已设置的单文件/任务大小限制。没有声称任何大小在任何浏览器均可成功。
- 本站LAN接口只交换有限的文件元信息和连接描述，不接收文件块，不写入 `temporary_shares` / `transfer_chunks`，不产生临时存储预留。`server_file_bytes=0`表示该协议没有文件中转路径，不是实机网络仪表的测量值。HTTPS信令仍消耗少量服务器流量。
- 服务器无法核实点对点文件字节数。任何适用的全站/身份/匿名每日、每周、每月硬配额存在时（包括0），拒绝直连，提示使用临时分享；不会绕过硬配额，也不把客户端申报量计为真实VPS账单。原临时分享配额记账保持不变。
- 既有LAN速率设置由官方客户端发送端配合限速，不声称其为服务器可核实的强制限速。默认不限。当前管理界面仍保留原200MiB单文件配置输入上界；留空时LAN不受该上界约束，缓存分享仍受200MiB技术上界约束。离线策略和大小配置统一在第六步处理。

## 浏览器与部署条件

两端必须能打开同一主站HTTPS地址。发送端需WebRTC及Web Crypto；接收端还需 `showSaveFilePicker` / `createWritable`，通常使用支持此接口的桌面Chrome/Edge。页面按实际API能力判断，不支持时关闭直连接收按钮并保留临时分享。没有实现手机/iOS的整文件内存下载兜底。

在远程设备直接打开普通HTTP局域网IP通常不满足安全上下文要求；localhost特例不等于另一台设备也满足条件。无需给主站新增服务端监听端口，但浏览器间WebRTC连接需要网络允许点对点流量。访客Wi-Fi隔离、防火墙、设备VPN可能导致失败；页面会提示检查，不能保证所有标称同一LAN的设备都能连通。

本次只对Windows/Linux本地主站适配器提供直连，Worker独立适配没有宣称完成同等实现。暂停/跨刷新断点续传未加入LAN；中断重新配对并重传，现有临时分享暂停/续传继续有效。

## 升级

1. 备份当前代码、数据库和整个 `transfer-data`，停服替换代码，保留实际数据目录。
2. 从0.15.67升级无新增schema迁移，按原配置启动主站即可。若仍是0.15.66或更早，先按 `transfer-bounded-v67.md` 执行停服升级；独立快传旧库按0.15.66迁移说明处理。
3. 后台开启工具和局域网直连，检查双方身份规则、VPN保护和配额。不要为方便测试擅自关闭生产限制；可用独立测试环境验证。
4. 两端刷新页面加载新脚本，配对并选择保存路径。原主站、后台、临时分享需要一并检查。

未在用户实际数据库、服务器或文件目录执行升级。

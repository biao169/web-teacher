# 第三步：HTML页脚与受控按钮（0.15.39）

## 修复原因与实现

原“页脚文本”被模板按普通文字转义；所有非后台位置的公开导航被合并到顶部，因此footer配置不能在页脚生效。同时原内容页和基础模板各输出一处footer。

现在基础模板统一输出一个网站页脚，首页、内容列表、详情和联系页面复用同一模板。纯文本保持换行；HTML经过项目已有JustHTML清理器的页脚白名单策略后渲染。保存的原始代码不改写，也不会当作Jinja程序执行；英文有效译文同样经过安全处理。没有文字和按钮时使用网站名称作为页脚。

“导航与按钮”的footer条目不再混入顶部；header仍在顶部，hero暂沿用此前合并到顶部的行为。本步不新增首页hero布局。顶部与页脚复用链接模板和安全路径处理，支持HTTP/HTTPS外链、站内路径、fragment锚点及普通/强调/描边样式；仅指向前台`/zh`或`/en`的站内路径随当前语言切换，外部链接保持原路径。

## 如何设置

1. 打开“网站设置”，编辑当前启用的网站配置，在“页脚文本”填写HTML或纯文本。
2. 字段下展开“HTML页脚示例与按钮设置”，点击“复制示例”，粘贴到页脚文本后替换团队名称、邮箱和版权文字，保存。示例也在 `docs/examples/footer.html`；不会自动覆盖现有内容。
3. 打开“导航与按钮”新增或编辑条目：位置选择“页脚”，填写标题/英文标题、路径，选择类型、样式和可见范围，启用后保存。排序数字较小者先显示，同序按记录ID稳定排序。
4. 例如联系按钮：类型button，位置footer，路径`/zh/contact`，中文标题“联系我”，英文标题“Contact”，样式primary，启用，公开。英文页面目标自动成为`/en/contact`。

受控占位区写法：

```html
<nav data-footer-navigation aria-label="页脚导航"></nav>
```

占位区内部由后台已启用且当前访问者可见的页脚条目替换。重复占位只呈现一组；未放置占位区时，按钮自动追加到页脚正文后。不需要在HTML里复制按钮的标题和网址。手写普通`<a>`链接不受“导航与按钮”设置控制，需要由您修改页脚文本。

支持div、section、nav、p、br、span、small、h2/h3、strong/b、em/i、ul/ol/li、a和hr。提供`footer-grid`（宽屏两列、窄屏一列）、`footer-brand`、`footer-meta`、`footer-note`等受控类；脚本、事件属性、任意内联样式、iframe和图片不渲染。页脚不通过图片引用额外开放媒体权限。HTML不是脚本或模板，`{{ ... }}`等表达式不会执行。

## 可见性与语言

- public：所有访问者；authenticated：登录用户；staff：已登录且角色可见范围包含staff的成员。
- hidden和owner：不在公共页面输出。导航本身没有可核验的所有者字段，不将owner当作公开或全部登录用户。
- 按钮是否可见不授予目标页面的权限，目标仍执行原有授权。
- 英文按钮优先使用title_en，缺少时复用现有有效译文，否则保留原文；中文页面使用原中文标题。网站页脚文本也继续使用现有译文选择规则。
- 本步没有改造翻译服务的HTML结构保留流程；请检查翻译后的排版。即使译文没有保留按钮占位区，页脚按钮仍自动追加，并经过权限过滤；显示页面不联网翻译、不保存新译文。

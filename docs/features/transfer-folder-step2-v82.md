# 文件夹增强第二步：统一任务与缓存发送（0.15.82）

## 已完成

- 一个根目录对应一个临时分享任务、一份配额预留和一个分享令牌。延用账号、CSRF、同源策略及事务内权限检查。
- POST `/transfer/api/folders` 创建任务；POST/GET `/transfer/api/folders/{id}/manifest` 每批最多100项提交/读取清单；POST `/transfer/api/folders/{id}/seal` 核对总字节、文件数、目录数后封存。
- 保留根目录、相对路径、文件修改时间、空目录、零字节文件。服务端重新校验路径、Unicode/大小写冲突、父目录顺序与声明的额度；重试已提交批次要求内容一致。
- 复用共享数据库的service_meta存储逐项清单和唯一规范路径键，不新增数据库或SQL初始化文件。每页条目一次批量INSERT，与任务计数在同一事务提交，保持既有25语句事务预算。
- 每个文件保存起始字节位置；其确认字节和状态由任务的持久确认位置计算，避免逐文件状态与真实分块进度不一致。
- 封存清单前禁止上传分块。封存后复用原有indexed分块上传、SHA-256恢复核对、限流、磁盘预算、额度及自动清理。纯空目录/零文件目录无需上传数据即可完成。
- 前台新增发送、停止、继续、解除关联、总进度及目录分享链接；会话存储只保存任务凭据，重新选择后核对原目录。文件内容保持在用户授权的File引用中。
- 虚拟文件视图每次只切出最多1 MiB的Blob；跨文件边界的分块不要求预先拼接或压缩整个目录。
- 清理任务时同时清理该任务目录元数据。旧的单文件流式下载/接收会话明确拒绝目录任务，避免产生错误的拼接文件。

## 范围与后续

这一步只接入离线临时缓存的发送端，尚不能在接收端选择目录并还原文件；分享链接留作下一步接入。第三步实现目录授权、逐文件写入、空目录创建与失败恢复；第四步再统一局域网直连、在线中继、离线缓存三种模式。未增加后台设置项，不更改后台业务界面。操作系统权限、符号链接、扩展属性不在当前目录清单范围内。

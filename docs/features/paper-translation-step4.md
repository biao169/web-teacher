# 第四步：论文通讯作者与翻译列表（0.15.40）

## 论文联网查询

在已有论文查询框勾选“补查通讯作者”（默认勾选）。先走原查询服务；候选缺少通讯作者且有 DOI 时，通过已启用的 OpenAlex 按相同 DOI 补查，只补通讯作者，不替换题名、期刊、其他作者等主来源字段。须先在原有全局论文查询配置中启用 OpenAlex，并按供应商要求配置凭据；未启用时不额外调用。补查沿用缓存和权限验证，最多处理五个候选，受整体20秒及单次8秒时限约束；补查失败仍保留原候选。

仅采用 OpenAlex 的明确通讯标记或通讯作者ID，不根据作者排序、末位作者或姓名相似度猜测。供应商未提供时保持空白；其 authorships 最多包含前100名作者，超长名单可能不完整。字段依据：[OpenAlex Authorships 官方文档](https://help.openalex.org/data/authorships/)。

选用候选后，空白通讯作者项会填入当前编辑草稿；已有不同填写会保留，需在差异区明确勾选才能替换。修改仍须保存，字段旁保留原值和撤销。作者输入框下显示姓名预览，与通讯作者项完整姓名匹配的作者右侧显示上标 *；忽略大小写及多余空格，未匹配姓名提示核对。星标不写入姓名字段或引用文本。

## 翻译列表

沿用原分组与共享规则。普通文本最多显示三行；原文区域为两行正文加一行语言/格式信息。来源记录支持上下滚动及键盘聚焦，每组预览最多20个不同来源，其余通过“来源与版本”分页查看。来源查询按批执行，不逐条查询整个来源集合。

右侧“编辑译文”进入当前代表译文记录；存在不同人工版本时先进入版本核对。“翻译该词条”针对该组一个可用的待译/失败词条，先确认，再复用已有单条翻译服务：优先共享有效译文，需要时才调用已配置供应商。一次只处理一个目标，完成后刷新列表；它不是整组覆盖。没有待处理目标或存在人工版本冲突时不显示此按钮。

沿用CSRF、导航权限、当前筛选范围、实际目标版本、原文一致性、人工译文保护和任务锁。旧页面、原文已改或权限已撤销时拒绝操作并提示刷新，不自动重试写入。

## 升级和验证

先停服、备份，按根目录README更新程序并保留原数据库、媒体与配置。本版无数据库结构变更；已完成0.15.38升级的数据库无需额外迁移。0.15.37及更早版本仍须按第二步说明运行安全升级入口，不要重建数据库。

自动回归覆盖精确DOI补查、空结果/失败/不匹配、启用配置与缓存、多通讯作者、共享词条单次翻译、权限和版本保护，以及模拟DOM中的星标安全渲染、自动回填、保护已有值、明确替换和撤销。本轮164项Python测试及34项模拟DOM测试通过（33项完整回归及1项新增请求绑定测试），139个Python文件通过语法检查；Cloudflare本地构建成功，数据库文件与0.15.39一致。供应商响应使用测试数据；真实供应商、Windows浏览器和云端D1/R2仍需在目标环境验收。

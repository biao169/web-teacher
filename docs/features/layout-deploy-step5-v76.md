# 第五步：Ubuntu / Debian 一键部署与管理（0.15.76）

## 本次实现

- 根目录 install.sh：公开 GitHub 仓库与分支下载安装，依赖环境检查，调用部署管理程序。只有这一个新增根目录入口。
- deploy/linux/tweb.py：独立管理程序、交互菜单和子命令；安装、启动/停止/重启、状态、日志、全局/前台局部更新、数据库初始化/结构核验/重建、完整受管卸载。
- 共用唯一 database/schema.sql、原数据库锁和初始化、管理员创建方法；不新增业务表、不写迁移或备份流程。
- 安装生成 systemd 单服务及存储配置；快传仍在同进程/端口/数据库，项目根目录 transfer-data 指向独立持久目录。
- 提供路径/URL 汇总、系统防火墙与代理检查、Caddy 和 Nginx 配置片段。只输出示例，不自动修改已有代理/防火墙。
- 源码下载、解释器与依赖准备完成后再停服；普通更新健康失败切回旧源码，重置后失败保持停止；前台局部更新必须通过后台/结构兼容核对。
- 受管目录标记、禁止接管已有非空路径/账号/入口、限制 GitHub URL 和分支文本、拒绝源码符号链接、管理操作互斥锁、卸载前校验外部入口。
- 完整包及 Windows 包均包含 install.sh 与 Linux 说明。现有 Windows 开发启动规则保持。

## 运行与边界

详细指令见 deploy/linux/README.md。用户尚未提供 GitHub 仓库/分支/域名，文档使用明确占位符。本次没有上传 GitHub、没有运行 apt/systemd/useradd 或修改真实服务器。目标需要 Ubuntu/Debian + systemd + Python 3.12；旧系统可指定自备解释器。默认只支持公开仓库。

卸载删除本站受管目录内全部文件与本站服务/账号/命令，不删除共用系统软件、系统日志、他站目录、手动合并的外部代理配置或证书。数据路径手动移出受管目录后，外部数据不在自动卸载范围。重置数据库保留磁盘媒体；需要清除本站全部文件时使用卸载。

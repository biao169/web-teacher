# v0.15.152：第六步，任务状态与整体验收

## 任务状态面板

在后台“两站同步”页面上部增加“任务运行状态”。默认显示未完成的读取、准备、等待确认、等待批准、执行与暂停任务；取消筛选可查看完成/取消/失效记录。每页20条，以创建时间及UID游标翻页，不读取全部任务正文。

每行显示：任务UID、同步方向、最新500项模式、当前阶段、保存步骤数、读取数量、候选数量、已提交数量、媒体文件进度/已下载KB、当前协商分片大小、创建/最近启动/最近保存时间、等待截止时间、失败次数和简短错误原因。时间按浏览器本地时区显示。

状态区分等待、暂停、等待完成回执、待继续读取、待推进、待确认/审批、完成、取消和失效。没有实时心跳，不能确认进程仍在运行：running只是持久化的步骤启动标记，界面明确标为“等待完成回执”。计数是已保存检查点，并非实时字节流，也不虚构整体完成百分比。

点击“查看”只打开已有检查点，不调用resume、不推进步骤；之后可使用现有“继续”“取消”等操作。准备子任务仍通过原父子映射定位。后台策略状态同时显示当前预览/执行任务ID及等待时间。未生成任务的推送提案在原提案模块中显示。

## 限制刷新开销

默认每60秒读取当前页状态，可关闭自动刷新或手动刷新。页面隐藏、正在进行同步界面操作时跳过定时刷新。同一监控请求不并发；失败即关闭自动刷新并保留原列表。状态接口只查询本站，不联系对端、不启动同步、不写数据库。SQL只投影状态字段、截取500字符错误，最多读取21条摘要用于判断下一页，不返回正文、密钥或整个state。

SQL内部仍须解析任务JSON；不能把返回20条等同数据库只访问20条。此版本不新增索引或修改表结构。近期记录清理由已有10条/7天规则持续进行，活跃和待批准任务保留。

## 部署后建议核对

1. 在两端查看本站模式、重试间隔与分片说明。
2. 接收端创建一次少量内容的同步；刷新面板，查看准备→传输→写入→清理→完成的检查点变化。
3. Worker新文件应协商16KiB，旧文件任务可能仍为64KiB；如存在媒体重试，等待到期后继续，不重置数据库。
4. 仅在接收站启用定时拉取，关闭浏览器后等待Cron推进，再打开面板检查最近保存时间。
5. 持续没有保存进度时，结合等待截止时间、任务锁和服务端诊断日志排查，不能只凭running字段认定仍在运行。

# 两站同步第二步：v0.15.121

本版在 v0.15.120 的连接和差异预览之上，接入 **对端 → 本站** 的真实执行。两站均更新本版本后，可在任一站后台操作拉取，来源网站保持不变。**本站 → 对端仍只预览**，接收方批准、待批准请求合并/替换将在第三步实现；无人值守定时执行属于第四步。

## 使用方法

1. 打开“数据与备份 → 两站同步预览”，确认两站连接测试通过。
2. 选择模块，点击“对端 → 本站 · 预览”。核对新增、更新、删除及自动勾选的前置依赖。
3. 在“实际拉取到本站”输入 `从对端同步到本站`，点击“确认并开始拉取”。
4. 查看下载、内容提交、媒体删除和清理进度。暂停后，或刷新/关闭页面后，从“最近预览”打开任务，再点击“继续 / 重试任务”。登录过期时重新登录即可继续，进度不绑定旧会话。
5. 不再执行时，点击“取消剩余步骤并清理暂存”。**已经提交的内容不回滚，尚未删除的旧媒体保留**。未提交阶段只清理本任务可确认拥有且未登记的暂存媒体，不覆盖或删除已存在的其他文件。

运行期间不能改动该任务的选择或对端连接；需要调整范围时先取消当前任务、等待清理完成，再生成新预览。一次仅允许一个实际同步任务，预览可保留多个；有未完成任务时，创建新预览不会清理掉它。

## 执行顺序

- 重新验证来源身份、连接配置、两站数据版本及全部已选依赖。
- 通过签名的只读接口按 **256KiB** 分片读取媒体，逐片校验 SHA-256、对象版本和区间；分片存入现有缓存目录/R2 缓存前缀下的 `site-sync/<任务ID>/`。
- 按文件核对整体摘要、大小、格式签名与 MIME；来源登记缺少摘要时仍校验各分片与稳定的对象版本，并计算接收文件摘要。
- 只创建不存在的目标文件；同名同内容可复用，同名不同内容明确停止，**不覆盖正在使用的文件**。
- 复用现有字段规范、领域校验、外键/正文引用检查、权限保护和数据库批事务：一次提交所选非媒体删除、所选新增/更新与任务提交标志，不更新未选中的普通业务记录。
- 所选内容引用的已有媒体也会校验和补齐；外链只同步登记，不把外站内容下载进本站。
- 内容提交成功后，逐个重新检查待删除媒体的最新状态和全部引用。无引用才转入回收站，再复用既有手动永久删除方法删除真实文件和登记，不等待回收站保留期。
- 最后分批清理分片。数据库提交、媒体永久删除和任务完成均沿用后台操作日志。

例如删除 a、改用 b：先取得 b → 更新教师/新闻指向 b → 再检查 a → 删除 a。若此时 a 又被其他条目引用，则保留 a，任务显示原因；可解除引用后重试或取消剩余步骤。

## 中断和失败

阶段、分片偏移、媒体版本、已提交标志和删除计划存于现有同步内部表；普通网络错误停止当前步骤，不自动扩大范围、不清空数据。数据库变更和提交标志处于同一事务，提交成功后即使响应丢失，也不会重复导入。文件删除复用既有持久化清理意图，可处理“文件已经删除但响应丢失”的重试。

提交前，任一站的业务数据发生变化，就拒绝使用旧预览继续提交；应取消并重新生成。提交后出现新的媒体引用或媒体版本变化，也会停止删除并保留文件。取消不能撤销已完成的内容或已经完成的永久删除。

若暂存文件在取消前被其他操作改写，会保留并提示到“媒体目录核对”检查。极少数进程崩溃窗口（对象已创建但拥有者版本尚未落库）也可能留下未登记文件；重试可核对复用，取消不会猜测归属后误删，使用已有目录核对工具处理。

## 范围与资源边界

- 沿用 v120 的支持模块、秘密字段排除、单例设置匹配和预览上限。
- 每次实际执行最多 **500 个变更项**，媒体最多100个、单文件20MiB、总计24MiB（包括相关的已有媒体）。超限提示分批选择，不截断清单。
- 最终字段校验沿用恢复工具的单表900KiB及整体4MiB限制。
- 网络传输按256KiB分片；最终文件校验及 Local/R2 写入沿用现有有界整文件接口，最多载入一个20MiB文件，不宣称全过程仅占256KiB内存。
- 已有媒体 UID 对应的对象路径/存储类型切换，以及同名不同内容，不做原位强制覆盖。建议按日常媒体库流程上传为新媒体条目，再修改引用并删除旧媒体。
- 本版没有独立“全库文件一致性扫描”：未选内容且无关联的媒体不逐一读取，仍可使用媒体目录核对功能检查。
- 当前由后台页面推动短批次；关闭页面会暂停，进度可恢复，不是后台守护任务。

## 部署和数据库

**v0.15.121 与 v0.15.120 表结构完全一致**，无需重建或迁移数据库，不新增依赖和端口。状态保存在现有 `sync_tasks.state` 中。两站更新源码/完整包并重启或重新部署即可，连接配置和共享密钥保留。

从 v119 直接升级：先按 [v120 说明](site-sync-v120.md) 补齐三张内部表；本地执行原虚拟环境的 `python -m backend.cli migrate`，已有 D1 使用构建变量 `TEACHER_D1_INIT=upgrade`。不要使用 reset 清空数据。新站正常初始化。

## 复用与验证

共用 SQLite/D1、Local/R2 适配器；共用 `data_restore.prepare/references` 和管理员事务权限保护；共用 `MediaAudit.purge_plan/execute_purge` 及媒体引用锁；界面沿用 v120 模板、后台请求封装和表格样式。只在引用预检方法增加可选的“本次删除记录”参数，默认调用行为保持不变。

测试覆盖真实独立本地数据库/文件与 HTTP 路由、依赖顺序、仅选中内容变更、来源不变、失败重试、取消清理、同名冲突保护、分片版本变化、提交响应丢失、新引用阻止删除、引用媒体补齐及前端确认/暂停/继续。Worker 构建与入口回归用于检查兼容性；未在用户真实 Cloudflare 账号、R2 或公网 VPS 上完成部署验收。

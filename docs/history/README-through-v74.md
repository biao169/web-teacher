## 翻译批次管理

后台“翻译”列表可进入批量扫描与翻译，选择公开模块、扫描、执行下一批或连续运行，并可暂停和重试失败。重新打开页面只读取进度，点击继续才推进；关闭页面后不再发起后续请求。人工译文受保护，停用不删除正文。功能说明见`docs/features/translation-batch.md`。

## 启动入口

- `start-windows.cmd`：启动主站；首次没有账号时提示设置管理员。
- `start-with-transfer.cmd`：兼容入口；与普通启动一样只启动主站，快传访问 `/transfer/`。
- `add-demo-data.cmd`：使用已有管理员登录，显式添加新版113条示例；重复执行保留用户修改。
- `deploy/vps/start.sh`：Linux主站启动入口，复用同一Python启动器。

Windows可通过环境变量`TEACHER_PYTHON`指定现有`python.exe`。启动器使用`requirements-vps.lock`准备虚拟环境，依赖未变时复用；新环境只安装预编译包，不在VPS编译依赖。

## 更新已有网站

1. 停止原启动窗口中的本站进程，将新版本解压到新文件夹。
2. 保持原`TEACHER_CONFIG`或显式数据库、媒体、缓存环境变量不变；使用启动器默认数据位置时，保持`TEACHER_LAUNCHER_HOME`和运行账号不变。
3. 若虚拟环境位于旧源码目录内，可将`TEACHER_VENV`指向它的完整路径继续复用；之后仍需保留该环境目录。也可使用源码外的独立环境。
4. 从0.15.37—0.15.65升级本版，有旧快传时先按 `docs/features/transfer-integration-v66.md` 执行导入；无旧快传时在新文件夹运行`upgrade-data.cmd`（Linux沿用原配置运行`python -m backend.cli migrate`），完成快照和字段迁移后再运行相同启动脚本。保留数据库、账号、人工译文、媒体和快传任务，不执行示例脚本，也不执行`reset-data.cmd`。

`reset-data.cmd`只用于明确需要清空数据库的操作，与普通更新无关。本版主站新增快传表；提供已知旧结构的显式新增字段/表迁移，旧快传文件导入另有受保护工具。旧0.15.37同时补齐媒体原文件名字段，未知结构拒绝修改，不自动删除。

## 数据地址与部署

将`storage.example.toml`复制到源码目录之外，填写路径，并将`TEACHER_CONFIG`设为该文件的绝对路径。相对路径以配置文件所在目录为基准。数据库、缓存、媒体和保存联合启动密钥的数据根目录均位于源码外部；两个服务可各自配置。

环境变量优先于TOML。主站使用`TEACHER_DATABASE_PATH`、`TEACHER_CACHE_DIR`、`TEACHER_MEDIA_DIR`，快传使用对应`TRANSFER_*`；详细字段见`docs/features/storage.md`。`python -m backend.cli doctor`显示生效地址。切换路径不会自动移动旧数据。

Cloudflare主站和快传独立使用Python Workers、D1、R2；准备工具仅整理代码、模板、SQL和绑定配置，见`deploy/cloudflare/README.md`及`transfer/README.md`。`initialize.sql`仅用于空数据库，更新已有D1时不要重新初始化。

功能入口见`docs/README.md`；当前边界以`docs/features`为准。源码包另含测试、计划及验收证据；精简运行包使用同一业务代码和功能文档。真实Windows、500MB VPS及Cloudflare生产部署仍需在目标环境验收，本地测试不能替代这些结果。

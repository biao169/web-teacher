# 安全清理 v0.15.104

## 范围

复用集成快传的应用生命周期、现有数据库批处理、媒体文件清单与版本校验、跨进程运行锁。主站维护与快传到期清理独立运行，关闭快传自动清理不会关闭主站维护；不增加后台路由或授权范围。当前针对 Windows/Linux 本地存储，Worker/R2 不运行本地维护。

会话的失效时间或撤销时间超过 30 天，且最后更新时间也超过 30 天时才可删除。限流记录必须已过期且不处于有效封禁期。报告必须存在有效 state.json，标识匹配，expires 已过去 24 小时。正在持有扫描租约的报告跳过；执行前抢占相同的短租约，删除时校验对象版本。报告状态最后删除，确保中断后仍能判断资格和重试。

临时文件仅处理缓存目录中 metadata/v2 和 media-audit 已知命名规则下的原子写入 .tmp 文件，最后修改超过 24 小时；不按扩展名扫描媒体原文件或任意其他目录。损坏报告、未知文件、符号链接和无法确认资格的内容不自动删除。快传已结束任务中的临时块继续复用原有快传清理，不扩大删除范围。

## 执行与预览

自动默认间隔 900 秒；有积压时 1 秒后继续下一批，失败时 60 秒后重试。每类数据库记录最多 200 条，缓存访问最多 20 个目录条目。数据库在同一删除语句重新检查资格；命令行与自动任务通过同一进程锁串行化。无法取得锁时本次不执行，稍后重试。

cleanup-preview 不删除业务数据、文件，也不推进扫描游标；为协调并发可能创建维护目录/锁文件。结果是下一批候选数量，不是全量统计，report_files 包含需要等其他页清理后才能删除的状态文件。cleanup-run 执行一批；backend.cli 支持 --batches 1～100，preview 始终只有一批。不要将预览视为固定删除清单：执行时会重新核对当前状态。

扫描游标与最近批次结果分别保存 data/maintenance/cursor.json、status.json，固定覆盖。结果含类别计数、最多 20 项错误类别/异常类型及是否还有候选，不包含原文、令牌或密码；运行日志也记录批次失败。计数是本次执行值，不是历史累计。文件删除后目录偏移变化可能使部分项留到下一轮，属于安全的延迟回收。状态读取使用 cleanup-status。损坏状态文件可由管理员停服后核对并删除这两个维护 JSON，下一次从头扫描。

Windows 使用 deploy/windows/cleanup.cmd；Linux 使用 tweb cleanup-preview / cleanup-run / cleanup-status。同样可用项目 Python 解释器执行 python -m backend.cli 对应命令，并设置与网站一致的 TEACHER_CONFIG。命令行依赖操作系统目录/数据库权限，未开放匿名网络入口。后台集中管理页面在第四步实现。

数据库结构保持不变。此步不清理历史操作记录、快传计量明细，不自动清空媒体回收站，不执行 VACUUM。会话/报告等期限暂为上述固定默认值，后台策略配置按第四步接入。

验证：两组回归分别 43 项和 34 项通过（含重复用例）；另实际执行 CLI 预览、执行与状态查询成功。覆盖新旧会话、限流分批、报告状态最后删除、活动租约、未知文件、符号链接、删除失败重试及快传/部署回归。未进行 Windows 实机长期运行验收。

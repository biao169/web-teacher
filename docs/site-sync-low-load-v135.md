# v0.15.135：统一低负载同步——第三步

## 本步完成

预览读取和版本复核完成后，按以下阶段推进。浏览器与后台调度复用相同代码，Windows、Ubuntu/Debian、Worker 使用同一低负载策略。

| 阶段 | 每批工作 | 断点 |
| --- | --- | --- |
| 内容入库时建立索引 | 复用当前内容页，登记外键目标和媒体UID映射 | 与快照和读取游标同一事务 |
| 引用分析 | 1条记录，沿用原字段与富文本解析规则 | 站点、模块、记录ID |
| 差异比较 | 1对来源/目标记录，每侧只规范化一次 | 模块、记录ID |
| 删除依赖 | 最多5个指向待删除项的引用 | 反向引用ID，已完成依赖列表 |
| 发布预览 | 数据库汇总已完成的精简差异项 | ready状态与汇总原子提交 |

普通内容页仍最多5条/64KiB，长记录单独读取并受200,000字节上限约束。正文引用沿用当前每种格式最多10个不同媒体的解析规则；单条分析输入最多20项，兼容译文HTML/Markdown两种格式，普通事务仍不超过25条SQL。

索引、引用边、分析结果均保存在现有`sync_task_items`中，使用保留的`@lookup:`、`@refs:`、`@back:`、`@diff:`模块前缀。仅业务快照进入实际执行；这些临时分析行不作为网站条目同步。清理任务时通过现有外键级联清理，无需新增表、索引或迁移。

查找引用改为主键精确查询；检查删除改为反向引用范围查询。同模块续读明确使用`record_uid > 游标`，跨模块单独查找下一模块，避免复合游标与IN条件组合导致重复扫描当前模块。SQLite查询计划测试确认使用主键范围。

## 正确性和恢复

- 中间结果和游标仍由既有事务/CAS保存，继续使用任务租约。
- SQL事务失败时，分析结果与游标一起回滚；提交成功但响应丢失时，下次从数据库保存的位置继续，不重复累计依赖。
- 删除旧媒体仍依赖相关教师、新闻等条目先更新/删除；来源仍引用、引用缺失或无法解析时，保留原阻止规则。
- 推送仍需接收站人工审批，最新提案规则不变；已有后台授权仍复用同一预览流程。
- 每次推进更小，因此请求次数和总耗时可能增加。浏览器仍间隔1秒，后台仍按原调度周期推进。

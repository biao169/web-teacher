# v0.15.158：第四步，日志管控

在本轮 v0.15.157 上完成；同步模块独立目录、社交数值、原始图标和多域名支持均保留。无需数据库结构迁移。

## 使用入口

系统管理员进入后台 → 系统管理 → 日志管控（`/admin/log-maintenance`）。Windows、Ubuntu/Debian、Worker 共用页面及权限、CSRF、策略版本校验。可保存策略、预览下一批、确认删除一批。普通用户不能访问。

本地原有“运行维护”仍保留资源占用统计和完整清理功能。两个入口共享策略和自动数据库清理开关；旧策略自动补默认条数目标，不直接重写其版本。保存期间如有其他管理员修改，要求刷新后重试。

## 默认策略与边界

| 对象 | 默认限制 | 本步行为 |
|---|---|---|
| 本地运行日志 | 10 MiB/份、5份归档、14天 | 含当前文件最多60 MiB；调低容量立即收缩旧文件，保留尾部；归档到期删除，长期无更新的当前文件到期清空 |
| 数据库操作日志 | 180天、目标20,000条 | 超期或超过条数目标时删除较早记录；本地每批最多200条，Worker最多20条 |
| 同步任务历史 | 沿用现有专用清理 | 不改变活动任务、断点和待审批任务的保护规则 |
| 快传历史及计量 | 沿用现有专用清理 | 不修改当前日/周/月配额保护和载荷清理规则 |

数据库条数是逐批收敛目标，不能保证高写入速度下始终低于目标。缩短期限或降低目标可能删除较早但尚未到期的操作日志。预览仅表示下一批，不是全库总量；如有需要，请先使用已有操作日志导出功能保存记录。

数据库删除释放的页可被后续写入复用，但 SQLite/D1 文件或配额占用不一定立即缩小。本步不在网页请求或自动任务中执行 VACUUM，不触及教师业务内容、留言或媒体原文件。

## 本地部署

使用项目自带的 `deploy.shared.service` 启动入口。现有 Windows 启动器和 Linux 服务已使用此入口。直接自行运行 uvicorn 会绕开文件日志轮转管理。

日志位于配置的数据目录下 `logs/service.log` 及 `.1` 到 `.20` 的受管归档。只处理这些精确文件名，不递归删除其他日志；符号链接不会被当作可清理文件。超限收缩使用64 KiB复制缓冲区，不把整个文件载入内存。后台保存立即应用当前进程的日志参数；原运行维护后台任务也会周期读取策略。

`tweb logs` 查看运行日志；原 `tweb cleanup-preview`、`cleanup-run`、`cleanup-status` 沿用。管理器现有“清空运行日志”操作仍要求确认并停止服务；本步不删除任何真实部署日志，也不修改共享 nginx/Caddy 或系统 journal 全局策略。

关闭自动数据库清理不关闭本地文件日志轮转。既有重复警告合并、单条长度限制、最多128个去重键和访问日志关闭机制继续保留。

## Worker

日志维护使用已有每分钟 Cron 的独立槽：十分钟周期内，第0槽清理快传，第1槽清理同步历史，第2槽清理操作日志，其余7槽推进同步。每次调用只执行一种维护工作，不把操作日志清理附加到同步请求中。实际自动清理需要部署已有 Cron 触发器。

操作日志清理只访问 D1，最多返回20个ID，不读取日志详情、不构建网站资源对象、不扫描R2、不使用本地文件线程。初始化前跳过，自动清理关闭时跳过。条数判断最多跳过配置范围内的100,000个主键位置；大量积压按后续定时调用或手动批次逐步清理。

空闲/禁用等跳过的 Cron 不再输出成功/跳过控制台记录；错误仍保留诊断。Worker 的平台控制台/请求日志由 Cloudflare 管理，本地 MiB/份数/天数设置不控制平台保留期限或收费；应在平台配置相应保留与采样。本步不连接或更改线上账户。

- `frontend/admin/templates/native-log-maintenance.html`：日志策略与手动预览、执行。
- `frontend/admin/templates/native-maintenance.html`：原维护页面增加条数目标。
- `deploy/cloudflare/runtime/maintenance.py`、`entrypoint.py`：独立日志槽与空闲日志减量。
- `tests/test_log_control_v158.py`、`site_sync/tests/worker/test_sync_schedule.py`：新增与更新测试。

# v0.15.149：第三步，自动同步最新500项

## 规则

新建的自动拉取任务，只处理已选模块中最新的最多500个候选。按两端记录的 updated_at 倒序合并，同一模块和UID去重；相同时间按站内id、模块和站点侧稳定决胜。不是每个模块各500项。删除记录已经不在来源数据库中，因此删除候选以接收端保留记录的更新时间排序，而不是实际删除时间；无需新增删除日志。

每个分页只返回一条元数据（编号、名称截取160字符、更新时间和排序id），不返回正文。分模块维护两端的游标和至多一个待合并摘要，达到500项即停止，不先下载全部条目。为完成合并可能读取少量前瞻摘要；同一记录在两端各有一条摘要，不能把500项理解为总共只调用500次接口。

候选“最新”按两端现有记录时间定义。更早内容不会在后续周期自动翻页补齐；每轮重新读取最新状态，同内容仍可能覆盖。需要完整同步或更早内容时使用手动预览。

## 删除与依赖

- 候选未出现在来源的最新窗口，不表示已删除。接收端候选必须按具体编号查询对端，只有确实不存在才列为删除。
- 未入选的旧记录不修改、不删除。对端永久删除的媒体不要求本站跟随删除；本站独有媒体不进入自动删除扫描。
- 继续复用准备阶段的依赖核对、媒体引用保护和逐条提交，不省略授权与签名。
- 最多500项指主动候选。必要依赖另逐条追加，自动任务总数上限2000；超出时暂停且保留检查点。手动同步/推送仍保持原500项选择限制。
- 预览不保证冻结业务数据库；扫描期间修改可能留待下一轮，实际准备和提交仍沿用原来的版本与引用检查。

## 恢复与兼容

游标、待核对记录和候选存入原 sync_tasks / sync_task_items；失败不会从头建立新任务。重新开始保留“最新500项”模式。旧的正在执行/预览任务保持原逻辑，新建自动轮次才启用本次模式。

两端均需更新到v149。hello新增 latest_preview 能力标记；未支持时给出升级提示，不回退到全量预览。签名协议和任务格式号不变。表结构、数据库文件、媒体文件不变，无需初始化、迁移或重置数据库。

## CPU与内存边界

每步最多一个摘要查询、一个去重查询或一次对端记录存在性核对，然后保存检查点；不会一次读取500条正文。Worker与Ubuntu/Debian使用相同轻量候选流程。教师、学生、论文、项目、专利、课程、新闻读取复用已有 updated_at/id 索引；新查询不使用OFFSET。

LIMIT仅限制返回行数，不保证SQL内部仅访问一行。其他模块若缺少匹配索引，数据库仍可能排序或扫描；本版未新增索引，避免引入数据库部署变更。已有权限检查、任务锁和检查点读写仍有SQL开销。此次减少Python处理、网络数据和候选数量，但不能保证消除所有1101/1102。媒体仍为64KiB，第四步再协商更小分片。

## 更新方式

基于v148覆盖增量包中的相对路径，提交到原部署分支并重新部署两端；VPS更新源码后重启服务。保持Worker每分钟Cron配置。旧任务可完成后等待新周期，或通过原界面取消/重新开始；不删除数据库或媒体。多实例部署脚本与自定义教师模板未被改动。

# 09 后台对象编辑统一设计

## 结论

后台共有 19 个正式功能，但“功能数”“可编辑业务模块数”“编辑器实现文件数”不是同一概念：

- 19 个功能中，控制台是聚合看板，操作日志是只读审计，导入导出是数据传输工作区。
- 其余 16 个功能具有可保存的对象编辑能力。
- 源码通过 7 个编辑器实现复用这些能力；账号权限内含用户、角色两种对象，新闻还额外提供富文本编辑入口。
- 操作日志虽然不可写，也复用统一壳展示详情区块和返回动作。

因此，不能按左侧菜单数量复制 18 份结构相同的 Vue 文件。统一组件加业务定义能够保证字段、权限和生命周期差异继续存在，同时让导航、保存、返回和危险动作保持一致。

## 根因与修复

统一编辑壳位于 `app/components/admin/shared/AdminEditorShell.vue`。Nuxt 自动组件命名会包含目录前缀，生成名称为 `AdminSharedAdminEditorShell`；原调用方使用 `<AdminEditorShell>` 且没有导入，导致模板无法挂载统一壳，其内部的 `admin-form-nav` 与 `admin-editor-footer` 也不会出现。

当前 7 个调用文件均采用以下显式导入：

```ts
import AdminEditorShell from '../shared/AdminEditorShell.vue'
```

显式导入在当前文件建立稳定的 `AdminEditorShell` 绑定，不再依赖 Nuxt 自动命名规则。`tests/backend/admin-editor-layout.test.mjs` 会逐文件检查显式导入，防止再次退化为只有模板标签、没有真实组件绑定。

## 统一编辑壳契约

`AdminEditorShell` 接收标题、说明、分区、写权限、脏状态、保存状态、通用 busy 状态和按钮禁用状态，并发出 `back`、`save`、`save-and-return` 三种事件。

顶部 `admin-form-nav` 根据 `sections` 渲染区块按钮；点击后滚动到对应表单区域，滚动和窗口尺寸变化时同步当前区块。底部 `admin-editor-footer` 固定提供记录状态区和动作区：

- 所有详情都有“返回列表”。
- 可写对象有“保存”和“保存并返回”，并支持 `Ctrl/Cmd + S`。
- 业务危险动作通过 `danger-actions` 插槽注入，不把所有对象强行解释为物理删除。
- 未保存内容由共用 `useAdminEditorLifecycle` 保护，覆盖 route leave、同页 route update 和 beforeunload。
- 保存、删除及确认框共用互斥锁；写入时字段、返回、危险操作与 Ctrl/Cmd+S 统一不可操作。
- 稳定 UID 和并发版本继续由原业务服务校验；显式加载最新版本才丢弃输入并更新基线。

## URL 与面包屑

通用内容对象使用独立文件路由。原本在同一列表页内切换的资源、媒体、翻译、账号/角色和日志详情，使用查询参数记录当前对象。打开、保存新记录、返回、删除/回收/失效，以及浏览器前进后退都会同步或恢复参数。

`shared/admin/registry.ts` 根据当前完整路径生成面包屑。管理后台、功能分组和功能列表项是可点击的 `NuxtLink`；最后一级表示当前页，使用 `aria-current="page"` 而不创建指向自身的冗余链接。

至少执行：

## 2026-09-06 字段标题与批量控件收敛

`AdminFormItem` 统一原生字段标签和必填星号；`AdminCheckedFormItem` 在此基础上提供查重。内容模块与资源模块的批量操作共用 `AdminFieldRenderer`，旧 `content/FieldControl.vue` 已删除。详见 [本步修改与验收记录](15_后台统一字段标题与批量编辑验收.md)，其中视觉验收尚未完成，不能将静态检查视为全页面验收。

## 2026-09-06 编辑生命周期收敛

同页工作区以 URL 作为编辑对象状态来源，守卫通过后才切换/关闭表单；保存并返回只有一个完成事件。内容对象使用实例 key 防止跨 UID 残留；异步详情采用最新请求约束。权限矩阵共享未保存提醒并保留独立并发令牌；媒体和译文的冲突恢复要求明确重载。业务危险动作仍分别为删除、回收、失效、禁用，日志保持只读。详见 [6/7 验收说明](20_后台编辑生命周期统一与验收.md)。

# v0.15.182：修复部署包启动检查误判

## 原因

v181的SNAPSHOT-CHECK禁止generated_resources进入启动导入图。但前后台模块预加载会经backend.app.native.catalog导入generated_resources.NATIVE，它是打包生成的静态字段定义。源码环境不存在generated_resources.py时，catalog回退读取本地JSON，因此之前仅对源码执行的启动检查没有发现误判。用户日志中的失败是部署检查断言，不是1101/1102，也不表示Cron正在执行。

## 修复

允许静态生成资源预加载；在导入前用AST校验generated_resources.py只包含五个预期名称的字面量赋值，拒绝函数调用、导入、重复/未知名称及缺失资源。继续阻止运行时资源工厂、同步执行入口提前导入，以及随机数、数据库连接、网络、子进程、文件写入等启动副作用。

保留v181网页应用与路由预构建。同步调度、五分钟Cron、内部三小时巡检与断点协议没有改变。

## 验证

36项检查通过。新增测试生成完整部署目录（含真实generated_resources.py、运行时代码、快传源码及配置），从独立进程和部署目录执行与pipeline相同参数的SNAPSHOT-CHECK；同时验证往生成文件插入可执行代码时仍会拒绝。其他检查覆盖启动副作用、预构建网页登录及匿名隔离、巡检与部署配置。

未执行真实Cloudflare上传、Wrangler打包或线上CPU测量。本修复针对已报告的部署检查失败，不保证消除所有运行时1101/1102。

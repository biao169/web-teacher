# v0.15.173：同步执行按需初始化（第三步）

Worker Cron 继续先进行 SQL 回执核对，最新候选仍走 172 专用只读路径。
其余同步阶段改用 `worker_runtime.sync_resources`，复用已有 SQL 连接、后台授权和完整同步调度器。
不再调用网站资源工厂；不构造模板渲染器、网站认证配置、密码派生器、元数据和翻译客户端。

| 阶段 | 初始化需求 |
| --- | --- |
| 内容读取、准备、校验、普通内容写入 | SQL、原后台授权、共享审计函数 |
| 媒体下载、目标媒体校验 | 实际首次访问时创建 media_store 或 cache_store |
| 提交和清理 | 按原执行逻辑访问需要的存储；没有存储访问则不创建 |

存储按单次授权上下文缓存，返回真实 R2Store，保留库存查询、分块与版本检查。
首次需要存储时通过原 Settings 校验绑定名称、前缀及缓存/媒体隔离，兼容自定义绑定和前缀。
SQL-only 阶段不因未使用的 R2 绑定缺失而提前失败；需要该绑定的步骤仍报错。

背景上下文通过服务资源自身的标记选择仅审计服务；HTTP 管理端和本地完整资源上下文继续构造原 Content/Media。
Content.audit 和同步专用服务使用同一个 audit_log.audit，SQL、字段、事务位置和审计内容不变。

保留原用户/角色/权限/对端/任务绑定复核、调度锁、执行锁、事务检查点、人工审批及回执恢复。
没有增加总任务时长限制，也没有把诊断或资源创建计作有效业务进展。
阶段变化后仍由原调度器选择业务步骤，因此不维护第二套写入或恢复算法。

诊断沿用 resource_modules、schedule_modules、resource_factory 阶段键，界面文案改为同步专用资源。
历史版本对应字段曾代表通用工厂；定位旧回执时应结合部署版本。

## 验证范围和限制

新增按需存储、自定义绑定、前缀冲突、共享审计、实际 Cron 绕过网站工厂测试。
复用长期恢复场景，在窄资源上下文中注入 1101、1102 和 BaseException 强制中断，核对媒体字节、内容结果、单次审计及临时块清理。
覆盖最新候选路径和初始化诊断回归，以及现有跨平台、持久化、提交丢回执和授权错误测试。
这些是 D1/R2 适配器替身测试，不是线上 Cloudflare CPU/内存验收。
快照仍可能预加载部分业务模块定义；本步降低每轮对象创建和依赖配置工作，不宣称消除所有导入或保证不再出现资源异常。

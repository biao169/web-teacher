# 网站前台要求与说明

## 一、前台页面范围

前台是公开访问者看到的网站主体，应覆盖首页、团队、教师详情、研究方向、论文、精选论文、项目、专利与软件著作、学生、动态、动态详情、课程、联系页面和登录/注册入口。

前台页面应以学术展示为核心，强调内容可读性、检索效率和移动端可访问性，而不是营销式页面。所有页面应从数据库读取内容，并通过统一布局输出导航、页头、主体和页脚。

## 二、显示方式

前台应遵循以下展示规则：

- 只公开展示 `visibility=public` 的内容；登录用户可按角色扩展可见范围。
- 首页展示站点设置、重点成员、精选论文、精选动态和主要导航入口。
- 团队页面展示启用且公开的教师/团队成员，并支持头像缺失时的文字头像回退。
- 教师详情页展示个人简介、联系方式、教育经历、科研经历、招生说明和学术链接；联系方式应受 `contact_visibility` 控制。
- 论文页面支持搜索、筛选、分页、引用格式切换、作者高亮、PDF 链接和精选论文入口。
- 项目页面展示项目来源、基金/计划、承担角色、负责人、成员、周期、状态、经费和简介；`project_role` 应与项目来源处于同一信息层级，但样式应克制。
- 专利页面展示类型、国家、申请/授权信息、发明人、权利人、法律状态和证书入口。
- 学生页面应按可配置分类展示，支持不同培养层次、年级、方向和状态。
- 动态页面支持分类筛选、封面图、发布时间和详情页；正文格式可以是纯文本、HTML 或 Markdown。
- 课程页面展示学期、对象、简介、材料和参考资料；材料链接受 `material_visibility` 控制。
- 联系页面提供基础留言表单，并使用隐藏 honeypot 字段降低垃圾提交。

## 三、响应方式

前台应支持桌面端、平板和手机浏览：

- 导航在窄屏下应保持可触达，不遮挡正文。
- 卡片、列表、筛选栏和分页控件应在移动端自然换行。
- 图片、头像、封面和 PDF 入口应设置稳定尺寸，避免加载时造成布局跳动。
- 字体大小不应依赖视口宽度无限缩放，正文应优先保证可读性。
- 列表页应支持懒加载或分页，避免移动端一次渲染过多项目。
- 锚点跳转需要考虑固定页头和吸顶导航高度，避免标题被遮挡。

## 四、语言与翻译

前台需要支持中文和英文模式：

- 已有人工英文字段时优先显示人工维护内容，如 `site_name_en`、`name_en`、`bio_en`、`title_en`、`label_en`。
- 没有人工英文字段时，可读取 `translation_cache` 中当前有效的译文。
- 翻译缓存失效或缺失时，应回退显示原文，不能造成页面空白。
- 新增前台展示字段时，必须纳入翻译需求扫描和缓存指纹，避免英文模式下长期显示中文。
- URL 中的语言参数和导航链接应保持一致，页面切换语言后仍指向对应内容。

## 五、媒体显示

前台媒体引用应统一使用 object key：

- `storage_kind=static` 的默认资源从打包静态目录读取。
- `storage_kind=local` 的上传资源在 Ubuntu/Debian 中从本地 `media` 目录读取。
- `storage_kind=r2` 的上传资源在 Cloudflare Worker 中从 R2 读取。
- `storage_kind=external` 的资源可直接使用外部 URL。
- 头像和图片缺失时必须有可读回退，不应显示破损图标。
- PDF 展示需兼容浏览器内嵌预览和下载策略，后台全局设置决定是否允许下载和是否加水印说明。

## 六、性能与缓存

前台性能要求：

- 公开页面及公开数据接口可根据内容特征使用浏览器缓存和边缘缓存，并允许合理的短期 stale 响应。
- 常用静态资源使用长期缓存和版本号失效策略。
- 列表页默认分批加载，数据接口只返回当前分页、游标或当前视图所需的数据。
- 筛选项和媒体统计可使用短 TTL 缓存。
- Cloudflare Worker 中应减少 D1 请求次数，优先批量读取后在内存中过滤和渲染。
- 前台可以依赖现代 JavaScript 运行环境，重点保证交互响应速度、加载状态、错误反馈和移动端体验。

## 七、安全与可访问性

- 所有用户输入输出到 HTML 前必须转义或经过受限 HTML 清洗。
- 外部链接应使用安全链接处理。
- 表单提交应遵守同源校验和必要的会话检查。
- 页面应设置安全响应头。
- 图片应包含 alt 文本，按钮和交互控件应有可理解标签。
- 公开留言接口应限制垃圾提交和异常输入。

## 八、运行效率与响应速度补充

- 前台公开页面应尽量成为“少查询页面”。首页、列表页和详情页所需数据应通过聚合 API 或批量查询统一准备，避免每个组件独立访问数据库。
- Cloudflare Worker 环境中 D1 请求延迟和 CPU 预算都更敏感，应避免循环中访问 D1；能一次读取的表不要拆成多次读取。
- 列表数据应由后端查询层执行分页、游标或数量限制；前端可根据体验需要采用分页、无限滚动或虚拟列表呈现。
- 首页、论文、项目、专利、团队等高访问区域的静态资源和可缓存公开数据应优先使用边缘缓存；内容保存、导入、批量更新、翻译更新和媒体变更后精确清理相关缓存。
- 筛选项的 distinct values 应使用短 TTL 缓存，不能每次打开列表页都全表扫描。
- 翻译缓存读取应面向“本页需要展示的字段”批量准备，避免每条记录、每个字段单独查一次翻译。
- 图片应使用缩略图、固定比例、懒加载、解码异步和缺失回退；首屏关键头像或封面可以 eager，非首屏媒体默认 lazy。
- CSS/JS 文件应通过版本号控制缓存失效，避免为了实时更新而关闭静态资源缓存。
- PDF、长正文、富文本内容和大图片不应进入首页首屏的同步重负载路径；需要时使用链接、摘要、预览或延迟加载。
- 前台交互脚本应按页面元素存在与否初始化，避免所有页面都执行不相关模块逻辑。
- 搜索和筛选参数应保持简单、可缓存、可分享；复杂实时搜索不应阻塞首屏渲染；筛选时浏览器URL的参数也要支持中英文转换。
- 对英文模式页面，不能每次请求实时调用网络翻译接口，必须读取 `translation_cache` 或人工英文字段。

## 九、源码目录规划

前台源码必须与后台源码完全分离。这里的“完全分离”包括 HTML 渲染、页面模板、CSS、JS、交互组件、页面初始化逻辑和业务模块文件。前台不得直接复用后台的模板、表单组件、CSS 类体系或 JS 初始化函数；后台也不得直接复用前台页面组件。

允许复用的范围仅限非 UI 基础能力，例如表模型、Repository 协议、安全函数、媒体 key 处理、翻译缓存读取、导入导出和平台适配接口。只要函数会输出 HTML、绑定前端交互、定义视觉样式或处理页面布局，就应归入前台或后台自己的目录，不能放入跨前后台共享 UI 文件。

建议前台目录结构如下：

```text
app/
  core/
    models.py                    # 表模型、字段定义、可见性枚举
    repository.py                # Repository 协议、Query 对象和通用查询行为
    security.py                  # 转义、会话、密码、链接、HTML 清洗等非 UI 安全函数
    media.py                     # 媒体 key、媒体 URL、存储类型、头像回退数据处理
    i18n.py                      # 语言切换、翻译缓存读取、字典加载
    cache.py                     # HTML 缓存、筛选缓存、统计缓存等非 UI 缓存逻辑
    frontend/
      routes.py                  # 前台路由分发
      layout.py                  # 仅前台使用的页面 layout、页头、导航、页脚
      components.py              # 仅前台使用的卡片、徽章、分页、筛选栏、空状态
      home.py                    # 首页 HTML 渲染
      team.py                    # 团队列表和教师详情 HTML 渲染
      research.py                # 研究方向 HTML 渲染
      publications.py            # 论文列表、精选论文、引用显示 HTML 渲染
      projects.py                # 项目列表和项目卡片 HTML 渲染
      patents.py                 # 专利/软著列表 HTML 渲染
      students.py                # 学生列表和学生分类 HTML 渲染
      news.py                    # 动态列表和详情 HTML 渲染
      courses.py                 # 课程列表 HTML 渲染
      contact.py                 # 联系表单 HTML 渲染和提交处理
      seo.py                     # 前台 SEO、站点地图、robots、开放图谱信息
  adapters/
    ubuntu/
      main.py                    # Ubuntu/Debian ASGI 入口
      db.py                      # SQLite Repository
    cloudflare_repository.py     # D1 数据加载与写入
src/
  worker.py                      # Cloudflare Worker 入口，只做平台请求、绑定和响应转换
public/
  assets/
    frontend/
      base.css                   # 仅前台基础变量、排版、链接、页面容器
      layout.css                 # 仅前台页头、导航、页脚、主体布局
      components.css             # 仅前台卡片、徽章、筛选、分页、空状态
      home.css                   # 首页样式
      team.css                   # 团队/教师详情样式
      publications.css           # 论文列表、引用和 PDF 入口样式
      projects.css               # 项目列表和承担角色样式
      patents.css                # 专利/软著样式
      students.css               # 学生列表和分类样式
      news.css                   # 动态列表和详情样式
      courses.css                # 课程样式
      contact.css                # 联系页样式
      main.js                    # 仅前台通用初始化入口
      navigation.js              # 前台导航、移动端菜单、锚点
      lazy-list.js               # 前台列表懒加载
      citations.js               # 论文引用格式切换和作者高亮
      media-preview.js           # 前台媒体预览和头像缺失回退
      modules/
        home.js                  # 首页交互
        team.js                  # 团队页交互
        publications.js          # 论文页交互
        projects.js              # 项目页交互
        patents.js               # 专利页交互
        students.js              # 学生页交互
        news.js                  # 动态页交互
        courses.js               # 课程页交互
migrations/
  0001_initial.sql               # 新库基础结构
  0002_xxx.sql                   # 后续增量迁移
```

前台拆分标准：

- 前台 HTML 只能由 `app/core/frontend/` 下的文件生成；不得从 `app/core/admin/` 引入后台 layout、表单或表格组件。
- 前台 CSS 只能放在 `public/assets/frontend/` 下；不得依赖 `admin.css`、后台模块 CSS 或后台专用类名。
- 前台 JS 只能放在 `public/assets/frontend/` 下；不得依赖 `admin.js`、媒体库后台脚本、翻译后台脚本或后台表单脚本。
- 论文、项目、专利、课程、教师、学生、动态等功能应各自拥有独立的渲染文件、样式文件和可选交互文件。
- 前台通用组件只服务前台，例如卡片、徽章、分页、筛选栏、列表空状态和前台导航；它们不得被后台引用。
- 前台页面按需加载模块 CSS/JS，高访问页面优先加载最小必要资源。
- 前台与后台可以共享 `models.py`、`repository.py`、`security.py`、`media.py`、`i18n.py`、`cache.py` 等非 UI 能力，但这些共享文件不得输出前后台可见 HTML 片段。
- 拆分期间可保留兼容入口，但兼容入口只能转发到前台目录，不应继续增加新的前后台混合代码。

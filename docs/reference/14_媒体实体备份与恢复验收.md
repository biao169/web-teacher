# 14 媒体实体备份与恢复验收

## 目标与范围

后台“导入与导出”现在可以把 `media_assets` 元数据和受管理的媒体实体组成同一个加密 `.acms` 快照。该能力覆盖 Node 本地文件存储与 Cloudflare R2，并复用现有 `MediaStore` 接口，不增加数据库表或迁移。

安全 JSON 和 CSV 仍只用于数据交换，不携带媒体实体。只有选择 `media_assets` 的加密备份才允许启用“同时备份受管理的媒体实体文件”。

## 快照结构

加密前的备份信封可包含 `mediaObjects`：

| 字段 | 用途 |
| --- | --- |
| `objectKey` | 规范化后的受管理对象键，不暴露本地绝对路径 |
| `storageKind` | 来源存储类型，仅允许 `local` 或 `r2` |
| `mimeType` | 经媒体安全规则规范化的 MIME |
| `size` | 原始字节数，并与 `media_assets.size` 对照 |
| `checksumSha256` | 实体内容 SHA-256，用于防篡改和复用判断 |
| `data` | Base64URL 编码的实体内容，整体再由 `.acms` 加密 |

整个信封参与预检摘要计算，因此预检后替换任何元数据、实体内容或实体清单都会触发摘要不匹配。

## 导出规则

1. 只读取 `storage_kind` 为 `local` 或 `r2` 的对象；`external` 与 `static` 只保留元数据。
2. 读取前后核对对象头、ETag、大小与校验和，读取期间对象发生变化则停止导出。
3. 在线快照最多 100 个实体、原始媒体总量最多 24 MiB；超限时整体拒绝，不生成残缺下载。
4. Provider 密钥、密码哈希和媒体文件只存在于 AES-256-GCM 加密备份中。

## 恢复和一致性

恢复顺序为“解密与预检 → 校验媒体目录 → 写入或复用实体 → 原子提交数据库、审计和缓存版本”。

- 目标存储已有同键、同大小、同摘要对象时直接复用，不重复写入。
- 同键对象内容不一致时返回冲突，不覆盖现有文件。
- 来源存储在目标运行时不可用时，允许 Local 与 R2 之间迁移，并更新本次恢复记录的 `storage_kind`。
- 数据库提交或提交前任一步骤失败时，按逆序删除本次新创建的实体；恢复前已存在并复用的对象绝不删除。
- 若补偿删除本身失败，服务返回明确的 `MEDIA_BACKUP_ROLLBACK_FAILED`，不能把部分成功伪装为完整恢复。
- 替换恢复不清理快照外的孤立存储对象；大规模镜像、垃圾回收和版本保留仍由部署层负责。

## 后台反馈

导出结果显示实体文件数量与字节数；恢复预检显示受管理对象数、已包含数、缺失数及总大小；提交结果显示已恢复、创建和复用数量。仅有媒体元数据时仍给出明确警告。

## 自动验收

`scripts/release/admin-production-regression.mjs` 在隔离生产服务器中执行真实文件往返：上传 PNG、导出加密快照、预检目录、物理删除文件、确认缺失、应用备份、深度检查恢复后大小与摘要一致。

核心命令：

```sh
node --test tests/backend/transfer-management-completeness.test.mjs
pnpm run typecheck
pnpm run typecheck:core
pnpm run build:ubuntu
pnpm run test:production:http
```

生产结果写入 `reports/final-regression/production-http.json`。

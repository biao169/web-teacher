# v0.15.177：媒体合并和校验的恢复边界（第三步）

## 修改内容

本版基于 v176，补齐媒体下载后的合并、完整摘要校验、发布及取消清理的断点。保留原媒体分片协议、完整 SHA-256 值、授权与租约、来源版本检查、同名冲突和人工审批规则。不新增数据库表，不要求对端为这一步同步升级；v176 长字段协议仍需两端具备其能力。

### 合并意图与回执丢失

每个合并组最多四个输入对象。执行前先保存输入键、长度、版本及预期输出键，下一轮才启动原生流式合并。输入版本在读取前及读取过程中检查。输出独占创建，不覆盖已存在结果。

如果输出已存在而合并游标未推进，进入恢复比对：绑定输出版本，每轮有界读取并与对应输入区间逐字节比较。全部一致后推进合并游标，不重新上传已经完成的对象。仅大小相同不构成复用依据；输入或输出版本变化、内容不符会停止准备，保留断点供检查。

### 可持久化 SHA-256

新增仅用于文件完整性校验的 SHA-256 状态格式，保存八个链接状态字、已处理字节数和不足64字节的尾部。每轮只读取一个区间，计算后将摘要状态与偏移一起保存。请求被终止、重启或回执丢失后，重新加载数据库中的摘要状态继续，不从文件开头重算。协议签名/HMAC 继续使用原 hashlib 实现。

Worker 默认校验预算为每轮4096字节，资源降速后为1024、256字节；本地默认65536字节。已保存的较小预算不会在同一文件中主动放大。最终补齐 SHA-256 填充是独立轮次，仍核对完整摘要与来源登记值。摘要状态绑定对象版本，不能把变更后的文件接到旧摘要后面。

媒体类型签名检查、摘要初始化、分段计算、最终摘要确认分别保存状态。暂存完整文件和已有目标文件都使用分段校验。旧版已经保存 assembled_version / sha256 的任务可以衔接新发布逻辑。

### 发布与安全清理

目标不存在时先保存发布意图，后续一轮才独占复制。正常完成时保存实际输出版本和 created_version；存在同名目标时先分段核对完整摘要，一致后复用，不同则拒绝覆盖。

如果发布已经完成，但创建回执及进度未能保存，不能仅凭文件内容一致认定所有权。恢复会校验并复用，但不补造 created_version。此后取消任务时，未登记且归属不明的目标会保留并记入 retained_files，避免误删其他操作创建的文件。已确认由本任务创建且版本未变化、尚未登记的文件，沿用原受控删除规则。

本地流式合并改用对应目标的固定专用临时名 .sync-compose.tmp：同一操作重试前清理上一轮残留，取消清理时也移除这些已知临时文件。不会扫描或批量删除其他临时文件。旧版本遗留的随机临时文件不在本版自动回收范围。

## 状态和进展

检查点版本更新为5，加入合并恢复比对位置、摘要角色与偏移、媒体子阶段和发布意图等小型证据；完整摘要状态及文件内容不进入监控投影。旧任务先建立新检查点基线，原统计保留。保存校验区间即视为有效进展，不必等整个文件校验结束。

任务列表新增“媒体恢复步骤”：合并分组、核对已完成合并、校验暂存文件、校验目标文件、发布文件。校验阶段显示已完成字节数和每轮预算，避免下载字节数不变时误以为没有推进。

## 明确边界

- 原生流式合并组和最终文件复制仍是单次对象存储操作，不是可在任意字节恢复的 multipart 上传。完成但回执丢失时可以核对复用；尚未形成完整对象的操作仍需重试该组/该次复制。
- 不依赖强制终止时 catch/finally 必然执行，继续使用既有冷却、租约到期核对和后台重试机制；没有任务总时长上限。
- 分段 SHA-256 用有限的 Python 计算换取可跨请求恢复，可能降低吞吐量。默认预算不是实际 Worker CPU 测量值；若仍超限，原资源降速机制可缩小校验量。大文件后台推进可能耗时较长。
- 每文件20MiB、总媒体24MiB等既有上限不变；媒体下载分块布局不在中途改变。未添加三小时巡检事件。
- 尚未部署到真实 Cloudflare，不能保证所有1101/1102均被消除。

## 验证

新增专项40项通过、1项跳过（本地组合不适用 Worker 降速用例）。覆盖空串/abc/百万字符已知摘要、随机数据和任意断点对照 hashlib；合并回执丢失、错误等长输出、输入或校验对象版本变化、摘要检查点回执丢失、发布回执丢失、同名冲突、旧任务续跑、取消保留未知归属文件、清理确认创建的文件和本地临时残留。使用真实 SQLite、生产 D1 适配器及模拟 R2 流绑定。

媒体协议、不同分片大小、局部任务补丁、进度恢复、轻量HTTP、最小Cron启动等相关回归通过；5项前端检查通过，媒体预算文案调整后专项再次通过。两条旧测试分别收窄为禁止完整业务聚合、以及缺失文件修复后显式继续；未为通过测试而放宽生产恢复规则。

部署后应观察媒体已校验字节数持续增加、有效进展更新，并验证最终文件内容及审批后的业务写入。三小时巡检与调度健康诊断属于后续步骤。

# v0.15.180：第一步，网页依赖预加载

网页访问优先，同步允许后台慢速推进。以v173为基线，纠正v175把整组HTTP定义转移到首次网页请求的启动路径。

## 改动

- snapshot.py重新预加载http_snapshot中的前后台定义，包括网页框架、渲染器、安全、同步及快传的纯定义；恢复ASGI与路由模块在入口顶层加载。
- 首次构建网页应用不再负责导入整组HTTP依赖。网站应用及路由实例仍按首次请求创建并缓存；本步骤未把应用对象、会话或存储绑定放进快照。
- 预加载模块定义不会发起同步任务。五分钟Cron、内部三小时巡检、授权、分轮预检查、长字段/媒体断点和冷却流程保持v179逻辑；不在首页请求中补跑同步。
- 启动门禁改为要求网页定义已加载，同时继续阻止启动期随机数、时钟调用、数据库连接、网络连接、进程启动、文件写入及运行时JS桥接导入；仍禁止提前创建网站应用和导入任务执行入口。

## 验证与限制

57项启动、网页/快传隔离、同步接口、Cron预检查及恢复巡检测试通过；另1项首次中英文网页、真实登录、后台访问测试通过，验证应用仅构建一次且未推进同步。

本地启动检查使用SDK替身，验证项目导入副作用，不能证明Cloudflare SDK及部署快照在免费Worker上不会超限。未线上部署或测量CPU/内存。此次移除首次请求的一组导入开销，不保证完全消除1101/1102；应用构建、路由注册、模板渲染仍有开销，后续应根据真实入口阶段日志处理。

部署后应核对0.15.180，分别检查首次首页、后台登录及后续Cron到达。网页和Cron仍共享Worker及快照，预加载会增加快照内容，不代表平台提供网页请求的绝对资源优先级。

# v0.15.176：长字段分片协议（第二步）

## 适用范围与兼容

在 v175 最小 Cron 启动路径基础上，新增按需准备子任务的来源字段分片。覆盖最新候选自动拉取、手动准备拉取、推送准备，以及接收方审批时的来源读取。业务审批、权限、版本冲突和逐条写入规则保持不变。

hello 新增 field_chunks: 1，主协议号和任务格式保持兼容。新任务保存双方协商结果；旧任务若没有该字段，在来源读取阶段单独进行一次能力检查。对端没有该能力时沿用原 record 读取，因此两端都升级后才能获得分片收益。协商为旧协议的任务不会中途偷偷切换，重新准备可以重新协商。无需数据库迁移。

## 协议与处理步骤

1. record-fields 返回来源 UID、updated_at、短字段值及长字段清单。超过 256 字节的 JSON 编码字段值进入分片，UID 始终内联。长度和短字段投影在 SQL 中计算，不把整条来源正文先送进 Python 再切片。
2. record-field 绑定表、来源 UID、updated_at、字段、字符偏移和请求大小。SQL 对 json_quote 后的字段值使用 substr；返回文本片段、下个位置和 SHA-256。沿用原 HMAC 签名、请求 nonce 和站点身份检查。
3. 接收端验证版本、字段、偏移、片长、摘要和累计字节数，每轮最多取一片。追加暂存内容与推进游标共享同一个任务 CAS 事务，回执丢失后从已提交位置继续，过期执行者不能重复追加。
4. 单字段接收完成后另用一轮在 SQL 校验 JSON 类型和完整长度，再解码合入暂存记录。接收完成前只存在辅助数据，不作为完整来源记录参与业务准备。
5. 所有字段完成后再次核对来源版本，发布任务内部来源快照，并原子删除两条辅助暂存数据。下一轮衔接原来的目标读取、规范化及引用检查。

字符位置针对 JSON 编码后的 Unicode 字符，不是原字段字节位置或浏览器 UTF-16 下标。转义符可跨片，先按原序拼接，再解码；中文、emoji、换行、反斜杠、引号、NUL 及字段内嵌 JSON 文本保持原值。

## 大小与恢复

Worker 单片默认最多 512 个 JSON 字符，本地默认最多 2048；服务端也按自身上限收紧。Worker 资源降速后可降至 256、128。接收端即使运行在本地，遇到对端 1101/1102 或未确认步骤后也可缩小请求。当前字段接收过程不会主动放大已缩小的请求宽度。两个新接口的网络响应读取上限为 32 KiB。

沿用现有冷却、租约、后台续跑及无总时长限制设计，不假设强制终止时一定能执行 catch/finally。已提交片段会保留；失败请求不能把游标提前。来源版本改变或数据校验失败会停止当前准备，不混合新旧版本，也不覆盖业务内容。未完成暂存随原任务历史清理流程回收，不在出错时删除有效断点。

检查点版本更新为 4，新增字段阶段、字段序号和偏移作为有效业务进展证据，片段保存即使整条尚未准备完成也会被计入进展。旧检查点先建立新基线，既有统计保留。状态接口只投影小型游标，不读取长文本；任务列表新增字段名称、已保存字符位置、总字符数与子步骤。

## 保留的边界

- 单条记录 JSON 编码后仍限制为 200000 字节；没有放开任意大 JSON/长文本。
- 规范化、引用分析和实际业务写入仍会处理完整单条记录。字段暂存追加及合入在 SQL 内进行，也存在数据库端读写开销。
- 保留的旧式详细全量预览路径没有切换至字段协议；新协议应用于按需准备路径。
- 未修改媒体合并/校验的断点粒度，未添加三小时巡检事件，未改变分钟 Cron 频率和 v175 预检查拆轮规则。
- 本地测试及 D1 绑定模拟不等于真实 Cloudflare 配额验收，尚未部署到线上，不能保证消除所有 1101/1102。

## 验证

26 项分片专项和适配测试通过：签名 HTTP 分片、Unicode/转义/NUL、回执丢失、并发旧游标回滚、来源修改/删除、无效参数与片段、暂存损坏、资源降片、远端 1102 后本地接收端缩片、旧对端兼容、旧任务协商、推送审批以及本地/Worker 三种适配组合。6 项前端测试通过，包含分片进度文案、状态重试及 Cron 预检查显示。

相关按需准备、检查点、恢复、轻量 HTTP、Cron 和启动依赖回归亦通过。一个旧回执丢失测试改为先验证冷却期，再到期续跑；生产重试规则未因此放宽。

建议部署后用一条包含长正文的候选验证：字段偏移持续增加、有效进展更新、整条准备完成，再由原审批流程提交。两端配套升级，原任务可保留；来源内容已变化的任务仍需重新准备。

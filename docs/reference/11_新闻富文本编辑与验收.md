# 11 新闻富文本编辑与验收

## 使用流程

新闻普通编辑区的“正文格式”旁提供富文本设计器按钮。选择“安全富文本”也可以进入设计器。

- 新建新闻：填写标题、Slug 等必填项，点击“保存草稿并打开富文本”。先创建非公开草稿，再打开其设计器；不会直接发布。
- 已有新闻且未修改：点击“打开富文本设计器”，直接打开，不重复保存。
- 已有新闻且有修改：点击“保存并打开富文本”，使用现有字段校验和乐观并发校验保存；成功后打开。失败时停留原编辑区并保留输入。
- 设计器“保存”写入正文并切换为 HTML 格式；“保存并返回”恢复新闻信息编辑区及原列表筛选、分页。列表直接进入设计器时，返回原列表。
- 放弃修改返回只询问一次。人工输入的返回地址仅允许新闻列表工作区；删除新闻后移除返回地址中的对象编辑参数。

已有 HTML 通过安全富文本接口保存，普通对象写接口仍拒绝任意 HTML。没有新闻编辑权限时，富文本写入入口不可用。

新闻对象和富文本接口不再使用会误拦截文本节点尖括号的通用 XSS 字符串过滤器，改由既有的新闻字段验证、富文本节点/链接/媒体白名单与输出转义处理内容。身份认证、CSRF、请求大小限制仍执行。浏览器验收同时验证普通接口拒绝直接写入 HTML、富文本接口拒绝 `javascript:` 链接。

## 原文与格式

纯文本通过结构化文本节点导入，保留换行、空行和尖括号。Markdown 在本阶段按原文导入，保留语法符号并给出提示，不宣称完成 Markdown 语法转换。只有保存成功后才修改原正文格式。

读取 HTML 时，同时识别服务器保存的 `rich-align-*` 类和编辑器使用的内联对齐样式。图片读取 `data-object-key` 和 `rich-image-*` 布局类。编辑区和弹窗预览恢复有序、无序列表标记。

编辑状态通过结构化文档与初始化基线比较，不使用两套 HTML 序列化结果作比较。因此，打开已有富文本不会凭空产生未保存修改。保存不重新初始化编辑器，保留光标和撤销历史。上传期间暂停保存，避免未完成图片插入就提交正文。

## 文件与职责

| 文件 | 方法或职责 |
| --- | --- |
| `app/components/admin/complete/AdminCompleteRecordEditor.vue` | `openNewsRichText()` 根据新建/修改状态启动保存或交接；`updateNewsFormat()` 将 HTML 选择转交设计器；`save()` 复用原保存逻辑，交接时不触发竞争性的列表刷新。 |
| `app/components/admin/complete/AdminCompleteResourceWorkspace.vue` | `openNewsRichText()` 携带当前记录及列表查询参数跳转；`openNewsRichTextFromList()` 保留列表直接进入时的位置。 |
| `app/components/admin/complete/AdminCompleteNewsEditor.vue` | 接收编辑器初始化文档作为基线；保存成功更新基线；安全处理返回、删除及未保存提示。 |
| `app/components/admin/complete/AdminCompleteRichTextEditor.client.vue` | `createEditor()` 按原格式初始化并报告加载失败；`publishDocument()` 输出结构化文档；不因保存回执重置编辑器。 |
| `app/components/admin/complete/news-rich-text-extensions.ts` | `newsRichTextExtensions()` 返回编辑器扩展；对齐和图片扩展兼容存储格式，避免重复注册链接、下划线扩展。仅后台按需加载。 |
| `app/admin/news-rich-text.ts` | `newsEditorInitialContent()` 安全导入原文；`newsEditorReturnPath()` 限制返回目标；`newsListReturnPath()` 删除对象编辑参数并保留筛选条件。 |
| `tests/unit/news-rich-text.spec.ts` | 真实 Tiptap 解析器与服务端渲染器的重复保存测试，包括对齐、嵌套列表、链接、文本样式及五种图片布局。 |
| `tests/unit/news-editor-workflow.spec.ts` | 挂载普通编辑器，验证草稿、修改保存、无权访问、已有 HTML 及保存失败流程；网络与周边组件使用替身。 |
| `tests/production/workflows.spec.ts` | `news rich-text step1` 使用隔离数据库和真实生产页面，验证草稿创建、格式操作、保存重开、返回参数及保存状态。 |

## 验收命令

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm exec vitest run tests/unit/news-rich-text.spec.ts tests/unit/news-editor-workflow.spec.ts
node --test tests/complete-admin/*.test.mjs tests/backend/admin-editor-layout.test.mjs
pnpm build:ubuntu
```

生产浏览器验收通过现有隔离运行器执行，`CMS_E2E_GREP` 设置为 `news rich-text step1`。可用 `CMS_E2E_BROWSER` 选择 Chromium 或 Firefox，`CMS_E2E_PROJECT` 限定具体项目，例如 `firefox-production`。运行器生成临时测试数据库和随机凭证，不使用本地业务数据库。

`happy-dom` 仅用于开发测试，不进入生产依赖。基础设计文档 01—04、业务数据库结构不变。

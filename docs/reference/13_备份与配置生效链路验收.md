# 13 备份与配置生效链路验收

## 完成范围

本阶段闭合“配置保存或恢复 → 数据库提交 → 缓存失效 → 运行服务重新读取 → 后台刷新”的完整链路，覆盖网站设置、全局设置和导航配置。未修改数据库表结构，也未修改 `01`—`04` 设计基线文档。

## 生效规则

| 场景 | 服务端处理 | 客户端处理 |
| --- | --- | --- |
| 普通配置保存 | 配置写入、审计日志和规范缓存 generation 递增在同一事务提交 | 后续请求读取新配置 |
| 配置备份恢复 | 恢复记录、审计和全部受影响缓存标签在同一事务提交 | 显示生效范围，确认后刷新当前后台 |
| 账号或权限恢复 | 原子恢复后撤销全部活动 Session | 清理本地会话并跳转登录页 |
| 媒体元数据恢复 | 默认仅恢复 `media_assets` 数据并失效媒体缓存 | 预检明确提示实体文件未包含 |
| 媒体完整快照恢复 | 加密备份可同时恢复 Local/R2 实体，随后原子提交元数据 | 展示包含、缺失、创建和复用数量 |

## 缓存标签

恢复不再写入 `site-settings`、`global-settings` 等无人订阅的旧标签，而是复用 `server/cache/invalidation-map.ts`：

- `site_settings`：`public:site`、`public:layout`、`public:home`、`public:seo`。
- `global_settings`：`public:settings`、`public:home`、`public:media-policy`。
- `navigation_items`：`public:navigation`、`public:layout`、`public:home`。
- 其他恢复表同样按业务模块生成 `module:*` 与对应公开数据标签。

## 跨平台有效配置顺序

全局设置运行时按 `updated_at DESC, id DESC` 读取。恢复时不能依赖数据库内部 `id`，因为 SQLite 与 D1 或不同实例之间的自增值没有可迁移语义。

恢复服务现在先读取目标表最大更新时间，再根据备份记录原始更新时间排序，为恢复记录分配连续、晚于目标库旧记录的新时间。由此保证：

1. 备份内原本最新的配置恢复后仍然最新；
2. 合并模式下备份配置能够成为当前运行配置；
3. 稳定 UID 仍是冲突匹配依据，数据库内部 id 不参与跨平台身份判断。

## 备份边界

- `.acms` 使用 AES-256-GCM 与 PBKDF2-SHA-256 加密，可包含 Provider 密钥和密码哈希等数据库敏感字段。
- 安全 JSON/CSV 排除敏感字段，适合交换和分析，不代替完整加密备份。
- 在线加密备份在选择 `media_assets` 后，可显式选择携带受管理的 Local/R2 实体文件；默认仍只导出媒体元数据。
- 单个在线快照最多携带 100 个受管理对象、原始媒体总量最多 24 MiB；更大媒体库仍应使用部署层对象存储快照。
- `external` 远程链接和 `static` 部署静态资源不会复制进在线快照；部署环境变量、运行平台密钥及构建产物也不在备份范围内。
- 跨平台恢复优先沿用原存储类型；目标平台缺少对应 Local/R2 存储时，会写入已配置的另一种受管理存储并同步改写恢复元数据的 `storage_kind`。
- 替换模式只替换数据库所选表及快照内对象，不主动删除目标存储中的孤立文件，避免误删其他快照或尚未建档的对象。
- 恢复继续采用摘要锁定、固定表白名单、Schema 版本检查、行数限制和单事务回滚。

## 自动验收

生产 HTTP 回归在隔离数据库中执行以下真实流程：

1. 导出包含全部 `global_settings` 记录的加密备份；
2. 修改当前配置的注册开关、上传上限和 DeepL 密钥；
3. 通过媒体统计接口确认保存值已经进入运行策略；
4. 解密并预检备份，核对配置生效范围；
5. 按稳定 UID 合并恢复；
6. 核对普通字段和敏感字段恢复结果；
7. 核对 `public:settings`、`public:media-policy` 等规范缓存标签；
8. 再次读取媒体策略，确认恢复配置已经运行生效。
9. 导出包含 Local 媒体实体的加密快照并完成目录校验；
10. 物理删除该媒体文件，确认深度检查报告缺失；
11. 合并恢复快照，确认文件被重新创建且摘要、大小及媒体元数据再次一致。

验收命令：

```sh
pnpm run typecheck
pnpm run typecheck:core
node --test tests/backend/transfer-management-completeness.test.mjs
node --test tests/complete-admin/*.test.mjs
pnpm run build:ubuntu
pnpm run test:production:http
```

生产回归报告位于 `reports/final-regression/production-http.json`。

# v0.15.179：免费方案与三小时恢复巡检

部署错误10072表示账号 Cron 条数额度不足，与执行错误1101/1102不同。降低频率本身不会减少条数，本版同时将两条触发器合并为一条。

## 调度设计

- 仅部署 `*/5 * * * *`，每天约288次定时调用，占一个 Cron 名额。网站访问、手动操作等调用另计。
- 三小时巡检保留在该入口内部：按事件时间的 UTC 三小时窗口判断，第一次收到事件或进入新窗口即运行巡检；错过整点后，下次到达的事件补做。
- 巡检只做一个恢复步骤，遵守授权、暂停、冷却及租约，不与普通维护串成重任务。同窗口其余事件继续普通维护；不因巡检失败把其他轮次都挡住。
- 巡检开始即保存窗口和独立心跳，结束保存回执。重复或延迟的旧窗口事件不重复启动周期巡检；业务并发仍由原有持久化调度锁控制。
- 普通维护使用五分钟逻辑槽位轮换：每十个槽位含一次快传清理、一次历史清理、八次同步机会；到期巡检替代当轮维护。
- 页面按五分钟调度计算等待，超过15分钟未到达才提示异常或尝试已有页面辅助唤醒。巡检仍显示独立最近到达、结果和错误。

这不是独立容灾：若唯一 Cron 完全不再到达，或共同入口持续启动失败，内部三小时巡检也无法执行。降低触发频率也不能保证避免单次CPU超限；原有最小启动、预检查、长字段及媒体断点恢复继续保留。正常同步会比每分钟调度更慢，预检查与业务仍分轮执行。

## 部署

用本版重新执行标准部署，确认本 Worker 仅有 `*/5 * * * *`。无需开启额外巡检变量；生成配置固定携带内部巡检与300秒间隔标记，旧的构建变量 `TEACHER_RECOVERY_CRON=true` 不会再增加第二条触发器。勿只修改控制台运行时标记来切换频率。

不修改其他 Worker。若账号没有本站可替换的原有触发器且已无空位，仍须先释放一个无用触发器名额。此前 schedules API 失败不代表代码等步骤已全部回滚，应以完整部署成功、页面版本和触发配置核对为准。本次未执行线上部署。

# 网站后台要求与说明

## 一、后台目标

后台是网站长期维护的核心界面，应让非开发用户也能安全维护科研主页内容。后台既要保留通用表管理能力，也要为高频模块提供定制化编辑界面，减少字段理解成本和录入错误。

后台必须优先保证：数据不丢失、权限明确、保存可靠、导入导出可恢复、跨平台行为一致。

## 二、后台模块范围

后台应包含以下模块：

- 网站设置：维护站点名称、首页标题、SEO、Logo、首页展示数量和页脚文本。
- 全局设置：维护注册、留言、上传限制、媒体回收站、PDF、翻译服务、元数据服务和辅助输入缓存时长。
- 导航与按钮：维护顶部导航、首页入口、页脚和后台侧栏导航。
- 教师与团队：维护人员身份、照片、简介、联系方式、学术链接、经历、招生和展示排序。
- 研究方向：维护研究方向名称、英文名、说明和可见性。
- 论文：维护论文元数据、引用格式、作者高亮、PDF、展示标签和收录信息。
- 项目：维护来源、基金、编号、承担角色、负责人、成员、时间、状态、经费和简介。
- 专利与软件著作：维护申请、授权、发明人、权利人、法律状态和证书。
- 学生：维护学生分类、培养层次、方向、状态、头像、获奖和毕业去向。
- 学生分类显示：维护学生分组标签、匹配关键词和排序。
- 动态：维护新闻分类、封面、正文、关联对象、发布时间和是否精选。
- 课程：维护课程学期、对象、简介、大纲、课件和参考资料。
- 留言：查看、筛选、处理和归档联系留言。
- 媒体库：上传、选择、检索、裁剪、回收、恢复和导出媒体资源。
- 翻译缓存：扫描前台翻译需求、批量自动翻译、人工修订和删除失效缓存。
- 操作日志：记录后台关键操作，便于追踪变更。
- 权限与账号：维护角色、用户和模块权限。

## 三、通用表管理标准

后台列表页应提供：

- 搜索框，基于模型中声明的 search 字段检索。
- 模块化筛选，如可见性、状态、分类、年份、类型等。
- 排序选项，常见为默认排序、更新时间、年份、状态、名称等。
- 分页显示，避免一次性渲染过多记录。
- 批量选择和批量更新功能。
- 删除保护，仅允许在明确支持删除的业务表中删除。
- 操作后返回原筛选/分页位置。
- 操作日志记录保存、批量更新、删除、导入、扫描、翻译等行为。

## 四、编辑界面标准

高频业务表应使用分组式编辑界面：

- 每个字段按业务语义分到清晰模块，例如基本信息、人员、时间状态、展示排序。
- 编辑区导航使用吸顶锚点导航，点击锚点时应正确抵消顶部导航高度。
- 右侧编辑区与浏览器滚动一致，不应出现内部滚动条和浏览器滚动条同时竞争的问题。
- 字段下方应提供简短帮助文本，说明填写格式、前台影响和注意事项。
- 必填字段应清晰标识。
- 文本域高度应符合内容类型，成员、简介、正文等多行字段使用 textarea。
- `sort_order` 可在新建时默认使用记录 ID，也允许人工覆盖。
- 所有保存应通过统一业务 API 和服务层完成；前端使用异步请求并提供提交中、成功、失败和重复提交防护状态。

## 五、辅助输入功能

后台应支持历史值辅助输入，降低重复录入成本：

- 论文：期刊/会议、年份、类型、作者角色、通讯作者、收录、展示标签等。
- 项目：项目来源、基金/计划、承担角色、负责人、成员、状态等。
- 专利：国家、类型、发明人、权利人、法律状态等。
- 学生：培养层次、分类、年级、方向、状态等。
- 动态：分类、关联对象等。
- 课程：学期、授课对象等。

辅助输入应使用后台 API 返回去重后的历史值，并通过短 TTL 缓存减少数据库扫描。多值字段应支持按逗号、分号、换行等分隔符识别当前 token 后插入建议。

## 六、媒体选择工具

媒体字段应统一使用媒体选择工具：

- 支持从媒体库搜索并选择已有资源。
- 支持直接上传新文件并回填当前字段。
- 支持图片裁剪、缩放、输出尺寸设置。
- 支持头像、Logo、封面、证书、PDF、课程材料等不同用途。
- 媒体 key 应写入业务字段，不能写入本机绝对路径。
- 上传后必须同步写入 `media_assets` 记录。
- Cloudflare Worker 中媒体写入 R2；Ubuntu/Debian 中媒体写入本地 `media` 目录。
- 删除媒体应优先进入回收站，定期按保留天数清理。

## 七、富文本工具

动态正文应支持富文本编辑：

- 支持标题、正文、引用、代码块、加粗、斜体、下划线、删除线、列表、对齐、链接、图片插入和图片浮动。
- 富文本编辑器应与动态编辑状态同步，最终通过统一业务 API 保存。
- 粘贴或保存 HTML 前需要清洗危险标签和事件属性。
- 正文格式字段 `content_format` 应准确标记 plain、html 或 markdown。
- 工具应支持弹窗编辑和独立编辑窗口两种形态，但不得破坏当前编辑状态和未保存数据。

## 八、翻译缓存

翻译缓存是英文前台稳定显示的关键能力：

- 后台应能扫描前台实际使用的字段，生成翻译需求。
- 自动翻译应支持批量、并发、超时和任务状态恢复。
- 翻译记录应保存源文本、目标语言、译文、来源字段、服务商、状态和错误信息。
- 人工修订的译文应优先于自动译文，并应能标记为当前有效。
- 当源文本变化时，应通过 hash 或引用关系判断旧译文是否失效。
- 新增前台展示字段必须加入翻译字段清单和缓存指纹。
- Worker 场景下翻译任务要控制批量大小和超时时间，避免 CPU 时间过长。

## 九、媒体库管理

媒体库页面应提供：

- 列表视图，展示预览、标题、object key、分类、MIME、大小、存储位置和状态。
- 搜索和筛选，支持按标题、key、分类和 MIME 查找。
- 批量选择、批量移动到回收站、恢复、删除和导出使用中媒体。
- 缺失文件检测和使用位置查询。
- 媒体统计缓存，避免每次打开后台都扫描文件系统或 R2。
- 对 PDF、图片、文档等不同类型使用合适预览方式。

## 十、权限与安全

后台必须要求登录和权限校验：

- 首次初始化应能创建默认管理员或引导配置。
- 角色通过 `auth_roles` 定义层级和可见范围。
- 模块权限通过 `auth_permissions` 控制查看、创建、编辑、删除和导出。
- 用户账号通过 `auth_users` 保存密码哈希、状态、角色和最后登录时间。
- 所有会改变数据或系统状态的后台请求都必须校验登录状态、模块权限，并执行与所采用认证方式匹配的跨站请求防护。
- 密码和会话签名必须依赖强随机密钥，生产环境不得使用弱默认值。
- 后台输入输出必须转义或清洗，富文本只允许安全 HTML 子集。

## 十一、导入导出与迁移

后台和工具链应支持：

- 导出 JSON、CSV、Excel 或整站备份包。
- 导入时按 `uid` 合并或恢复记录，避免重复创建同一内容。
- SQLite 和 D1 共用迁移 SQL，新增字段应提供幂等迁移说明。
- Ubuntu 更新脚本不得删除已有数据库和媒体，除非用户明确选择 reset 或 replace。
- Cloudflare 部署不应把资源创建放入普通构建命令；D1/R2 初始化应通过 Wrangler 或专门脚本执行。

## 十二、性能要求

后台应适配低 CPU 和边缘运行场景：

- 列表页必须分页，避免一次渲染全表。
- 筛选候选值、媒体统计、翻译需求应设置短期缓存。
- 保存、批量更新、翻译和媒体处理完成后应精确清理相关缓存。
- Worker 中应减少 D1 调用次数，避免每个组件单独查询数据库。
- JS 增强功能应懒加载或按页面元素存在与否初始化。
- 管理页面 CSS/JS 应与前台共用一致的基础布局规则，避免重复实现造成行为分歧。

## 十三、运行效率与响应速度补充

从后台效率角度看，当前说明还需要补充以下要求：

- 后台列表页必须坚持分页、筛选和排序在服务端完成，不能把全表数据一次性输出到浏览器后再前端过滤。
- 批量操作、导入导出、翻译扫描、媒体扫描等重任务应明确边界，避免在普通页面加载时自动执行。
- 辅助输入 API 应使用去重结果缓存，并允许按模块设置 TTL；保存相关模块数据后应清理对应建议缓存。
- 媒体库统计、缺失文件检查、使用位置扫描属于高成本操作，应缓存结果或改为手动触发。
- 翻译任务应拆分为可恢复的小批次，后台页面轮询任务状态，不应让单次 HTTP 请求长期占用 Worker CPU。
- 后台首页和侧栏计数应限制查询数量，避免每次打开后台都对所有大表做昂贵统计。
- 编辑页只加载当前记录必需的数据；下拉建议、媒体库、富文本编辑器、翻译进度等增强功能按需请求。
- 富文本编辑器和媒体选择器应延迟初始化，只有页面存在对应按钮或字段时才绑定事件和构造弹窗 DOM。
- 上传、裁剪和 PDF 相关处理应限制文件大小、尺寸和格式，避免在 Worker 或低配 VPS 上做过重计算。
- 后台 CSS/JS 应减少重复选择器和重复初始化逻辑；吸顶导航、弹窗、批量选择等通用行为应统一实现。
- 保存、删除、导入、翻译和媒体变更后应统一调用缓存失效函数，避免旧 HTML、旧筛选项或旧翻译继续显示。
- 后台接口响应应优先返回必要字段，媒体列表、建议列表和翻译状态接口不应返回整表完整记录。

## 十四、源码目录规划

后台源码必须与前台源码完全分离。后台的 HTML、CSS、JS、编辑组件、弹窗组件、表格组件、表单组件、权限提示和批量操作交互，都应放在后台专属目录中。后台不得复用前台页面模板、前台卡片组件、前台 CSS 文件或前台 JS 初始化入口。

允许与前台共享的只应是非 UI 基础能力，例如表模型、Repository 协议、安全函数、媒体 key 处理、翻译缓存、导入导出、迁移工具和平台适配接口。后台专用 UI 即使与前台视觉相似，也应在后台目录中单独实现，避免前后台样式和交互互相污染。

建议后台目录结构如下：

```text

  core/

      table_base.py                 # 后台通用列表、筛选、排序、分页、批量选择、删除按钮
      form_base.py                  # 后台通用表单控件、字段帮助、媒体字段控件
      permissions.py                # 权限判断、角色默认值、模块访问控制
      suggestions.py                # 后台辅助输入 API 与缓存
      import_export.py              # 后台导入导出、整站备份、恢复
      site_settings.py              # 网站设置管理
      global_settings.py            # 全局设置管理
      navigation.py                 # 导航管理
      profiles.py                   # 教师与团队管理
      research_interests.py         # 研究方向管理
      publications.py               # 论文管理、元数据、引用格式
      projects.py                   # 项目管理、承担角色、人员和经费
      patents.py                    # 专利/软著管理

      media_library.py              # 媒体库、回收站、使用位置、扫描

    ubuntu/
      main.py                       # ASGI 入口、静态/媒体文件响应
      db.py                         # SQLite Repository 实现
    cloudflare_repository.py        # D1 Repository 加载和写入
src/
  worker.py                         # Worker 请求入口、D1/R2/Assets 绑定、平台响应转换
public/
  assets/
    admin/
      base.css                      # 仅后台基础变量、排版、按钮、表单基线
      layout.css                    # 后台侧栏、顶部区域、主内容布局
      table.css                     # 后台表格、筛选、分页、批量工具条
      form.css                      # 后台编辑表单、字段帮助、吸顶编辑导航
      dashboard.css                 # 后台首页和模块概览

      students.css                  # 学生后台样式
      news.css                      # 动态后台样式
      courses.css                   # 课程后台样式
      messages.css                  # 留言后台样式
      media-library.css             # 媒体库样式
      media-picker.css              # 媒体选择器、上传、裁剪弹窗样式

      auth.css                      # 账号、角色、权限后台样式
      main.js                       # 仅后台通用初始化入口
      table.js                      # 后台表格、批量选择、批量更新

        profiles.js                 # 教师编辑增强

        students.js                 # 学生编辑增强
```

后台拆分标准：

- 后台 HTML 只能由 `app/core/admin/` 下的文件生成；不得从 `app/core/frontend/` 引入前台 layout、卡片或筛选组件。
- 后台 CSS 只能放在 `public/assets/admin/` 下；不得依赖前台 CSS、前台页面类名或前台视觉组件。
- 后台 JS 只能放在 `public/assets/admin/` 下；不得依赖前台 `main.js`、前台懒加载、前台导航或前台页面模块。
- 后台通用表格和表单能力只能在后台目录内复用，业务模块不得复制一套相似逻辑。
- 每个后台业务模块负责自己的列表列定义、筛选项、排序选项、编辑分组、字段说明和保存前规范化。
- 媒体选择器、富文本编辑器、翻译任务这类后台复杂组件应独立成后台专属文件，通过数据属性挂载到需要的后台页面。
- 平台相关逻辑只放在 adapter 或 Worker 入口中，后台业务模块不能直接依赖本地文件路径、R2 对象或 D1 API。
- JS/CSS 拆分后应按后台页面按需加载，后台首页不下载富文本、媒体裁剪、翻译任务等非必要模块。
- 前后台可以共享数据和安全基础函数，但不能共享任何直接输出 HTML、CSS 类结构或浏览器交互的 UI 层代码。
- 目录拆分应逐步完成，拆分期间保留兼容导入层；新增功能必须进入新的前后台分离目录，不再扩大旧的混合文件。

# v0.15.174：轻量同步入口与中断接续

本次针对“手动继续能推进、后台到达时间不更新、刷新状态也可能报错”的组合现象。
没有线上 Cron 日志，因此不能把该现象直接认定为 Cloudflare 锁定或某一个确定的代码异常。

## 请求和资源路径

- Worker 将 `/api/admin/site-sync/monitor` 路由至独立的状态应用；不建立网站路由、渲染器或完整资源工厂。
- `/api/admin/site-sync/*` 其余业务接口以及 `/api/site-sync/peer` 使用同步专用应用，复用原业务动作及授权逻辑。
- 状态与业务应用仍检查配置域名、当前会话、原 CSRF 与模块权限；对端接口仍校验签名。
- 每个请求只创建一次同步上下文。SQL、审计函数与认证是基础资源；媒体/缓存绑定和 R2Store 均按需解析。
- 共享请求解析和 CSRF 函数从原 web 模块原样提取，供两个入口复用。
- 状态读取的调度汇总从业务调度模块分离，避免为了读取状态加载完整执行图。
- Python 快照仍预加载已有确定性定义；本次没有声称消除所有模块导入或保证免费套餐 CPU 不超限。

## 更早保存进展

所选条目准备阶段现在逐次完成并提交：来源读取 → 目标读取 → 字段规范化 → 引用提取 → 逐项依赖读取。
新增加的 current.stage 值进入已有检查点投影，不把请求成功、心跳或诊断写入计为业务进展。
已有 source/target/refs/back 子步骤可由 174 接续。新增步骤同样适用于本地部署，保持两种运行环境相同的状态机。

Worker 默认每次版本读取由 5 条降为 1 条，新媒体协商首选由 16 KiB 降为 4 KiB；浏览器请求间隔默认 5 秒。
降速状态继续保留，后续可增加至 15 秒。实际 HTTP/数据库调用可能多于一次，但每次只推进一个持久化业务步骤。
已有媒体文件的 chunk_bytes 和偏移不改变；旧对端未声明小分块能力时仍使用原兼容宽度（16/64 KiB）。
协议版本和数据库结构不变。174 开始的新 normalize/references 子步骤需要 174 或后续代码接续，不能让旧版代码继续推进这些任务。

## 错误、清理和重试

可捕获的 HTTP 入口异常提供无模板、无数据库依赖的短 503 JSON；不返回异常原文、SQL参数或秘密。响应标记 no-store 和 Retry-After: 60。
已发送响应的流式异常不重复发送响应头；取消及模拟强制终止不被伪装成成功。Cron 可捕获失败仍重新抛给平台。

保留原任务租约、先写运行标记、事务检查点、回执核对和进展型重试。可捕获错误正常退出时释放现有请求上下文和租约；强制终止依赖持久化租约到期后核对。
不在错误路径扫描并删除已保存分块、强制 GC 或撤销已提交业务数据；这些做法会增加压力或破坏恢复。
失败步骤仍按原 60/180/600 秒退避；持续无进展进入低频重试。有效进展恢复连续失败计数，无总任务时长上限。

浏览器执行报错后，若读取任务回执也失败，不再立即退出重试循环；权限失效仍停止。
状态刷新遇到临时错误保持自动刷新设置，按 60/180/600 秒退避；401/403 停止并提示登录/权限问题。

## Cron 与页面辅助唤醒

- Cron 一进入处理函数就输出 CRON-ENTRY 平台日志（含版本），早于绑定和数据库初始化。
- 数据库可用后写独立 `site-sync:cron-health`：到达、任务槽、结束/失败和异常类型。记录失败不阻止业务；旧执行不能覆盖新心跳的完成状态。
- 原“后台调度到达”仍是同步调度器到达，页面分开显示“最近 Cron 到达”。数据库初始化之前的失败只能在平台日志中看到。
- 页面显示服务端版本、准备子步骤、超过3分钟未到达提示，以及“此轮未记录阶段明细”，不再静默省略。

Worker 状态接口声明支持页面辅助唤醒。当页面可见、自动刷新开启、存在已授权待推进任务、同步调度超过3分钟没有到达时，页面独立 POST `/api/admin/site-sync/wake`。
监控请求本身只读取状态；唤醒请求是另一个有会话/CSRF/权限校验的动作。
服务端 CAS 限制多标签页合计最多每3分钟申请一次，异常中断也保留冷却。唤醒复用同一后台调度器，仍遵守原租约、冷却、任务范围、授权撤回和审批规则；不会恢复用户暂停的任务或自动批准提案。
页面唤醒不更新 Cron 心跳，不伪装成 Cron 正常。关闭页面后自动推进仍依赖已部署的 Cron，不能由未触发的 Worker 自行唤醒。

# 两端同步部署后验收（v0.16.024）

本清单用于实际部署后的核对。本包已通过本地双站数据库、签名接口、故障注入和适配器测试；尚未替用户操作线上 Cloudflare 或 Ubuntu/Debian 服务器。

## 部署前后

1. 两端均更新为 v0.16.024。Cloudflare 沿用网页构建流程：`inline` 为主站与原生辅助两个 Worker；`separate` 另含独立同步执行器。原有变量、绑定及密钥配置不变，本步无需新增变量或 SQL。
2. 首次验证建议使用测试目标站，关闭两端重叠的定时拉取计划。整站克隆会替换目标业务内容和账号；不要用两个互相拉取的计划验收。
3. 打开两端后台“同步连接”，确认对端地址、当前授权和相同的同步密钥。点击连通性测试，记录响应结果。密钥无需发给他人，也不要放入截图或错误日志。
4. Cloudflare 确认本次部署的主站、原生辅助和可选执行器版本一致，DB/MEDIA 与对应网站一致；Ubuntu/Debian 更新后确认服务已启动、前台和后台均可访问。

## 建议验证顺序

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 普通手动拉取 | 来源端新增测试新闻，目标端勾选新闻后拉取 | 一次提交后后台完成；条目、引用媒体可打开 |
| 推送审核 | 来源端发出推送提案，目标端保留默认审核策略 | 目标端批准一次后继续；不会每片审核 |
| 定时拉取 | 仅目标端新增一个计划，关闭管理页面 | 到期仍创建并推进任务；不重复叠加同一接收任务 |
| 暂停及续传 | 传输较大正文或媒体时暂停，等租约结束后继续 | 任务 ID 不变，已持久进度保留；不会从零开始 |
| 两端换密钥 | 暂停任务，两端保存相同新密钥，再继续 | 不清空断点；未匹配的旧密钥不能继续访问 |
| 传输阶段取消 | 尚未应用数据时取消 | 临时分片清理，目标业务内容与旧账号保留 |
| 应用阶段取消 | 已开始应用时取消 | 停止后续覆盖并释放编辑锁；已发布媒体保留，不承诺回滚已应用内容 |
| 整站克隆 | 单独选整站克隆，包含空文件、未引用媒体和测试账号 | 完成后旧会话失效，使用来源账号密码登录；本站密钥、域名与计划保留 |
| 克隆后再次运行 | 登录恢复后的管理员，检查计划并再次触发 | 当前连接及计划归属正确，正常获得授权 |
| 来源业务变化 | 测试站在已暂存但尚未应用时修改来源新闻 | 清单变化会阻止覆盖目标，保留任务供排查；重新建克隆任务 |

## 报错记录与处理

出现 1101/1102 时，不要仅凭某次错误判断整项任务失败。查看同一任务的最近执行时间、推进序号、正文/媒体偏移及下一次执行时间：有持久进度即说明后台仍在前进。

记录任务 ID、阶段/子阶段、初始/当前/最小切片、HTTP 状态、平台码、Ray ID（若响应提供）、执行 ID、错误帧和断点保存位置。复制折叠诊断，不复制密钥、账号哈希或正文。时区统一为 UTC+08:00。

- 正文切片最小 4KiB，可配置至 4MiB；资源错误后允许自动缩小。
- 默认快速等待为 10 秒，慢速等待最多 1800 秒；这是调度等待配置，不是保证任务在准确秒数启动。租约、调度器及平台运行情况也会影响实际执行时间。
- 只显示等待但长期没有新的执行记录：先核对调度器、Cron 及执行器绑定，不能只缩小切片。
- 权限撤销、内容冲突与来源业务变化不能靠无限重试解决；先看任务状态和错误，再修复配置或重新建立任务。
- 平台强制终止时不保证执行 `finally`，恢复依赖已保存的进度与租约。不要将模拟错误测试当作真实云端额度验收。

## 本轮修复：换密钥引起的克隆误停

后台保存密钥会追加操作日志。此前克隆把操作日志变化也作为来源内容变更，可能在读取清单或最终检查时阻断任务。

v0.16.024 的一致性摘要排除操作日志，业务表、账号、角色、权限及媒体仍参与原有数量/最新更新时间检查。操作日志仍会被枚举和复制，但不要求来源审计日志在整个传输期间停止追加；复制的是发现阶段取得的日志，不保证包含同步结束前的所有新日志。这仍是轻量检查，不是数据库全局事务快照。

本步不更改数据库结构。升级前已经进入旧版克隆清单流程的任务建议取消后新建，使两端使用相同清单摘要规则；普通模块同步任务不受这项摘要调整影响。

## 验收完成标志

三种模式均完成，目标内容与媒体可访问，克隆后的来源账号可登录，同步连接/计划可继续使用，取消任务后编辑恢复正常；真实部署中任务重试仍有进度且前台保持可访问。完成这些检查后，再启用正式定时拉取。

# 整站克隆使用说明（v0.16.022）

本功能将来源网站的业务内容、配置、账号权限及媒体复制到目标站。选择“整站克隆”表示允许替换目标站这些数据，并清理目标数据库中来源站没有的业务记录。普通模块同步仍然保留原有的增量行为，不包含账号密码。

## 范围与保留内容

- 包含教师、学生、研究方向、项目、论文、专利、课程、新闻、分类展示、导航、网站设置、全局设置、留言、翻译缓存、操作日志、工具设置，以及账号、角色、权限。
- 密码传输已有 PBKDF2 哈希，不读取明文密码。同步完成后使用来源站的原账号和密码登录。
- 媒体按 `media_assets` 独立枚举，包括未引用文件、回收站中仍存在的文件和零字节文件。来源媒体必须实际存在；缺失文件会报错并保留任务，不能悄悄跳过。
- 业务 UID 保持一致，目标端内部数字 ID 可以重新生成。媒体路径会按目标存储方式重写，因此支持本地文件与 R2 之间迁移。
- 本站域名、部署环境变量、同步密钥和连接、同步任务断点、运行租约不从来源端覆盖。登录会话不迁移，完成后撤销目标旧会话。临时分享、临时传输任务、VPN 运行状态、节流与缓存等运行数据也不克隆。

这是网站业务恢复功能，不是整个数据库文件逐字节镜像。目标旧媒体的物理文件不会在克隆过程中自动删除；多余媒体数据库记录会移除，旧文件保留，避免误删或取消任务后无法追查。未登记在媒体表中的杂散文件也不在同步清单中。

## 升级部署

1. 两端使用同一份 v0.16.022 代码，并更新 Cloudflare 主站及原生辅助 Worker；`separate` 模式还需更新独立执行器。继续使用已有网页构建部署流程，无需 GitHub Actions。
2. 数据库仍只有 `database/schema.sql` 一个初始化 SQL。全新安装自动初始化；本分支上一版结构可自动扩大同步容量并保留已持久化断点。SQLite 会先建立备份；D1 部署需 `TEACHER_D1_INIT=auto`、现有账户与 API Token 配置及 D1 编辑权限，先保存恢复书签再更新。`check` 模式只检查。
3. 在两站的“后台 → 两站同步”中设置相同的同步密钥，保存各自的对端 HTTPS 地址和当前授权，再运行连通性测试。新范围需要系统管理员重新保存连接以授权导出。
4. 首次克隆建议先暂停其他同步计划，并暂缓修改来源网站。传输末尾会复核来源清单的表结构、业务表数量及最新更新时间（v0.16.024 起，追加的操作日志不参与一致性摘要）；有变化会停止应用，需重新建立任务。该轻量检查不是数据库全局事务快照，持续写入期间不保证一致镜像。

原有部署变量、后台密钥设置及秒级重试说明分别见项目部署教程和 [快速重试教程](sync-retry-setup.md)；本步不增加必填环境变量。

## 三种使用方式

### 手动拉取

在**目标站**新建手动拉取任务，范围仅选择“整站克隆”。保持“自动确认”和“包含删除”勾选，提交一次后在后台自动传输、应用、清理并完成。不要把整站克隆与普通模块混选。

### 手动推送

在**来源站**选择整站克隆并发送推送提案。目标站默认需要批准整个任务，批准一次即可，不审核每个切片，也不需要逐页选中全部记录。目标站若明确授权整站克隆自动确认，还必须勾选自动删除许可；否则仍进入人工批准流程。发送端不能绕过目标站的策略。

### 定时拉取

在**目标站**新增计划，范围仅选择“整站克隆”，设置间隔并启用。任务在后台自动确认完成；上一任务未结束时不会重叠创建新的接收任务。账号切换完成后，当前连接与计划授权会转接到恢复后的系统管理员。

## 执行与恢复

1. 逐条发现完整清单，整站模式不再受普通同步 500 条候选上限限制。
2. 下载每条正文和每个媒体的分段，将断点持久化；中断后从已有进度继续。媒体数据不经过 Python 与 JS 的正文桥接。
3. 全部暂存后，检查清单、完整性及可登录的系统管理员，再开始应用。传输阶段不修改目标业务内容。
4. 应用阶段按记录更新和清理。公开页面可继续读取，但可能看到逐步恢复中的内容；普通写操作返回 409，防止后台编辑与恢复互相覆盖。同步监控、暂停和取消仍可使用。暂停会继续保留编辑锁，取消后释放；已经应用的业务数据不会自动回滚。
5. 最后一个事务统一替换账号、角色和权限，撤销旧会话，保留本站同步连接和密钥，并写入完成事件。页面可能要求重新登录，请使用来源站账号。

1101/1102、网络和存储故障沿用前两步的限时执行、自动退避、断点恢复机制。平台强制终止不能保证执行异常清理代码，恢复仍依靠持久化进度和租约。任务日志不记录密码哈希、正文或密钥。

## 当前容量边界

| 项目 | 当前边界 |
| --- | --- |
| 单条正文封装 | 1 MiB，超出时明确停止该任务；包含记录本身及元数据 |
| 单个媒体 | 1 GiB，超过边界不会静默跳过 |
| 正文切片配置 | 最小 4 KiB，允许配置至 4 MiB；实际读取不超过剩余正文 |
| R2 持久分段 | 5 MiB 加尾段，原生流处理；与正文切片参数独立 |
| 最终账号事务 | 角色、账号、权限合计最多 1000 条，超出时在应用前停止 |
| 暂存记录保留 | 随任务历史清理；手动删除已结束任务也会分批清理暂存档案 |

账号档案保存在目标端自己的数据库暂存区，不通过任务详情接口返回。需要尽快释放暂存空间时，可在确认结果后删除已完成任务；不会删除已发布的网站内容和媒体。

本轮通过本地 SQLite、模拟 D1/R2、原生 JS 流和部署打包检查。未连接真实 Cloudflare 账户，未实测线上 CPU 配额或 1 GiB 文件；上述容量是代码边界，不是性能保证。

部署后核对步骤及密钥变更说明见 [双端验收清单](sync-deployment-acceptance.md)。

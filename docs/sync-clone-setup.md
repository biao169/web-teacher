# 分项同步与完整恢复（v0.16.026）

在“后台 → 两站同步”中，使用多选卡片选择要恢复的内容。系统管理员可选择 20 项，包含媒体、账号、角色、权限和全部业务表；点击“全选内容”可克隆网站业务数据。普通管理员仍受原有模块权限限制，不获得账号和系统配置导出权。

## 选择和覆盖规则

| 选择 | 实际行为 |
| --- | --- |
| 部分业务内容 | 同 UID 记录更新，来源新记录插入，保留目标额外记录和未选表 |
| 媒体 | 传输已登记媒体，包括未引用、零字节及回收站文件；缺失文件报错，不跳过 |
| 新闻 | 自动选入论文、项目、学生和媒体，确保关联记录存在 |
| 网站设置 | 自动选入教师资料和媒体，确保首页教师和图标引用有效 |
| 其他有媒体引用的内容 | 自动选入媒体文件；当前按媒体表整体传输，不逐篇筛选媒体 |
| 账号、角色、权限任一项 | 三项一起选中并整体替换；完成后撤销目标旧会话，用来源账号密码登录 |
| 全选 20 项 | 恢复全部业务数据，清理来源没有的目标业务记录，最后统一切换账号组 |

取消依赖项会同时取消依赖它的项目；例如取消媒体会取消已选新闻。卡片下方解释每项作用，所选计数包括自动加入的依赖。服务端也会补齐依赖并检查授权。

密码同步现有 PBKDF2 哈希，不传输明文密码。账号切换前必须存在一个可登录且具有数据管理权限的来源系统管理员；账号组超过 1000 条记录会拒绝恢复，避免 Worker 最后一次事务过大。

## 三种操作方式

1. **手动拉取**：在目标站选择内容，保持“自动确认”和“包含删除”勾选，创建一次，后台自动发现、传输和应用。这里的替换许可也适用于分项恢复和账号组，不代表每项任务都会清理所有目标数据。
2. **手动推送**：在来源站选择内容并发送提案。目标默认批准整个任务一次；后续切片和恢复不再审核。若目标希望自动接收，在“接收推送的自动确认策略”中勾选全部相应项目及依赖，并允许替换/删除。发送方不能替目标打开自动确认。
3. **定时拉取**：在目标站选择内容、填写周期并启用计划。服务端自动推进，关闭页面也继续；上一接收任务未结束时不会重叠创建。账号切换后当前连接与计划授权转接到恢复后的系统管理员。

后台可以查看创建时间、最近执行、下一次运行、正文与媒体进度、恢复表和日志；暂停、继续、取消及任务清理沿用原有按钮。

## 部署和首次使用

1. 两端更新到 v0.16.026。本地 Ubuntu/Debian 沿用现有部署方式；Cloudflare 在主站网页连接的构建项目运行 `python build.py deploy`，自动更新辅助服务。`inline` 为主站加原生辅助，`separate` 再增加独立同步执行器。不需要手工粘贴辅助代码或 GitHub Actions。
2. 本次不新增必填环境变量，也不变更表结构。数据库初始化仍只有 `database/schema.sql`。
3. 两端保存相同 `TEACHER_SYNC_KEY`、各自的对端 HTTPS 地址，并点击“保存连接与当前授权”。更新已有站点时也需要重新保存连接，取得新分项授权。
4. 运行连通性测试，测试通过后再新建任务。已有计划建议先停用，再以新卡片选好范围并保存。
5. 首次完整恢复期间暂停其他同步计划，并暂缓修改来源业务数据。传输末尾会检查所选表数量和最新更新时间；业务变化时停止应用，需重新新建任务。操作日志追加不参与这一摘要。

Cloudflare 网页构建参数与辅助自动更新说明见 [v0.16.025](releases/v0.16.025.md)；密钥和重试说明见 [密钥教程](sync-key-setup.md)、[快速重试教程](sync-retry-setup.md)。

## 保留内容和恢复边界

这是业务恢复，不是整个数据库文件的逐字节镜像。本站域名、部署环境、同步密钥、连接、任务断点、租约、登录会话、临时分享、VPN 运行状态等不从来源覆盖。未选择账号组时，本地账号和会话保持不变。

媒体必须登记在 `media_assets` 且文件实际存在。目标物理旧文件不会在恢复时直接删除，未登记的杂散文件不参与同步。业务 UID 保持，内部数字 ID 可重新生成；媒体路径按 SQLite/本地文件或 D1/R2 的目标存储方式重写。同 UID 媒体更新时，目标已存在的外键引用会一起调整，防止断链。

正文与媒体逐条、逐片持久化，资源或网络错误继续使用断点与快速重试机制。全部暂存后才应用；公开页面可继续读取，但应用时可能看到逐步恢复中的内容。普通后台写操作暂时返回 409，避免和恢复冲突；同步监控与控制仍可使用。暂停保留编辑锁，取消后释放，已应用内容不自动回滚。

来源清单校验是轻量检查，并非跨全部表和媒体的事务快照，持续写入期间不保证一致镜像。线上恢复结果请以任务详情及重新登录、抽查内容和媒体的结果为准。

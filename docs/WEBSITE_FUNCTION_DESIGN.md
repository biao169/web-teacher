# 教师个人/团队网站功能设计与文件职责

更新时间：2026-08-21

本文档是 `web03` 的长期设计台账。后续 AI 或人工继续开发本网站时，应先阅读本文档，再阅读 `docs/TEACHER_SITE_SKILL_AND_ARCHITECTURE_PLAN.md`、`README.md` 和相关源码。

## 0. 项目目录总览

本项目采用“核心渲染逻辑 + 双平台入口 + 可迁移数据”的结构。阅读或修改代码时，优先按下面的目录职责定位文件。

### 0.1 根目录文件

- `README.md`：项目快速说明，适合首次打开项目时查看运行方式和基本能力。
- `CLOUDFLARE_DEPLOYMENT.md`：Cloudflare Workers、D1、R2、Static Assets 部署说明；D1 初始化优先查看这里。
- `UBUNTU_DEPLOYMENT.md`：普通 Ubuntu 云服务器部署说明。
- `wrangler.toml`：Cloudflare Worker 配置，包括入口 `src/worker.py`、静态资源目录 `public`、D1、R2 和环境变量。
- `pyproject.toml`、`requirements.txt`：Python 项目依赖与运行配置。
- `start_windows.bat`、`start_ubuntu.sh`：Windows 和 Ubuntu 的一键启动脚本。
- `robots.txt`、`sitemap.xml`、`sitemap-index.xml`、`sitemap.txt`、`llms.txt`、`security.txt`、`.well-known/security.txt`：搜索引擎、AI 摘要工具和安全披露工具可识别的根目录入口文件；正式上线时需要将其中的占位域名 `https://example.com` 改为真实域名。动态路由版本会优先读取运行环境中的 `SITE_URL`。
- `db.sqlite3`：历史或临时 SQLite 数据库文件，不作为当前推荐运行数据源；当前默认本地数据在 `data/site.sqlite3`。
- `devserver*.log`、`runserver*.log`：本地开发服务日志，可用于排查启动错误，不应提交敏感信息。
- `.gitignore`：版本控制忽略规则。

### 0.2 `app/`

网站共享业务代码目录，Cloudflare Worker 和普通 Python 服务都会复用这里的核心逻辑。

- `app/core/rendering.py`：最核心文件，负责前台页面、后台页面、路由分发、权限校验入口、SEO 文件动态生成、媒体接口、翻译接口、导入导出入口和大部分后台表单渲染。
- `app/core/models.py`：数据模型和字段定义，决定后台表、字段类型、搜索字段、列表字段和可见范围。
- `app/core/repository.py`：仓储接口和内存仓储实现，供 Worker 无数据库或测试场景使用。
- `app/core/security.py`：密码、会话签名、安全 HTML 清洗、富文本安全渲染、CSRF 同源检查、文本清洗等安全相关逻辑。
- `app/core/media.py`：媒体 URL、图片标签和媒体显示辅助函数。
- `app/core/exporting.py`、`app/core/importing.py`：数据导出和恢复导入逻辑。
- `app/core/seed_data.py`：基础演示/初始化数据。
- `app/core/example_data.py`：更丰富的示例数据，用于本地演示填充。
- `app/adapters/ubuntu/db.py`：普通 Windows/Ubuntu 环境下的 SQLite 仓储实现，会按 `models.py` 自动补齐表结构。
- `app/adapters/cloudflare_repository.py`：Cloudflare D1 与内存仓储之间的数据加载和保存桥接。

### 0.3 `src/`

Cloudflare Worker 入口目录。

- `src/worker.py`：Worker 请求入口，负责接收 Cloudflare 请求、读取 D1/R2/Static Assets 绑定、组装运行环境变量，并把请求交给 `app/core/rendering.py`。Cloudflare 部署问题优先检查这里和 `wrangler.toml`。

### 0.4 `public/`

前后台公开静态资源目录，会被本地服务器和 Cloudflare Static Assets 直接服务。

- `public/assets/site.css`：全站前台和后台主要样式，包括后台列表、媒体选择工具、移动端导航、权限界面、筛选工具条等。
- `public/assets/site.js`：全站前后台交互脚本，包括媒体选择工具、后台快速操作、筛选/批量工具、移动端导航、媒体裁剪等。
- `public/assets/news-rich-editor.css`：富文本独立编辑器样式。
- `public/assets/news-rich-editor.js`：富文本独立编辑器交互逻辑，包括插入媒体、上传媒体、图片尺寸、对齐、吸顶等。
- `public/media/`：公开媒体文件目录，保存本地上传或示例图片、SVG、新闻媒体等；Cloudflare 生产环境可迁移到 R2，并通过 `PUBLIC_MEDIA_BASE_URL` 或 `/media/` 路由访问。

### 0.5 `migrations/`

数据库初始化脚本目录。

- `migrations/0001_initial.sql`：当前已合并为单个完整初始化脚本，适合 Cloudflare D1 空数据库首次建表时直接复制粘贴执行，或通过 `wrangler d1 migrations apply` 执行。
- 注意：该脚本不是已有正式数据库的升级脚本。已有数据迁移应先备份，再使用后台“导入与导出”恢复。

### 0.6 `tools/`

本地和 Ubuntu 运维工具目录，不直接暴露给前台访客。

- `tools/dev_server.py`：当前本地开发常用服务器，支持静态资源、媒体文件和动态路由，常用于 `127.0.0.1:8003` 预览。
- `tools/serve_ubuntu.py`：Ubuntu 普通云服务器运行入口。
- `tools/init_db.py`：初始化本地 SQLite 数据库，并可选择写入基础数据和示例数据。
- `tools/seed_examples.py`：向本地数据库添加示例内容。
- `tools/export_bundle.py`：本地导出完整网站数据包。
- `tools/import_bundle.py`：本地恢复导入数据包。

### 0.7 `data/`、`exports/`、`.cache/`

运行时数据目录。

- `data/site.sqlite3`：当前本地默认 SQLite 数据库。
- `exports/`：本地或 Ubuntu 生成的导出文件目录，例如 JSON、CSV、Excel、ZIP 备份包。
- `.cache/`：运行缓存目录，例如登录限流、媒体统计缓存等；不应手动依赖其中内容作为正式数据源。

### 0.8 `docs/`

项目文档目录。

- `docs/WEBSITE_FUNCTION_DESIGN.md`：当前长期设计台账，记录功能规划、文件职责、数据模型、部署策略和每次重要变更。后续修改网站时必须同步更新。
- `docs/TEACHER_SITE_SKILL_AND_ARCHITECTURE_PLAN.md`：早期技能加载、信息架构、技术选型与总体规划文档。

### 0.9 `seed/`、`content/`

辅助与预留目录。

- `seed/demo.sql`：SQL 形式的演示数据或初始化辅助数据。
- `content/`：预留内容目录，目前未承载核心运行逻辑；后续如果引入 Markdown/JSON 内容源，可优先放在这里并同步更新本文档。

### 0.10 生成目录

- `__pycache__/`：Python 运行生成的字节码缓存，出现在 `app/`、`src/`、`tools/` 等目录下，可忽略。
- 日志文件和导出文件可能包含运行状态或业务数据，提交或部署前应检查是否含有账号、邮箱、密钥、导出数据等敏感信息。

## 1. 项目目标

本网站是一个不使用 Flask 的轻量 Python 教师个人/团队网站，目标是同一套核心代码同时适配：

- Cloudflare Workers：前期生产部署环境，要求低 CPU、低请求开销、轻量动态渲染。
- Ubuntu 云服务器：后期迁移环境，可使用 SQLite/Postgres、本地媒体目录、ASGI 服务和更完整的导入导出工具。

核心要求：

- 首页展示教师个人照片、姓名、职称、单位、研究简介、学术档案、研究方向、代表成果、最新动态、项目、专利、学生。
- 团队页展示教师和团队成员照片、简介、联系方式和学术链接。
- 论文、项目、专利、学生、动态、课程等页面以紧凑、易扫读的学术列表为主。
- 前台导航栏、首页按钮、栏目展示数量、排序和启用状态可通过后台配置。
- 支持网站数据导出为 JSON、CSV、YAML、Excel、ZIP，方便从 Cloudflare 迁移到 Ubuntu。
- Cloudflare 请求路径避免高 CPU 任务，Excel 生成、完整备份、复杂导入优先放到本地或 Ubuntu 工具中。

## 2. 功能模块规划

### 2.1 前台展示

当前前台页面：

- `/` 首页：教师身份、照片、简介、学术档案、招生方向、研究方向、代表论文、最新动态、项目、专利、学生。
- `/team` 团队：教师与团队成员照片、姓名、角色、职称、单位、简介和个人链接。
- `/publications` 论文：关键词、年份、作者角色筛选；显示引用、年份、期刊会议、类型、DOI、PDF；支持批量勾选复制。
- `/featured-publications` 代表论文：复用论文页，只筛选代表作。
- `/projects` 科研项目：项目名称、来源、基金、状态、简介。
- `/patents` 专利与软著：名称、类型、授权号、法律状态、简介。
- `/students` 学生：姓名、照片、层次、分组、年级、状态、方向、简介和链接。
- `/news` 动态：团队新闻、项目进展、论文录用、学生获奖、课程更新等。
- `/news/<slug>` 动态详情：显示单条动态正文，可扩展封面和富文本。
- `/courses` 课程：课程名称、学期、授课对象、课程简介。
- `/contact` 联系留言：招生、合作、论文、课程、其他类型留言。
- `/sitemap.xml`：自动生成中英文双语站点地图，包含 `zh-CN`、`en` 和 `x-default` 的 hreflang 入口。
- `/robots.txt`：自动生成搜索引擎规则。

首页设计独立保留较完整的教师介绍布局。除首页外，当前前台页面采用接近 `web02` 的紧凑学术页面风格：页面标题、筛选条、编号列表、密集人员卡片、论文引用行、动态行。

首页教师照片使用随身份信息行高拉伸的无边界预览槽，图片必须完整显示：瘦高图片允许左右留白并居中，扁平图片允许上下留白并居中，不裁切顶部、底部或左右边缘；无图或路径失效时显示姓名姓氏 fallback。

前台图片统一只保留小圆角，不额外添加边框；主页教师照片、团队/学生头像和后台人员预览均保持图片完整可见，优先使用 `object-fit: contain` 或无裁切策略。

首页“代表论文”显示最近的代表作：先筛选 `publications.is_featured = 1`，再按年份、记录 id、排序值和更新时间倒序取站点设置中的首页论文数量；如果没有代表作，则从全部论文中按同样规则取最近论文兜底。

首页代表论文与 `/publications` 论文页共用 `global_settings.publication_display_style` 设置和 `publication_display_citation()` 引文生成逻辑；GB/T 前台展示保留作者录入时的英文大小写，不再把英文作者姓氏强制全部大写。

`/projects` 前台项目页使用专用紧凑项目卡片，不再使用通用列表：DOM 与复制顺序固定为来源、基金/计划、项目名称、周期、编号、金额、状态。视觉上第一行单独显示“来源 - 基金/计划”，第二行显示项目名称、周期、编号、金额和状态；宽度不足时第二行自动换行。项目卡片色彩保持克制，使用全站字号变量；来源用灰绿弱化，基金/计划与状态用温和绿色强调，项目名称用细左线和中等字重区分，避免多色填充标签造成视觉噪声。项目页继续复用通用搜索/筛选条，筛选项包括来源、基金/计划和状态。

项目金额前台显示规则：后台 `amount` 字段如果填写纯数字，按“万元”口径理解；中文前台显示为“6 万元”这类格式，英文前台自动换算为千元人民币单位，例如 `6` 或 `6万元` 显示为 `60k CNY`，避免出现 `6 10k CNY` 这种不自然表达。若后台明确填写 `60000元`、`CNY 60000` 等元金额，英文前台同样规范为 `60k CNY`。

`/students` 前台学生页使用分组名录，不再把所有学生笼统陈列成一个连续表格。默认按学生“分组”分段显示，分组顺序优先读取后台“学生分组”的 `display_order` 与中英文标签；也可在筛选条中切换为按“学历/层次”分段显示。每个学生仍使用“照片/姓名占位 + 信息”两列紧凑卡片，不再把序号作为独立宽列展示；序号改为视觉区左上角的小圆形编号徽标，并按每个分组独立倒序生成，例如某组有 4 人则显示 4、3、2、1，完全不依赖模型 ID 或全页总数。学生姓名、层次/分组/年级/状态、简介和链接保持紧凑排列；简介默认一行截断，移动端仍保持两列结构，避免头像与文字上下堆叠造成卡片过高。

前台移动端导航栏采用左上角悬浮“菜单”按钮展开/收起，header 会为该按钮预留左侧空间；展开面板从左上角下方弹出且不占用正文高度。后台页面隐藏该前台悬浮菜单，避免与后台侧栏开关重叠。

前台登录后在右上角操作区显示当前用户名或显示名；只有具备后台访问权限的账号才显示“后台”入口，未登录访客不显示后台按钮。

### 2.2 后台管理

当前后台路径：

- `/admin`：内容管理入口，展示各数据表数量。
- `/admin/export`：导入与导出中心，按集成、分组、分表三种粒度导出主要数据，并支持在本地/Ubuntu 环境粘贴 JSON 分表恢复。
- `/admin/table/<table>`：表格列表、搜索、编辑入口。
- `/admin/table/<table>/new`：新增数据。
- `/admin/table/<table>/<uid-or-id>`：编辑已有数据。
- `/admin/table/<table>/save`：保存表单。

后台当前以轻量通用 CRUD 为基础，由 `app/core/models.py` 的 schema 自动生成列表和表单。媒体库等高频模块可在保持通用编辑表单可用的基础上，额外增加专用概览页面。

后台界面约定：

- 后台主工作区使用比前台更宽的画布，便于在左侧导航右侧展示摘要列表。
- 后台左侧导航栏采用分组式应用侧栏：顶部显示管理后台标识，中部按常用操作、站点配置、人员与互动、科研成果、内容与媒体、账号安全分组，当前页面高亮显示；底部显示当前登录账号、角色和退出入口。窄屏下侧栏取消吸附，避免压缩主内容。
- 后台移动端左侧导航栏改为左下角悬浮“后台导航”按钮控制的抽屉面板；按钮位置与前台菜单区分，后台页不显示前台悬浮菜单，避免遮挡编辑区和底部保存按钮。
- 后台右侧功能区顶部显示当前链路路径，父级节点可点击返回。
- 所有后台功能编辑界面的操作按钮统一悬浮在视口底部，固定提供“保存”“保存并继续”和“返回”；“保存”回到列表，“保存并继续”回到当前记录编辑页。
- “通用设置”后台概览改为运行控制台样式，摘要显示访问与留言、上传与媒体、可用翻译源和缓存性能；常用设置可直接修改注册、匿名留言、PDF 下载、上传上限、媒体回收站保留天数、默认翻译源和论文显示格式。
- “通用设置”概览详情不使用横向大表格，而是每个功能域独立成行：访问与留言、上传与媒体、翻译服务、学术平台、缓存与性能、常用修改各占一行；常用修改控件使用自适应网格换行，避免后台宽度不足时产生横向溢出。
- “通用设置”编辑页按访问与留言、上传与媒体、动态 PDF、翻译服务、翻译接口配置、论文与专利平台、缓存与性能、系统状态分组；布尔配置使用开关样式，自动翻译任务状态只读展示。
- “站点设置”后台概览采用与通用设置一致的多行设置面板：摘要显示站点名称、首页展示、SEO 和品牌媒体；详情行显示基础名称、首页主视觉、品牌媒体、SEO、首页内容和页脚；常用修改可直接调整启用状态、中文/英文站名、首页教师 UID、首页论文数量和首页动态数量。
- “站点设置”编辑页按基础名称、首页主视觉、品牌与分享媒体、SEO 与检索、页脚分组；Logo、Favicon 和分享图继续接入通用媒体选择工具并显示媒体预览，字段说明使用浅色小字并限制为两行，避免长说明撑开布局。
- “导入与导出”后台页面按运行平台显示能力：Cloudflare Worker 上保留轻量 JSON 导出，Excel 生成、上传文件解析和批量恢复导入灰色禁用；本地/Ubuntu 环境允许主要数据 JSON、整站 JSON、分组 JSON/Excel、分表 JSON/CSV，以及上传 JSON/CSV/Excel 或粘贴 JSON 恢复。

- `/admin/table/media_assets` 使用媒体库专用概览：缩略图、标题、对象 key、分类、MIME、大小、状态、使用位置和操作按钮在同一列表中展示。
- 媒体库概览使用紧凑单行多列布局：每个媒体文件占一行，行内列展示选择框、预览、媒体文件、文件信息、使用位置和操作。
- 媒体库支持多选与统一修改，可批量改状态、改分类、移入回收站、恢复可用或彻底删除记录。
- 媒体库顶部显示容量概览，页面先快速渲染，再由 `/api/admin/media/summary` 与 `/api/admin/media/file-size` 异步读取容量数据；磁盘容量和文件大小默认使用短期缓存，手动刷新才强制重新检测。
- 媒体库列表的“可用”是计算状态：记录必须是 active 且本地媒体文件存在，才显示“可用”；active 但文件不存在时显示“文件缺失”，预览区不再输出失效图片标签，而显示缺失占位。
- 媒体库筛选增加“文件状态”，支持可用、文件缺失、有引用、未引用；可用于批量筛出失效媒体记录后移入回收站或彻底删除。
- 媒体库筛选行和批量操作行采用悬浮吸顶，适配未来媒体文件较多、分页滚动较长的场景；批量分类输入框提供示例和说明。
- 媒体静态文件服务必须对 URL 百分号编码路径做 `unquote` 解码；否则类似 `icons/æ--æ--è--çº-å-¾3-1.png` 的非 ASCII 文件名会在浏览器请求时变为 `%C3%A6...` 并导致预览 404。本地标准库服务、Ubuntu ASGI 和 Cloudflare Worker 媒体路径均已做解码。
- 媒体库详情页使用专用编辑表单：左侧显示大预览和系统只读信息，右侧维护标题、分类、MIME、状态和 object key；系统字段如记录 ID、大小、校验值只读。
- 媒体详情页接入图片编辑工具，可从当前图片打开裁剪面板。默认保存为新媒体文件并写回 `object_key` 输入框；勾选“替换当前媒体文件”时覆盖源文件、保持 object key 不变并更新大小/MIME/校验值。当前只允许 PNG/JPG/WebP 这类栅格图片直接编辑，SVG 等矢量文件不启用替换编辑，避免文件扩展名与实际内容不一致。
- 媒体库和回收站是两个独立界面：`/admin/table/media_assets` 只显示 `active` 媒体，`/admin/table/media_assets/trash` 只显示 `trash` 媒体；媒体库顶部提供回收站跳转按钮。
- 两个界面都支持搜索、分类筛选、MIME 类型筛选、多种排序和分页，适合媒体文件数量较多的场景。
- 回收站界面与媒体库使用相同的单行多列列表，支持查看媒体、恢复原位置、删除指定文件和一键清空；超过 `global_settings.media_trash_retention_days` 的回收站记录会在打开媒体库/回收站时自动清空。
- 媒体库使用位置通过扫描各数据表中 `kind = file` 的字段计算，优先跳转到后台编辑页，并在可识别前台页面时提供前台入口。
- 媒体库/回收站列表的列宽优先保障“使用位置”：媒体文件列和文件信息列较窄，文件信息最多约两行，使用位置可换行显示但尽量不超过三行；使用位置 chip 的 `title` 保留完整引用信息，鼠标悬停可查看完整内容。
- 媒体文件列中的对象 key 支持换行断词显示，例如 `students/li-si.svg` 可以显示为两行，不强制单行省略。
- 后台主业务概览页统一使用吸顶工具区：搜索/筛选/排序行与批量操作行在列表滚动时保持可见；筛选下拉框默认收窄，排序下拉略宽，优先把横向空间留给列表内容。
- 导航与按钮、教师与团队、研究方向、论文、项目、专利与软著、学生、学生分组、动态、课程和留言概览页均支持多选。每行最左侧显示选择框，顶部批量行提供全选、已选数量、统一属性修改和按当前列表顺序重排。
- 通用批量修改采用白名单字段，避免误改标题、姓名、编号、正文、附件等高风险内容。常见批量字段包括首页展示、启用状态、可见范围、联系方式可见性、论文类型/收录、项目状态/来源、专利类型/法律状态、学生层次/分组/年级、动态分类/评论、课程学期/对象、留言状态/类型等。
- 批量排序通过“排序起始”和“排序步长”实现；例如在筛选结果中填写起始 100、步长 10 后提交，会按当前列表顺序写入 100、110、120 等排序值。留空的批量配置不会改动对应字段。
- Cloudflare Worker 中通用批量修改复用核心白名单逻辑，并只把选中的记录逐条写回 D1；单次最多处理 500 条，避免低 CPU Worker 场景下产生过重请求。

### 2.3 数据管理与迁移

当前支持：

- 本地/Ubuntu SQLite 初始化。
- 示例数据填充。
- 整站 JSON 导出接口。
- ZIP 迁移包导出，包含 JSON、CSV、YAML、Excel 和媒体清单。

设计原则：

- 导出包必须包含 `manifest.json`，记录 schema 版本、导出时间、来源平台、表数量和校验值。

- Ubuntu 侧媒体目标是本地 `media/` 或对象存储。

## 4. 双平台部署设计

### 4.1 共享核心

共享核心位于 `app/core/`：

- 不依赖 Flask。
- 不直接绑定 SQLite、D1、HTTP Server 或 Cloudflare API。
- 通过 Repository 接口读取和写入数据。
- 页面渲染以字符串拼接为主，减少模板引擎依赖和 Worker 侧 CPU 消耗。

### 4.2 Cloudflare Workers

Cloudflare 适配层：

- `src/worker.py`：Python Worker 入口。
- `app/adapters/cloudflare_repository.py`：D1 数据访问适配。
- `wrangler.toml`：Cloudflare Workers、D1、R2、静态资源配置。
- `migrations/0001_initial.sql`：D1 初始化 SQL。

Cloudflare 设计约束：

- 每次请求只做必要查询和轻量 HTML 渲染。
- 列表限制在 300-500 条以内。
- 静态资源通过 Workers Static Assets 或 `public/` 分发。
- 媒体通过 R2 或公共媒体前缀读取。
- 高 CPU 工作不放在 Worker 请求路径中。

### 4.3 Ubuntu 云服务器

Ubuntu 适配层：

- `app/adapters/ubuntu/db.py`：SQLite Repository。
- `app/adapters/ubuntu/main.py`：ASGI 应用入口。
- `tools/serve_ubuntu.py`：Uvicorn 启动脚本。
- `tools/dev_server.py`：无需 Uvicorn 的标准库开发预览服务器。

Ubuntu 设计约束：

- 可使用 SQLite 起步，后续可扩展 Postgres Repository。
- 可运行 Excel、ZIP、批量导入导出、图片处理等较重任务。
- 应保持与 Cloudflare 使用同一套 `app/core/` 业务逻辑。

### 6.2 非首页紧凑设计

2026-08-15 起，除首页外的前台页面统一使用 `compact-page` 容器。

相关 CSS 在 `public/assets/site.css` 的 `Compact public pages` 区块中：

- `.compact-page`

- `.compact-list`
- `.citation-list`
- `.citation-item`
- `.person-card`
- `.student-card`

设计目标：

- 内容比首页更紧凑。

- 团队和学生保留照片，但缩小尺寸，提高信息密度。
- 团队页使用单列紧凑成员档案：每张成员卡片右侧内容固定为三个行模块。第一行显示姓名和头衔/身份标签；第二行显示个人简介，默认最多两行；第三行显示邮箱、电话和已填写学术/社交链接，最右侧小按钮打开新标签页展示完整个人字段。

- 论文页前台筛选条的下拉框按字段设置不同宽度：年份最窄，论文类型、作者角色和收录使用中等宽度，期刊/会议保留更宽空间；移动端统一回到全宽控件，保证触控和可读性。

### 6.4 低 CPU 设计

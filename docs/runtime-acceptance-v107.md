版本：0.15.107。测试日期：2026-09-28。环境：Linux、Python 3.12，本地临时 SQLite 与合成文件。没有连接生产数据库、真实云服务器或外部传输接收方。

- 复用既有中转、离线缓存、日志与部署测试，不新增另一套维护机制。

| 在线中转 | 32 MiB | 2,125,449 B | 43,360 KiB | 数据校验通过；中转保留上限 1 MiB；取消后为 0 |

## 真实本地 HTTP 连续负载

3 轮，每轮 45 秒并发访问及约 10 秒空闲观察，共约 166 秒，完成 3,924 次页面请求。每轮同时建立 3 个中转会话，其中 2 个完成 4 MiB 文件，另一个在第二块仍保留时取消；共校验接收 27 MiB。页面、分页、媒体、扫描和预览请求均成功；服务重启后原管理员会话和媒体读取有效；在线中转没有遗留 `.part` 文件。运行日志 1 份、1,232 字节。

| 轮次 | 页面请求数 | 响应中位数 / P95（ms） | 空闲后 RSS（MiB） |
| --- | --- | --- | --- |
| 1 | 1302 | 12.77 / 46.21 | 52.54 |
| 2 | 1313 | 12.85 / 41.01 | 53.57 |
| 3 | 1309 | 12.47 / 44.69 | 52.59 |

第三轮内存回落到接近第一轮水平，此短测试中未出现持续单向增长。性能数值仅代表当前测试机器与合成数据，不能直接作为云服务器性能承诺。缓存统计占用为 0、预算为 32 MiB，本轮未构成缓存容量压力验收；隔离环境未能读取服务进程文件句柄数，报告中的 `fd_count` 为 null，不能据此宣称文件句柄实测稳定。扫描句柄关闭由既有自动化测试覆盖。

## 重复执行

在项目根目录，使用已安装开发测试依赖的 Python：

```text
python -B tests/benchmark_runtime_endurance.py --rounds 3 --seconds 45 --output runtime-check.json
python -B tests/benchmark_runtime_endurance.py --rounds 24 --seconds 3600 --output runtime-check-24h.json
```

每轮还有约 10 秒空闲观察时间。脚本独立创建临时数据库、合成媒体和随机本地端口，移除继承的 TEACHER_/TRANSFER_ 配置；完成后删除临时数据。报告路径由 `--output` 指定，若文件已存在会覆盖。该脚本不会测试已经部署的站点。Windows 中请将 `python` 替换成 `deploy/windows/local.cmd` 配置的解释器完整路径；Windows 实际运行仍待验证。

32/256 MiB 服务层探针分别使用 `tests/benchmark_relay_resources.py 32` 和 `tests/benchmark_offline_resources.py 32`，替换参数可扩大文件；这两个旧探针使用 Unix 的 `resource` 模块，只适用于 Linux 等支持该模块的环境。

## 部署后验收与边界

1. 保留正式站点的数据目录配置；Windows 更新代码后使用原启动脚本。Linux 使用 `tweb update --scope all`，随后 `tweb restart`。
2. 系统管理员打开“运行维护”，确认内存、数据库、磁盘和缓存状态可读取；点击文件占用统计直到完成。
3. 先预览清理候选，按实际保留需要调整策略。正式数据删除有实际影响，确认候选与保留期限后再手动执行。
4. 在真实设备验证浏览器发送/接收、断线、取消、目录保存及反向代理超时。局域网直连、跨公网网络与 Windows 浏览器行为无法由本地 HTTP 测试代替。
5. 在真实业务负载下观察至少 24 小时，比较空闲阶段 RSS、日志上限、快传到期目录及磁盘剩余空间；本次没有完成多日浸泡测试。

运行日志有大小、份数和天数边界，默认最多约 60 MiB（当前文件与 5 份归档，每份 10 MiB）。正式媒体、数据库中的有效业务记录，以及系统 journald、nginx/caddy 日志仍可能增长；本应用不会越权清理这些系统服务日志。资源占用小并不代表磁盘可以永久免维护。

原始测量见 `runtime-acceptance-v107-verification.json` 和 `runtime-endurance-v107.json`。

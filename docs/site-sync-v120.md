# 两站同步第一步：v0.15.120

入口：后台 → 数据与备份 → 两站同步预览（`/admin/data-tools/sync`）。

## 本步交付

两站使用同一套预览服务，不区分 Cloudflare / Ubuntu / Debian 的主从身份。每次选择“对端 → 本站”或“本站 → 对端”，箭头终点都是接收方，“新增/更新/删除”也是相对于接收方。当前只保存连接、快照及选择，不复制文件、不修改业务记录、不发送审批。

权限复用数据与备份的系统管理员限制；读取完整业务快照另需相关模块导出权限。两个方向共用差异、依赖和选择方法。页面复用后台布局、表格样式、表单样式、管理员请求封装；新交互脚本只处理该页面的预览状态。

支持教师、学生、分类、研究方向、项目、论文、专利、课程、新闻、导航、网站设置、部分公开全局设置、人工译文和媒体登记。自动译文仅作为依赖检查背景，不独立列入同步差异。全局设置只包含注册/匿名留言开关、新闻 PDF 配置与论文显示格式。账号、角色、会话、部署信息、服务密钥、留言、日志、快传临时数据、同步内部表不参与业务同步。

记录按 UID 对应；网站/全局设置按单例对应。自动时间戳和数字 ID 不参与内容比较。本地与 R2 的受管理媒体存储类型不会独立形成差异；对象键仍参与比较，实际目标端存储映射将在第二步实现。预览阶段不读取媒体二进制，不能据此认定文件存在或完整。

## 连接配置

1. 两站更新到本版本并初始化或升级数据库，分别登录系统管理员。
2. 本站填写对端的公网 HTTPS 根地址。支持 `workers.dev` 或自定义域名；不填页面路径，不支持 HTTP、内网地址或非 443 端口。
3. 生成一份随机密钥，复制到另一站。两站填写相同密钥，分别保存并启用。密钥至少32字符，生成器使用32个随机字节。
4. 点击“测试已保存连接”。该测试验证 TLS、共享密钥签名、对端标识、协议和字段结构；不创建管理员、不探测媒体文件。
5. 选范围、方向，生成预览。勾选条目会自动加入必要的前置依赖，并显示范围外依赖；取消原始选择后重新计算依赖。

密钥保存在各自的同步内部表，不在页面回显、不进入业务导出或操作日志。完整数据库备份仍属于敏感文件。换域名或密钥后重新保存两站配置，旧预览会失效。关闭“启用业务数据读取”即可停用对端入口。

对端只开放签名的只读 `hello/page` 操作，没有通用 SQL、文件路径或执行同步接口。请求/响应都签名，响应绑定本次随机 nonce；接受120秒时钟偏差。只读请求不设计消耗式一次性授权。后续审批/执行须采用独立的持久化授权状态，不能复用此只读接口作为写入权限。

## 预览与媒体依赖

例如接收方的教师、新闻引用媒体 a，来源已改为 b 并删除 a：勾选删除 a 时，依赖清单加入教师/新闻更新及 b 的新增。若来源仍引用 a、引用无法确认、引用条目无法解除，则显示阻止原因。第二步执行时仍必须再次核对接收方的真实引用，不能仅凭历史预览删除文件。

预览读取所有支持模块用于依赖检查，只把勾选范围中的差异作为主动选择项；范围外项目可作为必要依赖进入清单。读取按每页20条保存，支持暂停、刷新后继续。结束前核对两站版本标记、分页记录总数、对端配置和身份；读取失败、结构不符、数据变化或记录数不完整时不生成可用删除预览。

本阶段限每站2000条、两站字段总计4MiB、单条字段200KB、单页编码1MiB。超过上限会明确停止，不截断。保留最近10个预览；新建时清理更旧的内部快照，不删除业务内容。版本标记复用现有 UID/updated_at 约定；直接在数据库控制台修改业务字段时必须更新 updated_at，修改后应重新生成预览。历史选择不是可直接执行的批准凭据。

## 数据库更新

本版本新增 `sync_peers`、`sync_tasks`、`sync_task_items` 三张内部表，既有业务表字段不变。唯一初始化 SQL 仍是 `database/schema.sql`；JSON 是结构校验快照，不是第二个初始化脚本。

### Windows / Ubuntu / Debian

新站沿用现有初始化/启动流程。已有 v0.15.119 数据库：停止服务，在项目根目录使用**该站正在使用的 Python 虚拟环境和数据库环境配置**执行：

```bash
python -m backend.cli migrate
```

命令识别已知结构，新增内部表并保留业务记录；沿用已有迁移工具的备份行为。不需要 reset，不会修改媒体文件。之后重启。若路径自定义，必须继续使用原数据库环境变量，不能在另一套配置下运行迁移。

### Cloudflare D1

已有 v0.15.119 D1 数据库，在 Worker **构建变量**设置：

```text
TEACHER_D1_INIT=upgrade
```

然后重新部署。该模式只允许在原有结构完全一致时补齐本版三张内部表；已有表定义异常或出现无关表时停止，不进行通用结构修复。中断后可重试；不会重建/覆盖业务表。首次空库可继续用 `auto`，升级完成也可改回 `auto` 或 `check`。

继续保留既有构建配置：根目录 `/deploy/cloudflare`、构建命令 `python build.py check`、部署命令 `python build.py deploy` 以及 `SKIP_DEPENDENCY_INSTALL=1`。本功能不新增 Python/npm 依赖，不需要改 R2 配置。

## 下一步

第二步实现“对端 → 本站”的真实执行：按选项重新预检、先传新媒体并校验、再更新内容与引用、最后处理获准删除；复用现有数据校验与媒体服务，提供持久任务进度及失败重试。第三步接入推送待批准及同方向待批准请求替换。第四步接入定时拉取与两平台整体验收。

## 验证边界

本版测试使用两个独立本地数据库及真实 HTTP 路由模拟两站通信，检查双方向差异、签名拒绝、权限/CSRF、无业务写入、依赖闭包、数据变化中止和 v119 无损升级；D1 测试模拟 Wrangler 输送真实 SQLite DDL，并验证构建无需系统 sqlite3 模块。另有真实后台模板的 DOM 勾选/依赖/XSS 回归。尚未在用户真实 Cloudflare 账号、R2 或公网两站执行部署验收。

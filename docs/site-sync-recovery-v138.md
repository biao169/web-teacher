# v0.15.138：低负载同步第五步——继续、重新开始与有界重试

## 操作与界面

- 打开最近预览：未读完的预览继续原游标；实际执行任务打开后由“继续/重试任务”推进。
- 手动继续：保留任务、快照、游标和已提交数据，重置错误重试状态；内容页降为1条，版本页降为5条。已开始的提交前/确认前版本检查同步使用较小分页。
- 按原范围重新开始：沿用方向和模块，若有未完成执行，先取消并分批清理暂存，再建立新预览。新预览不继承勾选、执行确认或批准；已提交内容不回滚。
- 创建新预览和保存旧→新关联在同一事务内；响应丢失后重复请求返回同一新预览。旧任务复用数据库既有expired状态，不增表或字段。过期关联仍受历史清理范围限制，已清理记录不会凭空重建。
- 推送审批预览继续使用“重新读取最新差异并核对”，通用重启按钮禁用且后端拒绝，不绕过最新提案和人工批准。
- 等待重试期间可以暂停。暂停停止当前浏览器后续请求，不中断已到达服务器的事务；停止后台需关闭后台同步策略。取消执行后的暂存清理也可继续。

## 重试策略

统一策略复用site_sync_work；前端从模板读取策略，无独立第三方重试库。

| 条件 | 行为 |
| --- | --- |
| 已识别的超时、过载、数据库暂时锁定、网络/流中断、对端429/502/503/504 | 同一步最多自动重试3次，等待2、5、15秒；首次尝试加重试共最多4次 |
| 浏览器网络异常或无结构化错误码的本站429/502/503/504 | 当前操作同样最多重试3次；重试前先读取服务器保存状态 |
| 权限、签名、证书、配置、版本冲突、用量额度、查询数量/记录大小超限、数据校验失败 | 停止自动重试，保留阶段供人工处理 |
| Worker终止且异常处理未执行，只留下running标记 | 后续进入记录未确认次数；超过3次恢复尝试暂停，需手动继续；存活的任务租约仍须正常过期，避免并发执行 |

后台不通过sleep占用请求：持久化重试次数和到期时间，在之后的Cron或本地调度轮次检查，因此实际等待通常长于2/5/15秒。后台识别到失败则原任务暂停或按上述策略继续，不自动重建新的任务。

一次成功推进清除该步骤的连续失败计数。手动继续明确开启新的重试机会。浏览器网络中断导致无法写入数据库时，浏览器重试次数属于当前操作；刷新后仍以服务器检查点为准，不能保证浏览器与Cron共同拥有一个跨断网的精确全局请求次数。后台记录和任务租约限制后台推进及重复执行。

不要把1102简单当作访问太快：减小分页只降低可以分页的工作量。最终原子事务、原生媒体流摘要/复制等仍有单请求工作，退避不能保证解决单次CPU超限；失败上限用于防止持续重放。

## 保留的规则

v137媒体规则不变：来源已删除媒体不传播删除；目标媒体保留，本站手动彻底删除仍删除真实文件。媒体先准备，再提交内容引用。业务删除按选择项执行。权限检查、CSRF、任务锁、事务守卫和推送审批仍复用已有方法。

协议仍为7、任务格式仍为8，可继续v137任务；无需更新或重置数据库表。建议两端配套更新以使用相同交互。v136及更早任务仍按原升级说明处理，不跨任务格式继续。部署脚本继续跳过源码完整性校验。

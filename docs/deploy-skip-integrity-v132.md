# v0.15.132：部署跳过源码完整性校验

Ubuntu/Debian安装、完整更新、修复和续装不再比对release-manifest.json，不计算发布清单的文件大小/SHA-256，不因清单缺失、过期、无法解析或源码部分更新而中断。终端显示“跳过源码完整性校验”。不需要重新生成清单才能部署。

保留必要部署入口文件存在性、路径、依赖安装、数据库初始化及启动健康检查。缺少必需入口时直接列出文件名。少量更新若造成模块接口或数据库不兼容，仍可能在依赖安装、启动或实际访问时报错；跳过完整性校验不等于验证运行兼容。

为兼容旧版已安装管理器，`python -B deploy/vps/release.py verify --root .`默认返回成功退出并明确标记skipped，不读取清单。只有显式加`--strict`才进行严格检查。发行ZIP打包内部继续校验生成物，不参与服务器部署。仅前端更新的范围限制、服务配置所有权及删除范围检查继续沿用，避免局部操作误改其他对象。

## 如何更新与恢复

将下列两个功能文件更新至GitHub的web-py分支：

- `deploy/linux/tweb.py`
- `deploy/vps/release.py`

随后使用原来的一键安装命令，填入自己的实际域名和端口。脚本会下载新版管理器；发现残留时选择“保留数据修复”，需要重新安装才选择清理。没有必要为发布清单错误删除数据库或媒体。

已经安装的`tweb`是服务器上的脚本副本，上传GitHub不会立即替换它。新版一键入口可加载新管理器；旧管理器重新下载到新版release.py后，其verify调用也会默认跳过。若旧续装目录仍是旧脚本，请通过新版入口修复，不要持续对同一个旧目录重试。

本版数据库、站点业务和Cloudflare运行代码不变，不需要重置数据库。本轮不执行远程部署或服务重启。

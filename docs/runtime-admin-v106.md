# 运行维护后台 v0.15.106

## 入口和权限

左侧系统管理下新增“运行维护”。共用 admin/layout 模板、系统角色标识、global_settings 权限与原有 CSRF/Origin 校验。需要系统管理员角色且允许查看全局设置；保存策略还需编辑权限，执行清理还需删除权限。普通账号即使猜到 URL 也无法读取状态。Worker/R2 明确不提供本地维护。

## 资源与交互

展示当前进程驻留内存、系统/容器可用内存、数据库主文件及 WAL/SHM 总大小、前台查询缓存用量与预算，以及目录所在磁盘的可用量。进程内存不包括 Nginx/Caddy；磁盘可用量按目录展示，不应相加。

媒体、网站缓存、日志、快传文件、快传缓存采用按需扫描。每批最多访问 200 个条目，最多 32 层目录，不跟随子目录符号链接，文件数和跳过项分别统计。浏览器在显式点击后逐批请求，隐藏页面后停止继续请求；闲置 60 秒自动关闭扫描句柄，退出服务也关闭。完成结果缓存在当前进程中，刷新状态复用；重启后需重新统计。扫描中的目录变化会影响结果，数字为近似快照，不用于计费。

清理页面复用 Maintenance.tick，支持下一批预览和确认执行，展示最近结果、失败类型、后续批次提示及快传到期清理状态。预览仅代表一批候选，不是全库总量，执行时仍重新核对。失败时保留表单输入，按钮恢复可操作；禁止同时提交多个页面操作。自动/CLI/网页清理继续使用同一运行锁。

## 策略

已有 service_meta 保存 runtime:maintenance-policy，带 revision 乐观锁；保存与操作审计同事务。配置范围：自动间隔 1～1440 分钟，会话/操作/快传保留 1～3650 天，报告宽限/临时文件最少 24 小时，单份日志 1～100 MiB，归档 1～20 份、1～365 天。前台配额保护仍独立计算当前日/周/月边界，不会因缩短历史保留而删除有效计量。

自动循环每最多 30 秒读取策略；日志处理器使用锁更新参数，启动时先加载保存策略再处理旧归档。关闭自动清理仍更新日志策略。手动及 CLI 每次加载当前策略。更改归档数量会删除超过新上限的编号归档；新容量上限在后续写入时轮转，既有归档不会强制裁剪。历史清理生效后无法恢复被删除记录。

不新增表或索引；不自动清空媒体回收站、不压缩数据库、不修改快传配额设置。仅此版本新增策略共用配置及管理入口，既有默认值保持不变。

## 验收范围

自动验证管理员/普通账号/未登录权限、CSRF、策略冲突及字段范围、共享清理策略、关闭自动清理与手动预览、日志策略生效、分批扫描和缓存结果。真实后台模板的 DOM 测试覆盖保存失败保留输入、预览与执行确认、按钮状态恢复。尚未进行 Windows 实机视觉及长期负载验收；第五步完成整体持续运行验证。

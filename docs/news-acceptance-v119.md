# 第五步：新闻与后台编辑联调验收（v0.15.119）

本轮五个步骤全部完成。第五步补充跨功能回归，修正历史测试中的资源版本断言，整理部署与使用说明；没有再增加业务接口、数据库字段或依赖。

## 已交付内容

| 步骤 | 功能与验证范围 |
| --- | --- |
| 新闻封面 | 详情头部显示已配置封面，图片或支持的视频复用媒体组件；未配置时不留详情空位，列表保留分类占位。 |
| 新闻留言 | 遵守“允许评论或留言入口”，复用现有表单、验证与消息表；留言为私密消息，在后台查看，不生成公开评论区。关闭入口或新闻下线后拒绝新提交。 |
| 时间与时区 | 后台时间组件默认北京时间，可选 IANA 时区，保留实际时刻和毫秒；处理夏令时无效/重复时间。数据库继续保存 UTC，前台按浏览器时区显示。 |
| 列表排序 | 有编辑权限的列表可快速保存排序，复用现有保存和并发校验；保留筛选、勾选及其他行草稿，处理版本冲突与请求失败。 |
| 联调验收 | 同一新闻连续编辑时间、显示封面、提交私密留言、保存排序、调整为未来发布；核对字段互不覆盖、公开页面/站点地图及留言提交的发布限制。 |

## 更新方式

不需要数据库重建、重置或表结构迁移。

- 从 v0.15.117/v0.15.118 更新：更新完整代码并重启，运行依赖没有变化。
- 从 v0.15.116 及更早版本更新：同步依赖，v0.15.117 新增的 tzdata 为缺少系统时区数据的环境提供支持。
- Windows：保留数据时运行 `deploy/windows/start-existing.cmd`，现有引导器会检查依赖锁文件摘要。`start.cmd` 用于重建开发数据库，不应用于保留现有数据的升级。
- Linux：先将完整版本发布到已配置 GitHub 分支，再执行 `sudo tweb update --scope all`；不要加 `--reset`。本次交付没有自动推送仓库或部署服务器。源码单独更新遇到依赖差异会拒绝，应使用整站更新同步依赖。
- 自行维护 Python 环境时，用该环境的解释器执行 `-m pip install -r deploy/shared/requirements/requirements-vps.lock` 后重启。

时区选择由当前后台浏览器记忆，不为每条记录新增时区字段。前台使用浏览器时区设置，不申请位置权限。新闻留言仍是私密留言，而非公开楼层回复。

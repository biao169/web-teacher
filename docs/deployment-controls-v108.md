# 部署管理增强验收（v0.15.108）

日期：2026-09-28。基于 v0.15.107。只修改部署入口、管理脚本、教程和相应测试，未修改网站前后台业务代码；database/schema.sql 字节保持一致。

## 交付内容

- install.sh 支持 --port 或交互输入，start.sh / start-transfer.sh 支持 --port。校验 1024–65535，并保持主站/快传同端口。
- tweb 无参数显示循环双语菜单，带说明和终端颜色；重定向/NO_COLOR/dumb 终端自动关闭颜色。受管入口复用安装解释器，普通用户经 sudo 授权后进入。
- 更新分为 all、source、frontend、dependencies、database、config。源码/界面局部更新复用原虚拟环境；不兼容定义在停服前拒绝。
- 删除分为 cache、logs、media、transfer、database、source、all，显示路径并校验确认词。源码/数据库删除后停服，保留必要恢复入口；整站卸载删除本站管理对象。
- 端口同步到安装状态、service、健康检查和代理示例；冲突拒绝、健康失败恢复原配置。外部 nginx/Caddy 配置不自动改写。
- 新增服务账号目录创建/删除探测、源码/配置读取和已有数据库读写打开检查；可停服修复受管目录所有权和权限。不采用 777，不跟随数据目录内链接操作外部目标。

## 更新与操作边界

现有站点先在 GitHub web-py 分支上传完整包内容，再执行原 tweb update 更新管理器；之后重新运行 tweb 使用新菜单。脚本不自动发布 GitHub。

数据删除或重建有明确确认词；测试只使用临时合成数据。分项删除媒体/快传物理文件会留下数据库引用，旧资源将无法下载；逐条业务删除仍使用后台。完整卸载不删除系统共用依赖、journald 或其他站点的代理配置/证书。

默认正常更新不清库；本版无需数据库更新或重建。开发需要新站时沿用 db-reset，不新增迁移/备份机制；database 更新模式复用项目原有升级器，只有它已识别的旧结构可以升级。

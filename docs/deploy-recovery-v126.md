# v0.15.126：安装残留检测与部署修复

## 本次错误原因

`发布文件被修改、缺失或多出；拒绝验收` 表示 Git 克隆已经成功，但下载后的文件与 `release-manifest.json` 不一致。常见原因是只上传了部分新版文件、修改源码后未刷新清单、漏传隐藏文件或文本换行发生变化。现有日志不足以确定具体哪个文件。与系统账号残留是两个独立问题，删账号不能修复清单。

本版校验输出 missing、extra、changed 三类具体路径及总数，每类最多显示40个；不输出文件内容。安装端不自动重写清单来跳过校验。

## 发布到 GitHub

将本版完整代码更新到 `web-py`，包括根目录隐藏文件及 `release-manifest.json`。不要只覆盖几个脚本。预置媒体仍放在源码 `data/media/`。

如果你在发布前修改了代码，在最终源码根目录执行：

```bash
python -B deploy/vps/release.py manifest --root . --refresh
python -B deploy/vps/release.py verify --root .
```

将修改和新清单一起提交。建议在干净的 Git 克隆中再次执行 verify，避免本地存在但未上传的文件导致发布失败。不要在服务器下载到的、不完整的源码上直接刷新清单掩盖缺失。

## 一键安装保持原命令

先发布新版，然后执行以下命令；替换示例域名：

```bash
f=$(mktemp) && trap 'rm -f "$f"' EXIT && curl --fail --show-error --location --proto '=https' --tlsv1.2 'https://raw.githubusercontent.com/biao169/web-teacher/web-py/install.sh' -o "$f" && sudo bash "$f" --domain 'teacher.example.org'
```

脚本获取新版管理程序后检测旧目录、账号、用户组、服务和命令入口。有残留时提供：

1. 修复/续装，保留已有数据。
2. 彻底清理后重新安装。
3. 直接回车退出（不执行后续安装）。

第二项会列出固定清理范围，并要求输入 DELETE。它删除本站源码、数据库、媒体、快传文件、配置、服务、入口和专用账号。共享 Python/Git、系统包缓存和系统日志、外部 Nginx/Caddy 配置不删除。执行一次后退出，不循环显示菜单。

无终端输入时不自动清理。若只剩账号且没有安装记录，选择清理重装；不再需要你逐个执行 userdel/rm。同名登录账号、被其他账号使用的组、其他路径的同名服务、安装路径符号链接或挂载点不会被自动接管/删除。

## 修复范围

`repair` 从保存的仓库/分支重新获取源码，先校验后停止服务；恢复缺失的程序、current链接、专用账号、目录标记、入口、服务及默认权限。保留现有 storage.toml 和环境文件；缺失时按安装记录及默认存储布局生成。数据库初始化复用原有幂等方法，不执行重置。

- 有效 `install.json` 必须保留；缺失/损坏时无法猜测原仓库、域名等配置，应清理重装或人工恢复记录。
- 自定义存储路径需人工按原配置恢复，不自动改写。
- 被手动删除的数据库/媒体不能恢复；空库将走原有初始化流程。
- 本地缺少源码时可以重新下载；远程仓库本身的清单错误仍需修正发布。
- 修复中途失败可再次运行新版安装入口选择修复。原有数据不会被重置，但失败后服务可能保持停止。

新版管理入口可用时：

```bash
sudo tweb repair
sudo tweb clean-remnants
sudo tweb uninstall
```

后两者复用同一个清理方法，均需 DELETE 确认，支持安装记录已被删除。旧入口缺失时重新运行上面的一键安装命令。安装并不会自动修改防火墙或现有代理配置。

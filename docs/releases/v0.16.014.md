# v0.16.014 — 后台同步密钥接口（第二步）

基于 v0.16.013-step1。唯一初始化 SQL 和数据库表结构不变。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | /api/admin/site-sync/credentials | 返回配置来源、修订号、修改时间和操作者，不含密钥 |
| POST | /api/admin/site-sync/credentials | JSON key 字段保存密钥，返回不含密钥的状态 |
| POST | /api/admin/site-sync/credentials/reveal | JSON空对象，显式获取完整密钥用于后续显示/复制 |

所有接口要求当前有效后台会话、系统管理员身份和 data_tools 查看与编辑权限。POST要求 application/json、有效来源及会话CSRF令牌（x-csrf-token 或 _csrf），请求最大1024字节。读取完整密钥不支持GET，不通过URL参数传密钥。

保存和读取完整密钥均在事务中重新校验授权并记录无密钥审计。成功、业务失败以及405等路径响应均带 no-store；数据库异常不向客户端暴露SQL参数。HTTP调用方必须使用HTTPS和现有站点会话。

关键文件：site_sync/integration/credentials_api.py、credentials.py、web.py；测试 site_sync/tests_website/test_credentials_api.py。

阶段边界：runtime_integration=pending。接口可保存数据库配置，但现有同步运行仍读部署环境密钥；不要在此中间版本用后台配置替换实际运行密钥。后台按钮尚未添加，生成基础函数尚未开放HTTP接口。未进行真实Cloudflare D1线上验证。

下一步统一Linux/Python主站、原生JS辅助Worker及独立执行器的密钥读取；处理轮换后的鉴权失败和断点恢复。之后接入输入、生成、复制与保存按钮，调整部署和诊断并补充教程。

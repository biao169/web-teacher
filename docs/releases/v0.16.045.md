# v0.16.045 — 连通性与授权诊断（第二步）

基于本分支 v0.16.044 完整源码。未部署生产网站，未修改线上数据库或任务。

## 使用方法

两端均部署本版完整源码。无新增必填环境变量，无数据库结构变更；继续使用唯一的 `database/schema.sql`，已有站点不重新初始化。Cloudflare 沿用原网页构建部署流程，主站、原生辅助与独立执行器仍由现有流水线自动发布和核对版本，不需手工替换辅助 Worker。

1. 两端分别登录连接所属管理员，确认20项目录，并按需要点击“更新同步授权”。更新本站不会自动修改对端授权。
2. 点击“测试同步连通性”。测试仅读取少量签名能力元数据，不再选择媒体或其他业务范围读取候选页，也不创建任务。
3. 结果分别显示本地连接、原生辅助状态（Worker）、对端实例、签名握手、对端授权。`connectivity_ok=true` 表示签名握手通过；`authorization_ok=false` 表示当前本地可用恢复目录中有对端未授权项目。界面会列出中文名称及范围标识。
4. 创建手动拉取、发送推送提案、保存启用的定时计划时，服务端重新检查实际选择及自动依赖。只需授权本次所选范围，不要求全部20项都开放。
5. 如果提示缺少“角色、权限”，例如本次选择了用户账号，请在对端补齐对应授权后再提交。不会自动替用户扩权。

旧版对端未实现 `probe-v2` 时，提示握手或协议检查未完成，需升级两端。不能根据握手失败直接认定密钥错误，更不能推断1101/1102。域名、网络、签名、时钟、HTTP状态、原生辅助错误仍通过原诊断链提供。

## 创建前检查与错误响应

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `SYNC_PEER_SCOPE_MISSING`（409） | 签名握手正常，但对端未开放所需范围或导出已停用 | 显示 `missing_scopes`、`missing_scope_details`，到对端更新授权 |
| `SYNC_PREFLIGHT_UNAVAILABLE`（503） | 网络、签名、协议或运行状态导致能力检查未完成 | 保留 `diagnostic`、请求ID及可获得的对端追踪信息；不冒报缺少范围 |
| `SYNC_INPUT_INVALID`（400） | 本地参数不合法 | 继续提供字段名、要求和请求ID；先校验本地参数，再联系对端 |

响应中的缺少范围包括依赖。例如教师资料需要媒体；账号需要角色与权限。缺少授权时不写入新任务、执行日志或启用计划；推送预检失败不记录为“已发送但结果未知”。

任务创建预检最长10秒，连通性测试整体最长15秒；控制响应沿用8KiB上限及签名验证，不传正文、媒体、密钥或密码哈希。能力握手必须经过现有密钥签名校验；同步全局暂停仍生效。

授权预检只是创建前反馈，实际每次读取仍执行原有授权校验。预检后授权撤销会由执行阶段识别，不缓存授权、不绕过接收端审核。既有任务及定时任务执行逻辑、三种模式定义不变。

同一请求ID重试已有手动任务、已确认推送回执时，复用持久化记录；不会因重复预检创建第二个任务。暂停、取消、删除及只读列表不进行对端预检。启用计划检查对端；暂停或删除计划允许对端离线。

## 文件

- `site_sync/integration/capabilities.py`：能力发布、签名握手、依赖范围比较、创建前检查。
- `site_sync/integration/peer_api.py`：新增有签名的 `probe-v2` 响应；不扫描业务数据。
- `site_sync/admin/connectivity.py`：拆分连通性与授权结果。
- `site_sync/core/preflight_errors.py`：结构化预检错误。
- `site_sync/core/receiver.py`：提取共享参数校验，确保不合法输入先返回400。
- `site_sync/admin/service.py`、`asgi.py`：任务/启用计划检查与错误输出。
- `site_sync/integration/web.py`、`proposals.py`：两平台统一接入；发送前校验与回执幂等。
- `site_sync/frontend/templates/page.html`、`static/connection.mjs`、`static/panel.mjs`：共用页面的分层结果、缺少授权提示和追踪详情。
- `site_sync/tests_website/test_capabilities_v045.py`：签名接口、授权不足、依赖、无副作用、重复提交、离线暂停删除与错误脱敏测试。
- 原有连通性、授权、推送、UI测试按新协议更新；原生传输增加签名能力响应验证。
- 运行与构建版本常量同步为0.16.045。无需修改原生传输允许类型：新握手仍使用原有 `probe` 类型。

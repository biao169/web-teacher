# v0.16.022 · 第四步：整站克隆

基于本对话 v0.16.021 第三步交付包继续修改，未使用其他分支代码。操作教程见 [整站克隆说明](../sync-clone-setup.md)。

## 本步完成

- 增加系统管理员专用 `site_clone` 范围，手动拉取、接收推送和定时拉取共用服务端流程。整站范围单独选择，包含账号密码哈希、角色权限、业务配置和媒体清单。推送默认一次整任务审核；切片不审核。
- 按表和 UID 索引逐条发现，取消整站模式的 500 条候选限制；媒体独立枚举，覆盖未引用、回收站及空文件。
- 全部传输暂存后应用，逐记录恢复和清理；支持唯一值冲突、媒体路径及外键引用更新。账号最后一个事务替换，撤销旧会话并将连接和计划授权交给恢复后的管理员。
- 本地媒体与 R2 使用既有持久断点和原生流。正文上限扩大至 1 MiB，单媒体至 1 GiB；R2 分段回执直接从 D1 读取，正文哈希在原生服务中计算，减少 Python/JS 跨界拷贝。
- 部署自动检查结构并从本分支前版扩大同步表容量，保留断点；仍只有 `database/schema.sql` 一个初始化 SQL。更新前保留 SQLite 备份或 D1 恢复书签。

## 验证与边界

- 同步核心、网站接入及 Cloudflare 部署相关 Python 回归：515 项通过，另有 47 项子测试通过。最终克隆专项 6 项通过，覆盖超过 500 条清单、长正文、媒体引用更新、目标多余记录、密码哈希、不同管理员 UID 授权接续、编辑锁、源清单变化、升级断点保留和一次推送批准。
- 原生 JS：39 项通过，包含超过 20 MiB 的流式媒体、空文件、失联恢复和原生快照哈希；DOM 与状态模型：6 项通过。
- `inline`、`separate` 均通过离线源代码打包、运行时导入及 VPS 配置生成。未运行真实 Cloudflare 发布、Wrangler SDK 上传或线上 CPU/内存额度测试。
- 整站克隆保留本站部署身份和同步控制数据，不复制会话及临时运行任务，不是数据库文件镜像。目标旧媒体物理文件保留；当前正文、媒体及账号事务边界详见教程。应用期间保持读访问，暂缓普通写操作；暂停/取消不会回滚已经应用的数据。

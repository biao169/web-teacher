## 预算与保留边界

- 后台正文切片配置仍允许 4 KiB 至 4 MiB，不静默降低用户的配置。小型候选、manifest 等响应预算仍为 8 KiB；正文 RPC 最高 4 MiB。
- 正文仍需在当前分片内完成签名摘要及持久写入，因此使用有上限的完整分片缓冲。本轮减少重复表示和拷贝，不宣称零拷贝或所有正文全程流式。
- 单记录导出快照保留既有 1 MiB 上限；SQL 先过滤长度，避免非法超限快照先被取回再拒绝。没有扩大记录、清单、数据库事务的既有上限。
- R2 媒体保持原生 Response.body → uploadPart 流式路径，不经过 Python 或整文件 arrayBuffer；R2 多段上传仍使用既有 5 MiB 分段，最后一段可更小。它与后台正文切片配置是不同边界，本轮不修改 R2 分段协议。
- 已审查活跃原生传输、运行时、适配器路径：未引入 Promise.all 或后台扇出下载。保持一个 tick 的一个重步骤；保留现有租约和调度约束，不新增进程全局并发器。
- D1 buffer 复用字典只存在于一次 batch 调用中，不跨请求保存正文、任务或断点。进度仍保存在数据库，沿用上一步候选/游标、正文回执、媒体回执的原子提交。
- separate 模式入口隔离不变：普通页面、任务列表/详情读取不会触发同步。没有新增初始化扫描、任务恢复入口或国家/PoP 特例。

## 错误与恢复

正常控制错误仍保留 HTTP 状态、平台码、阶段、请求 ID 等诊断；正文大小或长度不符明确抛错，交给已有任务异常边界记录并保留持久断点。平台直接终止执行的情况仍依靠已提交的 checkpoint 与租约恢复，不假设可以捕获或销毁 Cloudflare isolate。

协议不匹配显示 `SYNC_NATIVE_PROTOCOL`，不会退回高开销 Base64 正文传输。请部署完整版本，现有部署流程会自动更新原生辅助 Worker 和 separate 执行器；无需新增变量或手工更新辅助 Worker。多 Worker 发布不是原子切换，发布期间若发生短暂协议不匹配，应等整次部署成功后重试并核对各组件版本。

1101/1102 的诊断能力沿用此前实现；仅收到 1102 时仍不能凭空判定 CPU 或内存。需要 Cloudflare 平台 outcome/日志确认 exceededCpu 或 exceededMemory。本轮没有上线或操作生产数据库。

- 原生模块：51 项通过；后台 DOM/模型：7 项通过。
- 本地 workerd：2 项通过，包含生产原生辅助代码的跨 Worker Uint8Array RPC、4 MiB 正文、ArrayBuffer D1 绑定和签名传输诊断。

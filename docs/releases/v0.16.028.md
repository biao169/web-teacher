# v0.16.028 · 第一步：请求修复与分层诊断

基于本分支 v0.16.027-step3，不引用其他分支。唯一初始化 SQL 仍为 `database/schema.sql`。

## 本轮修改

- 连通性测试先执行签名握手，再读取单个合法范围的候选；授权列表中的普通模块与 `restore_*` 不再混合交给查询器。查询器也拒绝混合范围，避免查询不存在的虚拟表。
- 请求签名、时间窗口、密钥读取、导出权限和范围检查返回独立诊断码。对端返回空错误正文，通过有界响应头提供阶段、版本和追踪 ID。
- Python、本地 HTTP、原生辅助 RPC、任务日志保留安全诊断字段；后台日志直接显示具体原因。原生堆栈只保留模块名、函数与行号，不输出原始异常内容。
- 主站 FETCH、同步执行器、协调器增加组件及版本上下文；主站 500 响应记录追踪 ID、路由分类和可用的 Cloudflare Ray ID。
- 原有部署流水线继续自动打包并更新原生辅助；新增诊断模块随辅助代码一起发布，separate 模式同步更新执行器。不要只替换主站入口文件。

## 如何看日志

| 字段 | 用途 |
| --- | --- |
| code | 应用诊断码，见下表 |
| http_status | 实际取得的 HTTP 状态，如 403 |
| platform_code | 取得的 Cloudflare 1101/1102 信息；缺失不代表没有发生 |
| component / peer_component | 本地辅助、对端主站或对端原生媒体服务 |
| stage / peer_stage | 本地调用阶段及对端处理阶段 |
| request_id / peer_request_id | 对照任务诊断与对端日志；已发出的签名请求使用 nonce 关联 |
| ray_id | 存在时用于查 Cloudflare 请求日志 |
| release / peer_release | 本地及对端实际诊断代码版本 |
| frames / native_frames | 安全代码位置，不含正文、密钥与 SQL |

| 诊断码 | 排查内容 |
| --- | --- |
| SYNC_KEY_MISSING / SYNC_KEY_INVALID | 有效密钥是否存在，数据库保存格式是否正确 |
| SYNC_SIGNATURE_INVALID | 两端实际生效密钥是否一致；数据库配置优先于环境变量 |
| SYNC_CLOCK_SKEW | 请求是否超过 120 秒签名窗口、系统时间是否准确 |
| SYNC_ENVELOPE_INVALID | 签名头是否缺失或格式错误 |
| SYNC_EXPORT_DISABLED | 对端连接、导出授权是否启用及过期 |
| SYNC_SCOPE_DENIED / SYNC_SCOPE_INVALID | 授权是否覆盖选择范围，是否混用两类范围 |
| SYNC_SCHEMA_MISSING | 数据库表或字段缺失；检查部署初始化日志 |
| SYNC_RPC_FAILED | 本地到辅助 RPC 失败；不能单凭此码判定 CPU 超限 |
| PEER_HTTP_FORBIDDEN | 实际 401/403，但未取得可识别的应用原因；检查对端与安全规则 |
| SYNC_SOURCE_FAILED / SYNC_STORAGE_FAILED | 导出或存储失败，结合阶段和对端追踪日志 |

错误响应头是对端报告的辅助线索，不经过成功响应的签名验证，不能作为授权依据或可靠性证明；授权与正文验证流程保持独立。任务日志标明 `peer_diagnostic_verified: false`。平台强制终止可能来不及运行异常处理或输出日志，仍需查看 Cloudflare 原始运行日志。

## 更新与验证

两端使用本包，沿用现有网页构建/部署命令和模式变量，部署流程更新辅助 Worker；本次不增加环境变量或数据库表。部署后执行连通性测试，应依次显示连接、客户端、签名握手、候选读取四阶段。若失败，保留 JSON 中的诊断码、阶段、追踪 ID 与时间，对照对应 Worker 日志，不要公开密钥。

验证结果：Python 535 项及 47 项子测试通过；原生 JS 42 项、前端 DOM 6 项、workerd 传输 1 项通过。完成 inline/separate 离线部署打包与入口导入验证。未发布线上 Worker，未验证真实 D1/R2 与账户 CPU/内存额度；不能据此声称已解决线上 1101/1102。

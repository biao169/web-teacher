# v0.16.042：第五步，共享同步界面与计划管理

基于本分支 v0.16.041-sync-step4 完整源码。未引用其他分支代码，未操作线上数据库或执行部署。

## 本轮内容

- Ubuntu 与 Worker 继续共用 `site_sync/frontend/templates/page.html`、`panel.html` 和 `site_sync/frontend/static/`，新增打包一致性断言，防止两端打包出不同界面。
- `panel.css` 修复 `.sync-settings-block` 覆盖外层卡片内边距的问题：运行控制卡片桌面留白 24px、窄屏 16px，沿用后台配色与控件。
- `panel.html`、`panel.mjs` 增加“暂停自动刷新 / 恢复自动刷新”。可见页面默认每 60 秒刷新任务、计划和当前详情；隐藏页面不轮询，恢复可见后重新计时。编辑输入时跳过一次轮询。暂停仅影响浏览器状态读取，后台执行器仍继续工作；已发出的状态请求允许完成。
- 新增 `status-poller.mjs` 管理计时器，防止恢复刷新时重叠轮询，失败后仍按 60 秒间隔重试并显示错误。
- 定时计划增加删除按钮与确认提示，删除当前编辑计划后表单回到新增。已有任务和断点保留，需取消任务时使用任务自身的取消功能。
- `site_sync/admin/service.py`、`asgi.py` 新增 `POST /admin/site-sync/api/schedules/{id}/delete`。检查会话、CSRF、归属、有效授权、写权限和 revision；冲突返回 409。删除不唤醒同步任务。
- `site_sync/adapters/tasks.py`、`runtime/schedules.py` 在调度创建任务的同一 SQL 中检查计划 ID、修订号、下次执行时间、启用状态和归属，防止删除/暂停/编辑后，旧调度快照继续创建任务。删除之前已经成功创建的任务仍保留。
- 新增计划空状态、更新界面说明与 CSS/JS 版本参数。系统内容仍限定在相应权限的系统管理员授权范围，未自动扩大已有授权。

## 两端选项不同如何处理

当前源码中两端都使用同一套模板、权限判断与 20 项分项恢复目录。选项来自已保存的同步授权，不是按部署平台硬编码。

1. 两端都部署这个完整版本，避免混用旧静态资源和旧模板。
2. 使用具备数据管理权限的系统管理员登录。
3. 展开“连接、密钥与接收策略”，检查接收自动确认范围，点击“保存连接与当前授权”，再刷新。
4. 检查新建任务和计划是否均显示媒体、账号、角色、权限等卡片；普通受限账号不会因此获得系统恢复权限。

不能仅凭离线源码判断线上差异究竟是旧版本、缓存还是授权范围。页面已补充对应说明，未静默更改任何线上授权。

## 验证与部署边界

新增轮询计时器测试、SQLite/D1 适配器计划删除与过期调度快照测试、后台 API/CSRF/完整选项测试。离线 Worker inline/separate 打包均校验同步模板与静态资源和本地源码逐字节一致，覆盖快照及执行器冷导入。

验证结果：完整 Python 回归 730 通过、47 子测试通过、1 跳过；另行运行新增 UI/API 测试文件 13 通过。JavaScript 测试 62 通过。inline/separate 离线部署检查均通过。

没有新增环境变量、数据库表或初始化 SQL。保持唯一 `database/schema.sql`，不要为升级清空数据库或重新执行空库初始化。保留现有 TEACHER_SYNC_EXECUTOR_MODE 和部署绑定，按既有部署流程更新整包；Cloudflare 辅助 Worker 仍由既有部署流水线自动发布。

本轮未做真实浏览器视觉验收、Wrangler SDK bundle、线上 D1/R2 或 Ubuntu 实机发布，离线通过不等同于云端资源额度验收。

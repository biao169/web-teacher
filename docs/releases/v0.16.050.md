# v0.16.050：Step 1 后台首页轻量化

基于 v0.16.049-step0-baseline。仅完成后台首页减负，不提前拆 Public/Admin，不调整首页数据加载或媒体引用查询。

## 修改前后

原路径：GET /admin → 鉴权 → 逐个授权表调用完整 listing → COUNT + 记录读取/排序/对象构造 → 渲染卡片。

新路径：GET /admin → 鉴权 → 按授权模块渲染卡片（数量为 —）→ 页面专属脚本发送一次 GET /api/admin/dashboard-counts → 顺序执行标量 COUNT → 更新各卡片。

- Content.count 对表名使用既有 TABLES 白名单，调用现有 auth.require 与 scope。只接受已知表，不接收用户传入SQL。
- 数量与无筛选 listing 的 total 一致，包括角色可见范围；没有改成全库无权限计数。
- API 重新读取当前身份，匿名401、强制改密403；只返回可查看模块。没有权限的模块不出现在JSON中。
- 不调用 listing、媒体引用、翻译或同步执行逻辑；不加载业务记录。计数顺序执行，无 Promise.all 或服务器并发扇出。
- Cache-Control: no-store；不增加跨用户缓存。
- 脚本只在 dashboard 标记存在时动态导入，其他后台页面不调用统计接口。
- 每页一次统计请求、15秒超时、手动重试；进行中禁用重复请求。失败保持 — 与模块链接可用。
- 复用 adminFetch，登录失效或无权访问沿用统一提示。离页取消浏览器请求；这不保证服务器当前SQL被立即终止。

## 双平台对比

同一临时SQLite样本、最高管理员；数据来自 docs/baselines/step0/platform/baseline.json 与本版本测试目录 platform/baseline.json。

| 项目 | Step 0 | Step 1 |
|---|---:|---:|
| /admin 首屏 query 调用 | 40 | 4 |
| /admin listing 调用 | 18 | 0 |
| 新增统计API query调用 | 无 | 20（18个COUNT+身份读取） |
| 首屏和统计合计 query调用 | 40 | 24 |
| 统计业务记录读取 | 每表列表记录 | 无 |
| 页面请求数量（不含静态资源） | 1 | 2 |

这些是 query 方法调用数，未计鉴权既有 session 更新的 batch 调用；不等同于数据库内部语句数、D1计费行数或CloudflareCPU。COUNT成本仍随数据规模/索引而变化，本步不承诺任意数据量下固定CPU。没有提高cpu_ms，也没有引入未经测量的统计缓存。

Ubuntu/Debian仍为每站点一个systemd服务、一个端口、一个Uvicorn worker、一次install_local；预算不变。Cloudflare仍保留现有separate Executor与Native；没有增加Worker或Cron。两端使用相同模板、脚本与Content.count实现。

## 部署与边界

沿用原有Windows、Ubuntu/Debian或Cloudflare发布方式；无新增环境变量，无数据库结构变化，无需重置数据库、媒体、任务或授权。完整包同时更新HTML、native.js和新增脚本，避免只更新Python漏掉静态资源。

未执行线上发布、真实Cloudflare CPU/outcome/PoP测量或真实VPS资源验收。所有性能数量为可重复的离线样本结果；本轮无法保证仅此一步就消除所有1101/1102。

# v0.16.059 — Step 4：浏览器缓存策略

基于 v0.16.058，继续保留 ETag / 304、匿名 Render Cache、Public Data Cache 和前后台 Worker 物理隔离。

## HTTP 策略

| 响应 | Cache-Control |
| --- | --- |
| 匿名、安全完整 HTML 首页/列表/固定导航列表 | public, max-age=300（使用页面 TTL 实际配置值） |
| 登录、安全完整 HTML | private, no-cache + 身份/权限 ETag |
| 页面 TTL=0、数据缓存仍启用的完整安全 HTML | private, no-cache + ETag |
| 页面与数据 TTL 都为0 | no-store，无 ETag |
| contact、详情、一次性 challenge、Authorization、Set-Cookie、错误 | no-store |
| 原有 fragment | 原策略不变；当前修订的匿名分片使用数据 TTL；登录分片 no-store |
| Admin/Auth/Sync/Transfer | 本轮不改变原有 no-store 策略 |

公共响应继续 Vary: Cookie, Authorization, X-Public-Fragment。200、HEAD、304 和 Render Cache HIT 使用一致的策略。登录页面中的会话绑定退出令牌只随该身份的私有 HTML 保存，不能进入匿名共享缓存；带一次性 challenge 或 Set-Cookie 的响应仍禁止保存。

public_headers 新增 safe 标记，仅已完成路由、身份、导航、参数校验且具有本轮 ETag 的安全表示可以启用页面缓存。详情页本轮继续排除，避免把没有留言的详情误扩大为共享缓存。finish 再次检查 Set-Cookie / 错误状态，强制 no-store 并移除 ETag。

缓存 TTL 不改变业务可见性或服务器授权检查；条件请求仍先检查身份与当前有效权限。退出、会话过期、角色权限变化不会用原私有页面 ETag 返回304。

## 浏览器返回 / 前进

前端仍是普通 HTML 导航，不改成 SPA。复用 public-stream.js 原有 pageshow/pagehide 机制：

1. 身份指纹改为当前 principal（包含有效权限、角色和显示信息）的不可逆摘要；/api/public/cache-revision 与页面 data-public-identity 使用同一函数。
2. 登录页面 pagehide 时隐藏正文，暂停分片并取消正在进行的恢复检查；减少 BFCache 恢复时显示旧私有内容的机会。
3. 仅 pageshow.persisted 时调用 no-store 状态接口；首次普通导航不新增身份检查请求。
4. 相同身份/权限及修订号才显示旧页面、恢复分片；变化则完整 reload。
5. 检查失败、非成功状态、格式错误或5秒超时：登录页面保持隐藏并 reload；匿名页面在无法校验时可继续显示已有公开内容。
6. pagehide 后的迟到响应不能重新显示页面或推进分片；使用请求序号和 AbortController 防止竞态。

这是恢复流程保护，不代表可以撤回用户已下载的页面或清除所有浏览器历史。线上浏览器是否使用 BFCache 仍由浏览器决定。

## 五分钟的实际含义

匿名完整页面处于浏览器 freshness 有效期时，可以不发起页面网络请求。后台写入只改变服务器 revision，不能主动清除浏览器已经新鲜的 HTML。默认内容更新最多可能延迟一个300秒窗口；自定义 TTL 则按配置窗口。到期后请求带旧 ETag，未变化可304，变化则200新页面。服务器 Render Cache 与浏览器缓存职责不同。

本轮未加入导航预取；首次访问一个尚未缓存的页面仍需网络请求。新闻到点发布的服务器键失效保留，但不能绕过尚未过期的浏览器 freshness。没有宣称所有切换都即时响应。

# v0.16.013 — 同步密钥基础层（第一步）

基于 v0.16.012-step3，仅完成本轮规划第一步。

新增 site_sync/integration/credentials.py：复用 service_meta 的 site_sync.credentials.v1 单条 JSON，保存版本、密钥、随机修订号、UTC修改时间和操作者。唯一初始化 database/schema.sql 不变。

- 64位十六进制校验，允许粘贴前后空白，统一小写；拒绝空白清除。
- 安全生成32字节随机草稿，不自动保存。
- 新读取接口：数据库优先、环境变量后备；无长期缓存，损坏记录不回退旧密钥。
- 管理操作要求系统管理员及 data_tools 编辑权限；保存事务重新验证当前会话、角色和授权，密钥与不含密钥的审计记录原子写入。
- 状态响应和对象 repr 不包含密钥；内部 resolve 返回敏感对象，仅供运行链路调用，不得直接序列化、返回客户端或记录日志。
- service_meta 不属于普通业务导出或同步模块；完整数据库备份仍包含敏感密钥，存储未宣称加密。

边界：本阶段没有HTTP接口、后台输入框、复制按钮或JS原生Worker接入；原有环境密钥链路不变。部署密钥仍按旧规则必填。不要直接改数据库启用此中间实现。

下一步：增加后台状态、保存与受控读取接口，补充CSRF、no-store与权限测试。后续统一Worker读取、实现界面、放宽部署必填限制并验证轮换恢复。真实D1/Worker尚未验收。

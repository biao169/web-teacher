# v0.16.003：三种同步模式与服务端自动确认

本次在本分支 v0.16.002 上完成第二步，没有引用其他网站版本。完整站点来源仍为指定的 v0.15.160 分支。

## 使用方式

进入后台侧边栏“两站同步”（`/admin/site-sync`），两端配置相同部署密钥并分别保存对端 HTTPS 地址。

| 操作 | 行为 |
| --- | --- |
| 手动拉取 | 默认勾选“自动确认本次拉取”，点击“拉取到本站”后，由服务端发现候选、传输、写入和清理；取消勾选则停在人工审核。 |
| 手动推送 | 点击“推送到对端”，在对端创建接收任务并返回对端任务ID。默认由对端审核一次；批准后服务端完成剩余流程。 |
| 定时自动拉取 | 设置周期并启用计划，到期自动创建拉取任务，无需逐次批准。已有活动任务时不会叠加自动任务。 |

推送实际采用“通知接收端，由接收端后台拉取”的传输方式，不在按钮请求中长时间上传全部数据。返回任务ID表示对端已受理，不表示已经同步完成。

## 自动确认与权限

- 自动确认存为任务字段 `auto_confirm`，是否自动处理明确删除存为 `auto_delete`。每个候选发现后按策略选择；发现完成后在服务端直接转入传输，不依赖网页回调。
- 本站手动拉取默认自动确认，界面明确显示“包含对端明确删除”选项，仍需账号具备删除权限。只处理明确墓碑，不因本地多出记录推断删除。
- 接收端连接增加 `incoming_auto_scope` 与 `incoming_auto_delete`。自动确认范围默认空，即收到推送时默认人工审核。只有请求中的所有模块都落在接收端授权范围内，才自动确认整项任务；部分匹配不会悄悄自动执行一部分。
- 接收推送默认不自动处理删除。接收端可主动开启；没有删除权限仍不能执行删除。
- 推送请求不能携带或覆盖接收端审核策略。策略读取和任务创建绑定授权修订，避免并发修改后沿用过时授权。
- 重复创建请求复用任务；同一请求ID不能改为不同范围或审核方式。任务列表显示模式及自动确认/人工审核状态。
- 人工审核选定条目并批准一次后自动执行剩余流程。关闭网页、会话退出不会取消已授权任务；管理员撤销账号、权限或站点授权仍会阻止继续写入。

本地仍需网站服务持续运行，Worker 仍需正确配置现有 Cron 和私有原生服务；“后台完成”不意味着平台停止调度时仍能运行。

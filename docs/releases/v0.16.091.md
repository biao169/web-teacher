# v0.16.091 — 仅 PublicPage 平台缓存

## 请求路径

Default Router 不缓存。仅标准首页 /en、/zh 及标准列表（教师、学生、研究方向、项目、论文、专利、课程、新闻）的 GET/HEAD，通过 self.ctx.exports.PublicPage.fetch 进入可缓存 named entrypoint。MISS 才调用现有 dispatch/FastAPI；HIT 跳过 PublicPage 的 Python渲染与D1。Default本身仍是Python，会运行轻量路由与原有诊断；不能宣称整个请求零Python CPU。

所有详情页暂不进入PublicPage（新闻详情可能含评论表单）；自定义nav/nv、fragment、JSON请求、Range、写操作、__recover 均直通原路径。Admin/Auth/API/Sync 不进入PublicPage。未增加Worker数量。

平台配置：
```json
{"cache":{"enabled":false,"cross_version_cache":false},"exports":{"default":{"type":"worker","cache":{"enabled":false}},"PublicPage":{"type":"worker","cache":{"enabled":true}}}}
```

调用缓存之前沿用允许域名校验。仅对已确定可共享的路径，复制Request并删除Cookie/Authorization；原始请求保持不变。PublicPage不读取身份。私有项目字段由现有鉴权接口按需取得。

## Cloudflare网页部署

仍使用现有Git构建与 python build.py check / python build.py deploy 流程，不需要GitHub Actions或手工增加辅助Worker。建议在构建变量保持：
- TEACHER_WORKER_CACHE_MODE=simple
- TEACHER_PUBLIC_PAGE_CACHE_TTL_SECONDS=1800
- TEACHER_SYNC_EXECUTOR_MODE=separate

其余账户、数据库、媒体桶、域名与密钥变量沿用原配置。本次必须重新构建发布，让生成的exports配置和PublicPage导出一起生效；仅改运行变量不能创建named entrypoint。

不要在网页设置中把整个默认入口改成cache enabled。部署生成的配置应是Default OFF、PublicPage ON、Admin OFF。Wrangler固定4.143.0支持此exports结构（官方按入口缓存要求4.107.0或以上）。没有DO迁移改动。

simple/full现在都只使用PublicPage平台HTML缓存，full不再启用旧的Python SQL/Page Cache API，作为配置兼容别名。两者默认预取0、stream并发1。off关闭PublicPage缓存且Public TTL为0。TEACHER_WORKER_REQUEST_CACHE强制0。Ubuntu/Debian页面LRU及部署结构不变。

浏览器继续保留public,max-age=1800与ETag/304；原HTTP stale响应头保留，无应用层stale回退。共享内容变更可能在TTL内仍显示旧内容，本轮不添加主动失效查询。新发布版本缓存隔离。Cache HIT不会消除另行发起的fragment或身份接口请求及其D1开销。

## 身份状态

/api/public/session-summary仍转交SITE_ADMIN，使用Auth.public_principal。响应private,no-store及Cloudflare-CDN-Cache-Control:no-store。初始显示身份确认中；明确authenticated=false才显示登录。页面切换、网络错误和取消不会把用户名改成未登录；旧CSRF表单与私有字段仍会清理。显式退出/账号变更清除旧身份。完整页面跳转后不持久存储用户名，新页面先显示身份确认中。

## 验证

200项Python、14项子测试通过，13项DOM测试通过。Public/命名入口、匿名请求复制、域名阻断、API绕过、共享HTML/ETag、无私有字段、模式配置和Admin边界均已覆盖。simple/full/off+separate离线打包及Python快照导入通过。额外重跑30项入口测试通过（不重复累计）。

本轮未进行真实Cloudflare发布、Wrangler Python SDK bundle、Pyodide loopback运行、生产D1测量、CPU/内存或MISS/HIT实测。不能以模拟的loopback测试代替平台缓存验收。

部署后对 /en、/zh、/en/profiles、/en/projects、/en/publications 各进行两次顺序GET，不带随机参数或Cache-Control:no-cache。记录CF-Cache-Status、Age、耗时和Worker观测中的entrypoint调用；同版本同URL预期MISS后HIT。Default每次执行是预期行为，重点确认PublicPage及D1不再在HIT上重复执行。浏览器直接从本地缓存返回时没有平台请求，不能拿该请求判断Worker命中率。

再登录切换前台页面，模拟session-summary 503/超时，确认显示上次用户名或身份确认中；只有真实匿名响应显示登录。检查Admin/Auth/API从未调用PublicPage。若实际缓存头被外层覆盖，以PublicPage的Worker trace/cache事件核对，不人为伪造HIT响应头。

官方依据：
- https://developers.cloudflare.com/workers/cache/configuration/
- https://developers.cloudflare.com/workers/cache/debugging/

不改Sync Executor/Native、协议、checkpoint、媒体同步、数据库或Linux部署。没有新增Recovery层或snapshot预加载。

基线 v0.16.054。本次不发布到线上；Cloudflare 真实 Python/JS FFI、CPU/PoP 和浏览器视觉效果仍需上线验收。

## 交付核对（20项）

1. 修改文件见文末清单。
2. TTL 在 backend/app/public_performance.py 的 PublicPerformance.from_env 统一解析。
3. 分片并发在同一入口解析，服务器输出 data-public-stream-concurrency。
4. 未设置默认 TTL=1800 秒，并发=2。
5. TTL 0～86400，并发1～4；0关闭持久公共缓存，原请求内轻量去重仍可工作。
6. 显式非法值抛 ValueError，包含变量名、输入值、范围和默认值；Linux runtime 初始化和 Worker构建校验使用此解析器。
7. Worker Public运行变量与Builds构建变量使用相同两名称，修改后重新部署。Admin不需要配置。
8. Linux编辑 /etc/teacher-site/teacher-site.env 后 tweb restart，直接 start.sh 同样支持环境变量。
9. 命名实例各用 /etc/teacher-site-<instance>/teacher-site.env 和对应service。
10. tweb.generate 使用 preserved_keys/preserved_env 保留性能参数、容量和原同步配置；configure 修改端口/域名保留原env；普通升级/修复复用generate。无需增设服务。
11. 匿名带当前revision的列表JSON分片 public,max-age=TTL；内部缓存匿名公共读取结果，包括翻译/媒体映射读取。key包含版本、匿名身份、路径、规范排序查询、fragment标志、SQL与参数；语言/分页/home包含在路径/参数中。
12. 登录/管理员响应、表单、写操作、错误、Admin/Auth/Sync/Transfer继续no-store；其他未纳入缓存的公共API维持原策略。无版本匿名页面和分片 private,no-cache。Vary包含Cookie、Authorization、X-Public-Fragment。
13. Worker PublicSQL通过Cloudflare Cache API存储有界查询结果，命名空间隔离，不把结果长期保存在Python堆。每项64KiB、最多500行；缓存失败/驱逐回源，内存只有当前请求。此后端单元测试使用模拟Cache API，真实部署仍需验收。
14. Linux复用PublicReadCache的LRU/TTL、2048项上限和CacheBudget；压力下降缩容、严重压力预算归零并清空。缓存异常不替代正常DB读取。
15. service_meta只有一个public_cache_revision键，值为随机唯一版本token。公开业务批次写入时同事务替换；失败回滚。新增一次轻量SQL写入；同步日志/chunk/checkpoint不触发；公开数据真正apply会触发。没有新增表/第二个SQL文件。浏览器收到旧revision请求不获得长期新鲜缓存。
16. 首页section/group默认hidden；pending/loading保持隐藏，total>0且真实article存在才ready/显示；total=0为empty/隐藏。采用opacity transition，支持减少动态效果。无JS时通过原导航进入列表。
17. active/queue/concurrency有界调度，finally释放名额。pagehide取消请求，pageshow恢复；Save-Data仍加载隐藏模块第一页，后续自动滚动保持节流；首片失败提供统一重试按钮，不显示虚假的空模块。请求不再强制no-store。
18. 不改同步协议、20 scopes、调度、checkpoint或确认状态机。只经共用SQL适配器接入业务写入失效；site_sync中的改动仅版本诊断字符串。
19. Ubuntu仍单service/单Uvicorn worker/单端口/单FastAPI、install_local一次；Worker角色拆分保持。
20. README.md、deploy/linux/README.md、deploy/cloudflare/README.md新增“公共页面缓存与前台加载并发”及对应平台配置教程；deploy/vps/release.py env模板给出可选注释。

## 浏览器更新边界

仅服务器revision不能撤销浏览器已缓存的响应。因此完整HTML外壳采用private,no-cache，进入页面时重新取得版本；版本化分片按TTL缓存。BFCache返回时请求只读revision和脱敏会话指纹，变化时刷新；认证页检查失败时也重新导航。已经保持打开的页面不会收到服务器主动推送，要刷新或重新进入后取得新版本。不宣称“修改数据库瞬间清除所有浏览器缓存”。

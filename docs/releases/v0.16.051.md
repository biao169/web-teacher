# v0.16.051：Step 2 首页首次请求轻量化

基于 v0.16.050。共享首页由“首请求读取教师和全部启用模块”改为“首请求读取教师、网站配置、导航；后续串行加载各模块首批”。不拆部署，不修改同步业务、媒体传输或认证。

## 执行路径

原：GET /en 或 /zh → 首页教师 → 各启用模块列表、媒体映射和翻译 → 完整首页。

新：GET /en 或 /zh → 首页教师/配置/导航 → 启用模块空容器（page=0）→ public-stream.js现有FIFO队列 → 原公开fragment接口page=1 → 原后续分页。

- home_limit统一解析数量配置，初始容器和后续列表使用同一默认值；数量0不生成容器。
- publication/news/project/student/patent模块不在首次HTML中读取列表、正文或媒体；数据中只有profiles。
- 沿用原fragment路由、筛选、公开可见性、首页featured条件、数量上限、排序、引用格式、金额权限和翻译。没有新增一套公开数据API。
- 首批与后续分页共用队列，并发1；没有为5个模块执行Promise.all。
- 普通模式初始容器按页面顺序自动排队；没有IntersectionObserver时仍可自动串行加载首批。浏览器saveData模式保持手动加载。
- 单模块失败保留重试/分页入口，不阻塞其他模块。不自动无限重试。
- total=0时隐藏该模块；全部模块为空时隐藏所在网格，更新模块计数避免留空列。
- 无JavaScript时仍可使用“加载内容”“分页查看”“查看全部”普通链接。
- 保留离页AbortController和清空队列。浏览器取消不保证服务器已经开始的计算被立即中断。

## 译文校验边界

英文首页的共享译文复用会通过translation_cache查询校验供稿记录是否仍公开可用，SQL可能包含其他业务表的EXISTS。此逻辑必须保留，不能为了让SQL文本不含news/projects等名字而绕过权限或破坏跨模块译文共享。

所以本轮的准确保证是：首次首页不执行这些模块的listing或独立列表聚合，不枚举其正文和媒体；必要的共享译文来源校验仍存在。不能声称首页SQL绝不引用其他业务表。测试同时拦截Content.listing（首请求仅允许profiles）并检查排除译文校验后的业务SQL。

## 双平台影响与测量

同一临时SQLite默认配置样本，匿名英文首页：首次query调用12→6，listing调用4→1（仅profiles）；重复请求query调用2→0，取决于本地缓存。数据来自前版和本版的platform/baseline.json。

这是本地query方法调用次数，不是CloudflareCPU、D1计费行数或浏览器TTFB；有教师、图片、中文共享译文和更多导航时数值会不同。HTML增加空容器，空站点初始HTML字节数可能增大，不能用包体大小代替CPU结论。

HTTP由一次聚合首屏请求，变为一次首屏加每个启用模块一次首批请求（默认3个，全部启用5个）；这些首批请求顺序执行，后续滚动仍可触发分页。总HTTP数增加，不承诺整个页面总查询数减少；目的是降低首屏与单次调用负载。

Ubuntu仍为一个systemd服务、一个端口、一个Uvicorn worker、一次install_local；Cloudflare仍是现有主站+separate Executor+Native，不增加Worker/Cron。必要依赖预加载保持不变，无新增生产Python模块导入；public_home复用public_data中的轻量纯函数。

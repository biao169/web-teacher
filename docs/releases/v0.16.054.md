# v0.16.054 — Step 5 媒体引用统计按需加载

基于 v0.16.053。Ubuntu 与 Cloudflare Admin Worker 共用同一路由、模板和弹窗。

## 修改

- backend/app/native/web_admin.py：媒体列表移除批量 references.summaries，不再读取引用正文；保留分页、媒体状态计数和鉴权。
- frontend/admin/templates/native-media-parts.html、native-list-panel.html：使用位置列显示“点击查看”，未知状态不冒充未使用。
- frontend/admin/static/js/native-media-locations.js：复用单文件分页接口，同一列表一次只允许一个查询；关闭后忽略迟到响应。无页面加载自动请求、无逐行预取。
- frontend/admin/static/js/native-list.js：更新弹窗模块版本。
- tests/test_media_usage_step5.py、tests/media-usage-step5.test.cjs：点击前零统计、点击后单文件统计、重复点击和关闭竞态回归。

详情页仍按用户访问计算使用位置。引用权限遮蔽、分页、回收与永久删除时服务端复核均保持原实现；未修改数据库或同步执行规则。

## 验证

媒体回归 71 项通过；平台门禁 170 项、DOM 38 项通过；Worker 分包/角色测试 22 项通过；新增弹窗 DOM 测试 1 项通过。
同一临时 SQLite 基线中媒体列表首次/重复请求均为 7 条查询、0 次引用统计，前版为 20 条查询。此为本地测量，不是线上 D1 CPU 或 TTFB 测量。测试报告的 source_version 保留测量时尚未更新的 0.16.053 标识，代码已包含本次变更。
未执行云端发布或真实 Worker 额度/PoP 验收。Linux 安装拓扑和 Public/Admin/Sync Executor 分离保持不变。

## 下一步 Step 6

部署后采集 Public/Admin/Executor 的 CPU、wall time、outcome、HTTP 错误与请求 ID；对比媒体列表打开和点击使用位置的成本。根据真实线上瓶颈决定是否需要进一步拆分 Worker，不预先增加服务。

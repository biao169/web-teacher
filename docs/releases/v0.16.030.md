# v0.16.030 · 稳定性专项第一步：网站与同步执行入口隔离

唯一基线为本分支 v0.16.029-step2。未引用其他版本；未修改现有数据库内容、三种同步业务规则、候选上限或任务断点。仍只有 `database/schema.sql`。

## separate 模式

- 普通访问 → 主站业务路由 → 页面。任务列表、详情、计划查询和 POST 日志分页不领取任务、不唤醒恢复；保存默认参数也不再顺带唤醒旧任务。
- Cron / 原生协调器 Alarm → 独立执行器 `sync_tick` → 现有一个有限步骤 → 持久化状态 → 返回。
- 对端 `/sync/v1/read` → 主站轻量转发 `SYNC_EXECUTOR` → 执行器的独立同步 ASGI 入口。
- 媒体请求 → 执行器转发原生辅助 → 原有分段流式媒体处理。

主站的 `sync_tick` 在 separate 下直接返回 `separate-executor-only`，不会进入调度函数。执行器绑定缺失/抛错时，主站同步请求返回 503、`SYNC_EXECUTOR_UNAVAILABLE` 及追踪 ID，记录安全异常位置，**不回退到主站执行**。这不改变随后普通页面的应用状态。

独立导出入口只构造请求内 D1 和必要绑定包装，不创建普通网站 FastAPI 应用，不加载网站会话、模板或执行登录逻辑。签名、密钥、授权、暂停、正文大小边界沿用原实现。推送提案仅保存任务并唤醒协调器，不直接执行任务。

inline 模式仍由主站显式调度入口执行；其同步导出也经过独立的轻量入口，不构建网站应用。Ubuntu/Debian 挂载同一份签名处理函数，后台循环保持原有独立调度方式。

- `site_sync/integration/package.py`：生成主站 `SYNC_EXECUTOR` 绑定，执行器不绑定自身；校验主站及执行器绑定。
- `deploy/cloudflare/runtime/snapshot.py`、`startup_check.py`：预加载新增入口定义，检查执行器导入无初始化副作用。
- `site_sync/core/diagnostics.py`、`site_sync/worker/diagnostics.mjs`：新增执行器不可用诊断码。
- `deploy/cloudflare/tests/test_sync_isolation.py`、`site_sync/tests_website/test_web_isolation.py`：隔离及故障恢复测试。
- `deploy/cloudflare/tests/test_sync_executor.py`：更新 SDK 测试替身；版本、前端资源版本和发布清单同步更新。

## 部署

保留网页构建/部署命令和 `TEACHER_SYNC_EXECUTOR_MODE=separate`，提交本完整源码包后重新部署。程序自动更新原生辅助和独立执行器，并写入主站 `SYNC_EXECUTOR` 服务绑定，不要求手动创建辅助 Worker，不增加必填变量。

部署后检查主站绑定包含 `SYNC_NATIVE` 与 `SYNC_EXECUTOR`；执行器只有指向原生辅助的服务绑定，保持私有。先执行后台连通性测试，再恢复任务。出现 `SYNC_EXECUTOR_UNAVAILABLE` 时按追踪 ID 检查执行器发布和绑定，不能用“临时回退主站”绕开。

## 验证边界

测试覆盖：主站 separate tick 不运行；对端请求不初始化网站；执行器异常返回 503 后普通访问仍成功；独立 ASGI 签名握手；running 任务携带损坏 checkpoint 时首页、业务列表、登录页及后台同步只读查询不推进任务。inline/separate 离线打包、主站与执行器预加载检查通过。

未部署线上，未进行真实 Cloudflare CPU/内存额度或跨 PoP 验收。主站仍承担专用路由转发，共享 D1/R2 的压力仍需后续减小；此步不声称彻底消除 1101/1102，也不提供强制销毁 isolate 的能力。

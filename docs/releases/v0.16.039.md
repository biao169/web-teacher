# v0.16.039 · 第二步：Worker 原生流式媒体上传

基于本分支 v0.16.038。本轮不变更数据库、同步业务规则、任务数据、前台或后台 UI；仍只有 database/schema.sql 一个初始化 SQL。Ubuntu/Windows 保留原上传存储路径。

## 完成内容

Worker 三个原始文件上传接口（媒体库、媒体选择器、裁剪副本）保留 URL、登录 Cookie、Origin、CSRF 和权限检查。HTTP 入口为 ASGI 建立不带正文的请求封装；原始 ReadableStream 仅存在于请求局部上下文。校验通过后，经现有 SYNC_NATIVE 服务绑定的私有 upload_media RPC 交给原生辅助 Worker，不开放新的公开上传端点、不依赖同步密钥，也不受暂停同步开关影响。

Python 仍负责文件名/扩展名、用途权限、配置大小上限、500 MiB 配额、上传占用锁、媒体登记及审计。辅助 Worker 使用 BYOB 每次最多读取 64 KiB，顺序等待 SHA-256 DigestStream 和 R2 写入，不 tee、不整文件 arrayBuffer、不把正文转换为 Python bytes。FixedLengthStream 保持明确长度，实际字节数同时校验。成功只返回大小、类型、摘要；普通上传不返回正文。

R2 成功后才登记媒体。失败会终止读写和摘要流，尝试清理对象并释放上传锁；原始错误不被清理错误覆盖。R2 拒绝、源流断开、长度不符和类型错误有独立 MEDIA_* 码、请求 ID、阶段和受限栈帧。RPC 调用/协议异常转为受控 503，不把原始敏感异常消息返回浏览器。

普通页面不会读取正文上下文、访问上传 RPC 或推进同步。请求结束后 ContextVar 重置，不保存跨请求上传正文或进度。现有 R2Store.put 仍供其他小对象调用使用，本轮不把缓存等无关接口重构成流式。

## 边界

- 仍遵守后台大小配置，硬上限 20 MiB，并非放宽上传额度。
- 浏览器现有 File/Blob 上传会提供明确长度。自定义客户端若不提供 Content-Length，将收到 411；不回退成 Python 整文件缓冲。
- 裁剪副本保留 PNG CRC/尺寸及 JPEG 尺寸/尾部检查。只返回最多 64 KiB 头部和末尾 2 字节用于校验；JPEG 的尺寸段若位于这 64 KiB 之外，会拒绝。普通 JPEG 上传不受该裁剪头部限制。裁剪校验在 R2 写入后、媒体登记前执行，失败对象会清理，不作为已登记媒体公开。
- 平台硬终止不保证执行 finally，未登记对象仍可能残留；下一步建立持久上传会话和过期回收，本轮不宣称已实现断点续传或硬终止后自动清理。
- 不保证免费套餐不会再出现 1102；workerd 本地测试不能替代线上 CPU、内存额度与真实 Python FFI 联调。

## 网页部署

使用完整 v0.16.039 源码更新当前分支，继续原有 Cloudflare 网页构建项目及 python build.py deploy 命令。不新增环境变量，不调整数据库。原管线会先从当前源码打包并自动更新原生辅助 Worker，再更新主站；不要只覆盖 Python 文件或仅发布主站。

TEACHER_SYNC_EXECUTOR_MODE=inline / separate 均支持此上传链路，仍分别使用原有两/三个 Worker。上传不要求重新填写 TEACHER_SYNC_KEY；原有 Worker 创建/更新权限和绑定配置仍须有效。

部署完成后：
1. 正常响应 x-teacher-release 应为 0.16.039。
2. 分别在媒体库、编辑器上传及裁剪入口测试小文件和约 1–2 MiB 文件。
3. 主站出现 media-native-stream 日志，辅助 Worker 出现 MEDIA-NATIVE-END，request_id 一致；普通上传不应再出现 media-read-body/r2-buffer-conversion。
4. 上传后检查媒体记录、预览、首页和后台访问。失败时保留主站及辅助 Worker 同一请求 ID 的日志；后续首页失败应另外记录其请求 ID。
5. 仍出现资源终止时，结合 Cloudflare exceededCpu/exceededMemory/outcome 判断，不根据文件体积猜测。

# v0.16.083 — Admin稳定性第一步

完整Auth.principal原来每次访问均写auth_sessions；本轮读取last_seen_at，120秒内跳过heartbeat写入。到期才UPDATE，SQL再次限定last_seen_at阈值、未撤销、idle及绝对到期未失效，避免两个旧快照重复更新。每次仍读取session、账号、角色与完整权限；不缓存授权，不改变密码或CSRF规则。idle期限仍按更新时刻加1800秒并限制在绝对到期时间以内。节流意味着持久化最后活动时间可能落后真实活动不足120秒，未加入宽限期，不复活过期session。

42项测试通过：local与Worker资源分支各连续20次后台首页/教师列表返回200，仅一次heartbeat；119/120/121秒边界、绝对到期上限、撤销/idle过期/绝对过期不续期、两个旧读取只更新一次；账号回归及Public轻量认证回归通过。测试使用临时SQLite，Worker分支不是线上D1压力测试。时间格式沿用既有24字符UTC毫秒格式，与schema约束一致。未修改schema。

尚未拿到线上异常堆栈，不能断言session写入是持续500的唯一根因。源码另确认web_common的401/403错误处理再次调用resources，下一步修复二次鉴权与无效session清Cookie/跳登录，API返回401，真正无权限保留403。Admin异常边界和保守取消仍在后续步骤，不宣称本包已完成全部500治理。

Public缓存、Public轻量认证方法、同步模块及Executor/Native、Linux部署文件保持原样。版本标识更新不修改路由与同步逻辑；Public ETag表示版本仍保留原值。

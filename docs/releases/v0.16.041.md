# v0.16.041 · 第四步：同步连通性与主动推送反馈

基于本分支 v0.16.040。保留原生流式媒体上传、上传恢复以及三种同步模式；不改审批规则、初始化 SQL、同步任务数据或前台业务页面。未直接访问生产后台或线上发布，不能仅凭本地测试断言此前线上连通性问题已消除。

## 修复与增强

### 连通性与传输诊断

Worker 连通性测试新增 native_status 阶段：通过实际私有 RPC 查询辅助 Worker 版本，并在服务器内部比较主站与辅助 Worker 的生效密钥指纹。浏览器只得到是否一致和版本，不得到密钥或指纹。仍优先读取后台保存的数据库密钥，没有记录时才使用环境变量；不自动覆盖密钥或绕过鉴权。

版本不一致显示 SYNC_NATIVE_VERSION，密钥不一致显示 SYNC_NATIVE_KEY_MISMATCH。该检查在对端握手前进行，避免将本站辅助服务配置问题误认为对端签名失败。Ubuntu 继续使用其 HTTP 传输路径。

两端传输同时补充 PEER_REDIRECT（重定向）、PEER_ACCESS_CHALLENGE（Cloudflare challenge 标记）和 SYNC_RESPONSE_SIGNATURE（响应验签失败）。不会自动跟随重定向，不把重定向地址或 HTML 内容写入诊断。一般 403、网络异常、RPC 异常不能被直接判为 1101/1102；平台码仍须响应或平台日志证据。

### 推送交付与重试

原来的推送仅在浏览器 DOM 暂存请求 ID，也没有本站发送记录；刷新后很难确定对端是否已创建任务。原生 RPC 异常还可能跳出专门错误处理，前端收到非 JSON 响应时只显示解析失败。

现在推送统一使用既有 peer_factory/candidates 控制链路，Ubuntu 与 Worker 共用发送逻辑。仅连接所有者可发送，并重新核对当前管理员权限和已配置导出范围。服务器等待上限 25 秒；超时不能证明对端未创建任务，因此保留同一请求 ID 供重试。

新增 service_meta 下的 sync:outgoing:<管理员摘要>:<请求摘要> 发送记录，状态为 sending、unknown、confirmed。每个管理员保留最近 50 条，界面读取最近 20 条；插入时也清理历史，未完成发送不会无限积累。记录只包含域名、范围、时间、推送请求 ID、追踪 ID、对端任务 ID和受限错误诊断，不含正文或密钥。

相同请求 ID、域名与范围会复用确认结果；改域名/范围后复用旧 ID会被拒绝。并发失败不能覆盖已确认结果。接收端先核对原请求对应任务，再检查是否有其他推送待处理，从而能够恢复“旧任务已完成，但响应丢失且又有新任务”的请求。新的推送被待处理任务阻挡时显示 SYNC_PROPOSAL_PENDING。

### 后台反馈

推送按钮附近新增独立状态区，立即显示发送中、对端任务 ID、审核状态及详细错误；不再被任务列表刷新覆盖。

同一标签页刷新后，通过 sessionStorage 复用尚未确认的请求 ID；数据库发送记录也提供“重试同一请求”。禁用浏览器存储时，同页仍保留内存重试 ID，刷新后可使用服务器发送记录重试。此处只显示发送结果；任务实际执行进度仍在对端任务列表查看。

非 JSON 错误、HTTP 状态、返回的 1101/1102 文本、Ray ID、后台请求 ID 和结构化诊断均可显示。没有请求 ID 时明确显示“未取得”。推送请求 ID是稳定去重标识；后台请求 ID/trace_id 是一次执行的追踪标识，两者不是同一个字段。时间沿用 Asia/Shanghai。

### 隔离与安全

新增状态检查与推送仅由明确管理操作触发。发送记录读取不会推进任务或自动重试发送。普通页面不执行候选扫描、RPC、同步恢复或发送记录扫描；separate 模式的执行隔离保持不变。接收端审核/自动确认仍完全由对端策略决定，调用方不能通过请求指定跳过审核。

## 验证

- 同步/Cloudflare 回归：652 项通过、1 项跳过、47 个子测试通过。
- 最终推送/连通性定向测试：16 项通过，覆盖丢失回执、同 ID 重试、账号隔离、记录限额、原生错误返回、CSRF、旧任务恢复及待处理任务提示。
- Node 原生传输与前端逻辑测试：59 项通过。前端使用控件替身验证非 JSON 反馈及重载后 ID 复用，未进行真实浏览器视觉验收（当前环境缺少 Chromium）。
- 本地真实 workerd 验证新 status RPC、二进制传输与 D1 绑定通过。
- inline / separate staging、主站及执行器冷启动/延迟导入检查通过。
- 超时测试的 fetch 替身补齐“调用前 signal 已取消”的标准行为，避免测试在并行负载下等待不存在的后续 abort 事件；不改变生产超时策略。

以上不替代真实 Python Workers FFI、线上网络安全规则或免费额度验收。

## 部署与验证

上传完整 v0.16.041 源码到现有构建分支，沿用 Cloudflare 网页部署及 python build.py deploy。无需新增变量或手工执行 SQL；现有管线自动更新辅助 Worker。新增 status RPC 要求主站与辅助 Worker 同步更新，不能只覆盖主站文件。

1. 正常响应 x-teacher-release 应为 0.16.041。
2. 后台测试连通性：Worker 应依次显示 local_connection、native_status、peer_factory、signed_handshake、signed_candidates。失败时保留完整 JSON，尤其阶段、错误码、双方版本、请求 ID 与 Ray ID。
3. 主动推送一个小范围：按钮附近应显示对端任务 ID及是否等待审核，下方出现发送记录。
4. 如果提示结果待确认，从该记录重试同一请求；先核对对端原任务，避免主动换新 ID重复发送。
5. 若出现重定向或验证挑战，检查最终域名及同步接口的访问规则；本版本不会自动更改 Cloudflare 安全配置。

# v0.16.006 · 第五步：实时任务监控、操作与诊断日志

沿用本分支 v0.16.005-step4，最初完整基线仍为用户指定的 v0.15.160-step6，没有参考或复用其他网站版本。按首次部署设计，仅有 `database/schema.sql` 一个初始化 SQL。

## 使用

进入后台侧栏“两站同步”（`/admin/site-sync`）。默认显示全部任务，可切换运行中、待运行、已暂停和已结束；已结束包含已完成与已取消。每页可选10、20、50条，支持首页、上一页、下一页，不会一直向页面追加行。

可见页面约10秒刷新当前页，包括后续分页。隐藏页面停止刷新；刷新故障逐步退避，最高120秒；返回页面恢复刷新。编辑参数输入框时暂缓自动刷新，避免打断输入。监控接口只读取状态，不负责推动同步。关闭页面后，原有本地后台循环或 Worker Cron 仍推进任务。

每条任务可展开或收起详情，同一时间展开一条，减少 Worker 读取量。详情包含：

- 完整任务ID、阶段、状态、创建时间、最近执行、最近持久进度、下一执行时间、租约到期。
- 正文/媒体已保存字节与进度条、各状态记录数、连续无进度错误与累计错误、初始/当前/最小切片。
- 当前记录及模块、正文下一偏移、当前媒体分段进度与临时对象键、下一步动作、距离最近进度的秒数。
- 需要审核、人工暂停、慢速重试、租约超时等待恢复、安全取消/删除等状态。
- 分页候选记录及审批选择；日志和断点保存的数据库表位置。

发现阶段总量可能增长；正文进度只统计已获取清单的记录，不能把传输100%误认为已写入并完成。最终以任务“已完成”状态为准。全部时间统一为 Asia/Shanghai（UTC+08:00），不随浏览器时区改变。

## 任务操作

- **暂停**：阻止继续推进，现有在途操作的租约到期前不会开放新的执行权；授权/租约保护阻止旧执行者继续提交。
- **继续**：恢复已暂停任务；租约尚未到期、授权改变等情况会给出拒绝原因，保留此前的安全规则。
- **取消**：服务端进入安全清理，保留已经提交的网站内容，不回滚业务数据。
- **删除**：已结束任务排队分批删除元数据与日志；活动任务先取消并清理临时数据，再删除任务记录。每次清理最多50行，不在页面请求内递归删除大量数据。删除请求也会唤醒独立 Worker 的后续调度。

删除不会删除网站业务内容或已发布媒体。遇到明确撤销授权或无法清理的存储故障，删除可能仍显示等待状态，需要恢复授权或存储后继续；不会绕过授权强删。旧任务按保留期清理的机制继续有效。

## 诊断日志

新增 `sync_events`，每个任务保留**最近256条**；每页读取30条，可查看更早一页或返回最新日志。记录包括：

- 执行开始（与任务租约原子保存），执行结果、失败、租约过期后的中断恢复、授权变化，以及后台创建/确认/暂停/继续/取消/删除/参数操作。
- 时间、事件ID、执行尝试ID、阶段和状态、进度序号、前后进度差、重试策略结果、下次执行时间、当时切片大小。
- 下一待处理记录/媒体及已保存偏移，帮助定位重复停留的步骤。
- 错误类型及本项目 Python 文件/函数/行号；可获得时记录HTTP状态、1101/1102代码及 Cloudflare Ray ID。原生调用与上层异常保留有限的分类原因链。

不记录同步正文、密钥、Cookie或原始异常全文。平台直接终止时可能无法取得异常堆栈，此时通过上一次“执行开始”和后续“中断恢复”记录定位。超过256条的早期日志会滚动淘汰；本版不是无限保存的完整历史审计系统。日志容量与任务保留期/删除功能共同控制占用。

| 文件 | 内容 |

| `site_sync/frontend/templates/panel.html`、`page.html` | 任务分组、分页、折叠进度、日志界面与静态资源版本 |

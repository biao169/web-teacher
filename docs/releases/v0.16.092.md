# v0.16.092 — 修复PublicPage导出校验

091生成的main.py包含Default、PublicPage、TransferCoordinator，但integration_package.verify仍严格比较旧版两个名称的整行文本，因此在PACKAGE后、SITE-PACKAGE前报Missing Python Worker exports。这是构建校验遗漏，不是Cloudflare缓存或D1故障。

入口生成统一使用integration_package.entrypoint_source，pipeline和site_workers共用。verify_entrypoint通过AST校验三个必需名称，允许换行和不同顺序，缺少或重命名导出时报告具体名称。没有删除校验，也没有删掉PublicPage或TransferCoordinator。

修正此前测试盲区：流水线测试及离线staging不再手写旧入口，而是使用真实生成方法；入口在角色打包前后均检查。角色拆分后的校验仅针对入口，保留主站与Executor兼容标志原有差异，不改变同步代码。

73项测试与10项子测试通过；simple/full/off+separate源码打包、Public/Admin/Executor快照导入通过。未真实Wrangler Python SDK bundle或线上发布，不能替代平台MISS/HIT验收。

部署：使用本完整包替换091源码，提交到现有构建分支并重新部署；沿用现有变量，simple、1800秒TTL、separate。不需要重新初始化数据库、清R2、删除Worker或清理浏览器缓存。故障发生在发布前，不能把失败构建当作新版本已上线。

缓存和身份逻辑保持091实现；同步、数据库、Linux部署结构未改。

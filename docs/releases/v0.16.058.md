# v0.16.058 — Step 3：匿名整页 Render Cache

基于 v0.16.057。默认启用服务器匿名整页缓存，TTL 300 秒；本轮不启用浏览器五分钟 freshness 或导航预取。

## 执行顺序与范围

身份解析 → public_cache_revision → 导航/查询校验 → canonical redirect → ETag / 304 → Render Cache → 原有数据读取与 Jinja。

仅首页、公开列表、固定导航列表的匿名完整 HTML 可以缓存。详情、contact、表单、登录、后台、API、同步、快传、fragment、Authorization、Range 和 If-Match 请求不进入整页缓存。登录者使用原有独立渲染路径，不共享匿名 HTML。仅 200、HTML、无 Set-Cookie、无 no-store 且不超过 256 KiB 的响应可写入；缓存只保存 HTML 字节，不保存请求 ID、Cookie 或整套响应头。

命中后直接复用 HTML，重新附加当前 ETag、Cache-Control、Vary、X-Public-Revision，外层安全与请求诊断头照常处理。不再执行 site_settings、public_listing、media map、people_facets、导航组装或 Jinja。身份、修订号及必要的导航/新闻时间索引读取仍然存在。

HEAD 可以读取缓存，但 MISS 不存储空 HEAD 响应；304 优先于整页读取。

## Linux / Windows

新增 LocalPageStore，生命周期归属于已有 PublicReadCache；复用它的锁、时钟、修订号和 CacheBudget。没有第二份独立 Public 内存预算。

- 数据字节计账 + HTML 字节计账共同受当前 CacheBudget 限制。
- HTML 最多占总预算的 1/4，最多 128 个条目，单页最多 256 KiB。
- TTL 到期和 LRU 淘汰；预算下降时先淘汰 HTML，再按需要淘汰数据。
- 写入 HTML 不为其腾空间而淘汰有效数据。
- 业务修订号变化同时清空本地数据和 HTML 缓存；过期请求不覆盖新修订缓存。
- CacheBudget 的计账不是整个 Python 进程 RSS；其他运行时与模板开销仍存在。

Linux 继续一个网站服务、原端口与部署目录，不增加 Redis 或其他服务。

## Cloudflare Worker

使用 Workers Cache API 的 teacher-public-pages-v1 命名缓存；内部键为配置 origin + /.public-page-cache/ + ETag 摘要。该地址只是内部缓存键，不注册公开读取路由。没有 Python 全局 HTML 字典。

每次命中检查状态、内容类型、Content-Length、Set-Cookie；只读取已由本模块限长写入的 HTML，并核对实际编码长度。缓存读写操作设置 1 秒等待超时，异常或无法缓存时正常回源；业务查询/渲染异常不被吞掉。

内部缓存 Response 使用 public,max-age=300 等实际配置 TTL；返回浏览器时重新应用网站原有 HTTP 策略，不把内部缓存策略直接发给浏览器。

Cache API 按数据中心缓存，不保证跨 PoP 共享或一定保留到 TTL。真实 CPU、Python/JS FFI 和线上 Cache API 行为仍需部署验收。平台文档：https://developers.cloudflare.com/workers/runtime-apis/cache/

## 键与失效

直接复用 Step 2 的表示键：版本、public_cache_revision、匿名身份、语言/路径、规范化查询、full/fragment、导航 stamp、新闻发布时间标记、origin、资源模式及性能配置。数据库写入导致修订号变化后，不再命中旧 Worker 键；旧条目交给 TTL 淘汰。新闻时间跨越发布点时，即使数据库没有写入也会更换新闻列表缓存键。

没有新增数据库 revision，没有修改初始化 SQL、业务表或同步协议。

## 配置与响应头

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| TEACHER_PUBLIC_PAGE_CACHE_TTL_SECONDS | 300 | 服务器完整 HTML TTL；0 关闭 Render Cache |
| TEACHER_PUBLIC_CACHE_TTL_SECONDS | 1800 | 现有 SQL / 数据 / fragment TTL |
| TEACHER_PUBLIC_CACHE_MB | 32 | 本地 Public 总预算上限，实际预算继续自适应 |

两种 TTL 独立：数据 TTL=0 时可以使用整页缓存；页面 TTL=0 时数据缓存继续工作。二者均为 0 时完整页面 no-store 且不生成 ETag。相应调整了旧测试中“关闭全部缓存”的配置。

X-Public-Page-Cache：
- HIT：直接使用已存 HTML。
- MISS：未命中，正常生成；HEAD MISS 不写入。
- BYPASS：不适用、容量不允许或缓存服务不可用；304 也标为 BYPASS，因为无需访问整页缓存。

本轮匿名完整 HTML 对浏览器仍为 private,no-cache，登录 HTML 仍为 no-store；原 fragment 策略不变。下一步才实施浏览器 max-age=300。因此当前缓存命中仍需要网络往返。

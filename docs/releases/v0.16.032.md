## 日志含义与定位

普通 HTTP 结束记录一条轻量日志：request_id、component、route（路由类别）、method、入口 colo/country、Ray ID、HTTP 状态、开始/结束时间及 duration_ms。路由不记录查询参数，也不记录 Cookie、密钥、正文或完整 URL。异常另记录安全分类、代码、文件、函数和行号；原始异常消息可能含凭据，因此使用固定安全摘要，不直接输出原文。

同步 HTTP 和非 HTTP 入口还记录开始事件。任务步骤记录 SYNC-STEP-START / SYNC-STEP-END，并在已有持久事件内保存 trace、task_id、attempt_id、阶段、checkpoint、sync_mode、retry_count、retryable、分片大小及下一条记录/媒体位置。duration_ms 是墙钟耗时，不是 CPU 时间。SYNC-STEP-END 表示应用退出该步骤，并不宣称任务成功；任务结果以持久事件状态为准。

追踪方法：浏览器响应头 x-request-id → 主站或执行器日志 request_id → 任务 task_id / attempt_id → 数据库 sync_events 阶段与 checkpoint → 原生辅助日志。远端请求各有自己的 request_id；使用签名请求 nonce（peer_request_id / x-sync-trace）关联跨站跳转。入口记录的 nonce 仅用于关联，不表示该请求已通过验签，鉴权逻辑保持原样。

后台新增最近请求 ID、入口 PoP/国家、本次与对端 Ray ID、最近阶段/子阶段、最近成功推进阶段、错误类别、HTTP 状态、资源原因和 checkpoint。原有任务创建、执行、调度、下次恢复时间及当前记录/媒体字段保留，继续使用项目现有时间格式。

request.cf 记录的是请求入口元数据，不保证是实际执行器物理位置。execution_colo 未得到平台证据时为空；Cron / Alarm 没有 HTTP 元数据时显示“未提供”。没有国家或特定 PoP 的特殊处理。

## 1101 / 1102 的边界

分类包含 credential、authorization、database、network、json、state、http、exception、resource。单凭异常正文出现“1102”不认定发生资源超限；明确收到 platform_code=1102 但没有具体证据时，仅标记资源原因 unknown。

分类器预留可信 cloudflare-telemetry 来源的 exceededCpu / exceededMemory outcome。**本轮没有部署 Tail Worker、接入 Logpush 或自动导入平台 outcome**，因此多数应用事件的 platform_outcome / cpu_time_ms 为空。实际 CPU 与内存原因仍需在 Cloudflare Workers Logs 的对应 invocation 中核对；不能根据 1102 数字独立判断。

1101 可以用 request_id、安全栈位置、阶段和任务号定位可捕获异常。模块加载失败、平台强制终止或响应返回前的硬错误不保证有应用响应头、结束日志或 finally；此时使用 Cloudflare Ray ID、平台事件和最后的开始日志排查。不能把诊断封装理解成强制重启 isolate 或保证捕获硬超限。

官方参考：
- https://developers.cloudflare.com/workers/observability/errors/
- https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1102/

## 隔离、日志容量与恢复

separate 下，首页/登录/后台普通访问和查看任务详情只走业务或只读状态路径；诊断包装器不扫描任务、不调用 resume、不下载正文、不重建 manifest。同步推进继续由专用 executor / tick / Cron 负责；专用导出请求按上一轮的服务绑定交给执行器。没有新增普通页面触发同步的路径。

ContextVar 只承载当前调用的小型元数据，退出 reset；未新增全局任务、响应或下载缓存。数据库 checkpoint 仍是唯一恢复依据。原有租约、幂等步骤及断点恢复规则不变，本轮给恢复位置增加可见证据，不重建或删除任务。

持久日志仍每任务最近 256 条；应用详情 JSON 在插入前限制到 6000 字符，过长时保留追踪信息并标注截断，checkpoint/下一记录/媒体由同一 SQL 查询补充。普通访问日志只写平台控制台，不新增每请求 D1 写入。平台日志保留与采样沿用部署配置。

# v0.16.020：同步执行保护与故障恢复（第二步）

基于本分支 v0.16.019。Worker 每次只执行一个环节，增加 25 秒异步处理预算、15 秒原生请求及正文流截止时间，租约缩短到 60 秒。平台强制终止不能保证执行 finally，由后续调度核对持久断点恢复。CPU 密集同步代码不能依靠异步计时器强制抢占，实际平台资源仍需线上验收。

原生媒体保持原始响应流，避免整文件缓冲；R2 消费结束或报错时释放请求。R2 已提交的操作仍可能完成，业务提交继续由租约及回执保护。重试保留已持久化分段，不删除正常网站文件。

暂停/取消时，只有原执行者退出后才能提前释放自己的租约；旧执行者不能清除后来执行者的租约。硬终止后按到期租约恢复，实际推进时间还取决于 Cron。

Linux 保留后台线程 I/O 和 20 秒 socket 超时，增加 45 秒正文读取截止检查（正在阻塞的读取仍受 socket 超时限制）；不会把取消 asyncio 等同于终止线程。本地媒体清理每次最多 16 个文件，保留所有权标记直到清理结束，逐批记录进度。

## 应急暂停

Cloudflare 网页设置 → 变量与机密：在实际执行同步的 Worker 添加文本变量 `TEACHER_SYNC_PAUSED=1` 并部署。inline 设置主站；separate 设置独立同步执行器，主站也建议同步设置。Ubuntu/Debian 在站点服务环境文件添加同名变量并重启服务。恢复时改为 `0`。它只阻止新的同步推进，不立即杀死正在执行的调用；历史任务与断点保留。普通网页路由不受此开关控制。

# v0.16.093 — Public 缓存命中前减负

基于 v0.16.092，仅缩短 PublicPage 缓存前路径。

- Default.fetch 不再使用 traced；无 query 的标准 Public GET/HEAD 直接转 PublicPage。其他请求进入保留完整诊断的 _dynamic_fetch。
- Public 转发只有异常时记录 PUBLIC-FORWARD / ERROR 并保留异常；成功路径没有 request_context、scope 或 Response 二次包装。
- 任何非空 query（包括搜索、筛选、分页、nav/nv/__recover）走动态路径，不生成 Workers 页面缓存键。
- 没有 Cookie/Authorization 时直接传递原生 Request；有身份头时才复制并删除这两个头，保留原始请求。
- 保留 Host 检查、Browser 1800 秒、ETag、Default cache OFF / PublicPage cache ON。
- session-summary、Sync Executor、Sync Native、同步协议和 Linux 部署不改。未新增缓存层、warming 或恢复逻辑。

116 项测试、10 项子测试通过。simple + separate 离线打包及快照检查结果见验收输出；未进行真实 Cloudflare 发布和缓存 HIT/MISS/延迟测试。本地测试证明路由绕过完整 traced，不等同云端缓存命中证明。

部署仍沿用 simple、1800 秒 TTL、separate。无需数据库初始化或清理媒体。
上线后用相同无 query URL 重复 GET 检查平台缓存状态，并比较 /en/projects?page=2 的动态路径。浏览器缓存可能直接拦截请求，测试时应区分浏览器命中与 Worker 命中。

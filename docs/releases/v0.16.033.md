# v0.16.033 · 稳定性专项第四步：冷启动与按需安装

基于本分支 v0.16.032-isolation-step3。仅优化 Worker 初始化边界；数据库、已有任务、三种同步业务模式及前台 UI 均不变。唯一初始化 SQL 仍为 `database/schema.sql`。

## 修改内容

- Worker 构建网站应用时启用 `lazy_sync=True`。普通页面首次访问不再安装同步管理、密钥、控制及兼容导出路由；只登记一个严格匹配同步路径的延迟入口。当前主路由从 99 条降为 90 条（其中一条是延迟入口），未删业务接口。
- 首次访问同步路径才安装该组路由，之后复用固定路由定义。安装过程没有 await；全部完成后才发布引用。失败不缓存半成品，后续同步访问可以重试，普通页面不依赖这次安装成功。
- 子路由使用网站已有异常处理、Host 验证、登录及 CSRF 边界，不新建独立后台、不改 URL、不创建后台任务。新增 `INIT-SYNC-ROUTES` 开始、成功及异常诊断，关联上一轮的 request ID。
- 克隆期间的业务写入保护提取为轻量模块，始终安装；密钥接口的 no-store 响应头保护也始终安装。因此首次同步页面尚未打开时，已有克隆写锁仍然有效，密钥错误响应仍不可缓存。
- 保留原有确定性依赖预加载，并补齐被延迟安装的路由依赖定义。预加载不调用 install、不构建 Runtime/任务、不查询 D1/R2。
- 部署流水线增加 `EXECUTOR-SNAPSHOT-CHECK`：在全新 Python 进程中单独导入执行器，而不是先导入主站后再测执行器。禁止时钟、随机数、网络、数据库连接和文件写入等启动副作用，并断言执行器未加载主站 web、模板资源、主站资源工厂或文件快传界面。

## 审查与保留

| 路径 | 处理 |
| --- | --- |
| 模块加载 | 保留函数、类、固定 schema/权限映射和依赖定义；未发现启动时读取 service_meta、扫描任务、恢复 checkpoint、构造远端 manifest 或读取媒体列表的路径 |
| 主站应用 | 仍在请求时完整构建后缓存；本轮将同步路由安装从该构建过程移出 |
| 网站资源工厂 | 仍按请求解析绑定和配置；不调用同步运行时，不进行启动 schema 检验或迁移 |
| Jinja 模板 | 保留固定模板资源及有界编译缓存；模板仍按 render 需要编译，未将全量页面提前渲染 |
| 同步执行器 | 只加载签名导出/同步所需定义；不构建网站应用，不加载网站模板；新增独立进程验证 |
| Cron / 内部 tick | 沿用已有显式推进入口；本轮不改变调度、恢复或重试规则 |
| Ubuntu / Debian | create_app 默认仍使用原来的直接安装方式；共用写入保护和密钥头部逻辑，业务行为不变 |

普通 GET/HEAD 页面不会因延迟入口读取同步状态或推进任务。普通业务写入仍会检查已有克隆写锁，这是防止克隆应用期间并发编辑的既有规则，不能把它删除来换取“完全没有任何同步表查询”；该检查不会认领、扫描或恢复任务。

全局仅保留固定路由定义及既有有界模板缓存，不保存请求对象、当前 task、候选、正文或 checkpoint。本轮未新增任务缓存，也没有清空旧任务。

- `backend/app/native/web.py`：增加仅 Worker 启用的延迟安装参数。

- `deploy/cloudflare/startup_check.py`、`pipeline.py`：独立执行器冷启动检查及部署门禁。
- `deploy/cloudflare/tests/test_lazy_sync_routes.py`（新增）、`test_startup_check.py`：真实后台接口、失败恢复、普通页面隔离、写入保护及独立冷启动测试。
- 两个 `pyproject.toml`、`deploy/cloudflare/uv.lock`、同步诊断版本及前端资源版本：更新为 0.16.033。

## 验证及部署

沿用现有 Cloudflare 网页构建/部署命令和变量。部署流水线继续自动更新原生辅助 Worker，separate 模式同时更新同步执行器；新增的冷启动检查失败时停止部署。无需新增变量或手工修改数据库。

Python 全量回归 602 项及 47 项子测试通过；原生 JS 串行回归 47 项、后台 DOM 7 项通过；inline / separate 离线源码打包与启动导入检查通过。定向测试覆盖同步初始化失败后普通页面仍可访问、下一次安装成功，以及同步路由未初始化时写锁仍有效。本轮未执行线上发布、Cloudflare SDK 云端构建、真实 D1/R2 或 PoP 对照验收；99→90 是路由构建数量变化，不代表已经测得线上 CPU 或内存降低百分比。保留必要预加载并不意味着可以保证消除平台 1101/1102。

# v0.16.105 — 浏览器列表筛选、排序、分页

基线：v0.16.104-public-data-cache-step4。本轮完成第五步，未部署线上。

## 行为

八类标准列表的 zh/en 页面在原 HTML 显示后，匿名读取唯一固定地址 /api/public/data/{lang}/{module}。每页生命周期只发起一次模型读取，使用默认浏览器缓存策略（300秒），不创建筛选组合 Cache key、不进行轮询或重试风暴。数据完整且可用后，搜索、筛选、升降序、每页10/20条与分页均使用这份内存模型，不请求列表 HTML、片段、分类 API 或 D1。切换页面再次读取时可复用浏览器/边缘缓存；没有新增浏览器持久化数据库缓存或 Service Worker。

完整模型到达前保留服务端首屏，暂缓旧自动片段和分类读取，避免两条数据路径并发查库。网络超时/失败、4xx/5xx、未标记 JSON、模型不完整或超预算时静默保留原 HTML，恢复原有服务端分页/片段和分类行为；用户在数据未就绪时提交表单仍正常服务端导航。失败不会把第一页误当成完整数据集，不清空边缘成功缓存。

首页、公开详情、Admin/Auth/Sync、固定条件 /{lang}/n/{slug} 入口仍走原路径，不把固定条件导航扩展为全模块数据。自由参数只体现在浏览器 history URL，不进入共享页面缓存。Unsupported/非法访客状态不交给本地执行，沿原服务端验证路径处理。

## 语义与交互

- 搜索使用原文/有效英文双语字段，ASCII NOCASE、字面子串；%，_和反斜杠不变成通配符，搜索词沿用服务端 trim。
- f.* 普通文本为原值二进制相等；预设多值字段保留组合原值兼容，并支持整词 ASCII NOCASE；项目角色沿用已知别名；数值字段按数值比较。
- c.* 仅允许模型公开字段和服务端许可的 contains 运算，不按显示译文替代原始筛选值。
- 后台默认顺序保持，学生分类顺序固定，降序只反转组内；页码和旧50/100条链接沿用服务端夹取与20条上限。
- 保留 s 的UTF-8/base64url访客状态编码；pushState/popstate恢复筛选、页码与顺序，更新语言切换及详情 from 链接，清空旧选择。
- 全选、复制、简介展开、公开链接/附件、新闻视频与论文作者强调继续使用现有增强功能。浏览器创建DOM使用textContent，不把模型文字作为HTML注入；链接校验http(s)，媒体和详情校验同源。

论文为了保持原卡片展示，Read Model 增加当前网站配置的一种公开 citation 和 highlight；不输出其他引用格式、source_citation或后台/私有字段。只增加一次粗粒度网站展示配置读取，仍遵守40次查询、500条、512 KiB、单字段4096字符预算；过长引文使模型失败并回退旧列表，不截成成功引用。当前展示格式复制可直接使用缓存公开文本；用户选择其他引文格式继续按需调用原鉴权接口。旧边缘模型没有新增 citation 字段时先显示基本著录信息，按需复制仍读取实际引文。

Read Model 增加已引用公开媒体的 MIME 类型和简介截短标记；存储 key 不输出。简介摘要仍最多2000字符，筛选/搜索保持预算内完整原文。学生/课程长简介可按需读取原description接口，教师保留详情读取。项目管理员私有字段仍通过现有实时鉴权/no-store接口单独加载，绝不进入共享模型。

“不重复访问D1”指完整模型就绪后的公开列表筛选、排序和分页；详情、长简介、其他引文格式和管理员私有字段是独立按需请求，仍可能查库。HTML MISS继续原FastAPI/D1/Jinja，不依赖Read Model。

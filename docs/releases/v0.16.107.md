# v0.16.107 — Cache-Tag 与提交后的精确失效

基线：v0.16.106-identity-heartbeat-step6。本轮完成第七步，未部署线上。

## 成功响应标签

只有原成功门控允许的Public HTML/PublicData 200以及相应HEAD/304具有Cache-Tag；所有错误、动态私有/Auth/Admin/Sync响应仍no-store且不带Cache-Tag。TTL、ETag、SWR/SIE和Default cache OFF保持。

| 依赖 | 标签 |
| --- | --- |
| 首页 | public-home |
| 八类模块 | public-profiles/public-students/public-projects/public-publications/public-patents/public-courses/public-news/public-research-interests |
| 详情条目 | profile-<uid>、course-<uid>等 |

模块详情也携带模块标签，模块级通知覆盖列表、详情和该模块中英文Read Model。32位小写hex UID直接用于详情标签；其他UID先做稳定hash，防止标签大小写不敏感导致不同UID混淆及非法字符进入标签。

Home变化单独通知public-home。模型不依赖HTML布局，不带public-layout；布局单独修改不会调用PublicData失效方法。

## 提交后通知

SQLite在事务with块完成提交以后回调；D1在binding.batch成功返回以后回调。CAS/授权/约束失败、回滚和未提交操作不通知。原25/64语句上限、事务审计和public_revision原子推进不变。回调失败不把已提交数据伪装成保存失败，避免用户重提。

Content.save/delete提供当前行与合并后字段的内部变更提示，不增加查询；隐藏行编辑和项目纯私有字段修改不影响匿名缓存。普通公开修改、排序和新增用invalidate；删除、public→非public、停用/取消发布、公开联系方式/附件改私有等用purge。媒体回收/地址替换purge media依赖，普通媒体登记/元信息更新invalidate。

后台批量工具、恢复和翻译批次采用已提交SQL的固定表名/操作分类作为保守模块依赖回退，不缓存任何SQL或SQL结果，不解析业务JSON参数，不额外查询D1；批量upsert/删除/未知公开权限变化按对应依赖purge。一个批次有多条同表写入时所有模式合并，purge优先于同名invalidate。没有before/after上下文的批量通知比单条保存更保守，未宣称逐行精确依赖。

全局工具参数/翻译job进度/checkpoint写入不触发这些缓存通知，因为当前共享HTML及模型不消费这些动态设置；避免每次进度更新都刷新公开页面。站点展示配置和公共导航仍触发layout，当前论文引文展示格式变化触发public-publications。

public-translations反映现有跨模块译文复用：原文/公共来源资格变化可能影响其他模块；不能只失效原模块。撤回可公开翻译来源时该依赖必须purge，因此其影响可能覆盖多种公开模块。这是实际共享依赖的保守失效，不是purgeEverything，也不清除媒体HTTP、后台、Auth或Sync缓存。

## 内部转发路径

Admin Worker的请求ContextVar收集已经提交的变更，合并去重后通过原SITE_ADMIN响应携带限界的内部通知头。主Worker在原后台转发中读取并移除该头，分别调用ctx.exports.PublicPage.update_public_cache和PublicData.update_public_cache；RPC执行各自ctx.cache.invalidate/purge。只传标签与模式，不传SQL、内容、Cookie、CSRF、账号或私有字段。

这样遵守Cloudflare缓存控制按entrypoint隔离的规则，又不新增service binding、HTTP维护接口、API Token/Zone ID或发布循环依赖。RPC绕过fetch缓存；控制方法不渲染、不生成模型、不读取D1/R2。通知在既有后台失败边界转换响应之前消费，已提交后出现503仍保留通知；失败前未提交则没有通知。复制响应只复用body stream，不读取、缓存或重放响应正文/写请求。

每次后台请求最多两次内部RPC（纯layout只一次），同请求的多批写入合并。各模式最多64个合法标签；大量冗余详情标签压缩为覆盖它们的模块标签，收集器亦保持有界；计划/内部头限界8192字符。禁止未知标签、通配符、pathPrefixes和purgeEverything。缓存接受结果必须明确success=true；检查返回值而不是把完成await当成成功。

主站最多等待3秒，不自动重试、不升级为全站purge。成功保存仍保留原状态/正文/Set-Cookie/跳转；响应可带X-Teacher-Cache-Update accepted或pending，失败另记录PUBLIC_CACHE_UPDATE_PENDING。accepted表示平台接受通知，不是已验证全球缓存传播。pending、绑定/API不可用、限流或超时不回滚数据、不清空更多成功缓存。部分通知失败也不对其他标签追加purge。

## 故障和平台边界

读取页面/模型时发生1101/1102、D1临时异常、5xx或超时，不触发任何自动通知；只有实际提交的公开业务修改产生计划。故障本身不清成功缓存；正常invalidate保留旧成功body作为原stale-if-error回退。只有已经提交的删除/公开资格收紧等明确破坏性业务动作purge对应依赖。

没有新增Cron、扫描、缓存枚举、请求恢复层、D1 outbox或无限重试。若Worker在提交后、通知发送前被平台硬终止，通知可能丢失；若通知pending，旧缓存可能继续存在。遵守不增加Recovery层的约束，因此不宣称可靠投递或即时隐私撤回。浏览器已缓存HTML/JSON和当前页面内模型不受Worker Cache-Tag失效控制，仍按30分钟/5分钟窗口或页面重新加载更新。

Ubuntu/Debian单服务结构不变，本地成功HTTP响应使用同样标签；本地默认没有Worker共享缓存和通知回调，不增加Cloudflare凭据或网络失效调用。SQLite提交顺序用真实独立连接验证。Sync Executor/Native、同步协议、checkpoint/状态机及媒体同步均未修改；同步导入路径没有自动接入本轮后台通知，不能声称对端同步后即时失效，继续受现有缓存窗口约束。

官方接口核对（2026-10-12）：
- https://developers.cloudflare.com/workers/cache/purge/ ：按Worker/entrypoint隔离、invalidate保留body标记stale、结果success和限流。
- https://developers.cloudflare.com/workers/cache/configuration/ ：Cache-Tag格式与缓存配置。
- https://developers.cloudflare.com/workers/runtime-apis/rpc/visibility/ ：内部RPC可见性边界。

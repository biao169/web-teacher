# v0.16.005 · 第四步：持续恢复与独立同步 Worker

本版只从本对话分支的 v0.16.004-step3 接续，最初完整网站基线仍是指定的 v0.15.160-step6；没有参考其他网站版本。按首次部署设计，唯一初始化 SQL 为 `database/schema.sql`。本次没有部署线上站点。

## 已完成

- 主站、对端都可以部署为 Cloudflare Worker；签名 HTTP 请求继续使用允许公开 Worker 到 Worker 请求的配置。
- 新增可选独立 Python 同步执行器 Worker，专门由每分钟 Cron 驱动。同站网页 Worker 保留前后台、签名导出接口和其他维护任务；原生 JS Worker 负责媒体流和网络请求。执行器共用本站 D1/R2，不创建第二份站点数据库或后台。
- 每次只执行一个有界阶段。独立执行器只构建同步资源，不初始化网页应用、模板、登录或翻译服务。持久任务锁用于防止主站/执行器重复持有执行权。
- 沿用并验证强制恢复：调用被 CPU/内存限制终止后，下一次可用 Cron 在租约到期后对账；超出快速重试次数转为持续慢速重试，不设任务总时限；有持久进度就清零连续无进度失败计数。正文切片自动收缩仍尊重上一步配置，最低 4KiB，初始值可设 4m。
- 原生 RPC 没有正常返回、HTTP 429/5xx（包括平台 1101/1102 页面）、D1/R2 临时异常进入资源退避，不再因被误判为内容冲突而暂停。错误正文、凭据不写入任务字段。
- 每次请求重新生成时间戳、随机数和签名，不复用过期的短时请求签名。长期任务不依赖管理员浏览器在线。接收端原有审批策略保持有效，无新增分片审批。
- 正文及媒体访问续期源端快照；快照清理后，按已保存的主记录版本重新创建，内容摘要一致即可继续原偏移。摘要只在每个有界快照创建时计算一次，避免每个切片重复处理整条正文。
- R2 分段上传会话过期时，先检查对象是否已完成；未完成则仅清理该文件失效的上传回执，自动创建新会话重传该文件。正文、已完成记录、其他文件及任务确认状态保留。
- 导出授权增加到期检查；明确撤销授权、源内容变更、人工暂停或尚待接收端审核仍须停下，不会强行覆盖权限或拼接新旧内容。

## 启用独立执行器

在现有 Cloudflare 部署环境中加入：

```text
TEACHER_SYNC_EXECUTOR_MODE=separate
```

使用当前仓库原有 bundle/deploy 流程即可。未设置时为 `inline`（网页 Worker 的 Cron 执行同步）。`separate` 是**构建及部署配置**：仅在 Cloudflare 控制台给旧网页 Worker 添加此变量，不会自动创建执行器，必须重新执行部署流程。

部署器生成并校验：

| Worker | 用途 |
|---|---|
| 原站点名 | 前后台、对端导出、常规维护；独立模式下让出同步调度 |
| 原站点名-sync-executor | 每分钟执行一个同步步骤，关闭公开地址，不接收管理请求 |
| 原站点名-sync-native | 原生签名请求、D1/R2 媒体流；通过服务绑定调用 |

过长名称自动截断并附加摘要。执行器和主站绑定完全相同的 D1/R2，原生流服务绑定也相同。部署前分别进行原生服务、执行器、主站的打包检查；发布顺序为原生服务→执行器→主站。提供 `TEACHER_SYNC_KEY` 时现有秘密写入流程同步配置三者，不把密钥写进公开配置。

每一端仍在 `/admin/site-sync` 设置**对端网站的 HTTPS 地址**，不是私有执行器地址；两端设置同一对站点共享密钥。对端部署 Worker、本端独立 Worker 执行同步可以同时使用。自动拉取、手动拉取和经接收端允许的推送都走同一持久执行队列。

Ubuntu/Debian 仍使用现有本地后台循环，进程重启后从数据库任务和回执恢复。独立 Worker 模式面向共用同一 Cloudflare D1/R2 的本站部署，不是从远程 Worker 直接访问服务器的 SQLite 文件。

## 验证与边界

本地自动化结果见同目录 `v0.16.005-tests.json`。包括真实进程终止后恢复、模拟 D1 双执行器连续 40 次中断、过期签名换新、快照同内容恢复/变更拒绝、R2 上传会话恢复以及前台和实际 HTTP 集成回归。主站模式及独立执行器模式均经过离线部署整理检查。

没有在真实 Cloudflare 上验证额度、1101/1102 故障注入、Cron 触发时延或 SDK/Wrangler bundle；未发布线上。恢复依赖服务最终恢复可用和后续调度可达，不能保证永久故障也能完成。当前单记录正文仍为 200,000 字节上限；4MiB 是正文请求切片上限，R2 媒体继续原生 5MiB 分段（末段可小于 5MiB），不把媒体整块搬入 Python。

R2 过期上传代码依据：[Cloudflare R2 错误码说明](https://developers.cloudflare.com/r2/api/error-codes/)，`10024 / NoSuchUpload` 表示上传不存在或被中止。仅该明确错误会重建上传会话，其他存储故障按原进度重试。

# v0.16.116 — 固定公开导航短HTML缓存与精确失效

基于v0.16.115，未发布线上。没有新增Worker、缓存层、Cron、巡检、预热或Recovery机制。

## 策略与数据流

仅合法slug的 /zh/n/<slug> 与 /en/n/<slug> 无query GET/HEAD可成为候选。未知、停用、非公开、非法范围、query、分片、详情及错误不共享缓存。PublicPage MISS继续原有D1/Jinja路径：在同一请求加载导航配置一次，匿名验证公开条件后复用解析结果，跳过会话查询并渲染匿名视图。成功必须同时满足200、HTML、无Set-Cookie、已验证scope及成功标记。HEAD/条件304保留一致标签和TTL，未验证的200也no-store。

Browser max-age=60；edge max-age=120、stale-while-revalidate=30、stale-if-error=300。短故障回退窗口避免导航范围长时间残留。原标准Public HTML 1800秒和PublicData策略不变。本轮未把固定入口的筛选迁到PublicData，仍保留原SSR/分片流程，留待第四步。

Default仍cache OFF，转给现有PublicPage时移除Cookie/Authorization。匿名404且原请求确有配置名称的会话Cookie，才转给已有动态路由实时鉴权一次，保留登录专属入口；取消丢弃的404流。语言Cookie不会触发此分支。200/304/5xx及timeout不走此鉴权分支，不重试、不purge。受限成功响应no-store，无成功标记或tag。

## 精确失效

公开固定HTML带已有layout/translations/media依赖、模块tag及以slug哈希生成的public-nav tag，同一入口中英文共用。普通内容修改按模块invalidate，模块维护purge自然覆盖其标准HTML、固定HTML及PublicData。导航标签文字修改invalidate；路径/固定范围、url_name、开关、可见性、kind、fragment或location变化purge旧/新导航tag，删除同样purge。导航范围改变仅需清HTML，模块ReadModel内容未变化则不清数据；现有translations依赖仍按原规则联动。批量写缺少具体行时用已有layout依赖保守purge，不发起扫描。沿用提交后通知、pending诊断和单次RPC，不重放写入、不预热。

## 验证

最终相关Python183项、10项子测试通过（1项依赖弃用警告）；覆盖原导航范围/鉴权、标准PublicPage、tag提交顺序、模块维护、错误矩阵、新固定页短TTL/匿名视图/HEAD/304/一次导航配置查询/无auth_sessions读取、无scope的200拒绝、条件变化/删除/重命名purge、标签修改invalidate。Router模拟HIT不构建应用，受限404仅一次正常鉴权，5xx不重试；模拟不证明真实缓存。

inline与separate两种源码staging、snapshot边界及VPS配置生成通过。源码包按清单和SHA校验。Sync运行文件保持基线字节一致。本轮未执行Wrangler SDK dry-run、真实Cloudflare发布、真实平台HIT/CPU/D1计数、1101/1102故障注入或tag传播验证。

Cache-Tag失效由平台执行，不能即时撤回浏览器新鲜缓存；RPC pending/传播延迟时不能保证即时移除旧对象。stale只针对已有可用成功对象，不保证Default在转发前终止、缓存驱逐或新PoP时可返回旧内容。生产验收见docs/public-performance-acceptance.md。

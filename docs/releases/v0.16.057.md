# v0.16.057 — Step 2：ETag / 304 条件响应

基于 v0.16.056，新增轻量表示校验器；本轮不加入 Render Cache 或导航预取，不改变同步执行策略、数据库结构、Public/Admin 物理拆分和 Ubuntu 单服务部署。

## 请求链路

身份解析 → 唯一 public_cache_revision → 固定导航可见性与版本验证 → 查询解析与 canonical 303 → 列表参数验证 → 计算 ETag → 匹配 If-None-Match → 304；未命中继续原有数据读取和模板渲染。

命中时跳过 site_settings、public_listing、media map、people_facets、导航渲染和 Jinja。仍需身份验证、修订号读取；固定导航需读取导航定义；新闻列表额外执行一次索引查询。304 不是零 CPU 或零数据库请求。

## 校验器

新增 backend/app/native/public_http_cache.py，使用弱 ETag；只对小型表示元数据 SHA256，不遍历或哈希数据库正文。

键包含：发布/模板版本 0.16.057、public_cache_revision、当前会话与有效权限/显示身份的摘要输入、语言及路由、规范化查询、full/fragment、导航 stamp、新闻发布时间标记、站点 origin、资源模式、PublicPerformance 配置。只输出最终散列，不输出用户名、UID 或 CSRF 原文。之后 Render Cache 可复用同一 representation_key。

同一身份的角色权限、显示名、会话发生变化时 ETag 变化；匿名与登录身份不会互串。未来修改公开模板时必须同步提升 REPRESENTATION_VERSION，防止只更新源码而数据库修订号不变时复用旧 HTML。

If-None-Match 支持弱/强标签比较、多个标签、标签内部逗号、重复请求头和独立通配符 *。长度上限 8192、标签上限 64；非法头降为普通响应，不触发错误或错误命中。存在 If-Match / Range 时不提前处理条件响应。参考 RFC 9110 §13.1.2、§15.4.5：https://www.rfc-editor.org/rfc/rfc9110.html 。

304 无正文，带 ETag / Cache-Control / Vary / X-Public-Revision。公开路由新增 HEAD；成功 HEAD 与对应 GET 的表示头一致且不发送正文。

## 范围与安全

- 支持首页、公开列表、固定导航列表、原有列表分片。
- 详情页全部暂时绕过；contact、登录、后台、API、同步、快传入口不加入本轮校验器。
- Authorization 请求及 PUBLIC_CACHE_TTL_SECONDS=0 时绕过。
- canonical 重定向、导航不存在/权限不可见、参数错误先正常处理，不因通配符变成 304。
- HTTP 非 200 和带 Set-Cookie 响应不附加本轮 ETag；异常不吞掉。
- 本轮匿名完整 HTML 仍为 private, no-cache；登录用户仍为 no-store。身份绑定 ETag 已具备，显式条件请求可验证；浏览器对登录页面的 private, no-cache 策略留在 Step 4 启用。
- 原 fragment 缓存策略及协议不变：带当前 _rev 的匿名分片仍使用数据 TTL 1800 秒。ETag 只在请求实际到达服务器时检查，不会使浏览器已处于 freshness 期限内的响应主动失效。

## 新闻定时发布

news.published_at 随时间跨越可见边界时不一定发生写入，不能仅用 public_cache_revision 判定内容不变。新闻列表使用：

```sql
SELECT published_at FROM news
WHERE visibility='public' AND published_at<=?
ORDER BY published_at DESC LIMIT 1
```

返回值加入 ETag。复用现有 idx_news_published(visibility,published_at DESC,sort_order,id)，SQLite EXPLAIN 回归确认 SEARCH 并使用该索引；不做全表 count、不提取历史列表。它是时间依赖元数据，不增加另一套数据库 revision。首页当前只 SSR 教师和分片占位，不额外查询新闻。

## 验证结果与边界

124 项测试通过（1 项依赖弃用提示），覆盖 ETag 专项、已有性能配置、固定导航、public stream、首页渐进加载和 Data Cache。实际 SQLite/HTTP/Jinja 测试断言 304 不调用列表、facets、媒体映射和渲染；普通匿名页面命中只读一次修订号，新闻列表多一次索引读取。

Worker Public app 的模拟 Cache API 请求链路通过；inline/separate 两种临时源码打包及各角色 snapshot import 检查通过。日志在 docs/releases/v0.16.057-tests/。

这些不是线上 D1/Cache API 验收；未部署到真实 Worker，未测真实 CPU、内存、PoP 命中或浏览器 HTTP 缓存回退/前进效果。SQLite 索引测试不能替代远程 D1 指标。没有声称此次修改消除所有 1101/1102。

初始化 SQL 仍唯一为 database/schema.sql；不修改真实数据库、task、checkpoint 或同步协议。没有增加全局可变 HTML 缓存。

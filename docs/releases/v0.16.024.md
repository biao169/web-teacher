# v0.16.024 · 第六步：双端同步与失败恢复验收

基于本对话 v0.16.023 继续修改，未使用其他分支。部署后请按 [双端验收清单](../sync-deployment-acceptance.md) 核对。

## 修复

整站克隆期间保存同步密钥会追加操作日志，原清单摘要因此变化，可能误判来源内容变化而停止。现在一致性摘要排除操作日志，允许审计记录追加；业务内容、账号、角色、权限及媒体仍执行原有检查。操作日志仍复制，但不承诺包含发现阶段结束后的追加记录。

本步不修改数据库结构、初始化 SQL、部署变量或后台布局。两端都应更新；已经进入旧版整站清单流程的任务建议取消后新建，普通模块任务不受摘要规则变化影响。

## 新增验收

`site_sync/tests_website/test_clone_acceptance.py` 使用两套真实网站 SQLite 结构、实际网站 ASGI 接口、请求/响应签名以及生产同步引擎，验证：

1. 手动整站拉取遇到注入的资源异常后缩片，保存两端新密钥、重建执行器，保留断点并完成；来源账号可登录，本地新密钥保留。
2. 定时整站拉取自动完成，账号切换后计划归属接续，并能创建下一轮任务。
3. 推送提案经接收端一次整任务批准后完成，原账号密码可登录。
4. 传输阶段取消，清理正文分片，目标原内容与账号保留。
5. 应用阶段取消，已发布媒体保留，编辑锁释放，原账号仍可登录。
6. 暂存后来源业务数据变化，在恢复目标之前停止，目标原内容与账号保留。

既有测试继续覆盖真实本地进程终止后的持久恢复、密钥不匹配、权限撤销、过期租约、模拟 D1/R2、原生媒体流、断流、丢失响应和上传会话过期等。

## 验证结果与边界

- Python 用例共 523 项分批验证通过，含新验收组 6 项；另有 47 项子测试通过。验收适配器已按生产语义将 HTTP 409 映射为冲突暂停，修正后重新验证该组。
- 原生 JS 39 项通过；DOM/状态模型 6 项通过。
- `inline`、`separate` 的离线 Worker 源代码打包、运行时导入及 VPS 配置生成通过。
- 签名接口验收在本地 ASGI 测试客户端进行；既有 HTTP 测试另覆盖真实本地网络。模拟 D1/R2 不等于真实 Cloudflare；资源异常注入不等于真实 1102 额度压测。
- 未执行线上部署、真实 D1/R2 配额验收、Windows/Ubuntu/Debian 实机安装或浏览器截图验收。

关键改动：`site_sync/integration/clone.py`、`site_sync/tests_website/test_clone_acceptance.py`、`site_sync/tests_website/test_full_clone.py`，以及部署验收清单和版本说明。仍仅保留一个初始化文件 `database/schema.sql`。

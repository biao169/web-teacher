# v0.16.086 — Admin稳定性第四步

Admin产物配置enable_request_signal及no_request_signal_passthrough，移除正向透传标志。Public主Worker保持既有enable_request_signal和request_signal_passthrough，Sync产物不变。配置由site_workers生成，无需手动改辅助Worker；pipeline调用既有生成链，无需重复添加设置。

Main转发后台请求前使用原生Request与独立AbortController.signal复制请求，不缓冲、不重复读取body，不重放写请求。入站请求已取消时仍在发出前返回499。/api/public/身份组件保持原有转发信号。Admin不主动监听导航取消来中断已开始的Python/D1。该措施仅阻断信号传播，不能保证平台在断连或强制终止后无限维持执行，不增加waitUntil后台任务。

后台JS已有pagehide/导航离开清理：停止后续读取，列表dispose清理组件；客户端AbortController保留超时及释放本地读取功能，服务端后台链路由独立信号隔离。未改共享navigation-guard及Public取消策略，也未改写操作超时、不确定结果和不重放规则。

69项边界/取消/隔离测试通过，新增原生Request替身验证独立信号及body/header保留；simple+separate离线角色配置/快照打包通过。实际Cloudflare Service Binding与快速导航仍待线上验收；离线替身不能代替真实运行时取消测试。

官方说明：https://developers.cloudflare.com/workers/configuration/compatibility-flags/ （Request.signal及request_signal_passthrough）。

下一步第五步：综合Admin回归、部署后20次导航及真实D1/Worker日志验收，核对500根因和503追踪信息。

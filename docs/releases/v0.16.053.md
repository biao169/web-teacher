# v0.16.053 · Step 4 Cloudflare 前后台 Worker 拆分

基于 v0.16.052-app-step3。完成代码与离线验证，未操作线上账号、数据库或部署。网页操作教程见 deploy/cloudflare/README.md。

## 结构与路由

主站名称不变，执行 Public 应用；新增 <主站名>-admin，执行 Admin 应用。Admin 为私有 HTTP Worker，原站点通过 SITE_ADMIN Service Binding 转发原始 Request，保留 URL、Origin、Cookie、CSRF、查询参数和上传流。没有新增 JS 网关 Worker，也不需要逐域配置 /admin/* Zone Route；workers.dev 和已允许的多个自定义域名共用同一归属表。

| 路径 | 执行位置 |
| --- | --- |
| /、/zh、/en、公开列表/详情/导航、/api/public/*、/media/*、SEO、健康检查 | Public |
| /admin、/admin/*（快传管理除外）、/api/admin/*、/api/assistance/*、/api/backup/*、/auth/*、/setup | Admin |
| /admin/site-sync/*、/api/admin/site-sync/* | Admin 内原 LazySyncRoutes，只管理/监控 |
| /sync/v1/read | separate 仍由 Public 转发原 SYNC_EXECUTOR；inline 保留原 peer 边界 |
| /transfer、/transfer/*、/admin/transfer | 原 Public 脚本持有的 TransferCoordinator |
| /assets/*、/transfer-static/* | 原站点静态资源绑定 |

部署阶段从真实 Public/Admin 路由生成 site-route-ownership.json 并校验，额外明确 /setup 和快传归属。此次校验补入容易遗漏的 /api/backup/business；不是仅匹配 /api/admin。

separate 共 4 个 Worker（Public、Admin、Executor、Native）；inline 共 3 个。原站点维护 Cron 仍唯一，Admin 无 Cron、无 sync_tick、无 Executor 绑定。Native 的 SYNC_RUNNER 仍指向原 main 或 executor；同步调度规则、协议、候选限制、切片、签名和 checkpoint 不变。

这是两个独立站点应用和 Worker 脚本，不是两个完整 FastAPI App 嵌套。后台请求仍经过 Public 的轻量分发入口，再到 Admin；不是绕开 Public 的独立 Zone 路由。不能据此宣称单次调用链获得额外 CPU 配额。Cloudflare Service Binding 请求可在同一服务器线程运行；共享 D1 的压力也仍存在。

## 依赖和模板

- Public 从 web_public 构建，启动不导入 web_admin、完整 web.py、setup、media_upload、后台工具客户端或全站模板。
- Admin 从 web_admin 构建，预加载后台必要声明、密码 KDF、论文/翻译适配器、setup 和上传桥；不导入 Public 路由模块。
- site_resources.py 共享绑定、配置、D1、R2 和身份基础构造。Public/Transfer 不创建密码写入、论文查询和翻译客户端；Admin 按需构造。原 vps/local factory 未改。
- generated_native_resources.py 保持独立，Executor 隔离检查保留。
- 构建生成 generated_public_templates.py（73,569 字节）、generated_admin_templates.py（193,802 字节）、generated_transfer_templates.py（196,984 字节，含原快传资源）。完整 generated_resources.py 只作为构建输入，生成角色资源后从 src 删除。
- Admin 保留登录页及其实际依赖的 public 模板；并非机械删除所有 public 模板。Public 不包含 admin/sync 模板。
- 必要路由/资源定义进入快照；应用仍在请求时创建。inline 专门预加载原 peer/host 声明，separate 不恢复这条执行依赖。
- 原 TransferCoordinator 类、迁移 tag 和 DO 名称保持，房间状态仍在原协调器实例。DO 现在只安装快传所需 App/模板，未安装全套后台路由。
- transfer/backend 六个模块的 payload 导入改为 web_common，避免快传预加载绕回完整 web.py；工具默认值改为读取专用 generated_transfer_templates，Linux 仍读取原 JSON 文件。

上述字节是生成的源码文本大小，不是压缩上传量、快照内存或 CPU 测量。未裁剪所有未被导入的 Python 源文件；本轮的重点是运行导入与模板解析边界。

## 发布与失败恢复

新增 site_workers.py 管理网站角色打包，新增 admin_release.py 管理 Admin 发布；未把 Admin 塞进同步协议打包模块。

SITE-PACKAGE 使用已经安装锁定依赖的 host Python 子进程执行。最外层 build.py 仍可在 SKIP_DEPENDENCY_INSTALL=1 的无 FastAPI/Jinja2 环境启动，避免构建流程重新发生依赖导入失败。

所有产物校验完再修改平台。发布检查同名归属；Native/Executor 准备好后发布 Admin、核对私有入口/无 Cron/配置/产物摘要，再由关联 Builds 发布原 Public，最后激活原同步调度。辅助 dry-run 使用独立环境副本，排除 CI 主站覆盖名称/tag；Public 的 CI 身份保持原样。

Admin 新增/更新自动完成；上传使用固定目标 API URL，不会把 Admin 代码发布到主站名。重试可复用相同产物并补齐可见性/Cron 设置。同名归属不匹配时停止，不自动接管。多 Worker 发布非原子事务，失败可能留下新旧版本混合或暂停调度；修复后重跑构建，不删除数据或自动回滚。

Admin 共享主站 D1/R2 和允许域配置，只需要 SYNC_NATIVE，不持有 SYNC_EXECUTOR、DO 或静态资产绑定。后台环境服务密钥采用固定白名单从构建 Secrets 写入 Admin；不会把辅助发布 API Token 写入运行时。同步密钥继续支持共享数据库配置。

cloud-check 现在校验 Public、Admin、Native、存在的 Executor 的 TEACHER_RELEASE、资源绑定、SITE_ADMIN、私有访问、Cron 和归属。预期版本来自当前源码；不同版本明确报 release_mismatch。平台配置检查不等于 HTTP 业务验收。

## 请求失败与诊断

Admin 转发失败记录 ADMIN-FORWARD、ADMIN_UNAVAILABLE 和 request_id，返回有界 503，取消未锁定请求流；不构造 Public App、不设置全站失败标志。正常转发保留 x-upstream-request-id、x-upstream-component；每个执行端仍有自己的 request_id 和现有诊断。

平台硬性终止可能无法被应用异常处理捕获。因此不承诺拦截所有 1102，不将 1101/1102 吞成成功，也不改变同步恢复策略。

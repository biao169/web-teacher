# v0.16.029 · 第二步：统一暂停与恢复

基于本分支 v0.16.028-step1。唯一初始化 SQL 仍为 `database/schema.sql`；本轮沿用 `service_meta`，不增加表或第二份 SQL。

## 使用

后台“两站数据同步”顶部新增“同步运行控制”：暂停全部同步、恢复同步、刷新状态。仅系统管理员可操作，保存校验登录、权限、CSRF。暂停不依赖连接或密钥可用；修改密钥或排查故障前可先暂停。

开关存入本站数据库 `service_meta / site_sync.paused.v1`。主站、独立执行器、原生辅助读取同一个状态，Ubuntu/Debian 后台循环也受此开关控制。不缓存暂停状态，避免不同实例保持旧值。

暂停后：

- 阻止新任务领取，领取时在数据库 UPDATE 中再次检查开关，覆盖检查后被暂停的竞争窗口。
- Cron 不推进同步；Alarm 和唤醒入口删除待执行 Alarm；执行器返回后再次检查暂停，避免重新挂起 Alarm。
- 正文、候选、清单和原生媒体导出返回 HTTP 503 / `SYNC_PAUSED`，不进行后续读取；原生传输的新步骤也被拦截。
- 不删除任务、媒体分片、已有断点，不改变单条任务的人工暂停/审核状态。定时计划配置保留。
- 已开始的有限步骤允许安全收尾，返回后由原租约所有者释放租约；被平台强制终止的执行等待租约到期，恢复时对账。后台显示尚未过期的活动租约数量。
- 对端明确报告暂停时，任务延后 60 秒、释放租约，保留切片大小与错误计数，并记 `deferred` 事件。

恢复后，协调器清除自身失败退避并重新计算下一次唤醒。仍遵守任务下次执行时间、活动租约、授权和人工审核；不会把人工暂停任务全部改为运行。通知失败时数据库开关仍已保存，后台显示“调度器未确认”，Cron/后续唤醒兜底。暂停期间的任务取消/删除清理会在恢复后继续。

**边界：** 暂停不是跨 Worker 的强制终止或内存回收命令。已进入网络传输或数据库提交的步骤可能完成当前操作；不会强行清空其租约以引入重复写入。此步不承诺立即消除 1101/1102，也不解决首次 Python 应用构建开销。普通网页读取不增加暂停状态查询；现有整站恢复写锁仍按原策略保护提交中的数据。

## Cloudflare 网页应急操作

优先用网站后台开关，无需重新部署。后台无法进入时，可在 Cloudflare 的 D1 数据库控制台执行：

```sql
INSERT INTO service_meta(key,value) VALUES('site_sync.paused.v1','1')
ON CONFLICT(key) DO UPDATE SET value=excluded.value;
```

它供共享该 D1 的主站和辅助使用。下次调度/导出入口读取后停止新同步；已有在途步骤按上文收尾。恢复可在后台点击按钮，或把上句值改为 `'0'`，等待后续 Cron/唤醒。不要删除租约、分片或同步任务表。

可选应急变量 `TEACHER_SYNC_PAUSED=1` 的优先级高于后台开关。本版支持在主站项目的**构建变量**中设置后重新部署，部署脚本自动写入主站、原生辅助及 separate 执行器配置；恢复时改为 `0` 并重新部署。若只在某个 Worker 的运行时设置中修改变量，不会自动同步其他 Worker 的设置，建议使用共享 D1 开关。后台会提示环境变量暂停，避免误以为点击恢复已解除。

Ubuntu/Debian 也可设置进程环境变量 `TEACHER_SYNC_PAUSED=1` 并重启服务；恢复改为 `0` 后重启。日常操作仍推荐后台开关。

按现有教程部署本完整包，原生辅助会自动更新，separate 执行器也随部署更新。无需新增必填变量。

## 主要文件

- `site_sync/integration/control.py`、`control_api.py`：持久开关、权限接口、活动租约状态。
- `site_sync/integration/host.py`、`worker_schedule.py`、`web.py`：后台循环、调度和导出入口。
- `site_sync/adapters/tasks.py`、`core/engine.py`：领取时原子拦截、对端暂停的无惩罚等待。
- `site_sync/worker/control.mjs`、`sync_coordinator.mjs`、`native_service.mjs`、`native_dispatch.mjs`、`source_media.mjs`：共享状态、Alarm/RPC/媒体入口。
- `site_sync/frontend/static/control.mjs`、`frontend/templates/page.html`：统一后台风格的控制区。
- `deploy/cloudflare/pipeline.py`、`site_sync/integration/package.py`、`deploy/cloudflare/runtime/entrypoint.py`：应急变量部署与主站导出快速拦截。

# v0.16.047 — 同步接收响应边界修复

基于本分支 v0.16.046。保留 separate executor、签名和授权规则；不修改数据库或既有任务。本轮未线上发布，未取得用户指定 Ray 的 Cloudflare 日志。

## 发现与修复

已核对项目锁定的 workers-py 1.17.4 SDK：service binding fetch 返回 Python workers.Response（headers 为 HTTPMessage），原生 Response 存放于 js_object；workers.asgi.fetch 返回原生 JS Response。原诊断装饰器将两者直接作为 JS ResponseInit 使用，遗漏 SDK 包装归一化。该边界可能在 executor 已成功返回后、主站添加追踪头时抛出异常；因此不能仅凭公网 1101 判定 executor 内部失败。

- deploy/cloudflare/runtime/request_diagnostics.py：复用原装饰器，先取 js_object，再包装响应。保留流、状态码、签名头；不读取正文、不增加缓冲或依赖。
- deploy/cloudflare/runtime/entrypoint.py：增加 SYNC-FORWARD / RETURNED，记录主站请求 ID、对端握手 nonce（只用于关联，尚未验证）、executor 请求 ID 和 HTTP 状态。
- deploy/cloudflare/runtime/sync_executor.py：延迟导入增加 SYNC-HTTP-IMPORT 异常阶段；ASGI 执行沿用 SYNC-EXPORT。异常继续记录并向上抛出，不吞错。
- deploy/cloudflare/tests/test_request_diagnostics.py、test_sync_isolation.py、test_sync_executor.py：SDK 返回契约、流和签名保留、转发隔离、真实 peer_read 签名握手与应用层 403、executor ASGI 调用及导入异常回归。
- 版本元数据及现有日志 release 字段同步更新。

无新增运行时模块或依赖；共用归一化同时覆盖主站和 executor 调用原生辅助 Worker 的返回值。

## 部署与复查

按现有 Cloudflare 网页构建流程部署完整源码；保持 TEACHER_SYNC_EXECUTOR_MODE=separate。现有流水线会更新原生辅助 Worker 和独立 executor，无需手动逐个发布。确认构建中的辅助部署阶段成功。没有新增变量，不要重建 D1、删除任务或重跑空库初始化。

部署后从 Ubuntu 再次测试；确认 Worker 响应 x-teacher-release 为 0.16.047。成功握手后再查看授权范围，签名/权限失败必须保留应用层错误，不能当作连通成功。

如仍失败，在主站和独立 executor 的日志中按新的请求 ID / nonce 检索：

| 日志 | 定位 |
| --- | --- |
| 主站 SYNC-FORWARD / RETURNED | executor 已返回；用 upstream_request_id 关联 executor |
| 主站 response-wrap 或 INVOCATION-ERROR | 响应装饰/返回边界 |
| 主站 SYNC-FORWARD / ERROR | 绑定调用失败，结合异常栈与 executor 日志 |
| executor SYNC-HTTP-IMPORT / ERROR | 延迟导入或模块初始化 |
| executor SYNC-EXPORT / ERROR | ASGI 执行；结合 INVOCATION-ERROR 异常栈 |
| 应用层 x-sync-error / x-sync-stage | peer_read 的签名、权限或业务错误 |

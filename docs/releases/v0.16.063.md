# v0.16.063 · 媒体摘要与同步任务来源

基于v0.16.062。

## 媒体库

列表首屏不计算引用，显示“待读取”。停留1000ms后仅收集当前列表媒体，每批20个、并发1、批间200ms，逐批更新摘要。复用原summaries()，不调用locations()；保护引用和待核对状态保留，避免误显示为未使用。点击原链接仍打开完整使用位置。

新增GET /api/admin/media/usage-summaries，重复uid参数，最多20个；先验证媒体查看权限，再批量查询资产并一次调用summaries，返回no-store。缺失资产不猜测为未使用。

AbortController取消当前摘要请求，cleanup清理定时器和事件；搜索、筛选、排序、翻页、离页/pagehide、列表刷新停止旧批次，旧响应不写入新DOM。客户端取消不承诺撤销服务端已经开始的一条数据库查询；不创建服务端后台任务，也不继续提交后续批次。现有引用判定内部查询规则完全保留，未宣称可消除其单批计算成本。

## 同步监控

摘要SQL增加operation_id字段，不增加查询；仅mode=scheduled且auto:<schedule_id>:<revision>:<scheduled_time>格式有效时输出source_schedule_id。内部operation_id不返回浏览器。缺失、异常、手动和提案任务不显示来源；通过textContent安全显示在现有身份单元格内，不增加表格列。

## 文件与验证

主要修改：web_admin.py、native-media-parts.html、native-media-locations.js、native-list.js；monitor.py、service.py、panel.mjs。native.js及两处模板仅更新模块版本入口，另更新发布版本标记、回归与文档。

49项Python、21项前端测试通过；Cloudflare separate离线配置、快照导入、前后台边界及executor延迟导入检查通过。未线上发布、未执行真实Cloudflare额度验收。

确认database/schema.sql、media_references.py、同步engine和scheduler原文件未变；无数据库迁移、无新字段、无同步任务创建或执行策略变化。源码仅有一个初始化SQL。测试原始记录见validation-v0.16.063。

## 已覆盖的业务链路

| 场景 | 本地/离线验证 |
|---|---|
| 手动拉取 | 服务端默认确认，浏览器不参与后台推进；显式人工审核仍等待批准 |
| 手动推送 | 接收端审核一次，或按接收端预设范围自动确认；发送端不能放大权限 |
| 定时拉取 | 自动创建任务；同一对端防重叠；暂停任务不被计划偷偷重启 |
| 小切片与大上限 | 4KiB最低切片、4m输入、参数继承、正文切片与原生媒体流边界 |
| 多次中断 | 真实本地进程终止后重开数据库；模拟D1双执行器竞争和连续40次中断；保存进度后重置连续失败计数 |
| 长时间恢复 | 每次请求重新签名；快照同内容重建；内容变化拒绝混拼；R2失效上传会话恢复 |
| 前台访问 | 真实本地HTTP两端同步、媒体发布和前台请求并行；不把容器结果当成线上性能保证 |
| 任务监控 | 分页轮询、折叠进度、日志、暂停/恢复/取消/删除；越权拒绝和文本转义 |
| 数据清理 | 删除活动任务先取消和清理；不删除已同步业务内容；日志与元数据分批清理 |
| 维护与部署 | 统一维护入口、同步侧栏；空库初始化/结构比较；主站及独立执行器绑定和Cron生成 |

## 本地复验入口

安装项目开发依赖后，在源码根目录运行：

```bash
python -B tests/run_acceptance.py --report acceptance.json
```

此命令覆盖整站Python测试、两种模式离线部署和可用时的原生Node测试。Node缺失会在报告中显示 `not_run`，不得视为原生测试通过。

安装 `tests/package.json` 中固定版本的测试依赖后，可加入DOM检查：

```bash
npm ci --prefix tests
python -B tests/run_acceptance.py --dom --report acceptance.json
```

Playwright及Chromium已安装时再加入 `--browser`；明确请求的浏览器检查失败将令验收失败。`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 可指定已安装的Chromium路径。不要将运行生成的报告、数据库、媒体或环境密钥混入源代码发布目录；如保存验收报告到源码内，重新生成发布清单。

## 新站部署

数据库只从 `database/schema.sql` 初始化。本包按首次部署使用；使用专属空数据库和媒体位置。已有不匹配结构会被拒绝，不自动清空用户数据。

- **Windows**：按根目录README配置 `deploy/windows/local.cmd`，使用 `deploy/windows/start.cmd`；验收入口是 `deploy/windows/test.cmd`。本轮没有实际执行Windows脚本。
- **Ubuntu/Debian**：可先用 `bash start.sh --port 8003` 做非特权启动；正式安装沿用根目录README和 `install.sh` 的已有流程。安装脚本从配置的Git仓库/分支获取代码，先确保其中确为本次源码；本轮未推送任何仓库。
- **Cloudflare**：沿用 `deploy/cloudflare/README.md` 的变量与构建流程。实际Root directory为 `deploy/cloudflare`，检查/打包/发布分别为 `python build.py check`、`python build.py bundle`、`python build.py deploy`。它们不是本轮已经执行的线上操作。

独立同步执行器请在**构建/部署环境**设置：

```text
TEACHER_SYNC_EXECUTOR_MODE=separate
```

不要仅修改旧主站变量而不部署执行器。两端分别配置本站资源，私有执行器共用本站D1/R2；后台对端地址始终填写对端网站HTTPS地址。两端配置同一随机共享密钥 `TEACHER_SYNC_KEY`，在后台保存连接授权。多个允许访问的站点地址使用已有 `TEACHER_ALLOWED_ORIGINS` 配置。

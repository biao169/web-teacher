# v0.16.052：Step 3 Public／Admin 代码边界

基于 v0.16.051-home-step2。只拆代码边界，当前生产部署继续运行完整站点。没有新增 Worker、修改 Cloudflare Route 或修改数据库。

## 执行路径

原：create_app → 单个 web.py 注册公共、后台、同步控制、快传路由。

新：create_app → create_full_app → create_base（一个 FastAPI）→ install_admin → 本地快传安装 → install_public。

后台特定路由和本地快传路由先注册，公开 /{lang} 通配路由最后注册。完整应用不是两个 App 的 mount，不会重复初始化生命周期、中间件、运行资源或同步循环。

新增 create_public_app 和 create_admin_app。单独的 Public 工厂直接从 web_public 导入；不会导入完整 web.py、web_admin、后台编辑器、媒体管理、维护路由、同步模块或快传模块。Admin 工厂不导入 web_public 路由模块，但登录页仍使用同一套公开风格模板与共享上下文。

## 路由归属与部署边界

- Public：/、/{lang} 内容路由、/{lang}/contact、公开导航、/api/public/*、/media/{uid}、robots/sitemap、/transfer 入口跳转。
- Admin：/auth/*、/admin/*、/api/admin/*、/api/assistance/*、/transfer/login，以及现有同步控制接入。
- 基础：健康检查、请求资源、安全策略、按工厂选择静态资源挂载。
- 本地文件快传的实际路由只在 create_full_app 中安装一次。单独 Public/Admin 工厂不是本轮新的 Linux 部署入口。
- Worker /setup、原生上传、同步 executor 转发和 DO 快传仍由现有平台适配层负责；此步不迁移它们。
- 本轮没有裁剪业务目录、账号权限基础模型或打包模板。共享上下文仍保留菜单/品牌兼容字段，完整 Worker 仍预加载两组路由。物理部署和模板资源裁剪在 Step 4 执行。

Ubuntu/Debian 的 backend/entrypoints/vps.py、deploy/linux/tweb.py、deploy/vps/release.py、deploy/shared/service.py 与上版字节一致。仍一个 systemd 服务、一个端口、一个 Uvicorn worker、一个 local runtime；install_local(app,r) 一次。Cloudflare 继续原网站 Worker + 既有 separate Executor/Native，未新增绑定或 Cron。三种同步模式和已有任务数据不变。

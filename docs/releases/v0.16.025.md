# v0.16.025 · 第一步：修复原生请求与诊断

基于本对话 v0.16.024 修改。同步范围细分和顶部快速导航留在后续步骤，本步只修请求、诊断及部署核对。

## 修复内容

- 原生客户端默认请求函数改为 `(...args) => globalThis.fetch(...args)`，避免将原生 `fetch` 当作 `SignedPeer` 实例方法调用时触发 `TypeError: Illegal invocation`。
- 错误诊断细分请求编码、请求签名、发出请求、HTTP/响应头检查、响应流读取、响应签名验证及元数据检查。
- 增加安全错误分类 `INVOCATION_CONTEXT`、`NETWORK_REQUEST_FAILED`、`STREAM_READ_FAILED`、`NATIVE_TYPE_ERROR`、`REQUEST_TIMEOUT`。不把原始异常消息、密钥、签名或正文传到管理页面；仍保留已有的 HTTP 状态、1101/1102 和可用 Ray ID。
- 清理响应流失败不再覆盖原始请求异常。没有 HTTP 状态不再笼统解释为签名/权限问题；网络分类也不武断判定为 DNS 或 TLS 故障。
- 正常部署本来就包含辅助 Worker 自动更新。本步增加更新后的产物版本核对，不一致则停止主站发布。代码变化自动触发上传；只有相同产物和配置才允许复用。

## Cloudflare 网页如何更新

将本包完整代码更新到当前 `web-py` 分支后，只在**主站**关联的构建项目发起一次部署。无需进入辅助 Worker 逐个粘贴代码或单独创建构建项目。

主站 Settings → Build 保持：

| 项目 | 值 |
| --- | --- |
| Root directory | `deploy/cloudflare` |
| Build command | `python build.py check` |
| Deploy command | `python build.py deploy` |

Build Variables / Secrets 沿用已有配置：

| 配置 | 用途 |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | 主站及辅助服务所在的账户 ID |
| `TEACHER_AUX_API_TOKEN`（Secret） | 本账户 Workers Scripts 编辑权限的辅助发布令牌；不要填同步密钥 |
| `TEACHER_WORKER_NAME` | 与主站控制台名称一致 |
| `TEACHER_SYNC_EXECUTOR_MODE` | `inline` 或 `separate`，保持当前部署模式 |

其他数据库、媒体桶、域名及主站发布凭据不变，本步不新增必填变量。`TEACHER_SYNC_KEY` 可以继续使用后台保存的数据库密钥，无需为了这次修复重新生成。

部署顺序为：检查辅助名称与归属 → 打包当前辅助源码 → 自动上传有变化的辅助 Worker → 核对配置及产物版本 → 发布主站 → 接通回调与调度。`inline` 自动维护原生辅助；`separate` 同时维护原生辅助与独立执行器。

应看到 `AUX-UPLOAD`（相同产物重试时可能为 `AUX-REUSE`）、`AUX-REVISION`、`AUX-READY`，以及主站发布后的 `AUX-ACTIVE`。若辅助更新失败、权限不足或版本不符，本次部署应报错，修正后重试同一主站构建，不需要手工更新辅助代码。

自动更新发生在上述**构建部署脚本**中。只在网页代码编辑器里单独保存/发布主站，或者将部署命令改为绕过脚本的命令，不会执行辅助更新。

## 部署后验证

1. 回到 `/admin/site-sync`，使用已保存的连接测试连通性。
2. 预期 `signed_candidates` 通过；若仍失败，查看新的具体子阶段及错误分类。
3. `fetch_request` 且 `INVOCATION_CONTEXT`：检查是否确实执行本次完整构建，辅助服务是否绑定到预期名称；不要先反复换密钥或减小切片。
4. 获得 HTTP 401/403、签名验证错误或平台状态后，再按实际错误检查授权、密钥或对端运行情况。
5. 对已有暂停任务，在连通性恢复后检查状态并继续；仍在自动重试的任务会沿原断点推进。

本步不修改数据库结构，也不改变 v0.16.024 的清单摘要规则，无需因本补丁清空数据库或重新建立全部任务。

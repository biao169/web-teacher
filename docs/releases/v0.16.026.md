# v0.16.026 · 第二步：分项同步范围与依赖处理

基于本分支 v0.16.025-step1。顶部快速导航工具栏留在下一步，本步完成同步范围细分及实际传输、恢复和授权接入。

## 变更

- 系统管理员的手动拉取、推送提案、定时计划和接收自动确认策略展示 20 个独立项目：媒体、教师、学生、研究方向、项目、论文、专利、课程、学生分类、新闻、导航、网站设置、全局设置、留言、翻译缓存、操作日志、工具设置、角色、账号、权限。
- 移除界面中的笼统“整站克隆”卡片。卡片支持多选、全选、清空及简短说明。
- 账号、角色、权限联动选择并在最后一个事务中一起替换。业务内容的媒体及关系依赖由前后端共同补齐；服务器检查补齐后的授权，不能通过直接调用接口绕过。
- 只发现、传输和恢复所选表及依赖。部分选择按 UID 合并记录，保留目标额外业务记录；全选 20 项才清理目标端多余业务记录。账号组无论是否全选，都会整体替换并撤销目标旧登录会话。
- 每种分项有独立授权标识，清单元数据也逐项检查授权；不能借媒体权限读取账号。传输仍按记录和切片推进，不增加切片审核。
- 任务详情按实际选择的业务表显示恢复进度，手动接收推送仍为整任务批准一次。
- 不修改数据库表结构，继续仅使用 `database/schema.sql`。站点部署身份、同步密钥、任务和运行状态保留在本地。

## 部署与使用

两端更新到本包。Cloudflare 主站网页构建继续使用根目录 `deploy/cloudflare`、构建命令 `python build.py check`、部署命令 `python build.py deploy`。部署脚本会自动检查并更新原生辅助 Worker；`separate` 也更新独立执行器。不要绕过此脚本单独发布主站代码。

本步不增加环境变量；辅助发布令牌等沿用 [上一步说明](v0.16.025.md)。在两端后台重新点击“保存连接与当前授权”，让已有连接获得新的分项授权，然后测试连通性并新建任务。已有定时计划建议停用后按新卡片重新选择范围保存。

操作、覆盖规则和保留内容见 [分项同步教程](../sync-clone-setup.md)。

## 主要文件

- `site_sync/core/selection.py`：项目定义、依赖、元数据范围与界面说明。
- `site_sync/integration/clone.py`、`website.py`、`catalog.py`：分项清单、快照和恢复。
- `site_sync/integration/host.py`、`web.py`、`proposals.py`：分项授权、后台页面与推送策略。
- `site_sync/adapters/tasks.py`、`site_sync/admin/service.py`：任务、计划及实际恢复进度。
- `site_sync/worker/source_media.mjs`：分项媒体读取包含回收站文件。
- `site_sync/frontend/templates/{page,panel}.html`、`static/{panel,connection}.mjs`、`static/panel.css`：卡片与联动。

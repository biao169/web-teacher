# v0.15.124：同步连接诊断与顶部提示

两站更新完整代码并重新启动/部署，数据库结构和依赖不变。无需重建数据库或重新生成密钥。

## 改动

- 复用 `native-notifications.js` 和现有右上角固定通知区。开始、完成、失败均有通知；错误不自动消失，可手动关闭。相同操作更新同一个通知，不按分片刷屏。页面状态及保存的任务进度继续保留。
- 后台定时任务错误在打开页面/刷新后台状态时提示，同一次页面访问不会反复弹出相同错误。
- 区分域名解析、非公网地址、证书校验、TLS握手、连接拒绝、网络中断、超时、HTTP重定向/状态、无效JSON、协议格式、签名、时钟以及Worker请求/流读取异常。
- 每次传输错误附诊断编号，服务器日志关联 `sync_transport id=...`，记录操作类型、目标主机、耗时、异常类型和代码位置；不记录密钥、签名、业务正文或原始异常文本。
- 本地最多尝试4个经过公网校验的地址。只在TCP/TLS建立阶段尝试下一个地址，POST提交后不自动重发，避免重复推送。证书验证失败直接停止。
- 网络阶段预算调整为30秒，TCP单地址连接最多5秒；本地系统DNS调用仍受操作系统解析器行为影响，不能把30秒理解为强制终止DNS线程的保证。Worker请求和读取总计30秒。
- Worker不自动跟随重定向，明确提示使用最终HTTPS根域名；响应流清理异常不会覆盖主要错误。
- 实际任务错误保存阶段和数据库是否已提交；不是所有失败都代表“数据未修改”。

## 排查

先在两站分别点击“测试已保存连接”。遇错记录完整提示及诊断编号，在报错站运行日志查对应编号。HTTP错误同时检查对端日志。时钟误差指真实系统时间，不是网页显示时区。HTML/JSON错误可能来自访问认证页、挑战页或反向代理错误页，不能通过关闭TLS验证解决。

本版提升诊断并修正连接回退与提示行为，未连接用户生产站点。实际网络、证书、防火墙或Worker运行限制需要依据部署后的细化错误进一步确认。

# 媒体上传与两站同步：部署后验收

适用 v0.16.043。部署步骤沿用 [Cloudflare 网页教程](../deploy/cloudflare/README.md)、[Ubuntu/Debian 部署](../README.md) 和 [同步密钥设置](sync-key-setup.md)。本轮不新增环境变量、不改表结构、不重新初始化现有数据库。

## 1. 更新与准备

Cloudflare 只连接主站构建项目，Root directory 为 `deploy/cloudflare`，Build command 为 `python build.py check`，Deploy command 为 `python build.py deploy`。保留既有数据库、媒体桶、域名及发布凭据。构建变量 `TEACHER_SYNC_EXECUTOR_MODE=separate` 自动发布主站、原生辅助和独立执行器三个 Worker；`inline` 自动发布主站和原生辅助两个 Worker。不要手动把辅助代码部署到主站。

部署日志应走到 `PUBLISHED`。辅助模块由流水线更新，出现 `AUX-REUSE` 不代表漏更新：以产物核对结果为准；不应通过改归属标记来强行覆盖名称冲突。

Ubuntu/Debian 更新完整源码并重启现有服务，保留数据库、媒体目录及环境配置。不要为了升级重新导入 `database/schema.sql`。已有安装的具体目录和服务名称沿用原安装配置。

两端使用系统管理员访问 `/admin/site-sync`。保存相同同步密钥，再保存对端连接与当前授权；缺少媒体、账号等选项时检查是否使用同一完整版本、系统管理员权限和已保存授权。生成/复制密钥不等于保存。密钥不用手动同步到本站辅助 Worker。

**克隆验收使用独立测试站与测试数据库/媒体桶。** 账号同步会替换目标账号和密码哈希；全选会替换目标业务内容。不要直接以生产站为目标测试覆盖、取消或密钥变更。

## 2. 先验证媒体上传，再开启同步

| 操作 | 检查结果 |
|---|---|
| Worker 后台依次上传 100 KiB、900 KiB、2 MiB 的有效 PNG/JPEG | 成功登记，可预览、下载；下载内容与原文件一致 |
| Ubuntu 上传相同样本 | 同样可预览、下载，文件名显示正确 |
| 在允许大小内继续测试较大文件 | 按后台上传配置检查；不要为验收扩大生产限制 |
| 测试站上传不符合格式或大小限制的文件 | 显示明确错误；不留下已登记的无效媒体 |
| 失败后立即访问首页、新闻、登录、媒体库、同步后台 | 页面仍正常；再次上传有效文件能完成 |
| 测试上传过程中断网络 | 记录请求 ID 与上传会话；恢复后查看是否已登记，避免反复点击造成重复上传 |

注意：浏览器媒体上传当前不是分片断点续传。上传中断可能需要重新上传；过期会话清理和登记保护用于避免孤儿对象与误删已登记文件。它与同步任务的媒体断点续传是两个不同流程。

若上传返回“登记结果未确认”，先查看媒体列表，不要直接删除桶对象。后台登记可能已经提交，只是响应丢失。清理过程需保留已登记媒体。

## 3. 三种同步模式逐项验收

只在接收站开启定时拉取，避免两端同时覆盖。

| 模式 | 操作 | 通过标准 |
|---|---|---|
| 手动拉取 | 目标站选择少量业务与媒体，创建一次任务，关闭页面 | 同一任务在后台继续，默认自动确认，最终内容及媒体可读 |
| 主动推送 | 来源站发起推送；目标站保持默认审核策略 | 来源显示提案回执及目标任务 ID；目标批准一次后继续，不按分片审核 |
| 定时拉取 | 目标站创建启用计划，关闭页面 | 到期创建任务并自动确认；已有接收任务未结束时不重复叠加 |
| 目标端自动确认策略 | 仅授权指定范围，再发起对应推送 | 只在目标端已有授权范围内自动确认，不扩大权限 |
| 计划暂停/删除 | 暂停或删除测试计划，跨过下一调度点 | 不再创建后续计划任务；之前已创建任务及断点仍保留 |
| 页面自动刷新 | 暂停刷新，再恢复 | 暂停时停止页面轮询，后台任务仍推进；恢复后每 60 秒读取状态 |

使用分项卡片选择媒体、教师、新闻、账号、角色、权限等；全选才是完整内容替换。账号/角色/权限联动选择。账号恢复完成后原会话失效，使用来源站测试账号密码登录；再次检查同步连接和计划归属。

## 4. 中断、重试与普通访问隔离

在测试任务已有正文或媒体持久进度后暂停、恢复，确认任务 ID 不变，持久偏移不归零。两端改成相同新密钥后仍应从已有断点继续；403 时先查密钥及导出授权，不将其判为资源不足。

`separate` 模式下，普通页面、任务列表和详情不应执行发现候选、下载或恢复任务。同步执行来自执行器、调度器或明确任务入口；签名导出由主站转交独立执行器。测试同步的同时访问首页及后台，检查网站请求是否仍独立。

传输阶段取消应清理临时分片，尚未应用的业务内容不变。应用阶段取消只能停止后续步骤，**不回滚已应用的数据**，且已发布媒体需保留。平台终止请求时不能保证执行 `finally`，恢复依据数据库断点和租约，而不是 isolate 内存。

不能把应用异常边界解释为能捕获平台强制终止，或能主动销毁 Cloudflare isolate。若普通页面仍报错，必须单独定位主站的请求日志与初始化路径。

## 5. 错误取证

记录版本、主站/原生辅助/执行器名称、任务 ID、request ID、Ray ID、colo、country、阶段及子阶段、checkpoint、HTTP 状态、错误码、异常栈、最近成功进度和下次执行时间。后台时间统一按 Asia/Shanghai 显示；平台日志如采用 UTC，比较时换算为 UTC+08:00。

- `1101`：查具体异常及堆栈；未完成的 Promise、错误调用上下文等也可能导致此码。
- `1102`：结合平台资源日志定位；不要仅凭网站响应把 CPU 和内存原因写成已确认。
- `CredentialRetryError` / 403：核对两端密钥、连接启用状态、导出范围和当前账号授权。
- `MEDIA_STORAGE`：检查对应原生辅助 Worker 的 R2 写入日志。
- `MEDIA_STREAM`：检查请求流中断及原生调用日志。
- `MEDIA_SESSION` / `MEDIA_EXPIRED`：检查上传会话和期限；不是同步任务的正文切片错误。

无法获取平台 outcome 时保留“未知”，不要根据 CN/MXP 或 US/EWR 判断原因，也不要针对国家或 PoP 写特殊分支。可临时暂停同步观察普通页面，收集证据后再恢复。

官方错误说明（2026-10-08 核对）：[Workers Errors and exceptions](https://developers.cloudflare.com/workers/observability/errors/)。

## 6. 离线验收命令与报告

使用独立开发环境，安装项目依赖，以及测试依赖 `pytest`、`pytest-subtests`、`httpx`、`uvicorn`。Node 环境需要可导入的 `miniflare`；若安装在其他目录，将 `MINIFLARE_MODULE` 设置为其模块入口的绝对路径。脚本不自动安装依赖、不发布、不连接生产站。

在项目根目录运行，输出目录必须尚不存在：

```bash
python tests/acceptance_media_sync.py --output /tmp/teacher-acceptance-043
```

报告目录包含 `report.json` 与各阶段 `.log`：

| 阶段 | 覆盖 |
|---|---|
| python-regression | 同步模式、签名、账号/媒体恢复、权限、断点、进程中断、普通路由隔离及媒体异常登记保护 |
| javascript | 原生传输、前端状态刷新与提案行为 |
| workerd-rpc-r2 | 真实本地 workerd 的原生 RPC、R2 流式上传、D1 二进制绑定、错误后再次上传 |
| stage-inline / stage-separate | 两种模式的离线打包、快照及执行器依赖导入、资源一致性、Ubuntu 配置生成 |

任何阶段失败，脚本退出码为 1，报告给出日志位置。没有 workerd 环境时可显式传 `--skip-workerd`；报告标记 `partial`，不能算完整验收通过。缺少依赖默认是失败，不会自动跳过并报成功。

这些测试不等于已跑通部署后的 Python Worker FFI、真实 Cloudflare 套餐 CPU/内存限制或特定 PoP。线上验收仍须按前述步骤执行。本轮也未做浏览器截图视觉验收。

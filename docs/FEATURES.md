# 当前功能与使用手册

本文只说明源码现有功能。函数调用与文件位置见 [函数索引](FUNCTIONS.md)。内部函数不是无权限检查的公开API，外部操作应使用站点页面或已安装的路由。

## 2. 后台内容与权限

后台统一处理教师、学生、研究方向、项目、论文、专利、课程、新闻、导航及网站配置。列表提供分页、搜索/筛选、排序、列显示偏好和表头交互。编辑采用字段元数据与统一模板，写入需通过权限、字段验证和版本戳检查。

| 功能 | 操作方法与限制 |
| --- | --- |
| 内容增删改 | 进入对应模块；编辑提交携带记录版本戳，冲突时先重新读取，不能强行覆盖 |
| 学生分类 | 配置分类条件与顺序；预览匹配结果，学生按规则进入分类 |
| 论文辅助 | 配置元数据供应商后检索/解析，核对结果再写入；通讯作者等按编辑器配置处理 |
| 翻译 | 配置服务与凭据；查询来源、分组及批次，按来源版本复用/选择译文 |
| 新闻富文本 | 支持图片定位、尺寸控制、编辑工具及PDF等媒体；媒体权限独立检查 |
| 媒体库 | 上传、预览、选取、引用检查、回收站及永久删除；已引用文件受保护 |
| 账号与角色 | 用户、角色、会话管理及模块权限；系统/本人/被引用对象有删除约束 |
| 留言与日志 | 处理留言；查看只读审计日志，不将其当作可随意编辑的业务记录 |
| 业务导出与恢复 | 在“数据与备份”选择范围；恢复先预检与确认，敏感范围受额外权限控制 |
| 运维与清理 | 后台查看运行与清理状态，预览候选再执行；不会把所有媒体当缓存删除 |

后台内容入口通过 [Content](../backend/app/native/content.py) 和 [Auth](../backend/app/native/auth.py) 统一执行业务与权限约束。不要在扩展功能中绕过它们直接更新表。

## 3. 文件互传

入口 `/transfer/`，后台工作区 `/admin/transfer`。与主站共用认证、数据库和HTTP入口，不需要开放独立快传端口。

- 局域网直连：双方在线，经网站协调后由浏览器传输；是否能直连取决于浏览器与网络环境。
- 在线中继：双方在线，数据分片经过服务端，使用服务器带宽。
- 离线缓存：发送方先上传到暂存空间；接收方在有效期内获取，受容量、下载次数和配额控制。
- 接收码：两位字母加四位数字；接收码不提供发送方控制权限。原分享链接也可使用。
- 文件夹：验证相对路径、分片传输；浏览器支持目录保存时保持目录结构，否则使用界面提供的兼容方式。
- 管理：总量及用户/角色/匿名规则、日周月流量、单文件大小、并发、存储与清理期限等。

“在线不限总文件大小”不等于不受资源、配额或平台请求限制；实现采用有界分片。详见 [文件互传设计](reference/file-transfer.md)。

## 4. 异地网站同步

入口：后台“数据与备份”→“两站同步”。双方配置对端HTTPS地址和相同共享密钥；先测试连接，再生成预览。连接通过不代表业务同步已经通过。

| 模式 | 工作方式 |
| --- | --- |
| 手动拉取 | 接收站生成候选，选择条目/依赖，明确确认后分步执行 |
| 待批准推送 | 发送站提交提案；接收站重新核对并人工批准后执行，不自动接受 |
| 定时拉取 | 仅在接收站开启；依据保存的模块与授权分步拉取，浏览器关闭后由后台调度推进 |

自动预览按所选模块两端更新时间倒序选取最多最新500项候选，依赖另行分步准备；未入选旧内容不因截断而删除。任务可涉及业务条目删除，但不删除本站独有媒体。相同正文候选也可覆盖，不做全文相同跳过。

任务状态显示保存检查点、阶段、读写/媒体进度、父子任务、等待与错误原因。20条/页，默认每60秒刷新；查看不会触发续跑。“等待完成回执”不能证明进程仍在运行；逾期也不自动等同失败。

Worker使用较低批量与16KiB媒体协商分片，本地之间默认64KiB；临时失败进行有限退避。切换内容主站前关闭原接收站的定时拉取，避免两端互相覆盖。详见 [异地同步设计](reference/site-sync.md)。

## 5. 日志、缓存和运行数据

本地常用位置以配置为准：运行日志在 `data_dir/logs`，主站缓存为 `cache_dir`，维护检查点在 `data_dir/maintenance`，快传实体为 `transfer_media_dir`。VPS多实例各自独立；Worker使用绑定的D1/R2及平台日志。

运行日志、业务审计日志、匿名读取内存缓存、媒体审计报告和快传离线文件是不同对象，清理时分别处理。维护默认保留业务日志180天、快传历史90天；日志文件默认10MiB/5个归档/14天，实际以已保存策略为准。维护只处理可识别、到期且符合保护条件的对象。

VPS可使用 `tweb paths`、`tweb logs`、`tweb cleanup-preview`、`tweb cleanup-run`、`tweb cleanup-status`；多实例替换为对应命令，如 `tweb2`。详见 [日志缓存设计](reference/log-cache.md)。

## 域名与会话

部署入口读取 `TEACHER_ORIGIN` 作为主域名和 SEO 来源，`TEACHER_ALLOWED_ORIGINS` 为逗号分隔的完整 HTTPS 来源白名单，主域名自动包含。网站请求、登录/注册、留言、后台操作及媒体链接使用共用域名策略；开发调用可通过 `AuthConfig.from_origin(primary, allowed_origins)` 显式配置多个完整来源，详见 [函数索引](FUNCTIONS.md#域名策略基础接口)。

每个域名单独登录，Cookie 不跨域共享。同一白名单内的不同域名也不能相互跨来源提交表单。多个站内域名的媒体地址解析到同一媒体记录，仍受原权限控制；canonical 和 sitemap 统一指向主域名。Worker 与本地服务均读取白名单；Ubuntu 安装和管理命令用 `--allowed-domains` 接收不带协议的域名，生成相应环境变量与代理示例。域名和路由仍须实际绑定到同一服务。

文件互传的局域网协商、在线中继、接收码、离线缓存与接收接口共用网站来源策略。本站其他白名单域名的分享链接可粘贴到当前传输页，验证后转换为当前域名，沿用当前登录状态。不同域名共用任务、接收码和额度；域名切换不会增加下载次数、重置限额或赋予权限。

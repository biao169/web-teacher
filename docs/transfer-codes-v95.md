# v0.15.95：统一六位传输码后端

此步骤不改快传页面；第三步接入码的展示、输入、复制和接收状态。

## API

以下均为同源 POST JSON，前缀 `/transfer/api/codes/`。已登录请求须携带现有 CSRF 请求头；匿名请求仍受模式、访客和方向权限控制。

| 接口 | 请求 | 返回 |
| --- | --- | --- |
| `issue` | `mode`（`lan`、`relay`、`offline`）、`target`（原内部会话/任务 ID）；在线模式另带发送端 `key` | `code`、`mode`、`expires_at`（毫秒） |
| `resolve` | `code`；在线模式另带接收端随机 `key` | 在线：`mode`、`session`、`expires_at`；离线：`mode`、`token`、`file`、`expires_at` |
| `revoke` | `code`；在线模式另带发送端 `key` | `revoked` |

发送页面先按原流程创建任务。在线会话创建后可申请码；临时分享上传完成、状态 ready 后申请。相同活动任务重复申请返回原码。文件和文件夹使用同一机制，在线文件夹仍须完成清单封存后才能配对。

在线解析直接调用原有 join；返回的 session 与原 join 相同。接收端继续使用原来的信令/中转接口，不获得发送端 key。离线解析返回派生的长接收令牌，可以调用现有 `/api/share-info`、`/api/receive`、目录接收接口或 `/s/{token}`。它不泄露原分享令牌，也不授予发送端管理权限。解析不扣下载次数；开始接收时仍由原流程原子扣减次数、预留配额。

## 生命周期与边界

- 使用安全随机源，严格两位大写字母加四位数字；解析允许小写和首尾空白。数据库全局唯一，冲突最多重试 32 次。
- 在线码最长 30 分钟，原会话租约、取消、服务器重启会使它提前失效。30 分钟后发送端可重新申请码；不改变在线传输的内存块上限和文件大小设置。
- 离线码到期时间等于原分享到期时间，重启后仍可解析；分享暂停、删除、到期、下载次数用尽或策略禁止时不能接收。
- 撤销阻止此码的后续解析和派生令牌的新接收请求。已经获准建立的传输会话和原分享链接不因撤销短码而失效；停止传输请取消原会话或撤销原分享。
- 撤销或过期的码保留至原有效期结束至少 24 小时，避免立即重新分配。清理在申请码时执行。
- 每个客户端 IP 每分钟最多 20 次短码操作，每进程最多 600 次；包括错误输入和失败鉴权。计数内存有界，请求体最多 2 KB，读取超时 10 秒，响应禁止缓存。
- 六位码空间有限；只分享给预期接收方。保留现有 HTTPS、身份权限和流量约束。在线模式仍遵循项目现有单进程会话部署方式。

## 数据库

唯一初始化入口 `database/schema.sql` 新增 `transfer_codes`，同步 teacher schema 校验快照。旧数据库与本版结构不同。本步骤按新站开发约定，不添加自动迁移或自动重置。既有历史版本迁移生成器仍生成当前完整结构。

## 验证范围

自动化覆盖两种在线模式的发码、大小写输入、发送方鉴权、接收端独占、撤销、取消失效；离线派生令牌、篡改拒绝、下载、到期、重启、撤销后的新接收拒绝、原链接兼容；碰撞重试、接口限流、CSRF、禁用下载及精确 schema 校验。另回归现有流量/分块、文件夹接收、账号整合与部署打包流程。未将模拟 HTTP 测试表述为真实跨设备局域网或云服务器传输验证。

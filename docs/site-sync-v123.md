# 两站同步第四步：v0.15.123

本步补齐后台持续推进、定时拉取及跨平台调度。复用已有预览、依赖选择、分片传输、恢复校验、原子提交和媒体删除服务，不增加数据库表或第三方依赖。与 v120–v122 表结构完全一致。

## 使用方式

1. 两站更新完整源码并重启/重新部署。保留各自数据库和媒体。进入“数据与备份 → 两站同步”，确保已设置对端地址、相同共享密钥且连接测试通过。
2. **仅需关掉页面继续执行**：勾选“关闭页面后继续推进已确认任务”，保存。此后已在本站确认的拉取、已由本站批准的推送任务，会在服务后台继续。普通预览和待批准推送不会自动执行。
3. **需要 B 定期获取 A**：只在 B 开启“定期从对端拉取”，选择模块，设置间隔（5–10080 分钟），输入 `允许定时拉取并同步增删` 后保存。每次重新读取 A/B 最新完整清单，将所选模块的新增、更新、删除以及必要依赖同步到 B。首次下一轮检查即开始；以后间隔从本轮完成起计算。期间不存在两站同时编辑。
4. 主站由同步方向决定，无需数据库“主站”字段。切换为 A 获取 B 前，先关闭 B 的自动拉取，再在 A 开启。不要两边同时自动拉取，以免覆盖彼此的新编辑。
5. 点“刷新后台状态”查看下一次检查、当前任务及错误；打开“最近预览”中的任务可查看实际阶段、重试或取消。页面不高频自动轮询。

## 运行与暂停

- Windows、Ubuntu/Debian：沿用 `backend.entrypoints.vps:app`，网站服务启动后每 15 秒检查一次；无需新端口、独立进程或系统定时脚本。关闭浏览器不影响；停止网站服务后暂停，重启后从保存进度继续。
- Cloudflare：复用原有每分钟 `scheduled` Cron。部署时保留现有 Cron 配置；控制台须能看到每分钟触发器。未开启策略时只读取一项配置，避免初始化 HTTP/快传应用；开启后每次只处理一个分页、分片或提交阶段。日志使用 `SYNC-CRON`，不记录共享密钥或对端正文。快传清理与同步分别执行，一个失败不阻止另一个尝试。
- 每轮完整预览需要读取两个站点的全部支持模块以核对依赖。Worker 首轮常需几十次 Cron，而非一分钟内完成。大文件同样跨多次触发继续。设置的拉取间隔不是“单轮完成时限”。
- 同步授权单独保存，不依赖登录会话，不生成长期登录令牌。保存策略的管理员被停用、密码/角色变更，或连接配置变化后暂停；管理员重新保存策略才恢复。每个受保护写事务核对当前授权和角色权限。
- 关闭后台策略停止之后的批次，正在进行的一次文件操作可能先结束；已提交数据不会回滚。页面“暂停读取/执行”仅暂停该浏览器，**不会关闭后台策略**。
- 实际执行出错后保留任务并停止自动重试。管理员打开任务点击“继续 / 重试”，清除该阶段错误后可交回后台；也可取消并清理暂存。预览阶段失败会按间隔重新读取，不执行半份清单。授权/连接错误会显示原因。
- 定时策略始终是“对端 → 本站”。对端推送仍需本站重新读取最新差异并人工批准；积压的新提案替换旧待批准提案，已批准任务不受影响。

## 数据与媒体边界

继承 v121/v122 上限：最多 2000 条/站、两站预览合计 4MiB、实际变更最多 500 项；媒体单个 20MiB、单次最多 100 个/24MiB。超过上限会报错暂停，管理员缩小模块或手动分批，不会静默截断删除清单。

先校验媒体 b，再原子更新教师/新闻等引用，最后重新检查并删除媒体 a。范围外的必要依赖会纳入同步；无关记录不随之更新。来源或接收站变化、引用变化、同名文件冲突时停止，沿用原有保护。

两站同步只同步业务白名单与相关媒体；不同步账号权限、登录会话、部署密钥、同步策略、日志、留言或快传临时数据。任务和状态持久化到现有 `sync_tasks`/`service_meta`；关闭页面不会丢进度。空闲等待期间不持续写任务状态或生成成功日志。

## 验证范围

使用隔离的两站 SQLite/文件目录和签名 HTTP 请求完成：登出后执行、人工审批后后台续跑、待批准提案不执行、媒体替换及依赖删除、失败暂停/重试、角色/密码/策略撤销、过期配置拒绝、繁忙互斥及本地生命周期停止。D1SQL 使用本地绑定替身验证真实适配器与批次路径；Worker Cron 验证未构造 HTTP 应用及清理失败隔离。

本轮共通过 52 项 Python 测试和 4 项前端 DOM 测试，JavaScript 语法检查通过，数据库初始化 SQL 与 v122 字节一致。覆盖前三步回归、无 sqlite 构建与资源生成。没有连接或操作用户的生产站点；真实 Worker/Pyodide/D1/R2 网络、计费及 CPU 配额，需部署后按上面的操作进行线上验收。不得把本地绑定替身测试当成生产 Cloudflare 验收。

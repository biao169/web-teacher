# v0.15.151：第五步，退避与恢复

## 生效行为

可重试的超时、网络、流中断和429/502/503/504等临时错误，Worker依次等待60、180、600秒，本地平台依次等待5、15、60秒。最多自动重试三次（加首次执行共四次失败），之后暂停，检查点不清空。权限、签名、证书、冲突等错误不自动重试。

服务端在取得任务锁及进行昂贵步骤前检查持久化等待截止时间，提前请求返回429/sync_retry_wait，不推进业务步骤、不增加重试计数；取得锁后再检查一次以协调并发。耗尽重试后返回sync_retry_exhausted，需管理员检查后继续。取消后的清理保留原入口，不回滚已提交内容。

每次开始任务步骤先保存recover_after（5分钟），适配既有任务锁时长。如果Worker被1102等强制终止，异常处理可能没有机会运行；下次根据已保存的running标记等待后恢复。仍在占用的锁不会被绕过。旧任务没有该字段时保持已有兼容逻辑。

前端先读一次持久化状态，再在浏览器本地等待较长的截止时间，不在等待期间持续轮询。显示下次可重试时间，可暂停后续请求。刷新不会清除服务端等待。网络完全不可用、连状态都读不到时停止，需稍后打开原任务。

人工继续不会跳过未到期等待；等待结束或重试耗尽后，可显式继续原任务。恢复时保留候选、选择、游标、媒体宽度/偏移、已提交内容，并清除对应后台任务的失败等待状态；不会清除无关的新任务状态。重新开始沿用既有原子重建流程，活动执行必须先取消并完成暂存清理，不继承旧批准或选择。

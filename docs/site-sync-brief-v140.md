# v0.15.140 — 第一步：轻量候选预览

## 本步范围

手动点击「对端 → 本站 · 预览」或「本站 → 对端 · 预览」，默认采用简要候选模式。

- 仅扫描所选模块，读取 UID、截短到160字符的名称、更新时间；翻译记录额外读取人工翻译标记。
- 简要读取采用 UID 游标，每次最多20条，额外读取1条判断下一页。
- 逐条合并两端编号清单，生成新增、覆盖候选、删除项；不读取正文、不计算全文摘要、不解析富文本引用。
- 两端都有的记录即为覆盖候选，即便内容完全相同。此时不宣称存在真实字段差异。
- 源站缺失的媒体不生成删除项；纯自动翻译记录保持不参与同步。
- 候选明细留在现有 sync_task_items 表；结束时只更新状态与计数，不用 json_group_array 汇总到任务 JSON。
- 列表在服务端筛选和游标分页，每次只返回20项。筛选全选逐页读取，跨页选择保留，最多500项；超过时不改变旧选择。
- 候选阶段没有业务写入、媒体读取或远程写入权限。

## 当前操作顺序

1. 生成简要候选，选择需要处理的记录。
2. 点击「准备所选内容及依赖」。复用现有分批完整快照与依赖准备流程，生成独立的准备任务。重复点击返回同一任务，不重复创建。
3. 准备完成后显示实际差异；相同内容可能从最终清单消失，必要依赖仍会明确显示。原主动选择自动带入。
4. 核对实际清单后，再输入确认文字开始拉取；推送则发送提案，仍需对端批准。

准备过程中刷新或失败，可从「最近预览」打开准备任务继续。候选一旦进入准备，原选择冻结；如需另选内容，重新生成候选。未再次确认前不会写入业务数据。

## 明确保留的限制

本步只完成手动新预览的分离，不等于整个同步执行链已经精简：

- 执行准备仍会读取全部同步模块的完整快照并进行原有比较、依赖分析和结果汇总，因此重负载只是从初次候选预览中移出；准备阶段仍可能遇到1102。
- 接收方审批复核、定时自动拉取、旧版本已有任务继续使用既有完整预览路径。本步不改变它们的批准范围或自动授权含义。
- 原有单记录200KB、单次媒体20MiB等执行限制尚未改变。大正文可进入简要候选，不代表现有执行器一定能处理。
- 全选会保存最多500个编号；筛选仍需在任务的简短候选明细中匹配，不保证其数据库扫描量恒定。
- 未在真实 Cloudflare Worker 或实际 Ubuntu 服务上部署验收，没有承诺消除所有CPU/内存超限。

后续第二步应将完整准备改成所选记录及必要依赖的按需读取、逐条写入与独立检查点，移除上述临时衔接；随后改造媒体传输及审批、调度的统一推进。

## 部署

两站都更新至 v0.15.140。新接口通过 hello 的 brief_preview 能力标记确认；对端未更新时提示先更新，不静默退回重负载流程。

数据库表结构未改变，无需重置、清空或重新初始化。沿用现有任务表。Worker 在构建快照时预载新增预览模块，避免首次请求才导入模块。

Ubuntu 部署源码完整性验证的既有跳过行为未改变。

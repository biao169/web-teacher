# 第七步：本地故障恢复验收，整站接入待确定基线

本包是第一至第六步模块的累计版本，新增本地验收工具，未修改业务同步协议或数据库结构。
没有读取或参考 v0.15.181。第七步尚未整体完成，本包不能直接覆盖教师网站。

## 已实施

- `site_sync/tests/test_process_recovery.py`：使用临时磁盘 SQLite、独立 Python 子进程与真实 SIGKILL。
  领取任务后终止：租约到期前不能抢占，到期后只统计一次中断并减小切片。
  候选落盘后终止：重开数据库后进度仍在，连续失败归零。
  业务提交后终止：重试不重复执行写操作。
  业务事务内部终止：业务写入和条目状态一起回滚，恢复后只执行一次。
  每种场景检查磁盘数据库完整性。非 POSIX 环境会跳过这些测试，不能据此声称已验收。
- `site_sync/tests/verify.py`：重新运行所有本地测试，真实探测浏览器能否启动。
  生成 `site_sync/docs/step7-results.json`，区分通过、失败、缺少环境。
  浏览器启动成功才运行后台交互测试，启动异常不伪装为环境缺失。
- `site_sync/tests/browser_admin.cjs`：截图使用第七步文件名，不覆盖第六步历史证据。
- 唯一初始化 SQL 仍为 `database/schema.sql`，schema 版本仍为 4。

## 运行

```sh
python -m site_sync.tests.verify
python -m site_sync.tests.verify --require-release
```

默认退出 0 仅表示本地可执行检查通过，绝不表示整站可上线。
`--require-release` 在检查失败时退出 1；本地通过但整站/云端未验收时退出 2。
当前 `release_ready` 固定为 false，这是未接入的事实，不能修改布尔值代替真实验收。
这只是验收命令，不是对现有部署脚本新增的强制发布拦截。
